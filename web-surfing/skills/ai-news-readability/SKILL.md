# AI 日报可读性宪章（web-surfing）

> **使命错位修复**：当前 AI 日报走的是"学术 memo"调性，用高密度 inline 证据标签换严谨性。
> 该文件把"视觉动物优先"的格式规范做成独立合同，供 `infra/razer-server/ai_news_prompt.md` 引用。
> 严谨性不降级——所有不确定性信号保留，但**形式**从"inline 粗体灰度化"改为"末尾脚注分离"。

---

## 零、使命排序（硬优先级）

1. **我抽空就能读** —— 不是「读完能复核」，是「30 秒决定要不要往下读」。
2. **证据不缩水，但形式分层** —— 该标注的全部保留，呈现层把"事实"与"质疑"物理隔离。
3. **一次只讲一遍** —— TL;DR 讲过的，头条用"深化"而不是"重讲"；简讯只收 TL;DR/头条外的事件。

---

## 一、十条硬约束（格式级）

| # | 约束 | 违反信号 |
|---|------|---------|
| 1 | **页眉 ≤ 2 行**，四源用 ✅ ⚠️ ❌ 单符号表示状态，详情下沉 | 第 5 行一个 blockquote 塞 ≥200 字 |
| 2 | **TL;DR 每条 1 句、≤ 40 字、至多 1 个链接**，共 7–10 条 | 任一条 ≥ 2 行或含 `[转述]`/HN 分数 |
| 3 | **头条结构固定四段**：三句话速读 + 关键事实（bullets）+ 细读与质疑（bullets）+ 来源 | 大段 prose 直接灰到底，证据嵌在正文 |
| 4 | **正文禁止内嵌证据标签**（`[转述]`/`[仅标题级]`/`[检索快照，域名级]`/`[一手标注]`） | 发现任一 inline 粗体证据标签 |
| 5 | **证据标注走统一脚注**：每条头条/简讯末尾一行"来源"或用 `[^1]` 脚注，不混进事实段 | 事实句尾挂 ≥ 2 个括号标签 |
| 6 | **每段链接 ≤ 2 个**，其余移到"来源"行 | 任一段 ≥ 3 个 markdown 链接 |
| 7 | **「冷读 N 连」改 bullet**，禁止分号串联长句 | 发现 "冷读 X 连：A；B；C；D；E" |
| 8 | **Trending 表格后用 bullet**（≤ 5 条），不写编号 run-on 段 | "榜单特征：① … ② … ③ …" 单段 |
| 9 | **趋势总结 ≤ 3 节**，每节 `### 子标题 + 一句主张 + 3 bullets` | 单段 ≥ 500 字无副标题 |
| 10 | **页脚 ≤ 4 行短语**，详情迁入可展开的「数据源与直读情况」节 | 页脚一句话 ≥ 400 字 |

## 二、分段模板（Agent 必须按此拼装）

### 2.1 页眉模板

```markdown
# AI 行业日报 · {{DATE}}

四源：AIHOT {{A}} · GitHub Trending {{B}} · AI Digest {{C}} · HN {{D}}（{{A}}/{{B}}/{{C}}/{{D}} 取 ✅ ⚠️ ❌）
覆盖 {{DATE}}（含前日仍在前排的条目） · [上期日报 →](./ai-news-daily-{{PREV}}.md)
```

**不写**：直读失败详情、页面 canonical、publishedTime、各源字数。这些**全部**挪到页尾「数据源与直读情况」节。

---

### 2.2 TL;DR 模板

```markdown
## 今日要点

1. **{{关键词}}**：{{一句核心事实或冲突，≤ 40 中文字}}
2. ...（共 7–10 条）
```

**三条禁令**：
- ❌ 条目里出现 HN 分数、评论数、item id、时间戳、历史日报链接
- ❌ 条目里出现 `[转述]`/`[仅标题级]`/⚠️/[推测] 等标签
- ❌ 条目超过 1 行（视觉上折行视同违约）

---

### 2.3 头条精选模板

每条头条固定四段，视觉锚点清晰：

```markdown
## 头条 N · {{emoji}} {{标题，一句话主张}}

**三句话速读**：{{三句平白陈述，共 ≤ 150 字；禁止 inline 括号标签}}

**关键事实**
- {{事实 1，含必要数字}}
- {{事实 2}}
- {{事实 3}}
- {{事实 4，可选}}

**细读与质疑**
- {{冷读 1，一句话一条}}
- {{冷读 2}}
- {{冷读 3，可选}}

**来源** · [主来源 ↗]() · [次来源 ↗]() · 历史线：[上期头条 N ↗](./ai-news-daily-{{PREV}}.md)
```

**emoji 分类映射**（固定，必须对齐）：

| 分类 | emoji |
|------|-------|
| 基础模型 | 📏 |
| AI Agent | 🤖 |
| 开发工具 / 开源项目 | 🛠 |
| 产业事件 / 商业模式 | 🏢 |
| AI 安全 / 治理 | 🔒 |
| 推理/训练基础设施 | ⚙️ |
| 学术研究 / AI for Science | 📄 |
| 政策监管 / 公共事件 | ⚖️ |
| 硬件 / 边缘 | 💾 |

一条头条只取**一个主分类**的 emoji。禁止用 🧮/🎨/⚡/🐳/🧠 等视觉散装装饰。

### 2.5 简讯模板

```markdown
## 简讯

- **{{事件标题}}**：{{一句事实}}。{{一句意义或与头条的关系}}。[来源 ↗]()
```

### 2.7 页脚模板

```markdown
---

*报告生成时间：{{DATE}}*
*主数据源：AIHOT · GitHub Trending · AI Digest · Hacker News*
*检索通道：eacli Token Plan（web.search / web.read）*
*说明：评分为站点标注值；以官方链接为准。*

<details><summary>数据源与直读情况（详）</summary>

- **AIHOT**：{{状态与一手标注说明}}
- **GitHub Trending**：{{N 仓直读/折叠情况}}
- **AI Digest 中文**：{{是否停更、最新一期日期}}
- **Hacker News**：{{首页快照条数、item id 是否可提取}}
- **本期直读失败项**：{{列表，含失败原因}}
- **本期一手直读项**：{{列表，含 URL 与时间戳}}

</details>
```

**整个页脚 ≤ 4 行短语**；详细源情况折进 `<details>` 块（GitHub 原生支持折叠，用户默认看不到）。

## 三、证据纪律（保留，但形式迁移）

**根 METHODOLOGY §二**（证据分级与标注）继续生效。本宪章只改**呈现形式**：

| 原来（inline） | 新（分层） |
|--------------|-----------|
| 「**[转述]**」粗体标签贴在事实后 | 事实段不动，证据级别写到"来源"行标注 `· [主来源 ↗]()（转述）` |
| 「⚠️ 单源」inline 警示 | 挪到"细读与质疑" bullet，一句"该主张单源"结束 |
| 「[检索快照，域名级]」内嵌 | 来源行写 `[域名 ↗]()（快照级）` |
| 「[推测]」散布正文 | 不变——推测本身就该贴在推测句尾，但一个段落 ≤ 1 处 |

**关键原则**：**事实段只讲事实，质疑段只讲质疑**。不要在同一句里既做陈述又做自我质疑。

---

## 四、模型/风格约束（给 Agent 的硬行文规则）

1. **复合句上限**：单句 ≤ 60 字；超过就断句或改 bullet。
2. **粗体加密度**：只给**关键数字、产品名、机构名**加粗；不给整段情绪语加粗。
3. **省略修饰语**：禁用「一场」「一个完整的」「某种意义上」等废话修饰。
4. **术语对齐**：第一次出现时写全称 + 可选英文，之后用简称。
5. **数字必须有量纲**：$0.10/M token，不是「便宜」；+4,655 日增，不是「暴涨」。
6. **去重铁律**：一条新闻只在"TL;DR"或"头条"中选一个主位；简讯只收**既不在 TL;DR 也不在头条**的事件。

## 五、写完后的自检清单（Agent 自跑）

写完报告后，Agent 自己过一遍：

```
[ ] 页眉是否 ≤ 2 行？（不包含标题）
[ ] TL;DR 每条是否 ≤ 40 字、无 inline 标签？
[ ] 头条精选是否每条都有「速读 + 事实 + 质疑 + 来源」四段？
[ ] 全文内嵌 `[转述]`/`[仅标题级]`/`[检索快照，域名级]`/`[一手标注]` 粗体标签是否为零？
[ ] 单段链接 ≤ 2 个？
[ ] 「冷读 N 连」是否全部改成 bullet？
[ ] Trending 表格后是否 ≤ 5 条 bullet，无 "① ② ③" 单段？
[ ] 趋势总结是否 ≤ 3 节、每节有副标题？
[ ] 页脚正文 ≤ 4 行，详情是否迁入 <details>？
[ ] 每条头条 emoji 是否对齐分类映射表？
```

**全绿才算通过**。有一项违反就在同轮内改到绿。

## 六、什么没变

- **章节清单**（TL;DR / 头条 / Trending / 简讯 / 趋势总结）保留
- **证据纪律**（分级、推测必标、无法验证坦诚写明）保留
- **工具约束**（eacli Token Plan-first，禁止直调 WebFetch/WebSearch）保留
- **仓内写入边界**（只允许写当天报告一个文件）保留
- **四源**（AIHOT / GitHub Trending / AI Digest / HN）保留

本宪章**只改呈现**，不改边界、不改严谨性门槛。
