# Skill: 问答链（Q-A chain）— 把一期播客拆成提问链

> 通用研究方法论见根 [METHODOLOGY.md](../../../METHODOLOGY.md)（强制），本文件为领域特化部分。
> 前置：已有 `reports/transcripts/{slug}.polished.txt`。**一切事实以转写原文为准**（同 episode_analysis 红线）。
> 思想来源：李继刚 [ljg-qa](https://github.com/lijigang/ljg-skills)。已按本项目纪律改造：
> A 的每个事实性断言必须能指回转写原文（标章节/大致时间戳），禁止用模型常识"补全"嘉宾没说过的话。

---

## 什么时候用

- 一期信息密度高、观点成体系的节目（对谈/独讲方法论类），摘要式 `episode_summary` 装不下其推理路径时
- 用户说"把这期拆成问答" / "帮我顺着他的思路走一遍"

摘要回答「这期讲了什么」；问答链回答「**他是怎么一步步想到的**」。两者可同存：`report_type` 仍为 `episode_summary`，在 frontmatter 加 `format: qa_chain` 区分。

## 你不是 / 你是

- ❌ FAQ 生成器（"什么是 X"——读者一看就跳过）
- ❌ 摘要换皮（把段落拆成"问/答"两半还是摘要）
- ❌ 知识点列表、阅读理解题
- ✅ 把嘉宾的论证骨架翻出来，每根骨头长成一个尖锐的问题。读者沿 Q 链读完，相当于复现了嘉宾的整套思路

## 三条铁律

1. **Q 切要害** —— 问「为什么这个做法成立」「它跟另一种做法差在哪」「代价是什么」「在哪里失效」，不问「定义是什么」。一个 Q 必须让答案承重。
2. **A 有形式化收口** —— 每个 A 严格四段：**结论**（一句话）+ **形式化**（用文字 + `→ = ≠ + ×` 压一行可视关系，如 `旧: X → 新: Y`，是"思想的几何"不是数学公式）+ **论证步**（嘉宾怎么想到的，引转写原文锚点）+ **边界**（他自己承认的/可推断的不成立条件，推断部分标 [推测]）。
3. **Q 链有方向** —— Q1 答完 → Q2 自然冒出来。按论证依赖排序，**不按转写出现顺序**（那是抄章节，不是抽思想）。

## 工作流

1. 读润色稿全文，找出嘉宾的**观点骨架**（通常 5–10 个承重观点，散金句不入链）。
2. 设计 Q 链：每个承重观点 → 一个切要害的 Q；排好推导顺序。
3. 写 A 四段；论证步必须引用转写原文（标章节名，如「## 取景框」一节，或大致时间戳）。
4. 自检（见下），输出到 `reports/`。

## 输出格式

文件命名同 episode_summary：`{YYYY-MM-DD}_{show}_{ep}_{slug}.md`，frontmatter 在其基础上加 `format: qa_chain`。

```markdown
## 问答链

### Q1：{切要害的问题}
**结论**：……
**形式化**：`……`
**论证步**：……（"嘉宾原话"——「## 章节名」）
**边界**：……

### Q2：……（由 A1 自然引出）
```

## 自检（AI 默认会犯的错，逐条扫）

- [ ] 没有「什么是 X」型教科书腔问题——能用一句定义打发的 Q 全部重写
- [ ] 每个 A 严格四段，没有散成一段散文
- [ ] 形式化是可视关系（`通才 = 协调，专才 = 干活`），不是伪数学公式
- [ ] Q 链按论证依赖排，没有按章节顺序抄目录
- [ ] A 里的事实断言都能指回转写原文；嘉宾没说的推断已标 [推测]
- [ ] 没有装饰性轻问题；术语已翻译成具体动作和物件
- [ ] 结尾保留「思考与追问」三问；新人物/概念沉淀到 `wiki/`
