# 用 AI 三天设计一颗芯片后，一位清华博士决定「开卷」

> 张托肯（清华电子系博士→ETH 博后）是"AI for 芯片设计"最出圈的实操者：deadline 前三天用 AI 从零做出一颗 attention 计算芯片送流片（别人估一个月+），开源的 EDA 桥接工具四个月阅读 4 万+。这期的密度在三个判断：**数字芯片设计是 AI 落地最佳场景之一（"封闭世界的胜利"）、"AI 带我飞"的工作方式（加一→加二）、训模型=教书育人**。

## 一、概览

- **「芯片开卷计划」**：商业价值高的芯片要 99 分以上，但初学者大量精力耗在 0→60/80 分的教科书内容上——这部分应该被开卷、被 AI 极大加速，让人从 60/80 甚至 90 分起步。
- **Agent 渗透率口径**：纯数字芯片 **80-90%+**（"几乎没有一行代码手写"）；模拟芯片缓慢爬升（10%→30%），预计饱和在 **40-50%**；他的第一个 B 站视频给的全流程加权值是 30%。
- **"封闭世界的胜利"**：数字芯片工具链完备、边界明确、易 verify——"做芯片跟编程区别有，但没有想象的那么大"；且 token 消耗想象空间巨大（验证需要几百上千轮工具交互）。
- **"AI 带我飞"**：三天流片项目里"我只提了比较模糊的方向，真正感觉到当领导的感觉，具体任务都是 AI 实现的"；从 AI 的「加一」升到「加二」——派其他 agent 审查中间过程，"我觉得我升职了"。
- **Benchmark 定标**：自造 50 题模拟电路评测（Razavi Bench）——GPT-4o 时代几乎不可用，**2026 年 6 月后的模型已不亚于中上水平研究生**；同模型换 5 个 harness 分数差不太多、换模型则泾渭分明（**模型能力 ≫ Harness**）。
- **最被低估的能力=会用 Agent**："人作为 agent 驾驶员"——熟悉车性、开得快也刹得住、有效送达；批评被动的"AI 中转站"用法。

① Token Grant 与「芯片开卷计划」→ ② 一根 USB 让 Codex 走进物理世界（控电压电流、出波形）→ ③ Agent 渗透率 30%→80-90%（数字/模拟/验证三部分拆解）→ ④ 为何数字芯片是最佳落地场景（易 verify+定制需求爆发）→ ⑤ 三天从零到流片与"AI 带我飞"（反 one button、加一→加二）→ ⑥ 模拟电路画板与开源反馈（两天半 2 万+访问；重写优于修补）→ ⑦ Benchmark 两把尺子（50 题结果、模型>Harness）→ ⑧ 训模型=教书育人、agent 驾驶员、数据基建缺口。

## 四、主要话题

### 1. 三天 vs 一个月（点题故事）

课题组 MPW 拼版，一块面积空着浪费，deadline 前三天临危受命。"所有懂数字芯片设计的人都认为至少一个月到一个半月。"他从零开始让 AI 构思架构定义和每一步，"它教给我，我去想办法验证，验证好了再搬到芯片里实现"。文章《三天从零到流片，AI 带我设计一颗 attention 计算芯片》。**关键不是"用 AI"，是"AI 带我"**——他此前对 attention 硬件实现理解不多。

### 2. 渗透率拆解：数字 80-90% vs 模拟 40-50% 饱和

数字部分"几乎没有一行代码手写"；模拟目前 10-30%，预计饱和 40-50%（经验密集、隐性知识多）；验证的 labor work 归 agent、debug 靠人。芯片设计验证要求极高 → 需要几百上千轮工具交互 → "对模型智能要求更高，token 消耗量还能大幅上升"。

### 3. 反 one button

"我没有任何一个满意的软件是一键/一句话做出来的"——类比"招一个很强的员工也不能一句话干两个月不开会"。两个原因：AI 缺 context 和隐性经验；**人的需求本身不断变化**（芯片最初设计与最终形态往往差很多，边做边开会边改）。这与津晶（319 期）"人只看第一步和最后一步"形成有趣对照：张托肯还要"派 agent 审查中间过程"。

### 4. 重写优于修补

传统开发为向后兼容堆成"屎山版本"；agent 时代"不符合 best practice 就干脆重写"，重构无非多耗 token。开发节奏快上百倍 → 量变引起质变 → 省下的时间多项目并行。

### 5. Benchmark 两把尺子与"模型能力>Harness"

尺子一：相对比较（SWE-bench 式）；尺子二：**绝对能力定标**——"会做芯片"是连续刻度（本科生→10 年工程师），定量回答"哪些任务模型能解、哪些以后不该人干"。50 题结果：今年 6 月后模型≈中上研究生，test time scaling 有效；5 个 harness 同题三遍分数差不多，换模型泾渭分明。他故意"baby sitting"——砍所有模型都会做的题，保留有区分度的，"一步一步培养它，升级打怪"。

### 6. 训模型=教书育人 + 数据基建缺口

"写教程教人一个人一个人看，效率更高的就是直接教模型"——教好模型所有人随取随用。预训练≈义务教育、后训练≈做项目，**好的任务本身就是训练数据**。行业瓶颈：芯片厂商极度重视信息安全，真实数据拿不到只能合成；厂商想要本地模型，而可负担的本地模型效果还有差距。

## 八、思考与追问

1. **"封闭世界的胜利"清单**：他证明数字芯片（工具链完备+边界明确+易 verify）是 agent 高渗透区；按这个判据扫描你的领域——vLLM 源码线（编译+测试可 verify）算几分？研究报告写作（verify 靠人读）算几分？"可验证性地图"是不是该成为选择 agent 渗透顺序的第一判据（呼应屠龙期 a16z 四象限）？
2. **"派 agent 审查中间过程"（加二）值得进工作流吗？** 你的 polish/digest subagent 链目前只有产出端自检；要不要加一层独立审查 agent（对照转写抽核 digest 的引用准确性）？成本是多一遍模型调用，收益是抓"润色稿编造"——在哪类任务上值得？
3. **模型能力>Harness 的边界**：50 题上 5 个 harness 无差异、换模型泾渭分明——这与 ai-learning 的 Bitter Lesson×Harness 线（"能力普及削平表层脚手架"）互证。但张托肯的场景是**单轮问答评测**；在长程任务（芯片设计/软件开发）里 harness 还无关紧要吗？你的 herdr/eacli 编排（本质是 harness 层）的价值，会不会随着模型变强而被重估？
