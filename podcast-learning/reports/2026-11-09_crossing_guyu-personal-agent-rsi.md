# 十字路口对谈谷雨：当模型进步推翻旧方案，持续学习与创业该怎样重新定位

这期节目不是一张年度新闻榜单，而是 NeoCognition 联合创始人谷雨对自己判断变化的回顾。[1] 贯穿访谈的问题是：当模型不断吸收原来需要工程补偿的能力，研究者和创业者应该保留什么、放弃什么，又凭什么确认自己正在创造价值？

最值得带走的结论是：**判断被新结果推翻之后，需要重新定位问题，而不是把“相信模型进步”变成另一条不许质疑的信念。**

## 1. NeoLab 的机会：旧基础设施既是积累，也可能成为调整成本

**节目约 01:13—04:28。**

谷雨原先怀疑创业公司做递归自我改进（RSI）的机会：既要追赶前沿模型，又要拥有可以继续改进的模型起点，资源要求很高。看到新团队的发布后，谷雨开始重视另一种可能：当 AI 更能辅助研发，成立更晚、历史负担更轻的团队，可能更快采用新训练方法。

访谈用一个转述的例子说明：某项技术改动即使被认为有效，也可能因为适配旧基础设施的成本太高而没有实施。对新团队而言，这些既有依赖可能较少。

这个逻辑说的是**调整速度与组织摩擦**，不是“小团队已经不需要数据、算力和工程”。嘉宾也承认，做完整模型训练仍需要大量资源。成熟基础设施还承担可靠性、调度和长期维护等职责，并非只是一种包袱。

同时，应该区分 AI 辅助写训练代码、AI 参与研究迭代，与已经实现稳定、持续的递归能力提升。访谈中对新公司表现的评价是嘉宾的观察，本文没有取得足以独立证明其训练成果或 RSI 程度的实验资料。

## 2. Computer Use 的“手”变强以后，“脑”还缺什么

**节目约 04:28—13:10。**

谷雨将 Computer Use 的困难分成两层：一层是能否可靠操作界面和工具，另一层是能否理解具体业务应该怎样处理。嘉宾认为，前一层随模型进步改善很快，团队曾经用于反复尝试、挑出成功流程并封装为可复用能力的工程，部分失去了原来的必要性。

这是一种特定团队的经验，而不是“所有界面操作已经解决”的普遍证明。但它提出了有价值的诊断方法：

- 模型是不知道该点哪里，还是不知道这件业务需要先满足什么条件？
- 失败来自操作不稳定，还是来自缺少公司内部约定？
- 原有补偿层是在增加可靠性，还是限制了新模型的选择？

模型升级后，可以重新测量这些失败类型，而不是因为某段工程曾经有效，就默认它永远应该保留。

### 长程任务，不一定是一道题做得更久

访谈介绍的 ApprenticeBench，按嘉宾描述，将建筑行业会计场景组织成连续任务。任务涉及企业特定的约定、规则和审批流程，后续任务需要利用此前获得的反馈。[1]

其关键不是某一道题有多长，而是**任务之间不独立**。比喻成工作经历：目标不是让一个会计把一笔账处理很久，而是观察新员工怎样逐渐熟悉一家公司的工作。

官方页面可以核对 ApprenticeBench 面向 Computer Use、持续学习与长程 Agent 的定位；本次未取得完整公开任务与评测细节。[2] 因此，任务数量、分数与内部设置仍按访谈自述理解，不写成独立复现结果。

要检验这种能力，仅看后面的任务做得更好还不够。本文提出的评测问题包括：

1. 不保留经验的同模型基线，后续任务表现如何？
2. 顺序变化后，改进是否仍然存在，还是后面的题本来更容易？
3. 学到的规则能否迁移到新任务，而不是只记住某个答案？
4. 新规则与旧规则冲突时，模型能否修正，而不是持续积累错误？

这些是从访谈推导的验证要求，不是声称该基准已经完成的实验。

## 3. Memory Notes 的上限，被低估的可能是写笔记的模型

**节目约 16:18—17:55。**

谷雨曾认为，通过反复改写 Memory Notes 来实现持续学习不够可靠，因为它不像一个具有清楚性质的优化算法。访谈中，嘉宾修正了对这一方法上限的判断：模型更强以后，提炼、更新和使用笔记的能力也可能提高。

这里有两件可以同时成立的事：

- 外部笔记确实可能改善后续任务表现。
- 它仍可能丢失条件、写入错误、过度概括，或在新情境中使用旧经验。

所以，“写 Notes 有用”不等于“所有持续学习问题都解决了”，也不等于模型权重已经更新。可以把外部记忆、参数更新和运行时缓存分别看待：它们保存的对象、更新方式和失效条件不同。

对一个实际 Agent，更值得检查的是笔记是否保留了来源和适用范围、是否能纠错、是否影响无关任务，以及用户能否撤销不再适用的经验。评估记忆能力，应该看未来行为的变化，而不只是笔记写得像不像总结。

## 4. 相信 Scaling，不意味着停止验证结果

**节目约 13:10—16:18。**

数学能力的进步，也是谷雨修改先前判断的例子：嘉宾原先更看重形式化验证提供的训练信号，后来对自然语言路线的潜力有了更高预期。

本文不沿用访谈中关于具体数学难题已经解决的广泛说法，因为本次没有逐条核验这些成果的发表与验证状态。方法层面的启示是：过去认为某条路径存在上限，并不证明未来数据、训练或系统改进不能改变它。

不过，规模扩展也不是对正确性的替代。一个回答更流畅、一道题更像被解出来，与证明经得起检查，是不同事情。对研究者而言，合理反应是更新预期，并继续检查训练信号、评测方式与结果，而不是从一种确定性跳到另一种确定性。

## 5. 学术评价与人的价值：产出变便宜，判断未必同步变便宜

**节目约 17:55—25:34。**

谷雨对论文投稿、审稿和数量化评价表达了明显失望，认为大量低质量内容削弱了旧指标的意义。嘉宾更看重候选人能否清楚讲述问题、方法和判断，并在问答中体现真正理解。

这些是个人参与学术系统的经验和价值判断，不足以证明整个学术会议体系已经失效。但它指出一个结构问题：内容生产成本下降，不意味着可信评价的成本同比下降。

由此，对人才评估更有用的变化可能不是换一个更长的简历指标，而是检查候选人能否解释：为什么做这件事、什么结果会推翻自己的想法、哪些工作确实由自己完成。

访谈还讨论博士、职业回报与个人志趣。谷雨并没有替所有人给出“该不该读博”的统一答案，而是强调不同人追求不同。节目里的夸张职业比较不宜成为个人生涯决策公式；兴趣、资源、约束和具体机会都不能从宏观趋势中直接推算。

## 6. 灭火器与砖头：技术闭环之外，还需要市场闭环

**节目约 25:34—32:47。**

这一段是访谈中很坦率的反思：一个研究问题即使足够本质、技术方案也自洽，放进创业环境后仍可能变成“拿着解决方案寻找问题”。公司还需要回答它解决了谁的痛点、客户为什么愿意采用、价值如何交付。

“造灭火器还是先卖砖头”的比喻，指向发布节奏：团队可能一直等待足够成熟的方案，而其他人已经用不完美的产品进入真实反馈循环。

但更早发布应与虚假承诺分开。主持人在对话中也强调，不能承诺之后无法交付。一个明确说明能力范围、能被用户验证的早期版本，与把未完成的能力宣称为已有事实，并不是同一种策略。

这里可迁移的经验是：把技术研究循环与客户验证循环连接起来。不要为了让研究显得完整，就无限推迟暴露真实使用问题；也不要为了获得关注，就省掉影响用户判断的限制条件。

## 7. AI 电影与 Personal Agent：从技术尝鲜转向日常使用

**节目约 32:47—40:50。**

谷雨描述了观看 AI 生成电影时，从关注技术痕迹转向投入故事的体验。这是个人观看观察，不是对所有生成视频一致性、版权或商业质量的系统测量。它说明，用户最终可能更在乎交付物是否值得消费，而不只在乎它如何制作。

Personal Agent 的讨论也类似。嘉宾看重的并非“主动性”突然成为一种全新技术，而是持续身份、稳定交互对象、通知与任务完成方式的组合。实际使用中，邮件筛选与优先级提醒成为明确的日常价值。

“一个持续的聊天对象”首先是产品体验，不要求所有任务永远塞在同一个上下文窗口里。实现上仍可以区分任务状态、长期记忆和权限范围。若把连续感等同于无限保存和共享全部历史，反而容易增加噪声与隐私问题。

节目最后对下一年持续学习和 NeoLab 的预测，也应保留为预测，而不是将其写成确定的路线图。

## 本次学习的落点

这期的十个时刻，可以收束成三个检查：

- 模型进步以后，原来的工程补偿还在解决真实失败吗？
- Agent 是单次做得更久，还是能从前面的任务中学会后面的任务？
- 研究与产品的自洽，是否已经连接到用户可验证的价值？

对旧判断保留修订能力，同时对新判断保留证据要求，比简单地“全面相信”或“全面否定”更接近这期访谈的价值。
