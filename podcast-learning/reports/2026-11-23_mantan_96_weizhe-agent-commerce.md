# 卫哲谈 AI 电商：收入来源、购物社区与新入口的利益关系

## 概述

卫哲把收入分成广告流量、履约服务和商品差价，解释公司面对 Agent 入口的不同态度。淡季经营、内容场景和社区，又说明新供给怎样被发现、组合或激发需求。

利益关系贯穿讨论：谁控制曝光，谁承担交付，用户是否得到合适选择。硬件与支付记录提供资源，不自动补齐服务、权限和当下意图。 [节目](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

**提炼句：** 入口换了，生意怎样变，要沿收入和履约往后看。

## 取景框 f(x)

**x｜问题：** 用户先向 Agent 找商品以后，电商的收入和控制权会怎样变化？新的发现方式是否真的改善了购物？

**f｜取景框：** 从收入来源和激励看入口。广告、服务费和进销差价让公司关心不同环节；短期交易考核也可能挤压社区发现和长期体验。

**f(x)｜判断变化：** 应看被分流的是曝光、交易还是履约，而非按平台名字判断赢家。推荐成交后还要看匹配、退货与持续使用，才能判断用户价值。

## 三类收入，怎样改变对新入口的态度

平台靠广告盈利时，消费者在哪里发现商品，影响谁可以售卖展示位置；履约方仍可能负责仓储、配送等工作；自营零售商即使没有控制最初入口，也可能继续赚进销差价。卫哲据此解释，一些公司积极保护 C 端入口，另一些更愿意开放商品和交易能力。

| 收入来源 | 新入口改变的环节 | 需要另行验证的条件 |
| --- | --- | --- |
| 广告与流量 | 谁控制发现、推荐和商家曝光 | 用户是否迁移，付费展示是否进入 Agent |
| 履约服务 | 谁提供仓储、配送及交易服务 | 接口、服务质量、费率与合作安排 |
| 商品差价 | 谁供应商品并承担零售经营 | 采购成本、库存、退货与毛利 |

这是依访谈重构的经济分析表，不是公司财报的统一分部口径。一个平台可能同时拥有几类收入；“留住履约就能活，但只能赚小钱”是卫哲的概括，不能替代各公司的盈利数据。

沿这张表判断时，先定位一笔收入来自展示位置、服务费还是商品差价，再看 Agent 改变了发现、交易或履约中的哪一步。入口被分流，广告收入可能先受影响；继续承担配送的公司仍可能取得服务费，但要核对合作与费率。它给出的是待检验的收入路径，不能只按公司名字划定赢家，用户迁移和服务质量仍决定结果。

这与[蔡伟谈服务供给](./2026-11-23_latetalk_190_caiwei-personal-agent.md)形成了有用对照。卫哲强调供给方可能因为新流量愿意合作；蔡伟强调第三方是否授权、商业合作是否完成，不能因已有入口就默认获得全部能力。开放的经济动力和实际可执行权限，需要分别检查。

## 他为什么希望商家少盯大促，多填补淡季

访谈开头先谈存量经营。卫哲认为，大促时商品打折、流量和物流却昂贵；相比继续冲榜，消除一年、一周、一天中的淡季，更可能利用闲置能力。他用夏季烧烤、便利店会员日和早晨咖啡说明这种安排。[约 02:15—06:40](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

这段内容与 AI 的关系，是后面讨论“发现未被连接的供给”的基础。一艘还有空位的游轮、一家已有设施的门店，可能不缺生产能力，而缺合适用户知道它的机会。

但“淡季毛利几乎就是净利”仍需条件。新增品类、员工时间、损耗和促销并非总是零成本；如果只是把原来会在旺季购买的人提前吸引过来，也不能将新增销售全部当作增量收益。访谈案例是经营经验，本文没有核对其独立财务结果。

## 内容发现与搜索购买，用户的起点不同

卫哲用“先有鸡还是先有蛋”区分两种路径：搜索型购买通常知道要找什么；内容通过场景，让用户发现以前不知道的商品或用途。他举球形冰与威士忌的例子，说明一个具体使用场景怎样连接商品和潜在需求。[约 15:20—24:34](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

他批评内容平台过度变成直播打折场：本来可以解释新用途，却又竞争价格和规模。这是一种对平台方向的评价，不意味着所有内容交易都只应推广新商品；用户通过内容了解价格与比较，也可以获得价值。

好内容带来的自发转发，在他的经验中减少了投流依赖。但制作、运营、商品履约仍有成本；“没有朋友退过某台制冰机”是个人观察，不能写成产品退货率为零，更不能证明内容转发总比付费曝光更有效。

本文从这里提炼的区分是：**一次订单的来源，可以是搜索、比较、熟悉场景中的发现，也可以是冲动刺激。** 单靠成交量看不出它属于哪一种；后续满意度、退货与持续使用更能帮助判断匹配质量。

## 社区为什么会在短期压力下被削弱

卫哲回忆，早期淘宝和阿里 B2B 的社区既让用户来逛，也帮助发现新商品。交易相对低频，兴趣交流却可以更频繁。团队曾降低社区入口权重，马云夜间打电话要求纠正；他将这次经历视为自己重视社区的来源。[约 24:34—30:20](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

这是当事人的回忆，本报告没有其他现场材料佐证。它说明他怎样形成经营判断，不能凭一个故事确定后来平台所有变化的唯一原因。

上市公司要定期交出业绩，员工持股也可能让更多人关心股价。卫哲把这种压力类比为应试教育：知道长期该做什么，却容易优先做会进入下一次考核的内容。[约 39:54—41:41](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

这种激励关系同样会进入 AI 产品。若唯一指标是当季交易佣金，模型可能更倾向促成购买；若指标是用户真正完成需求，系统还需要识别无需购买、推迟购买或用已有东西解决的情况。本文据此认为，用户中心要落实到行为评价与利益披露，不能只用一句产品口号证明。

卫哲强调完播与转发是内容指标。它们有助于观察使用，但仍不能覆盖事实正确、内容伤害或购买是否合适；“用户多、停留长”的流量也不能直接等于用户获得更多价值。

## “创造需求”究竟发生在哪里

卫哲讲述埃及旅行：AI 帮他找到可以看日落的位置，以及同时提供夜游、表演和餐食的服务。他将其理解为把选择权还给用户，并让长尾供给被发现。[约 30:20—34:03](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

案例里，想看日落、夜游和用餐的愿望已经存在；AI 主要帮助找到并组合服务。将它称为“创造需求”是嘉宾的宽泛用法。另一类情形是内容让用户发现原本未意识到的需求，比如某个育儿用品。两类机制不同，应该分开观察。

他推测，模型可能从照片、桌号和不同位置的信息推导出最佳座位。**这只是嘉宾对成功结果的原因猜测。** 没有模型检索记录，不能写成系统已被证实采用视觉比较或自动读取桌号的方法。

对 Agent 的评测，可以把未知商品发现、既有需求匹配、套餐组合和最终履约分别记录。更多推荐、更长清单，既可能帮助用户，也可能增加不必要购买。要判断创造了有用需求，需要让用户能够比较、拒绝，并在使用后反馈。

## 支付和硬件为什么可能成为入口，又缺少什么

支付记录可以补充已经发生的消费行为；硬件可以带来分发和持续交互；模型帮助解释当下意图。卫哲据此认为，拥有这些资源的公司有机会建立新入口。[约 44:00—45:30、01:11:16—01:15:35](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

但消费记录没有说明所有动机：付款可能是替别人买，也可能来自一次尝试；历史消费不保证代表当前预算或偏好。拥有支付或医保服务入口，也不能直接推出获得全部医疗内容、更不能默认扩展为所有用途的授权。节目没有展开实际数据权限，这里不能补造。

主持人先假定大厂合规良好，再问用户是否仍需担心数据被用于别处。卫哲在这个前提下较乐观。本文保留前提：**这不是独立隐私审计，也不是已证明任何产品都不会误用信息。** 实际使用范围仍要看用户授权、产品政策和技术执行。

硬件部分，他更看好在已有高频设备中加入 AI，包括耳机、手机和笔，而非要求用户接受全新设备。他提到投资的光帆科技，希望它提供软硬件适配与生态，而非只做一款耳机。[约 50:20—01:01:09](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

这是投资者对项目方向的说明，不能当作产品全部能力已实测。操作系统能组织设备、模型、工具及权限，但不会自然消除功耗和散热限制。模型放在端侧，还需要算力、内存、能耗、更新和联网服务配合。

## “车、路、货”是成本框架，不是芯片设计结论

卫哲把大模型比作车，AI 基建比作路，应用比作货，强调昂贵基础设施会限制应用成本。他认为应用明确后，有机会围绕实际负载调整基础设施。[约 01:01:09—01:06:24](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

这个比喻有助于避免只看模型能力而忽略服务成本。但访谈没有提供芯片设计、功耗、性能或工作负载数据，不能由“通用效率低”推出某类专用芯片必然更便宜。写代码的模型仍要执行神经网络计算，不是把与代码文本无关的 GPU 功能删掉就自动省下相应成本。

他提到端侧可以解决 80%—90% 甚至更多诉求，不同位置的表述并不完全一致。没有任务分布和实测条件，本报告将其保留为方向预期，不写成确定覆盖率。端侧模型、云端模型和工具组合应按任务实际质量与资源需求比较。

## 新入口怎样真正改善购物

卫哲提醒商家理解模型怎样认识货、场景和人，避免只追求短期 GEO 变现。[约 01:20:58—01:24:56](https://www.xiaoyuzhoufm.com/episode/6b0153ef77e5b18a3330994c)

比较实际的落实是让产品资料准确描述用途、限制和交付条件，避免只堆宣传词；用户即使经由 Agent 找到商品，也需要知道价格、适用范围、替代项及售后。这是本文的编辑与资料建议，不是操纵模型推荐的已验证技巧。

实际检验可以沿用户的目的往后追：原本不知道合适商品，就看发现是否带来可用选择；已有明确需求，就看匹配是否准确、价格和条款是否清楚；完成购买后，再看履约、退货与持续使用。推荐数量和成交量只能覆盖部分环节，不能替代这些结果。这是从需求区分推导的评价办法，尚无用户实验结果。
