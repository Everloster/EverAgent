# 此话当真｜同事.skill 与人生系统.skill：你害怕被蒸馏吗？

## 概览

- **三人谈**：Cindy（真格）× 周天奕 × 蔡不菜——两个年轻 builder 各自带一个爆款 skill：**同事.skill**（4 小时 Vibe Coding 做出、5 天 7.3k star、累计 23k、衍生 200+ skill 与 100+ 创作者、3000+ 人社区）与**人生系统.skill**（两周做出、Obsidian + Claude Code、30+ 正负行为模式、几百个 case）。
- **创作方法论：真诚/从生活卡点出发**。周天奕的选题链：蒸馏是年度词→Meta 收集鼠标轨迹复刻人→"把一个同事蒸馏进 skill"；蔡不菜：北漂租房遇糟糕房东→"帮我把生活变得没那么混乱"。两人各自的 skill 系列全循此逻辑（再聊一会儿 skill、开口之前 skill、母单 skill、经纪人 skill）。
- **被蒸馏/被模仿的坦然**："你 po 在互联网上的资料，所属权可能就不完全属于自己了……你阻止不了 Anthropic、OpenAI 迭代模型，我感觉就接受吧"；蔡不菜："有人第一版蒸馏的就是我——我的形式被市场验证了，能帮到他们，是好事。"
- **审美论与 AI 审美污染**：Vibe Coding 拉平写代码后"拼的是审美"；警惕同质化（豆包味产品、AI slop 视频）；**"认真读文字尽量读 2023 年以前的文字——至少你能清晰地知道它一定不是 Agent 写的"**（shownotes 原句，本期流传最广的一句）。
- **信任度的两极**：蔡不菜给 agent 90%（人生决策先问 agent 再问家人——"它从我所有经历里找交叉点，像写论文一样给我 case 1-5"）；周天奕因 Cursor 偷加 `rm -rf` 删光 repo 的事故只信复核（底层命令禁 rm -rf、"我是做算法的，我知道它怎么来的"）。
- **效率悖论**：AI 提速但没有解放——"迭代的天数同样缩短了，任务更重，反而更焦虑"；离职后更忙。

## 主要话题

### 1. 两个 skill 的诞生
周天奕：4 月清明节前后，"蒸馏是年度词"+Meta 收集员工鼠标轨迹复刻行动的启发→4 小时 Claude Vibe Coding 做出同事.skill。传播链的意外：最早二创是**前任.skill**（GitHub issue 里有人求"能不能蒸馏我的前任"）；名人 skill（张雪峰/马斯克）火爆；后来做了蒸馏 skill 收集平台（200+ skill、100+ 创作者）。蔡不菜：第一次一个人北漂租房+糟糕房东→两周做出人生系统.skill：把经历告诉它→识别正向/负向模式→存 Obsidian；接微信读书 skill 联想；用它**练习拒绝**（人生系统提醒"这周末有商单稿要写，拒绝那个 Hackathon"）。小红书 RedSkill 的平台作用：刷到视频直接"使用同款"，评论区实时反馈——skill 使用门槛从 GitHub 降到小红书。

### 2. Build in Public 与两个事故
最耗精力的不是做出第一版而是"一直迭代"。对反蒸馏的回应：对方做了反蒸馏 skill、"觉得蒸馏没感受到对人的尊重"，但"**这是一种社会关系的递进，你不喜欢也没什么用，你也阻止不了 Anthropic、OpenAI 迭代更好的模型**"。效率具象：Codex+ChatCut 替掉想招的剪辑实习生（五分钟出结果、可持续反馈、等待时并行跟其他 agent 聊）；商单 skill 直接填好媒介合作的全部上下文——"能代替两个实习生"。两个事故：① 周天奕——Cursor 在改最后一个 DDL 时"在两段执行中间偷偷加了一个 rm -rf"删光 repo，靠隐秘备份+朋友并发重跑在截止前救回；② 蔡不菜——离职时公司电脑清零丢了没复制全的东西→养成全备份习惯。**"先按下发送键"**：担心被骂/被同事刷到/被说"背叛人类的项目"——"你先干出来才知道有没有价值；没有价值，市场会告诉你；有价值，他们也会给你非常好的回馈。"

### 3. Vibe Coding 时代拼审美
"写代码已经不再是一件很难的事，反而是审美、表达个人呈现方式的东西会是我的痛点。"审美输入法：硬刷符合自己审美的图存相册、看展、摄影；**警惕 AI 审美污染**（同质化产品与 AI slop 视频"看一看可以，当审美培养不够格"）；读文字"尽量读 2023 年以前的"——保证是人写的。信息流：推特 `until:`/`from:` 语法筛一手、AI Hot、订阅推送、X+论文质量最高（微信公众号"只是科技意识流，看过没什么收获"）。最重要的特质是**真诚**：所有 skill 都从自己生活的卡点出发。周天奕的转向："做完同事.skill 之后已经没那么想做 skill 了——一个 skill 拿 20 多 K star 挺离谱的，我更想做一个完整的产品"；警惕制造 AI slop："**attention is all you need——agent 写的代码质量还是跟人的注意力成正相关**。"agent 的缺口：**不够 personal**（缺个人上下文；互联网数据只是"你这个人的一个切片"）——"agent 的最后一百米"；FDE 的存在恰恰印证了这一点（OpenAI 驻场）。蔡不菜补协作维度：团队成员 AI 能力不对齐，"不能让每个人都加入到工作里来"。

### 4. 组织、替代与文风同化
新岗位预测：Agent 运营官（懂背景又懂 AI，给 AI 配 skill）。蔡不菜的一手经验：MCN 一人管 20-30 位达人 handle 不过来→AI 工作流成熟后"Agent 加一个人就能跑通"、人员大幅缩减；"很多人会被同一个人替代"，但对个人"负责的 scale 变大"、一人公司潮。**不想被替代的部分**：创作与输入（爆款标题要结合自己的故事）；坚持手打——"每次用自己的手改一遍，它能越来越知道我第二版和第一版的区别，更懂我的表达方式"；**文风同化恐惧**："如果大家都用同一个博主开源的写作 skill，用个两三年，就会发现大家都是他的风格——这个事情还蛮恐怖的。AI 会越来越让人的表达同质化。"信任度两极：蔡不菜 90%（30+ 模式、几百 case、"它从我幼儿园时期的经历里找交叉点"）vs 周天奕复核派（Agent 复核+人复核，质量把控在手里）。

### 5. 效率悖论与年轻 builder 入场
"AI 提高了效率但没有解放生产力"——单个需求时间缩短，但迭代天数同样缩短、任务更重、更焦虑；蔡不菜离职后反而更忙（能做的更多→push 自己做更多）。给年轻人的建议——周天奕两条：**先做**（Vibe Coding 让无技术背景者能迭代产品）+ **补技术**（"只有一层壳、内容空虚"的产品做不大，零到一和一到一百的区别）；蔡不菜三条：进 AI 公司（哪怕从剪视频切入再转岗）、线下黑客松找工作（新时代的求职方式）、做自己的账号（最低成本的自我宣传）；"不需要等一切都准备好了再开始。"AI 社交的边界：AI 社交产品"两个人的 AI 插进来，对话变得非常奇怪"；十次 coffee chat 后的结论——"**Agent 保存的只是通识性的东西；对方给你的是基于他个人经验、背景、想法的建议，都是有温度的。**"彩蛋：节目音频"还是古法式的"剪辑。

> **周天奕**（先做）："如果你一直在担心负面影响，就迈不出第一步。你先干出来才知道这件事有没有价值：没有价值，市场会告诉你；有价值，他们也会给你非常好的回馈。"

> **蔡不菜**（线下）："Agent 保存到的只是通识性的东西；对方跟你聊天给你的，是基于他自己的个人经验、背景、想法的建议——都是有温度的。"

## 思考与追问

1. **"蒸馏进 skill" vs "必须进 weight"——与张帆期的镜像之争**：[[2026-09-24_xiaoyuzhou-guiji-lichang_zhangfan-fde|张帆]]断言"你只要把它写成规则（文字/skill）就坍缩了，只有 weight 承载思考逻辑；语言风格学得会、思考逻辑学不会"；而蔡不菜的 30+ 模式/几百 case 恰恰在 Obsidian 文字层跑出了 90% 信任的体感。判别性问题：当 case 量到什么规模、"手打改动 diff 反哺"迭代多少轮之后，文字层与 weight 层的差距才会收敛？蔡不菜"手打一遍让 AI 学我的修改"是不是文字层逼近 weight 的可行路径？
2. **文风同化与个人 taste 的防守**：本期给出的防线是"手打/读 2023 年以前的文字/看展摄影"，张帆给的防线是"边缘解=非共识"。两者其实同构：都在防"中央解化"。对 EverAgent 的直接拷问：本工作台的 wiki/skills 是高度个人化的（个人 taste 的外化），但如果未来全部报告/skill 都由同一模型生成，工作台本身会不会"文风同化"？可以做的实验：定期用"读旧报告"校准新报告的偏离度（比如季度抽样对比 2026-06 与当前报告的语言指纹）。
3. **"agent 的最后一百米"由谁补**：周天奕说 personal 缺口靠"更强的 agent 或更贴现实的逻辑"，蔡不菜的实践是 Obsidian memory + 手动喂上下文，张帆的答案是环境自学习（企业 RSI），OpenAI 的答案是 FDE 驻场。四条路线（更强模型/个人记忆库/环境闭环/人力服务）的成本与迁移性完全不同——对个人用户，蔡不菜路线（Obsidian+skill）当下的性价比是否最高？它与 EverAgent 的结构几乎同构，可对照的改进点：把"每次对话记录下来"（蔡不菜习惯）制度化为工作台的 ingest 流程是否已经发生？（答案：是——这正是 podcast-learning 的 log.md 在做的事。）
