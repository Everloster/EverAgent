# Agent 游戏怎样才好玩：自由输入之外，还需要规则、记忆与反馈

AI 能让玩家自由询问嫌疑人、向大臣下达自己写的诏书，也能让开发者更快做出原型。但这些变化还没有自动回答一个游戏问题：玩家做出选择以后，能不能理解结果、积累经验，并且想继续玩？

这期由郑玄主持，少云、简律纯和筱宁分别从投资与制作、开发和体验观察的角度讨论 Agent 游戏。他们对机会和问题的判断并不完全一样，却反复回到规则、设计与反馈。[1] 本文保留这些差异，重点研究《积案拂尘》和《历史模拟器：崇祯》带出的工程问题，也区分已经发生的体验、开发者的方案和行业预测。

## AI 改变制作，与 AI 改变玩法，是两件事

节目谈到的 AI 应用，可以按介入位置分开：

| 介入位置 | 可能改变什么 | 需要怎样判断结果 |
|---|---|---|
| 制作过程 | 代码、素材、原型和工具的制作方式 | 是否减少返工，能否形成可维护的产品 |
| 角色互动 | 理解自由提问，生成对话或行动提案 | 角色是否一致，信息是否符合其所知 |
| 世界运行 | 将玩家行动转成事件并产生后果 | 状态是否可靠，规则与因果是否成立 |
| 玩家体验 | 表达方式、挑战、学习和社交 | 玩家是否理解、投入并愿意继续 |

前一行进步，不能直接证明后一行也进步。一个人更快生成大量关卡，不代表关卡节奏更好；NPC 能回答更多问题，也不代表人物更有吸引力。

少云尤其强调，制作人的工作仍然包括选择要表达什么、设计核心循环、判断什么值得留下。来宾用“零到七十分变容易，后面的三十分很难”描述原型与成熟作品之间的差距。这是经验比喻，不是一套统一评分或已测量的效率提升。

## 《积案拂尘》：玩家可以换问法，案件不能随便换真相

简律纯介绍，《积案拂尘》希望让玩家按照自己的怀疑调查、询问和判断，而不是只点预设选项。角色由 Agent 驱动，案件也被作为事件来组织；AI 既参与案卷生成，也在游玩过程中理解玩家的语义。[1，约 11:04—15:00]

这里最重要的区别是：开始一局时生成案件，与游玩过程中维持案件事实，是两个阶段。嫌疑人可以隐瞒、误解或撒谎，但玩家换个问法，不应让已经成立的关键证据和真相随意改变。

开发者在机核的作品页也将它描述为自由文本审问、非线性推理和案卷生成的尝试，并列出推理画布等功能。[2] 这是作品说明，不是本报告做过的实机验收。

简律纯还谈到一个真实的体验问题：文字太多。模型持续产生信息，玩家却可能越来越疲劳，不知道下一步该做什么。他提到证据卡、人物关系、时间线，以及正在试验的世界观电台，希望让不同表达方式承担叙事。

这个思路值得进一步拆开。缩短回复只能减少阅读量；更关键的是，一条新信息能否帮助玩家提出假设、寻找反证或决定行动。换成语音也不会自动解决信息过载，仍要决定哪些内容必须听见，哪些可以稍后查看。

## 自由度需要设计，随机性不等于涌现

筱宁期待玩家的细微选择能被记住，并在之后产生不同结果。但她也反对把自由度直接等同于“没有攻略、没有确定反馈”。玩家仍然需要理解目标，知道自己的努力为什么有用。[1，约 25:22—39:30]

少云以传统游戏举例，指出涌现并非生成式 AI 才能提供。若多个规则可以组合，玩家同样能发现设计者没有逐条写出的结果。因此，一个系统有意料之外的行为，不足以证明它必须使用语言模型。

他还把某些非阻断性的意外称为可以形成玩法的“bug”，同时明确排除了闪退、黑屏和丢存档等破坏体验的缺陷。这里应保留这个区别：令人意外但仍符合系统关系的结果，可能值得设计者保留；随意破坏已经承诺的规则，则是另一回事。

节目中关于模型容易产出平庸内容的批评，是对作品的评价。不能仅由 Transformer 架构推出所有生成内容必然缺乏创意，更不能把“需要惊喜”理解成不必做一致性和稳定性检查。

## 世界状态、事件与角色认知，分别由谁负责

在讨论《崇祯》时，简律纯明确说自己没有看过该游戏内部实现。他提出的三层结构，是结合自己经验的设计建议，而不是对《崇祯》源码的确认。[1，约 50:49—01:00:34]

| 层次 | 保存什么 | 允许怎样变化 |
|---|---|---|
| 世界状态 | 财政、位置、物品、职务、任务等已经生效的事实 | 由规则校验后的操作更新 |
| 事件与因果 | 谁提出什么行动，影响谁，何时生效或结束 | 保留可追踪的执行与后果 |
| 角色认知 | 该角色知道什么、相信什么、想隐瞒什么 | 可以有误解、遗忘和谎言 |

他用一句话概括这条边界：“角色可以说谎，世界状态不能说谎。”角色没有执行命令，可能是玩法；系统忘记已经生效的命令，则不能仅靠人物设定来解释。

按这个思路展开，一次行动可以经过：

```text
玩家自由输入
    ↓
模型理解意图，提出行动
    ↓
规则检查条件、资源、权限与当前状态
    ↓
提交有效变化，记录事件及后果
    ↓
角色根据自己的认知表达，界面反馈真实结果
```

例如，在一个自拟的游戏里，玩家只有 10 枚金币，却要求购买价格为 12 的物品。模型可以理解请求、解释原因，甚至让商人提出另一种合法方案；但如果规则没有赊账，就不能因为叙述说“成交了”，账本便直接改成已拥有物品。

这不要求游戏取消随机结果。规则完全可以规定掷骰、概率事件或不完全信息。重要的是，随机发生在哪一层、遵循什么约束，以及已经发生的事实如何保存，而不是让每次续写都重新决定世界是否承认上一步。

同样，一个角色没见过某件事，就不应仅因全局记忆库里有这条记录而自动知晓。长期记忆还需要处理知识范围，不能只追求“把所有内容都检索出来”。

## 长期记忆不只是把聊天记录保存下来

聊天历史是模型当前能看到的材料；游戏中的长期后果还需要参与后续计算。例如，一项政策是否仍有效、物品到底属于谁、任务何时结束，应该能够在没有重新询问模型时查到。

2023 年的 Generative Agents 研究提供了一种相关但不同的尝试：保存记忆，根据时近性、重要性和相关性检索，再结合反思与计划组织行为。论文也记录了记忆检索、行为地点和场所规则理解等问题。[3] 它说明这组机制可以研究行为连贯性，不证明某款商业游戏已经获得长期留存或更好的趣味性。

从游戏工程看，可以将需要精确执行的状态与用于表达和决策的记忆分开。模型检索不完整时，角色可能一时想不起一段对话；已经写入账本的资源和事件，不应因此消失。

重复发送完整历史还会增加计算需求。用一个自拟例子，假设每回合比上一回合多带 300 个历史 token，连续运行 100 回合，每次都重发全部历史：

```text
最后一回合的历史：300 × 100 = 30,000 token
累计发送的历史：300 × (1 + 2 + … + 100) = 1,515,000 token
```

这个例子已复算。它不含系统提示、其他 Agent 调用、输出、缓存折扣或实际模型价格，不能直接换算成某款游戏账单。它说明的只是：单次窗口能装下，不代表长期运行成本很小。

简律纯也明确说，并非所有步骤都应使用 Agent Loop。重复、规则明确、时延要求高的行为，可以交给程序或预先设计的流程；模型更适合处理难以穷举的语言与情景。两者结合，才有机会同时保留自由表达与可靠执行。

## 《崇祯》的启发，不止是“能用自然语言下旨”

来宾认为，崇祯这个题材容易让玩家产生“换成我会怎么做”的兴趣，自由下旨又把这种想象变成了输入方式。但输入自由，也会增加玩家的表达负担：不了解背景的人，可能连第一道命令怎样写都不知道。[1]

因此，自由输入需要配合目标、提示与反馈。玩家应逐渐学会怎样判断局势，知道哪些结果由选择造成，哪些来自外部事件。否则，系统虽然不断产生新文字，玩家却未必形成可积累的理解。

对命令不执行或被忘记的情况，筱宁认为设计与缺陷可能同时存在；简律纯强调，角色记忆与系统存储必须分辨。本报告没有该游戏源码，也没有进行复现，不能把节目里的体验直接定性为某一种实现错误。

同样，来宾对商业化成绩的判断，没有在本次获得财务或运营数据支持。它可以与他们对长期玩法不足的批评并列，不能因此变成“游戏已经验证了可持续盈利”的结论。

## 玩家买的是体验，但开发者仍要算成本

少云将定价问题拆成卖什么、卖给谁、怎样卖。Token 是一种成本和计量因素，玩家真正购买的仍是挑战、故事、成长或社交体验。[1，约 01:00:34—01:08:42]

Token 计费与点卡也不完全相同：游玩时长相近，不代表模型调用次数和输入输出长度相近。若玩家不知道一次行动会消耗多少、为什么需要重试，成本的不确定性也会进入游戏体验。

但持续推理有成本，不足以推出所有 AI 游戏都必须采用同一种收费方式。开发者需要结合使用频率、调用策略、可承受成本与目标人群设计服务；本报告不提供当前价格比较或某种商业模式必然成立的预测。

节目对几个小型尝试的讨论，也提醒我们先找到确实不同的体验。筱宁介绍的实时语音角色扮演，重点在快速反馈与情感反应；双人共同影响 AI 输出的例子，趣味来自玩家之间的博弈。AI 的作用要落到具体互动上，而不只是给传统界面加一个聊天框。

这些展会与试玩观察，仍是早期样本。愿意尝鲜、一次玩得投入、长期返回和愿意付费，需要分别观察。

## 更像人的 NPC，未必是更好的角色

简律纯区分了短时精心设计的可信体验，与持续数十或上百小时仍保持一致的角色。两种目标的难度不同，他对未来时间的估计也不是已经验证的路线图。[1，约 01:23:38 后]

少云与筱宁则提出另一种问题：有些传统游戏已经塑造了令人记住的角色，更多对话、更长陪伴和更高自主性，是否真的增加了价值？筱宁尤其看重人物的留白，不认为玩家了解得越多就一定越喜欢。

这意味着，NPC 设计不能只测它能回答多少问题。还要看人物是否有鲜明立场，互动是否推动关系与情节，以及哪些内容最好保持未知。持续迎合玩家，也可能削弱角色原有的张力。

这里没有统一答案。生活模拟、陪伴、推理和动作游戏，所需的角色自由度可以很不同。决定先来自希望提供的体验，再看 Agent 能解决哪一部分。

## 开源工具链与发行：制作更容易，成功并没有自动变容易

后半段对 Godot、Blender、插件和模型工具调用的讨论，主要指向制作管线怎样被重新组织。简律纯提到自己在做相关插件；少云更看好灵活的开源基础；筱宁则提醒，引擎既是生产工具链，也有运行时基础设施的职责。[1，约 01:31:25—01:43:22]

把“大模型像游戏引擎”作为比喻，可以帮助理解它对制作过程的影响；但生成代码、调度工具，与实时渲染、物理、资源管理和状态运行不是同一个职责。本报告没有对 Godot、Unity、Unreal 做基准测试，也不把嘉宾的偏好写成普遍选型排名。

少云进一步认为，当供给增加，获取注意力和接住玩家会变得更重要。这个判断值得讨论，但节目中的成本占比、上架数量或“是否已有爆款”等说法，不是本次重新调查过的市场统计。

最后的游戏推荐也回到了设计：旧的推箱子、构筑或社交机制，仍可能通过节奏与组合产生新体验。它们是嘉宾在录制时的偏好和试玩经历，本报告不据此提供当前发售与购买建议。

若要验证一个 Agent 游戏原型，可以先检查两个层次：同一条规则能否稳定成立，玩家是否能理解并利用它。再观察自由输入是否带来值得保留的新选择，生成内容是否减少理解障碍，以及新鲜感过去后是否仍有挑战与成长。技术演示只是这些问题的起点。
