# 曾晓东谈原生端侧模型：145B 怎样运行，成本与部署又怎样核对

这期最值得追问的一句话是“千亿模型能在消费设备上运行”。总参数量说明模型规模，却不直接说明一轮计算要用多少参数、哪些权重要常驻内存，以及设备能多快取到它们。曾晓东把端侧模型的问题放到模型架构与推理引擎的共同设计上，本文结合公开模型卡和源码文档，把这句话拆到可核对的条件。[节目页](https://www.xiaoyuzhoufm.com/episode/6b05b60544e24a385c034004)

节目约 67 分钟，覆盖创业选择、成本、模型训练、开源与商业化、语音演示及未来预测。曾晓东是无界方舟创始人，具有明确的产品与商业立场。公开资料能核对架构和发布方测试条件，公司收入、客户量及匿名客户案例仍保留为嘉宾自报。

## 为什么耳机的一次性售价碰到了持续成本

约 05:00—09:00，曾晓东解释转向端侧的三个原因：频繁调用云端的成本、网络可用性和延迟，以及数据不能离开部署范围的需求。他举耳机的语音交互、翻译和转写作为高频场景，模型可以在耳机盒的芯片或连接的手机上运行。

一次性卖出硬件以后，用户仍可能多年使用云端服务。厂商如果收不到持续订阅，云端 token 消耗就变成难预测的后续支出。端侧计算把一部分开销转到硬件和用户设备，但仍需要模型许可、更新、存储、电力、维护，以及必要的云端回退。用户数增加时，成本怎样变化取决于这些条件，不能把“本地跑”写成零成本。

一个自拟盈亏关系是：每用户预期云端费用高于本地新增硬件、部署维护及云端回退的合计，且任务效果达标时，迁到本地才有节省空间。对不同设备，要按整个使用周期比较，而不是用某一轮调用的单价决定。

网络好时，本地未必比强云模型更快完成复杂任务；离线或弱网时，本地则可以保证某些功能仍可运行。数据在本机计算也只是数据路径条件，应用日志、遥测、工具调用和远程更新仍要单独检查，不能从部署位置直接推断完整隐私保护。

## “原生”在这次访谈中的具体意思

嘉宾用“原生端侧”区分只把云模型缩小的方案。他主张依据设备的容量、带宽和功耗重新设计网络，再让引擎适配这种架构。这个用法是团队的产品定义，并非已有统一标准。

它也不等于所有模型都从零开始预训练。约 35:00—39:00，他说明小尺寸语音模型可以从预训练开始，而千亿模型受资金限制，使用 Qwen 的已有预训练基础，改专家结构后做长周期后训练。公开文档同样将 Edge0-145B 和 120B 写为源自 Qwen3.8-Flash-Next。[固定版本模型文档](https://github.com/Edge0-AI/Edge0/blob/2e5d284983e3f286a0ef8c94947e6c9db2c86eb3/docs/models/edge0-145b.md)

所以本期的核心主张是共同设计，而不是“端侧必须与已有模型毫无关系”。改架构、低比特训练、量化后的修复和模型蒸馏可以在不同阶段组合；各自收益应靠对照实验判断。嘉宾认为激进压缩会破坏底子，是自己的实践判断，不能替代对所有量化方法的评价。

## Latent MoE 怎么减少专家部分的搬运

公开文档列出 145B 总参数、每 token 约 10.12B 激活参数；每层有 512 个路由专家，选择 10 个，另有共享专家。专家输入从 2560 维投影到 1792 维，在较窄空间内计算，再投影回原宽度。48 层的专家池约 84.6B 参数，还包含注意力、PLE 表和其他模块。

用符号表示一个简化路径：

\[
h\in\mathbb R^{2560}
\longrightarrow z=D_g h\in\mathbb R^{1792}
\longrightarrow \sum_{e\in S}w_e E_e(z)
\longrightarrow U_g(\cdot)\in\mathbb R^{2560}.
\]

\(h\) 是当前 token 的隐状态；\(D_g\) 是某个路由组的降维投影；\(S\) 是被选择的专家集合；\(w_e\) 是专家组合权重；\(E_e\) 是专家网络；\(U_g\) 是升维投影。实际实现包含分组投影与共享路径，此式只解释数据怎样变窄再恢复。

专家尺寸缩小后，引擎可以缓存更多专家记录，也能减少一次未命中时需要搬运的数据。145B 模型的固定专家记录约为 1.63 MB；文档中的专家池参数相对基座减少约 30%。这不是整个模型的参数、FLOPs、峰值内存或端到端时间都必然减少 30%。[架构与专家记录](https://github.com/Edge0-AI/Edge0/blob/2e5d284983e3f286a0ef8c94947e6c9db2c86eb3/docs/models/edge0-145b.md)

稀疏激活只减少当前 token 所需的专家计算。其他专家在后续 token 仍可能被选中，所以它们需要留在某个可读取的层级。引擎根据专家命中、预算和带宽，在显存、主机内存与 SSD 之间安排数据；只是把未激活权重忽略掉，无法正确继续后面的推理。

一个数据搬运下界可以近似为“本轮需要传输的字节数 ÷ 实际带宽”。例如自拟的 1 GB 未命中数据在有效 100 GB/s 链路上至少需要 10 ms，在 20 GB/s 链路上需要 50 ms。还要加调度、算子执行和其他传输。提前预测下一轮需要的专家，只有在预测足够准、传输能重叠且不挤占当前工作时才有收益。

## 145B 为什么不等于 145B 权重全装进 30 GB

若把 145B 参数统一按四比特存储，不计元数据，也已经是 72.5 GB。真实发布包含不同格式、稀疏专家、映射表和按需加载，常驻集合又可以只保留一部分。因此不能拿总参数量与常驻内存直接相除，得出“每参数只有多少 bit”。

模型卡将 Q3_K 的权重构建列为 40.81 GiB，NVFP4 为 47.79 GiB；Q3_K 专家中的 gate/up 和 down 还使用不同格式。PLE 表等资源及运行时缓冲需要另行核对完整文件和加载方式。总磁盘占用、加载的权重、缓存和进程内存应分别记录。[官方模型卡](https://huggingface.co/Edge0/Edge0-145B-q3k)

模型卡的低内存测量用同一张 RTX 5090 D 24 GB，限制引擎显存与进程内存，未缓存专家从 SSD 按需读取。它明确将这些称为测试预算。该数据并非另一张物理小卡，也不是对任何笔记本的配置保证。

| 145B，Q3_K，发布方测试 | Chat decode | Agent decode | 16K prefill |
| --- | ---: | ---: | ---: |
| RTX 5090 D 24 GB，常规配置 | 99.7 tok/s | 121.2 tok/s | 3554.9 tok/s |
| 同卡，16 GiB VRAM＋20 GiB RAM 限额 | 36.8 | 44.9 | 335 |
| Apple M2 Ultra，Metal | 60.9 | 57.0 | 800.3 |

来源为[固定版本速度表](https://github.com/Edge0-AI/Edge0/blob/2e5d284983e3f286a0ef8c94947e6c9db2c86eb3/docs/models/edge0-145b.md)。这些数值不属于本次复现。显存限制、SSD、模型格式、prefill 长度和推测解码配置改变后，速度可以明显不同；表中的 Agent decode 也不是“多少真实任务一定能成功”。

核对还发现文档之间并未完全同步：运行参考页写至少 16 GiB 显存＋20 GiB 系统内存，模型卡又列出更低显存的受限测试；模型卡把调参放在模型包 `model.json`，本次固定版 `edge0-infer` 文档却说只读取其中的 `model_name`，其他参数通过模板及 `--strata-arg` 传入。准备复现的人应绑定入口和版本，不能混抄两套参数。[固定版本运行参考](https://github.com/Edge0-AI/Edge0/blob/2e5d284983e3f286a0ef8c94947e6c9db2c86eb3/edge0-infer/docs/edge0-145b.md)

## 编码评测分数需要怎样校准

约 28:00—34:00，嘉宾强调 coding 能力，提到 SWE 类与 Terminal-Bench 评测以及相对基座的提升。固定版本公开表具体列的是 deepswe 1.1 与 terminal-bench 2.1：145B 分别为 64.6、86.5，Qwen3.8-Flash-Next 为 58.7、83.3。

前一项差 5.9 个百分点，相对基座约提升 10.1%；后一项差 3.2 个百分点，相对约提升 3.8%。这不能统一写成“提高 7%”。其他知识类指标也有升有降，表中并没有支持全面领先的结论。[模型级评测表](https://github.com/Edge0-AI/Edge0/blob/2e5d284983e3f286a0ef8c94947e6c9db2c86eb3/docs/models/edge0-145b.md)

公开页还说明这些是模型级结果，没有把 Q3_K 和 NVFP4 分别做质量评测。本次没有取得完整逐题记录、harness 与运行预算来复验，所以不能将其中某个分数当作本地低内存配置的实测任务成功率。要评价端侧方案，应把同一任务、工具环境、权重格式与设备条件一起固定。

## 训练流水线、收入与开源分别是什么证据

约 11:00—14:00，嘉宾说千亿模型使用约 800 多张 H20，长周期后训练约三个月，口述算力费用约一千多万元，不含早期实验。若八卡机器的 4 万元报价是月租，按 100 台、三个月复算约为 1,200 万元，数量级相近；原话未完整说明计价和全部训练成本。数据合成、人员及失败实验不能被这个数字自动覆盖。

约 36:00—40:00，他将模型研发比作制造流水线，强调常态化数据工程、合成与人工校验。团队“做两百多种模型”不等于独立从零训练两百多个大基座，它可能包含任务、尺寸和部署变体。要判断效率，仍需要区分共享资产和真正新训练的工作。

开场自报 ARR 约 2.17 亿元，shownotes 概括为超过 2 亿元；客户数约 11 万，涵盖厂商、开发者和其他机构。这些尚未由本次取得的财务资料核验。ARR 是年化经常性收入的业务指标，不能直接当作已到账现金、全年确认收入或利润；定制化与部署收入怎样计入也未详细解释。

开源带来部署试用和硬件适配贡献，嘉宾认为它同时帮助获客。权重可取得不表示没有许可边界。模型目前的 Edge0 Community Model License 1.0 明确保留上游条款，对收费模型服务、模型销售及特定独立编码／办公助手等定义了商业保留；并不是所有内部商业使用或付费工作都一概需要另付许可。具体范围应读英文原件及 release scope，框架许可与模型许可也不能互相替代。[官方模型许可](https://huggingface.co/Edge0/Edge0-145B-q3k/blob/main/LICENSE)

## 语音演示与未来预测该放在哪里

后半段演示小型语音模型的对话、翻译和声音模仿，嘉宾称 0.1B 模型约需 500 MB 内存。现场听到的响应能说明演示可用，不能证明噪声、不同口音、多语言和长期功耗都达标；本次也没有用录音精确测量延迟。ASR 对其中英文、日文及歌声的识别不完整，本文没有据这些片段重建逐字回答。

结尾预测高频消费设备会更多转向本地，复杂任务再用云端，并认为端侧部署与 OTA 更换有较高切换成本。这是嘉宾的市场判断。云端 API 的商业利益、硬件厂商的成本与用户的效果要求可能不同，未来厂商选择还会变化，不能写成大模型公司永远不会做端侧。

本项目值得借用的想法，是按任务和设备约束选择执行位置。转写等可离线的高频任务与需要强模型的研究推理可以有不同路径，最终仍以效果、稳定性和全流程成本判断。本文没有部署 Edge0，也没有提出立即替换现有模型的操作。
