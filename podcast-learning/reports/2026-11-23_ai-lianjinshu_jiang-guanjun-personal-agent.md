# 蒋冠军谈 Personal Agent：怎样让一次办成，变成下次还敢用

## 概述

蒋冠军以航班延误赔偿测试展示组合能力：用户只接受现金，航空公司先给代金券，Agent 继续沟通并拿回七十元。随后讨论记忆、授权、工具路径、后训练和完整任务成本。

一次成功展示能力上限，日常使用依赖可靠下限。长期目标比单次代办更难；升级模型可能撤掉临时补丁，但用户需求、服务与评测仍可积累。 [节目](https://www.ximalaya.com/sound/1034046447)

**提炼句：** 一次办成让人愿意试，反复办成才让人敢托付。

## 取景框 f(x)

**x｜问题：** 个人 Agent 偶尔能办成一件事以后，还缺什么，用户才敢把下一件事交给它？

**f｜取景框：** 从能力上限与服务下限看助理。探索新产品关心有没有办法，日常服务关心同类任务能否反复达标，以及失败时怎样发现和处理。

**f(x)｜判断变化：** 模型、记忆与工具要放进同一代办链检查。确认是执行条件，相关性与失效是记忆条件；一次成功或上下文减少不能直接换算成总体成功率和费用收益。

## 思考和代码能力只是起点

蒋冠军认为，模型能规划、判断自己的输出并调用工具，构成 Agent 的初始能力。代码也不仅用来生成网页：它可以把工具和任务路径组织起来。随后，工具生态逐步适配模型，从信息检索走向更多实际服务。[约 01:26—08:30](https://www.ximalaya.com/sound/1034046447)

因此，个人助理至少要同时考虑模型、个人上下文及记忆、服务工具。Coding Agent 较早好用，在他的解释中，一部分原因是代码库提供了较完整的上下文，编辑和编译等工具也相对明确。生活任务常常缺少这些条件：用户没有重新解释自己住哪里、预算多少、某次行程为什么特殊，助手也未必有权接入相应服务。

这套拆解可以用于定位一次失败。先确认目标是否被理解，再看所取记忆是否仍有效，最后查服务是否可用、动作是否获授权、结果是否达到要求。理解错了需要澄清目标；取了旧决定需要修正记忆；服务没有开放则需要解决接口或合作条件，继续增加推理未必有用。这是本文据访谈整理的诊断顺序。节目没有给出三项要素各自的消融实验，也不能据此认定 coding 任务天然简单或某个模型具有固定成功率。

## 支付确认怎样从提醒变成执行要求

主持人用订错不可退机票追问可靠性。蒋冠军首先承认模型仍会出错，再说明系统可以围绕影响较大的行为增加用户确认：订单、交易、数据修改等，不应完全依赖模型自行完成。[约 08:30—13:29](https://www.ximalaya.com/sound/1034046447)

他描述了两层安排。一层在 Skills 中说明接口会造成什么结果、何时应询问用户，依靠指令遵循来引导；另一层可以由系统框架设置强约束，保证必须确认的事项得到确认。节目没有公开完整实现，不能把“可以做双保险”写成所有动作已具有可验证的强制检查。

**本文的工程判断：** 若要求某动作必须得到确认，验收应检查工具执行时是否拥有对应授权，而不只看模型回答里有没有说“我会先问”。工具参数改变后，之前的确认是否还有效，也需要定义。批准某个金额和收款对象，不应自动覆盖另一次交易。

电话案例还讨论了角色身份。嘉宾说 Agent 以助理身份沟通，而非假装用户本人；对外使用身份证或手机号等信息需要授权。这个身份安排有助于区分代理范围，但不能证明每家客服均接受代理，也不能用“帮我办事”替代具体数据披露的许可。

七十元是一个测试结果，不是通话任务的平均收益。节目没有给出失败次数、通话成本、等待时间或所有授权步骤，不能据此计算电话功能的成功率和投入回报。

## 记忆难在存什么、何时使用、怎样失效

主持人讲了一个失败体验：以前讨论过佛教，后来想吃烤肉，助手却又把回答拉回佛教。另一种失败是拿早已否定的十天前信息，覆盖三天前的新决定。它们分别涉及相关性与更新关系，不是多存一些信息就能解决。[约 26:58—35:56](https://www.ximalaya.com/sound/1034046447)

蒋冠军说，存储仍可以是文本；真正的差别在于如何定义记忆的内容、粒度与使用标准。他借“因果关联”解释选择依据，同时明确这不等于实际采用一张知识图谱。节目未提供因果推断算法、检索实现或评价集，不宜补写成某种已证明优于 RAG 的架构。

用户事实与系统抽象又是两类信息。嘉宾举例，用户谈到退休和成年子女未就业，系统可能在事实基础上概括其处于家庭焦虑阶段，用于理解后续问题。[约 35:56—39:47](https://www.ximalaya.com/sound/1034046447)

这个抽象需要经历后续使用的检查。**本文建议：** 写入时区分用户陈述和助手推测；检索时确认它与当前任务相关；新信息到来时允许修正或失效。于是，用户事实、推测和本次要求不会在同一层被当作同样可靠的输入。当前情绪不应长期变成身份标签，本次希望放松也不应被过去目标覆盖。访谈中的抽象属于产品思路，不是心理诊断。

| 信息类型 | 使用前需要确认什么 | 自拟例子 |
| --- | --- | --- |
| 用户明确事实 | 是否仍然有效，是否适用于本任务 | 常住地不一定是此次出发地 |
| 暂时约束 | 有效期和被谁修改 | 这次航班只接受现金赔偿 |
| 助手推测 | 根据什么推断，能否被用户纠正 | 可能因家庭情况感到焦虑 |
| 长期目标 | 与当前事情是否相关，用户是否希望被提醒 | 马拉松目标不必进入每次聚餐对话 |

这是本文对记忆验收的分析表，不是千问公开的数据 schema。

个性化还需要允许从较少信息开始。嘉宾说，新用户没有完整画像，可以在日常使用与本次任务输入中逐步积累；财经账户互通当时尚未做完。知道用户关注某行业，与已经知道其全部持仓，不能相互替代。

## 把常见任务做稳，怎样同时降低成本

蒋冠军认为，用户尝鲜会探索产品能做什么，持续使用更依赖某类事情能否反复办成。抢券、订票也许频率不高，但若结果可预期，用户遇到同类事情就会再用。[约 39:47—45:47](https://www.ximalaya.com/sound/1034046447)

内部观察称，过去三个月单任务平均 token 消耗“增加了一点六倍”。节目没有明确这是相对增量还是增长到原来的某倍，也未给完整样本定义；本文保留措辞，不转换成精确增长率。它至少提醒，用户尝试更复杂任务时，消耗增加不自动等于单位成本优化失败，也不自动证明需求或成功率提高。

降低消耗的一条路径是少走无效步骤：Skills 分层加载，避免相似工具造成选择混乱；与服务方迭代清楚功能范围；提高单步成功率；将常见代码和轨迹封装成可复用工具；压缩相关记忆。模型路由与量化是另一组手段。[约 45:47—50:58](https://www.ximalaya.com/sound/1034046447)

嘉宾说，过去一段时间将“整个上下文”降低约 40%。这不是已公布的完整费用降幅：没有控制任务难度、输入长度、缓存、模型价格和结果质量，不能写成总成本必然降低 40%。它是内部迭代的口述观察。

主持人还直接问，是否可能花二十元抢十元优惠券；嘉宾承认可能。这使成本判断回到任务价值：节约计算有用，但仍要看是否为用户换来值得付出的结果、时间或省心程度。

## 后训练对齐的是实际任务分布

蒋冠军描述，团队从三十多个行业归纳出八千多个较原子的基础能力，再检查这些能力及组合轨迹的覆盖、稳定性和多样性。线上环境与训练环境的对齐，目的是减少普通用户表达与模型熟悉任务之间的差距。[约 50:58—01:00:20](https://www.ximalaya.com/sound/1034046447)

这些是团队自己的分类数，不能看作八千项都已独立达成某成功阈值。访谈未公开能力清单、训练样本、奖励函数或测试结果。它也没有说把每个用户的完整个人数据直接训练进基础模型；嘉宾将个性化信息更多放在运行时输入与上下文中。

他一度用“模型能力可以百分之百”表达一种经验：工程师调整提示与路径后，某任务就能完成。但随后又明确说，用户需求与模型认知不可能完全对齐。前者描述特定条件下存在可行路径，**不构成普通用户端到端任务成功率为 100% 的实测证据**。

这与[Harness adapters 的环境内训练](../../ai-learning/reports/knowledge_reports/Harness_Adapters_环境内强化学习与LoRA合并_深度解析_20261123.md)可以对照：任务环境、工具定义和训练轨迹都会影响模型表现；同一个模型换到不同运行环境，不能直接继承原成绩。千问访谈没有提供同样可下载的训练和消融材料，所以只作机制上的对照。

## 主动提醒需要产品边界，也需要判断时机

好助理可能帮用户发现遗漏会议；不合适的助理可能不断催人回复营销邮件。蒋冠军说，主动服务仍在探索初期，先定义较明确的场景，再让模型判断事件关系、内容和时机。团队希望用语义规则限定范围，主持人将其类比为“产品宪法”。[约 01:00:20—01:06:55](https://www.ximalaya.com/sound/1034046447)

这只是规则设计的类比，不能据此说千问采用了 Anthropic 某项训练方案。节目也没有给出提醒的准确率、打扰率或用户收益。

**本文分析：** 主动行为至少有两次判断。先确认这件事是否属于可以关注的范围，再判断现在是否值得提醒。用户明确取消提醒，应进入下一次执行的有效状态；没有回复，也不能自动解释成同意进一步代办。相关知识可以帮助选时机，但用户偏好和动作权限仍需单独保留。

## 从一个明确事项，到长期目标的距离

“准备一次马拉松”有较明确的对象和训练过程；“半年内升职”牵涉项目、评价、人际关系与机会。嘉宾说，前一类目标可以较好跟进，后一类当前仍很难。[约 01:06:55—01:18:42](https://www.ximalaya.com/sound/1034046447)

教育例子进一步说明，能诊断某份试卷、给某学科提分建议，不意味着已能持续几年完成升学规划。把几个能力装进多 Agent 编排，也不能消除用户是否配合、目标是否改变、反馈是否及时等问题。讨论中的“愿意付工资的三成”是主持人的假设，不是付费调研。

节目后段的旅行案例同样区分了信息组合与完整交付：查天气、酒店、攻略可以组合，但用户没说出的预算和习惯仍限制规划质量。主持人分享填入境表的成功体验，属于其个人使用案例，不是千问的统一性能验证。

千问更偏向完成任务、达成目标的助理方向；情绪陪伴可以有价值，却不能用用户感觉满意代替事情办成。这也解释了访谈的克制：个人 Agent 仍在从代理明确事项，走向能够提供更多新价值的助理，尚不足以稳定理解一个人的整套人生目标。

## 云端、生态和模型升级，哪些投入可以持续积累

嘉宾说，千问有云电脑与云手机方案，也有 PC 入口，执行服务在云端。访谈没有给出用户环境隔离、计费或设备访问的完整接口，不能据此编写已验证部署步骤。[约 01:18:42—01:28:34](https://www.ximalaya.com/sound/1034046447)

成熟场景有规模和稳定路径，值得持续优化成本；新范式先验证延迟、体验和增量价值。它不是放弃成本控制，而是在不同阶段确定先解决哪个问题。生态资源降低了可接入工具的障碍，却不意味着跨平台接口和授权已经全部打通；对方禁止访问时，computer use 也无法保证解决。

模型更新会让某些补丁失效。蒋冠军不同意主持人提出的“80% harness 白做了”这个量化说法，主张区分两类投入：用户需求、工具服务、评测等可以持续积累；为当前模型某个缺陷写的业务补丁，可能随能力变化而撤下。[约 01:28:34—01:35:34](https://www.ximalaya.com/sound/1034046447)

访谈末尾回到小事：客服电话、改发票、填表、报销和订阅管理。它们未必显得宏大，却经常造成拖延。助理若能可靠承担这些环节，便有实际价值；这种价值既包括省时，也包括减少用户不愿面对的沟通负担。[约 01:35:34—01:48:36](https://www.ximalaya.com/sound/1034046447)
