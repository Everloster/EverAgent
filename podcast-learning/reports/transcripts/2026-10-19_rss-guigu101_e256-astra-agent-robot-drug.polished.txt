一 各领域实测 Astra 感受（04:18）
──────────────────────────────
[04:18] 泓君：Astra 发布已三周，你们用过吗？最惊艳的 demo 是什么？

[04:30] 许华哲（机器人视角）两个观察：
1. 适应能力非常强：给一个机器人本体让它做事，它很快发现该本体的运动速度与运动空间——比如撞到桌子会说"这个桌子还蛮高的，那我是不是应该把手抬得更高一点"。这本质上是把 CoT/反思过程变成实际动作的能力，过去的机器人模型和大模型都不具备。
2. 自我更新/自我升级：网上有人用 Astra 操作机械臂画金门大桥，第一次画得比较差，画完会想怎么画得更好，几轮迭代后"可以画得非常逼真"。（泓君问是否复现过画画 demo：没有，但试了很多别的。）

[05:47] 破壳的插花实验：把花插进花瓶，额外难度是花茎已被劈开两半、有点分叉，不好往里塞；Astra 知道"因为分叉了，所以我要捏住这个分叉，把它捏窄一点，然后再往里塞"。许华哲判断：它已经理解了一些物理世界和操作规范，"我觉得本质上还是理解3D"——从三维尺寸层面就能做出理解；这类理解"已经能够帮助到非常多的非动态的物理世界操作任务"。

[06:28] 另一能力是 real to sim：给几张图片，Astra 很快把仿真环境生成出来（学术圈叫 real to sim，真实到仿真的迁移）。过去需要拍大量视频照片、很多人手工标定修改；现在给指令就"很快把整个实验室或办公室的环境浮现出来"，拿这个仿真去训机器人，仿真侧也会有提升。

[07:10] 朱哲清 Bill（模型公司视角）：Astra 发布时强调的后训练、模型开发迭代能力，试下来"并没有那么那么惊艳"；但在长程任务与迭代上，比之前几款模型有 consistent improvement——对上下文及之前完成的任务有更稳定的认知，不太出现幻觉。问题有二：速度慢（可能与用量高有关）；跑一晚上、24 小时这种更长程场景，幻觉仍会发生，"并没有根本上解决"。朋友测前端与设计任务：审美与认知提升较大，可能与训练时对设计和审美方向有特殊训练有关。

[08:19] 泓君问：对比当年 Opus 4.6/4.7 发布对 coding 能力的进化，Astra 是大节点吗？Bill：单纯 coding 不是。4.5→4.6 的体感是近乎范式级的转变——原来只能做短程 coding（几个 file 的改动、小项目），4.6 之后工具调用几乎不出错、长程 coding 可自主进行；而这次只是"比原来相对比较长的任务之上可以做到更长，幻觉可以降得更低，审美变得更好"，没有解决以前完全解决不了的问题。

[09:13] 王晟：是大的节点。没有客观 benchmark 对比，但现实是团队已从之前的 Claude 系列模型全面切换到 GPT-6 Astra 做生物医学内部任务。特别好用的两点：Computer Use 与长程任务（详见下节）。生物医学任务常持续 8 到 24 小时，Astra 做得比较好；它比其他模型慢，但"做得慢……说明它可能会更深思熟虑一点"。现在采用切换模式：白天用反馈快的其他模型，晚上用 Astra 设计长程 pipeline/prompt 整晚执行。

▍09:11 生物医学"古董级软件"有了 Computer Use

[09:44] 王晟：生物医学领域有一批多年前发明的软件，是领域内默认必用，但编写年代久、界面设计差、术语多，跨领域的人使用成本非常高。Astra 的 computer use 能根据简单 prompt 直接操作得比较好；而且"我通过 Astra 怎么做 computer use、鼠标键盘操作，我还可以学习它怎么用这个软件"。他推测原因：Astra 不仅有能力，还把这些软件对应的网上 tutorial、别人的 user log、反馈以文字形式学进去了，"所以他真的理解怎么用这些软件"。这在生物医学特别重要——很多人对 AI 工具接受度低。

[11:23] 泓君：没想到 Computer Use 在 AI for Science 帮助这么大；它这次的核心提升是什么？王晟：没做个人感知上的对比，但公开 benchmark 分数提升比较大。Astra 发布时做了两个生物医学 demo，其中一个是 computer use demo，"在我们圈子内是出圈了"——它操作的工具叫 MultiQC，一个挺常用的网页工具；大家发现可以直接用 Astra 操作生物医学 tool，"比想象的要好用很多"。其实之前的模型也具备该功能，只是大家没有真的思考怎么把它融入科研 pipeline。

▍12:17 Computer Use 是什么？与 API 调用的区别

[12:18] Bill 一句话解释：通过模型对视觉的理解，决定 agent 下一步在屏幕上点哪里、输入什么文字，串联几十个动作完成人类想达到的目的。与 API 的区别（泓君+Bill）：不用给接口、不用给密码，它直接像人一样使用电脑——看到人类看到的屏幕、UI、所有可交互界面，通过人类可用的输入输出设备完成任务。

[13:02] 泓君：以前操作 Agent 一般两种——调 API 或让 agent 操作浏览器（即 computer use），这次为什么 Astra 又把它带火了？Bill：总体又火了一步。之前大家以为所有工具都会开 API、做 agent-native setup，但最近 Instinct、Meta Muse 背后其实都解了 browser。问题在于很多第三方 App——Amazon、shopping、travel 类——不愿意开放 API。这又回到当年 Manus 的情况：Manus 先做 browser use，别家跟上，后来大家发现不 efficient，又回到 coding 和 API 调用；"现在好像有些东西避不开，然后又回到了 browser use"。他觉得最后会是一个 mixture 的状态。

[14:20] Bill 的端侧观察：Pokee 目前发布的模型都是 30B 左右，可以在端侧/edge compute 上跑（一台 AI Box 或 AI PC 就能跑）。如果 browser use 发生在你自己的机器上而不是云端，就会改变它带来的 bottleneck：现在的远程 browser use 都通过商用机器，最多找 Bright Data 或 IP proxy 假装 consumer 用户绕开 IP check，而这些网站（商家开始屏蔽 AI 机器人、不希望其接入）对商用 IP 不放行——"奢侈品网站其实很早以前所有的都会屏蔽掉"；如果用的是你自己的 IP，就不会被 block。这可能是未来破局趋势，也可能 force 很多 app 厂商改变 browser use 机制——browser sandbox 在本地发生而不是云端。

▍15:47 Meta Muse 会走 Manus 的老路吗？

[15:49] 泓君接话：这让人想起 Meta Muse——定位个人 AI 助手、面向消费者，加上 agent 能力成熟和 Meta 的用户基数与广告投放，爆火可以理解；但它相当于给每人做了一台云端虚拟机（数据存在云端属于你的存储），按 Bill 的理论，这仍是商用 IP，未来商业化很可能被商家卡住。

[16:24] Bill：Meta Muse 从背后的虚拟机设置来说跟当时的 Manus 很像，主打 browser use；它的 use case 很多跟 travel、shopping、客服有关，这些场景没法靠 API 调用完成，基本都得靠 browser。当时 Manus 走了一模一样的路，"一模一样被全部 block 掉了"。所以 Manus 后期跟 Gensmark[?] 很像，都主打白领工作；去看 Claude Code、Claude Code Work[?]、ChatGPT Work[?]，最后都往白领工作效率偏移，核心原因就是很多东西一开始能做，但很快被巨头全部 block 掉——比如亚马逊现在就把 Meta Muse 屏蔽了。如果有更多网站加入，它能操作的网页就越来越少。但它不可能屏蔽你电脑上的 browser——"那你自己也不要上 Amazon 了"——所以可能是破局机会；不过肯定会有"比较大的来回拉扯的过程"。总体判断：2C 端的 agent 目前可能还不是很 ready。

[17:46] 成本侧：Instinct 和 Meta Muse 的 token burn rate 非常高——browser use 对模型需求和要求很高，不可能用便宜模型。Meta 给每人 1 亿 token 免费；泓君问折合多少钱，Bill 按全部 input、按他们成本估算约 100 美元/用户的免费额度（转写中"每个星期"的归属不清[?]）。很难在短期内拉出 Google Search、社交网络那种完全免费的现象级体量产品——"我们可能未来需要看到一个完全完全免费、Token 根本不是一个限制的这么一个产品才行"。

[18:34] 泓君转述另一说法：Muse 耗钱的不只 token，还有云端虚拟机成本——现在内存和 CPU 都很贵。Bill 用自己训练的经验佐证：一开始用虚拟 service 做虚拟 sandbox，发现太贵，最后直接租大的 CPU box 自己架 sandbox（技术上门槛不大，computer 资源很关键）；有一次大型 rollout 时"发现 CPU 的价格跟 GPU 的一样了，甚至就很离谱"。

▍17:31/19:37-22:21 破局关键：软硬件结合与身份确认

[19:38] Bill：这一波 consumer 最后一定会 land 到软硬件结合的状态；Meta 如果能把 wearable 做大，有可能有机会。理由：云端不能代表用户本身，这正是 browser 把它们完全 block 掉的原因——换一个云端虚拟机，商家无法验证操作者就是用户本人。用户 identity 是这一波 2C 的关键。

[20:11] 商家视角的因果链：如果商家能确认这个 agent 就代表这一个人，很多商家会愿意开 access；一对一比例（一个用户本来就要访问我，通过 agent 来访问）是 OK 的；但如果原本一个用户搞了 20 个 agent，这 20 个 agent 的消费能力跟原来一个 agent 一样，还不停比价、刷流量、把流量全弄乱，"对我来说是得不偿失的"。所以软硬件结合是机会：硬件本身属于这个用户，就可以直接确认 agent 是用户的代表行为，商家就愿意把 access 开给你。

[21:10] 泓君认同并补充：前几天和朋友吃饭也聊到——云端 IP 容易被 block，个人访问的 IP 在本地硬件（手机、Mac mini）里行不行？但对他们这也是大问题：怎么绕过苹果、如何确保个人终端设备安全。Bill：现在生态很复杂，Pokee 跟高通、英特尔、AMD、联想、惠谱[?]（转写作"会谱"，疑为惠普[?]）等都有合作；做"硬件+软件+模型"结合的一套要找落地方向，而做 2C/2B 的会卡在 access、identity 和硬件层面——双方未来从商业行为或生态上有合作的潜在机会；但最后肯定是"模型、软件和硬件三方都得要合作共盈（共赢）的一个状态"才能打破局面。

▍22:21 个人助手 Agent 新一轮烧钱获客大战

[22:24] 泓君问 Muse 后台接什么模型。Bill：有 rumor——官方会说用 Mule Spark[?]（转写如此，shownotes 不能确认）；但 X 上有人[?]（转写作"Excel有人buffer说"[?]）说有些调用 OpenAI 的场景。他怀疑存在 routing：Mule Spark 不够 strong 时靠 Astra 或 Fable 解决问题；"但我怀疑不太会，因为成本太高了"——如果十次 iteration 里有一次要靠 Astra 或 Fable，成本就不是 100 美元/用户，可能每月 200 美元，"这个获客成本有点离谱了"。

[23:01] 价格证据：泓君说 Astra 和 Fable 差不多是其他模型的两到三倍；Bill："不止不止，远不止。Astra 现在是 10 美金的 input 吧……也就是说比 GPT-6 高五倍的价格"——Astra 定价每百万 token 输入 10 美元、输出 50 美元，约 GPT-6 的四到五倍（嘉宾口径）。用它解决一个难任务，一次调用三四十美金。Bill 的亲历：之前用 Claude 的 subscription，把 20X[?] 的 plugin 用完了，任务很急，花 100 美金加 credits，"仅仅用了两再不是三次 back and forth 的 agent flow 就全部用完了"。所以如果 Muse 把 10% 的 traffic 引到 Astra 上，是"灾难性的 cost"；Meta 财大气粗可能没关系，但 Instinct 现在估计必须用至少是 Soul[?] 级别的模型、很多开源模型打底座再加 routing，每个用户的获客价格（不只是 marketing 上的）肯定非常可观，"烧钱会烧得很夸张"。

[24:28] Bill 的愿景：如果电脑自己就能跑所有东西，至少 60%–70% 的 token 在本地或私有 computer 产生，就不需要花那么多钱全都 routed 到 frontier model；希望未来有个 convergence——看他们能烧多久，如果钱够烧一两年、行业的小模型也逐渐成熟，最后能出现平衡状态。

▍24:57 Grok Bot，"走在后面的人"

[25:00] 泓君问：大家在 2B 工作流中会用 xAI 的 Grok Bot 吗？Bill：身边用 Grok Bot 的人更多在尝鲜，因为它相对比较主动一点；但用 Codex[?]（转写作 Codec）或 Claude Code 其实都可以解决，真正接近工作流的相对少。他身边真正在 Legal、Healthcare 等传统 Enterprise 工作的人，"现在还纠结于怎么能够脱离 Microsoft Copilot 的泥潭"，甚至不能 freely 使用 Codex 和 Claude Code，更别说 Grok Bot 这个级别。所以整个行业现在分化非常大："走在前面的人什么都会随便用，走在后面的人现在还在泥潭里挣扎。"

▍25:44 前沿 Lab 最烧 token 的是 AI for Science

[25:45] 泓君：Astra 可以调用很多自己的 agent——之前看 OpenAI 解数学题，内部调用了更强的模型，大概用了"一万个子 agent"[?]（转写作"一万个字agent"，无法确认）。她最近跟前沿模型研究员聊到一个观点：2C 与消费级 agent 的 token 使用量其实花不了多少钱（推理成本在下降，token 成本比想象中便宜）；现在真正最烧钱、包括 OpenAI/Claude/DeepMind 在竞争的核心领域是 AI for Science——那些未被解决、未被定义的科学问题，解数学题或跑王教授这样的生物实验，"这是非常少 token……而且是内部消耗量最大的一个方向"（口播如此，依上下文为"单位 token 价值最高、内部消耗最大"[?]）。

[26:43] 例证（泓君转述二手数字）：OpenAI 解 Navier-Stokes（纳维斯托克斯）方程这一个问题，它的 agent 发了大概 270 万条消息，消耗约 130 亿[转写为"1300亿"]输出 token（转写原文"约1300亿输出的token"，两处口径矛盾[?]，按转写保留 1300 亿），第三方按零售价算这部分约消耗 2200 万美元。模型使用分好几个梯队；对普通人来说，Astra 与上一代甚至 Claude 其他模型的区别感知已经不大，但对前沿科学家，能力提升的感知非常大。前沿 lab 的逻辑：如果 AI 能制药、能解决很多疾病，"那个利润是更可观的"。

▍27:48 小模型追大模型：差距在缩小，但可能追错了 benchmark

[27:49] Bill 抛问：Pokee 主要做 post-training 和 model architecture change，focus 小模型（想做到很 DC 化/去中心化[?]，转写作"很DC化的模型"）；他们这个层次的模型优化之后与 frontier model 的差距越来越小（至少在白领工作和自己的工作流中），虽然没钱训 trillion parameter model。他问许、王：从 AI for Science/Robotics 角度，每代 frontier（如 Opus 4.5→4.6 之于 4.8→Fable、5.6→Astra）的提升能比吗？

[28:42] 王晟：AI for Science 能力确实有很大提升，但提升主要来自 general coding、查文献[转写作"查文线"]和长程任务能力，并不是 biomedical knowledge 能力的提升——专门测生物医学知识的 benchmark，Astra 上并没有提升。且实际使用有个严重问题：模型对生物医学任务防范越来越严，会 refuse to answer；"所以我们其实内部用的时候都是用 Kimi K3 或者 Mule Spark[?] 1.3"，要用 Astra 时得用特殊说法（"我这是在设计一个 benchmark"）——"实际这种大模型的使用体验，随着能力的增强，其实是越来越差的。"他也认可 Bill：在已定义明确的 AI for Science benchmark 上，小模型与大模型差距确实越来越小；但他个人认为这些 benchmark 本身定义得就不好，所以大家追赶的方向、包括大模型进步的方向都可能不完全正确——定义时都会给出明确的生物数据集、要预测一个明确的问题，这和真实制药发现 gap 非常大，本质上现有生物医学 benchmark 就是一个 Kaggle[转写作"开构"]式 data science 比赛，退化成 MLE bench 那种 machine learning 问题，重在 coding 能力提升就能有很大进步。

[30:19] 许华哲：从 Robotics 角度，Astra 是飞跃式的——过去无论 Opus 4.5/4.6 还是到 Fable 的变化，都没有这次给 Robotics 带来的变化大，因为过去的升级在机器人测试上几乎都没有好表现，"原来不能做，现在仍然是不能做，相当于定性上面没有变化"；而 Astra 是定性变化，很多 robotics benchmark 失效了，像 RoboDojo[?] 等几个大家相对认可、尤其是仿真的 benchmark，Astra 都成了第一名——"无论它用了哪种数据，它带来的能力都是彻底的把原来的模型进行一个飞跃式升级"。

▍30:19 未来需要快决策模型 + Astra 的推理能力

[31:06] 许华哲：关于小模型与大模型，长期来说"我们一定是需要一个小的、跟 Astra 能力相当的模型"，原因是机器人任务有时间要求，需要及时响应和高动态任务——比如抖毛巾，Astra 做不了，因为它太慢；它知道要快动一下，但只能写 code 来做，让它直出动作是没有办法的。所以一定需要一个快决策的模型，把 Astra 的 CoT/reasoning 能力和 3D 理解加进去。

[31:42] 分层架构（泓君问：未来是大模型做规划、小模型实时控制的分层吗）：这个分层大家一直比较认同，辩论在"这一刀切在哪"。原来普遍认为 VLM[?]（转写作 VRM）做任务规划层——比如"我要吃西红柿炒蛋"，VLM 规划打开冰箱门、拿西红柿、拿鸡蛋；底下的小模型/具身模型执行"打开冰箱门究竟怎么办、打鸡蛋怎么做"。Astra 最大的变化是它现在能做低层次的动作控制：指令可以变成"把手往右伸两厘米""把手放在冰箱门的把手上，如果没有抓住的话，那你再往前靠一靠"——它把这一层往下压了。原来边界清晰（你负责那块，我负责底下），现在它说"我能力非常强，除了慢以外，我可以往下压一点点"，底下的就更像反射式的，"有点像是一个提线木偶的感觉"。

[32:51] 上层能否无限下压、最终变成完全端到端的 VLM[?]？许华哲认为不合理，两个理由：第一，速度——网上看到的 Astra 做控制都要 16 倍速或 24 倍速才能看，否则基本纯等待；第二，Astra 还是对物理非常缺乏理解，尤其是人类式的"直觉物理学"——随手碰一个物体，有水可能会洒、玻璃可能会碎；这些经过很多语言推理可以理解，但希望它在任务当中立刻有这方面理解，效果还不够好，还是需要世界模型或快速模型做直觉式反应。

[33:45] 慢的原因（泓君问：模型太大还是推理时间太长）：模型大是一个原因；另一个是内部 CoT 非常长（给出的 CoT 应该是假的/加密的），每步决策的思考非常冗余；观察到它面对复杂任务和简单任务的思考时长基本相似——复杂任务上显得聪明，简单任务上就成了额外开销，"使得他看起来非常笨"。泓君："内耗性人格。"

[34:22] Bill 问：以目前机器人可搭载的芯片，多大模型比较 ideal？云端 host 像 job 一样立刻输出 configuration，多大网络延迟可接受？许华哲：本地搭载最好小于 10B，比较舒适；十几 B 到小几十 B 也能做，但硬件成本要上去、芯片要升级。破壳机器人两条路都在走：模型也可搭载云端、以 API 形式供大家用，这样模型尺寸没有太多限制，更多是网络延迟和卡的代际问题。API 形式一定不能做高动态和时间敏感任务——倒水这种就不适合，卡一下水可能冒出来；假设都做准静态任务，200 毫秒甚至更长一点、几百毫秒都可以接受；但高动态任务一定要在本地，"因为卡一下就完全坏掉了"。

▍35:48 筷子夹小球：自研模型 V.S Astra

[35:49] 泓君提到破壳此前用筷子夹小球的 demo 场景：自己的模型 vs Astra 区别是什么？许华哲：自研模型做得快很多；抓的时候连续不断地尝试，过程中没有太多逻辑思考——抓一次失败了、稍微碰到一点它、状态发生了变化，就换一个角度再试。Astra 则每做一步都要分析发生了什么、原因是什么，再据此给自己调整指令，"这个过程看起来更像是人类的思考过程"；但一是带来缓慢，二是有时会陷入僵局——它有时无法理解为什么会发生这样的事，或者一旦分析出错了，就没有办法进一步推进。另外抓桌面上物体的旋转类动作，Astra 相对弱一些：能做，但要反复尝试怎么转——比如抓起东西后再塞到墙上的小孔里，"这样的能力我觉得目前还是有一定的短板"。

▍37:25 Astra 冲击：利好 Sim-to-Real 和本体硬件（含一处保留意见）

[37:25] 泓君问：Astra 对哪类机器人公司冲击大（做大脑的——又分 sim-to-real 路线与物理世界数据路线、做本体的、做数据的）？许华哲：
1. sim-to-real 路线：他一直认为仿真没有办法训出最好的机器人模型和策略。很多人说"Astra 让仿真重新复活了"，因为 real to sim 变得非常容易——"但是它其实只是把它这个 3D 的外观做得非常好，它并没有因为 Astra 出现，然后物理引擎变得更准确了"，因此在这个地方"我觉得是一个 hype"：虽然带来很多变化，但并不直接导致机器人变得更好用。
2. Astra 肯定利好本体、利好硬件：Astra 出来这两三周，斯坦福已经有一个课题组把 Astra 接入一个"语术机器人"[?]（转写如此，疑为具身/某一机器人品牌[?]）在家做家庭任务，论文大概两周就做出来，速度非常快。这说明 Astra 有了很强的跨本体泛化能力之后，"你的本体如果质量足够好，那可能连接 Astra 直接可以做一部分事情了"——尽管还只能是 demo 机。
3. 对做大脑的公司分两派：一派相信会有更快更好的具身模型，可以从 Astra 学数据标注方式、CoT 方式等，会带来行业增长，"我觉得是一个好事"；另一派认为自己模型能力可能不够强、可能直接放弃——"既然 Astra 好，我就专注在怎么用它"，或把自己的东西当做 Astra 的工具、让 Astra 调用来完成闭环，就更像是机器人部署公司。所以会有一部分公司走向更偏部署，另一部分做更小的、达到或超过 Astra 能力的模型训练。

▍39:07 从 TAMP 到 Agentic：机器人规划重回台前

[39:09] 许华哲：对研究会带来非常大变化。一是整个模型训练范式——大家未来都不会忽略 Astra 这样的范式，做模型的人肯定会产生新想法；二是以前做传统机器人规划的人，现在可能往 Agentic、更偏 Harness 的方向做研究——如何把各种各样的能力组合起来。机器人领域有个方向叫 TAMP（T-A-M-P），把规划和控制放在一起做长程任务；过去这个领域比较古板、上一个代际——用传统规划手段一步步做，比如下一步是开瓶盖，上一步就要确认瓶盖首先是关着的，否则不能到下一步——"但是到了 agentic 部分，它好像又重新焕发生机了。可能是规划去模型（去学模型[?]），然后现在有了好的模型以后，又回到规划，可能是变得很重要了。"

▍40:19 数据标注新门槛：标注因果与直觉物理

[40:28] 泓君问：好的机器人大脑公司可以向 Astra 学数据标注方式，您的启发是什么？许华哲：要把里面的因果和直觉物理标注清楚——做这件事成功是为什么、失败是为什么、做了这件事发生了这个结果，交互过程需要详细标注。过去很多机器人标注只标一句"你做了什么"，相当于只做正向标注，没有标注背后"我没抓住它，原因是抓的位置偏上了，还是这个东西沾了水太滑了"等。"有了这些东西，我们才能真正做一个通用的机器人大脑。"

[41:04] 对数据标注公司的影响：许华哲听到 rumor 是 OpenAI 现在只卖不标注的数据——觉得外面的标注都是错的，内部自己重新标注；另一方面也可能为了保密、不想把标注方式透露出去。数据公司会分两种：一种卖生数据（"生肉"），相当于卖石油、原材料，主要靠起量——管理 1000 个人或 1 万个人采数据，或者把所有的家都 map 一遍；另一种做"熟肉"熟数据，需要了解最前沿模型是怎么训练的——"这个是 OpenAI 的标注方式，这个是 Pi 的标注方式，你喜欢哪个，然后我去卖给你"，单价可以翻十倍甚至更高。泓君："这个水还挺深的。"许华哲补充：要知道模型公司的研究品位本来就不容易，需要在交易过程中获得局部观察来推理对方怎么使用数据，"也是一个 COT"。

[42:21] 泓君问：以后机器人训练会不会底层就是一个基模、只做后训练？许华哲：如果要真正意义上部署，一个 GPT[?]（转写作"GT"）级别的模型肯定很难去做部署；远程可以解决一部分任务，但不能解决所有任务。"如果我们都是 Astra 这种基础模型，我觉得是不太能成为未来所有机器人去使用的模型，一定是会有一个相比于 Astra 要小得多的、有相似能力的这样一个范式；即使它在云端去做服务、去做 host，我觉得也仍然是一个机器人专用的模型。"

▍43:06 惊艳之后，Astra 也有明显短板

[43:09] 泓君问心理变化：金门大桥 demo 出来时很多机器人创始人很慌，三四周后您的理解有变化吗？许华哲："会的会的。"刚出来大家尝试都觉得非常惊艳——从抓一个东西很快完成，到更复杂的空间要求（旋转）、更复杂语义甚至物理上的东西，逐步尝试时"我们会觉得机器人的 GPT 时刻还是 GPT"（呼应"机器人领域等了这么多年的 GPT 时刻居然是 GPT 自己"）。但再往深入看，还是看到很多问题：
1. 双臂任务几乎没有办法做——叠衣服这件事 Astra 是完全叠不了的。感受是："在一个语言不太好描述的任务上面，Astra 的能力其实并没有很强"，所以在足够灵巧的地方仍然有空间。
2. 总结能力不是很好：第一次做一件事花比如一个小时，第二次 45 分钟，之后持续不断地做"她永远都是 45 分钟"，基本从第三次开始就变成常数；不会像人或更小的模型在充分训练后时间越来越短——"最后我们可能随手干一件事就是几秒钟就做完了"。所以机器人本身的原生模型还有很多空间。
3. 现在更多要想的是系统一/系统二（快慢系统）到底应该怎么结合——上面的 Astra 到底是调用、还是给出指令、还是给出什么样的指令作为界面："因为它已经出现了，你不能回避它；但是它自己又有很多问题，你又没有办法直接用它。"下一个问题是怎么样把机器人公司擅长的东西和 Astra 这样的模型充分结合起来，做出真正通用的机器人——"到现在还是更多从技术角度去想未来怎么做。"

▍45:12 Jev"快系统"的潜在价值

[45:14] 泓君：最近还有一个项目很火叫 Jev[转写中此处作"Jeff"]，用系统一/系统二、快慢思考的理论去做，对机器人领域影响大吗？许华哲：Jev 自己叫自己系统一，跟机器人本身的原生模型很像——机器人一般被认为是主要系统一、带一小部分系统二的能力，"所以我觉得机器人就应该是一个相对来说的快系统"。但破壳也做了尝试，Jev 在机器人上表现是很差的，多方面原因：首先 Jev 本身没有办法输入图像，图像需要以状态的形式给到它——必须先跑一个视觉的 VLM 或其他视觉模型，把状态给到它，再让它做快速决策；实测叠方块[转写作"螺方块"]这种任务，它经常摞不起来，或者摞了以后就倒了。对比之下，Astra 能看到第一个块摞得有点歪，第二个块就要反过来一点、往另一边靠一靠才能平衡，Jev 没有这样的能力。现在很多人说 Jev 可能可以用来标数据，因为它很快；但许华哲刚好看到 OpenAI 要出一个快的、类似于 Jev 的东西，而且是有图像多媒体输入的快系统，"好像还没有尝试，应该是快要发布了"（传闻口径）。

[46:38] 泓君问整体影响是正向还是冲击。许华哲：对整个机器人领域肯定是正向的——看到新的能力；但肯定也有一些冲击，从每个个体来说，尤其是现在模型能力远远低于 Astra 的这些公司，可能会担心"我永远都追不上它这个能力"。"我整体还是偏乐观的。它相当于是一个新的思路，其实照亮了很多我们之前没有看到的地方。"

▍47:10 实验设计完成度只有30%，Astra 缺什么？

[47:10] 泓君：现在 Astra 还有 Fable[转写作"Fable 5"，疑为 Fable 与其他模型并称[?]] 这几个模型在 AI for Science 上谁更强？王晟：Astra 的能力会更强，因为它长程任务的能力稍微强一点。但"首先我们没有一个明确的 benchmark"，很难用现有生物医学 benchmark 衡量模型做生物医学任务的好坏。现在模型很缺的一件事：编程等任务做得挺好，但我们想要的是模型能指导我们在真实世界中做生物医学实验——最重要的场景是"AI 模型能不能出一个实验方案"：具体怎么实验、在什么温度下、用什么分子、什么湿度、什么情况下做。这是现在的模型都做不好、但非常重要的点。

[48:13] "human use"：类比 computer use 是 AI 控制 computer，王晟团队把这个方向叫 human use——AI 怎么控制真实实验中的实验员/technician 去做实验。对比 Astra 和之前的模型，发现 Astra 还是可以做得比较好的；这些任务的语料非常少，但 Astra 更强的能力可能可以带来提升。

[48:38] 泓君理出两类：一类 AI 给方案（预测新药可能的结构与分子组成），第二类方案做出来后要在真实干湿实验环节验证可行性——现在第一部分做得还可以，第二部分给的方案还不够好。王晟补充第一部分的悖论："如果一个问题……我如果知道答案，那这个问题其实我没有必要去研究了"，所以我们真正在意的问题都不能被 benchmark 衡量、都是没有答案的，最后都需要实验验证。定义：干实验=所有预测和分析都在计算机（CPU/GPU）里完成；湿实验=在真实实验室里通过试管、培养皿对老鼠细胞等进行操作。给 AI 出一道题是不可能知道答案的——"GPT 给我一个药物的分子式，说这个能治疗癌症；Claude 给我另一个分子式，我都得去湿实验去做这个实验"。而且不仅要分子式，还要具体的实验计划：怎么合成这个分子式、这个小分子应该怎么储存、以什么周期给老鼠使用——"这些特别细节的东西，是现在 AI 模型都做得非常差的"。它能生成分子式，因为世界上有很多这样的数据；但分子怎么合成、怎么给老鼠用药做得不好，"而这些其实是更重要的"。

[50:30] 完成度：现在大模型设计实验大概只有 30%[王晟口径]，很多时候需要人类专家修改。实验设计是 dominant expertise：需要特别深入的领域知识，这个领域的教授可能也不知道，需要专门针对这个方向做过很多实验的 technician 才能设计一个高效、成功率高、特别可行的实验。另一个问题：每个实验室的器材设备都不一样，Astra 没法根据这些设备器材针对性设计实验。类比："我这个饭店里有一些原材料，有番茄、有鸡蛋、有土豆，我让 Astra 来做一道菜，他并不能够理解这个饭店有哪些原材料……他可能说给我做一道海鲜大餐……这些就在现实世界中非常难以执行。"所以它缺乏的是对现实世界中资源的利用、协调和使用的能力，"这也是我们现在想要对模型进行改进的"。

▍51:39 AI 制药，离不开实验室的验证和数据积累

[51:41] 泓君：所以一个严肃想用 AI 生成药物的公司，还是要配备自己的实验室？王晟：一定要配备实验室——现在通用模型已经很厉害了，配备实验室可以有自己的验证、自己的数据积累。另一个瓶颈是验证周期很久：设计一个分子，拿到老鼠上做实验不可避免要花几周，因为老鼠有新陈代谢；这几周里模型可能已经进化到下一代（GPT-6.1、6.2 都出现了），"到时候 AI 模型都进化的比我这些真实实验要更快"。所以前沿 AI for science 研究室需要湿实验，而且要对实验室进行改造 redesign，让它更好地配合 AI：一上来就把所有细胞都准备好，只在 AI 要预测的那几步，预测之后立即把小分子放进去，把前置条件做好，"把湿实验和 AI 模型一起来设计，能够把这个闭环走得更快"。而不是像现在：AI 模型设计一个东西，移交给合作者；合作者不知道 AI 怎么设计、会给什么结果，又重新针对它设计一套湿实验——这样分割开就会比较低效。

▍53:15 制药时间线：AI 设计分子快，真实验证慢

[53:15] 时间线（王晟口径）：先做细胞和老鼠上的实验，几周可以做完；之后一般做一批猴子这种灵长类动物实验，"这个怎么样都要一个四个月的周期"，有时做两次就是 4+4=8 个月。作为 AI 制药公司，一般做完猴子实验不一定会推进到人的实验，而是直接 license 授权给大的药厂让他们做人体实验——这笔授权费非常可观，"一般都是 1000 万美金以上，甚至可以更高"；大药厂有病人的网络，可以更好地收集病人做针对性人体实验。所以一般走到猴子实验结束，周期在 6 到 12 个月的时间线上。"验证一个药物花的时间，是远比 AI 设计一个药物更久的。"

[54:18] 为什么数学快、生物慢：AI 数学发展快，是因为很多环节可以被验证、不需要做实验。生物学上 AI 设计了新分子新药物，"你怎么去确定它的设计是对的呢？"王晟："这个就是最大的难点，这也是 AI 能够在数学上做出很大的成就、攻克千禧年猜想，但在生物医学上其实到现在也没有一个说是 AI 完全开发的药物的一个根本原因，就是现实世界的反馈太慢了；而且这是受限于自然规律，一个老鼠一个猴子就需要那么久的时间。"

[55:01] 上一波 AlphaFold 时期（泓君确认指 AlphaFold 1、2 刚出来、蛋白质结构预测有大台阶时）：很多 AI Drug Discovery 公司雨后春笋般冒出，大部分后来没有成功——因为他们还是以 AI 设计和发现药物为主；即使把 AI 设计一个分子式的周期从半年提升到几天或几小时，之后还是会被后期的真实老鼠、人体实验限制。王晟："我觉得这是一个核心的问题。如果能够把这个问题解决，AI 在生物医学制药上的爆发，就会和 AI 解决千禧年数学问题一样，会有非常大的一个爆发。"而他自己认为这个问题"不可能从根本上解决，但是我们可以加速现实中的反馈，这样来间接地帮助我们解决和提升 AI 在上面应用的效果"。

▍55:01/57:43 从 AlphaFold 开源，看垂直科学公司的数据护城河

[56:12] 泓君：听说 AlphaFold 3 把所有研究包括数据都开源了，带来一波生物制药公司、垂直模型公司、工具公司崛起——类似机器人行业"派开源"[?]（疑指某开源生态[?]]），很多底层基础设施 ready 了。王晟：开源非常重要。当时社区里很多机构都在尝试造 AlphaFold 的开源版本，有个叫 OpenFold[转写作 OpenFord] 的工作——所以如果它不开源，大家也会很快用开源版本追上。开源之后对社区最好的帮助是大家更重视数据的积累：它虽然开源了，但垂直科学 AI 公司可以利用自己积累的数据维护自己的护城河。"其实这些数据都是非常非常珍贵的，一条数据都是非常高价值，几万或者几十万美金"，因为都是在真实的老鼠、人类身上做实验——不仅实验成本高，周期也久。"所以反而是开源之后，这些垂直的科学公司，它会更具备优势了。"

[57:24] 一条数据的定义（泓君问）：一个实验在一个完整的动物身上跑通就算一条——比如一个分子在老鼠上到底能不能杀掉癌细胞，这就是一条数据。泓君："那这个数据还是太便宜了"[依上下文应为"太贵了"，转写疑误[?]]，因为大家要工作好久、工作量挺大。王晟：是的，这是非常高价值的数据，也是在 internet 网上、大模型预训练语料库中根本看不到的。

▍58:24 未来趋势：湿实验公司用 MCP/API 直连大模型

[57:50] 泓君推论：生物医药界未来可能也会兴起很多数据公司——模型负责给想法，我成立一个实验室专门负责验证，可能是很好的商业模式。王晟：对，非常好的商业模式。类比现在的 AI 数据价格：买一道奥数题都要几千美金，Terminal Bench 一道题几千美金，新出的 Terminal Bench Science 上的题也是高价值的题——但这些还仅限于计算机里面的操作；"那未来如果是有真的生物、真实世界数据，那个价值会非常高。"另一个高价值方向：搭建一个能够帮助 AI 很方便地做真实生物实验的接口，仅仅这一个也会很高。现在有个公司叫 Adaptive Bio[?]，专门与 Anthropic 合作：Anthropic 生成一个 AI 的预测，它以 MCP 的形式立即开始做实验，刚刚融资了 40M。"我觉得这样的公司会越来越多：以后每一个湿实验的公司，都会有这种 MCP/API 的形式直接接到 AI 大模型里面……这样来给 AI 大模型直接进行服务，这样当中很多人的沟通成本都会减掉。"当然最重要的还是 AI 自己知道要做什么实验、怎么设计这个实验，湿实验公司能够和它配合。

[59:10] 前沿实验室配备湿实验室：现在像 OpenAI、Anthropic 这些前沿模型研究室，配备了自己的湿实验室。Anthropic 明确与 Adaptive Bio 合作，最近出了一个比赛——邀请大家做 Anthropic 定义的蛋白质设计问题，它会赞助 Adaptive Bio 为大家做湿实验的验证，"以湿实验的验证为最后的标准"。王晟也听到很多消息：Anthropic 在构建湿实验团队，招的人都有湿实验背景；OpenAI 应该也会有类似情况、慢慢布局。所以趋势是：各个 AI frontier lab 如果真的想做高价值发现，"不是就刷现有的 benchmark 的话，不可避免的是要有自己的湿实验室"。

[01:00:02] DeepMind 与 Isomorphic：泓君问 DeepMind 呢——感觉创始人 Hassabis 现在重点在从 DeepMind 分出去的生物制药公司 Isomorphic 上。王晟：不知道 DeepMind 和 Isomorphic 会是怎样的合作形式——是 DeepMind 搞 AI、Isomorphic 做验证，还是（他猜测更多）Isomorphic 自己做端到端：用一些模型、更多自己做验证，端到端解决。另外，Jumper——和 Hassabis 一起拿诺贝尔奖的那位科学家——加入了 Anthropic，"所以我觉得 Anthropic 在这方面会有很大的优势"。泓君提到同获诺奖的 David Baker 也做了新的制药公司，是叫 Zayal[?]；王晟：他有很多制药公司，"据我理解他应该有几十家的公司吧"，理解他还是更多专注自己的科学研究，之后看能不能拓展到商业或他的 startup 里。

[01:01:01] 模型能力提升的大节点（泓君问：哪些基础模型能力提升会让行业有质的飞跃）：王晟：现在的提升还几乎取决于 coding 能力的提升——因为大家还没有走到湿实验/真实世界控制这一块；coding 能力提升后，biomedical 相关的任务也会做得特别简单。"Biomedical 上这些 coding 任务，虽然那些 benchmark 上还没有达到满分，但我个人理解已经是几乎可以认为是解决了，因为它已经比人做得要好了。"像 Terminal Bench Science 上的一些 Biomedical 问题，他自己试了一下，"我做的都没有 AI 好"——虽然很多 AI 的分数即使 Astra 也只有六十几分（满分一百），"但是它其实已经做的比我好了，所以我认为它们已经解决了"。所以比较大的节点就是 coding 能力的提升，会把生物制药这些 dry lab 上的能力都解决。另一个问题是生物医学的数据特别大、特别复杂，"每个人的数据都可以达到两个 T"——未来模型要提升，对 2TB 数据的高效处理和理解是非常重要领域，也是非常大的机会。

▍01:02:15 人类科学家的角色转向"定义问题"

[01:02:20] 泓君：AI 在一些能力上已经超过您这样的顶尖科学家，它未来给你们带来的问题是什么——比如它做的东西你们很难验证？王晟：验证也是要靠湿实验验证。"如果一个问题已经定义得很好了，有明确的测试集、明确的输入，要知道解决什么样的问题，那 AI 解决这个问题的能力会比我强。那么人类科学家更多可以做的事情，就是定义哪些问题 AI 去解决。"所以未来在生物医学里的趋势：不再是解决问题、设计模型，更多的是设计 benchmark、设计 evaluation 的方法、定义一些重要的问题。另外生物医学关系到制药、治疗病人，直接和人打交道，很多时候还是需要科学家参与其中而不靠 AI 自动化——需要一个人类科学家作为背书："就像飞机就算能自己飞，我们也希望有个驾驶员在上面……AI 能自己看、能自己治疗出诊断书，我也希望一个医生真的肉眼看一下我的报告。"在科学发现这种一下就投入很多钱、很多时间的重大决策上，还是需要人类科学家一起把关、一起判断问题的价值。"如果纯粹是解决问题，我觉得 AI 已经会比最强的人类科学家都要强了。"

▍01:03:47 好的 benchmark，应该是无上限的

[01:03:59] 王晟：未来首先要设计那些没有上限、不可能被刷爆的生物医学题。比如现在的 SOTA 药物能把 30% 的癌症细胞杀掉，那 AI 能不能做更好的药物、把 40% 的癌症细胞杀掉——让 AI 不停地设计，以没有上限的方式做任务；同时任务做的过程中会形成数据飞轮——不停地做湿实验，虽然贵且慢，但持续对这个任务做实验，还是可以收集到可观的数据。要避免的是简单分类任务（比如分类这个基因会导致还是不会导致癌症），"这样的任务就很容易被 AI 解决了"；要设计的是宏大的、很难有上限的任务，比如怎样把人类的寿命提升——让 AI 持续解决、我们持续积累数据，积少成多，把特定问题的数据积累得更多。

[01:04:54] 泓君：AI 至今没有一款自己真正做出来、被验证可使用的药，为什么这个领域依然很火？是时间还早，还是未来会被解决？王晟：未来会被解决，只是时间还早——AI 是新时代的事（过去几年才发生），一个药的周期要五到十年，现在还没走到那个周期。"我觉得未来会有一个 AI 自己发现和更好地验证药物的机会。"现在新的药物发现，包括之前有公司说它的药物是 AI 高强度参与设计的，"这些可能更多的是一个 AI 参与吧，或者是一个噱头吧"——因为那些药物开始研发都是五到十年前，"那时候的 AI 和现在完全不是同一种 AI"。"所以我觉得未来是会的，这更多是一个时间的因素。"

▍01:02:15/01:05:43 ART 的启示：酶和蛋白质实验周期短，最先跑出来

[01:05:43] 泓君提到 Claude 最近的新成果：发现一种新的 ART，有点类似 CRISPR-Cas9 的基因编辑工具，但最后有没有被验证还不太确定，科学家也在观察这个现象。问：模型在生物医药哪些已知方向已经开始有突破？王晟："我们观察到这个突破，几乎就正比于生物医学实验的周期。周期越短反馈越快"——过去几十年大家积累了很多实验数据，通过写在论文里或被大模型公司收购等方式，已经被大模型公司拥有；所以实验做得越快的领域，模型就可以做得越好。比如 Anthropic 这次比赛做的酶[转写作"对酶 Anthema 的一个设计"，专名无法确认[?]]的设计，就是实验特别快的一个领域；未来像蛋白质、酶这些可以做快速实验的，都会有很快的迭代。但如果是衰老、罕见病这种特别 rare、特别 domain specific、特别长周期的问题，模型进展还是会很慢，很难有很快的进展。

[01:07:03] 蛋白质与酶各自的领域变化（泓君问：减肥、癌症治疗等特定领域？）：王晟：理论上蛋白质是万能的——减肥、癌症治疗，所有的病理论上都可以通过蛋白质的一些方式引导制药、改变人体来治疗。酶则很多是催化剂：比如设计一些酶把地沟油变成可食用的油，或让洗衣粉在不同温度下都有活性——酶更多是生活、各种工业化工过程中的加工与加速，"所以它的商业价值其实是非常大，而且可以快速落地的"；而蛋白质如果还是要设计药物，最后不可避免要做人体实验，还是有较长周期。

▍01:07:48 "蒸馏"是否让普通人失去了价值？

[01:07:54] 泓君：跟很多模型研究员聊"蒸馏"，很多前沿模型实验室的研究员说，很多普通人现在可能"连蒸馏的价值都没有了"，"这个话听上去很悲哀"；是不是训练信号正在转向专家数据和可验证环境？大家同意吗？

[01:08:13] 许华哲：机器人这儿很显然不是这样的。"机器人这儿每个人都是生活的专家，所以在机器人这儿没有那么悲哀，大家都值得被蒸馏——你擅长做饭，我擅长叠衣服，他擅长走路，他擅长跳舞。"当然再往后走也会经历那样的阶段：今天的机器人还做不了大模型时代的普通人档次的事情[依上下文整理，转写此句残损[?]]，"如果也许一年后、两年后才会到这样的一个阶段，就是说必须要是一个舞蹈专家，或者必须要是一个 Gordon Ramsey 这样的大厨，才值得被蒸馏。我觉得在今天就是家常菜的，每个人做的都值得被蒸馏。"

[01:08:51] 王晟：如果知识被蒸馏，现在 AI 的知识更全面，单个科学家肯定比不过；但有一些科学发现、长期投入还是需要科学家或工程师支持背书，这方面 AI 替代不了。同时存在反向蒸馏的问题："因为 AI 这么强……我天天也在蒸馏 AI"——尤其做 AI for Science 交叉学科，很多不知道的东西可以快速向 AI 学习，获取知识快，有时有新的 idea、创意，可以做更好的科研成果，"所以我觉得这是一个互相蒸馏的过程"。另一方面，从医学这个很 specific 的 domain 来说，人的作用永远非常大：人不仅解决问题，还可以定义问题、表达想让 AI 解决的问题——新的疾病，或者"人想要活到 200 岁、活到 500 岁"，这些问题源源不断；每个人还有自己不同的身体状况，不停地提供给 AI 新的问题、新的要解决的方向，"所以这些都是普通人绝对不会被 AI 所取代"的情况。泓君："说得特别好。"王晟/泓君最后补一句："可能很多是一层表层的技能，而不是底层的思维方式。"

[01:09:57] Bill：现在模型的能力还是在非常大的模型上 memorize/死记硬背很多知识，know-how 也是在训练当中硬加进去的——optimize benchmark、推进固定落地场景，会做很多 overfitting。在这种情况下，目前 overfit 的领域可能都还不够，很多领域值得被 overfit；虽然现在都说模型到了 general intelligence 的级别，"但是从我们目前在已经 overfit 的场景上面来说，我们可能没有到那么 general 的状态"。后面要做到真正非常 general 的 intelligence，可能要跳出"蒸馏/overfit 每个场景"的状态，进入到能不能模拟一个人从零开始学习的状态。"从这个角度来说，我们其实需要蒸馏人的能力，不在于说我能不能把这件事情做好，而是蒸馏人是怎么学习、从零开始学、怎么比人学得还要快。"例句：一个 foundation model 可能是非常 underfit[转写作"underfed"[?]] 的状态，能不能在某一个领域——模型自己想当一个医生——在一个月的 interaction 当中达到人类基础医生水平，三个月达到某个人类教授水平，完全靠模型自己迭代的方式来学习，"这个我觉得我们远远没有到这个程度"。未来可以从人这边得到的 intuition 其实还是很多，"人类还没有到完全被取代的这么一个状态"。

▍01:11:51 Agent、机器人与AI制药的核心问题（三嘉宾各答一题）

[01:12:04] Bill（Agent/小模型）：现在最关注的问题是硬件上全世界 memory 很有限、RAM/VRAM 非常贵，很多人 concern 算力分配[转写作"把所有的数据都算明了"，语义存疑[?]]。如果未来所有计算和算力被铺开——每个人、每家公司都有自己的算力，算力不再只集中于数据中心——"我们是不是可以想象到所有人都可以有自己的算力，可以运营自己的模型"，这模型不一定要做到最大，"我们能不能通过这些模型来解决生活当中 80%、90% 的问题，解决现在 AI 不能够完全无限量普及的这么一个问题"。

[01:12:47] 王晟（AI for Science）：还是同意未来模型需要往大往强走，但有个广度跟高度的问题——AI for Science 上可能需要一个非常高度很高的模型；而在正常的企业工作、个人生活当中，需要一个广度很高的模型，但这个模型大小不需要很大。"如果做好正确的结合，其实是可以解决目前的硬件需求和电力需求的瓶颈。"

[01:13:17] 许华哲（机器人）：最关心的肯定是零样本的泛化能力。之前的机器人有两条路——部署和泛化，这两条路有点正交。部署有点像 AI 赋能上一代的机器人：工厂里的机械臂原来是开环拧螺丝（不拿反馈、位置都标定好然后过去），有了 AI 可以闭环拧螺丝、闭环上货；"但是这件事情从我的视角来看，还是有点逆时代的"——仍然需要五个 PhD level 的人到工厂里睡三个月，去解决稳定性、速度、是否定制末端夹爪[转写作"甲状"]这些事情。最终希望的是通用机器人零样本快速部署："这个部署应该是五个任意的人，然后放在那，它其实更多就是说有一些体力劳动，或者是懂一些基本的技能，而不是说需要五个非常强的人。"这样的零样本方法肯定有冗余，"那这样的冗余我们是否可接受？我觉得是可接受的"。所以能否有一个足够好的、快的零样本方法的模型，仍然是机器人最主要的追求。
- 泓君问离这一步还有多远。许华哲："我觉得 28 年初会是一个通用机器人比较开始真正实用的时间节点。到现在开始可能 18 个月后，大家可以在家里面以语言的形式去让一个机器人做家里面 90% 的事情。"泓君："这个预测还是相当激进的。"许华哲："如果你玩了 Astra，如果你下个月也许可以玩我们的模型，应该觉得这个预测还是比较合理的。"
- 泓君说机器人进展很快，许华哲修正："我觉得机器人其实是相对慢的。因为 23 年的时候，机器人和大模型同步出发，大家看到大模型发展得非常快，机器人其实已经慢了一倍的速度了。但是我觉得物理世界的东西总是要慢一点的，就它没有办法像纯软件的东西那样超快速迭代。"
- 泓君总结气氛：整体乐观了很多——从 2020 年关注 GPT、2022 年 ChatGPT、再到多模态，前几轮模型层发展远超机器人；过去一两年甚至一年以前，大家还觉得机器人的 GPT moment 没有到来，"那今天其实我们已经在谈应用了"。

[01:15:45] 王晟（AI for Science 突破的最重要条件）：最重要的是 AI 对真实世界的理解、对真实世界资源的运用分配。"我们研究 Science，它本质就是研究真实世界：物理学就是研究宇宙，生物就是研究生命，化学研究微观世界。"这不是说设计一个机器人取代人自动做实验，而是 AI 知道根据现在实验室有哪些资源，应该让机器人或人去做什么。未来 prompt AI 的方式会变："不是说我设计一个药物能治疗癌症，而是说给你 10 万美金，你给我设计一个药物，并且我有这些实验可以做——比如说做一个老鼠实验要 2000 金[应为2000美金，转写漏字[?]]，做一个人体实验可能要一个怎么样的周期"——AI 能真的 plan 真实世界中超级复杂的任务；这些语料中很难见到，可能需要一个新的范式。范式翻转：现在是人研究怎么写好的 prompt、搭好的 agent 把 AI 指挥好；"未来可能是 AI 要写出清晰的、可执行的一个指令，是 AI 来 prompt 这个真实世界"——非常高效、清晰、不 ambiguous，人或机器人根据这些指令利用现实世界的资源高效完成；就像以前看 AI 能不能 follow 人的指令，未来要的是 instruction generation，生成更好的指令来调动现实世界的资源。甚至会对现实世界进行改造："未来的一些实验设备仪器，它不是给人看的、不是给人用的，是让 AI 用的。我们现在比如说拍 X 光拍 CT，我们还要合成一下图片，为了让人类医生能看；未来可能直接就拿出底层那些波形或者信号，直接给 AI 看就行了，都可以跳过生成图片那一步。"所以最重要的是 AI 能更好地走到真实世界中——无论通过机器人还是一个真实的人类——知道怎么样利用真实世界的资源来解决超难的问题。
