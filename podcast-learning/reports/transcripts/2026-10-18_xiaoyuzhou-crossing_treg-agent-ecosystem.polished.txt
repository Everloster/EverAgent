## 一、三次 Pivot：模型吞应用，也暴露真正的价值层

【00:02:18】Treg 团队创业约 9 个月，先后做过设计 Agent SuperDesign、全自动增长 Agent，最后转向给 Agent 提供数据和工具的 Treg。

SuperDesign 最初是周末开源项目：作为 Cursor/IDE 插件，一次生成多版前端或海报设计，几个月获得 6000+ GitHub Star。团队由此辞职创业，却一度放弃插件，转做网页产品；一年后，用户反而大规模涌向 Claude Code 和 Codex。更直接的压力来自基座模型：从 Gemini 3 开始，各家补强前端能力，通用 Coding Agent 再叠加设计 Skill，垂直设计 Agent 的差异被迅速压缩。

【00:06:59】第二次尝试是“0 人增长团队”：自动做 SEO、内容、广告和找客户。预售有人付费，交付结果却很难。数据源分散且不够准；增长需要大量业务判断和 taste；AI 能完成许多动作，却不能因此保证收入。团队后来暂停产品开发两个月，用 Agent 运营已有的 SuperDesign，得到两个结论：支持、修 Bug 等运营任务可以高度自动化；增长与创新仍需要人。至少未来 6–12 个月，“0 人公司”并不成立，真实问题是人和大量 Agent 如何协作。

## 二、一个 Codex 插件改变增长曲线

【00:14:42】团队做了许多增长实验，真正改变曲线的却是一个几乎没有宣发的 Codex 插件。当时插件市场很早期，SuperDesign 把已有 CLI/Skill 发布进去，还短暂利用字母排序把名称改成“01 SuperDesign”，获得了首批曝光。来自这个渠道的用户增长快、流失率也更低。

这让团队把 Claude Code 和 Codex 视为平台，而非普通开发工具：类似早期 Facebook 上的 Zynga、eBay 上的 PayPal，平台已有海量用户，创业公司可以只补平台体验中尚未做好的那一层。

回看增长 Agent 的技术栈，最可迁移的并非自建 Harness，而是内部那层数据与工具中转服务。真实的 GTM 或专业工作需要实时数据、垂直 API 和外部系统；通用 Agent 自带知识或浏览器抓取无法覆盖这些资源。于是团队把这一层拆成 Treg：一个 key 接入多家数据与工具，按用量付费，不收月费。上线约三周后，其收入已是 SuperDesign 的数倍（嘉宾未披露绝对值）。

【00:18:04】早期需求集中在找 B2B 客户、SEO/AEO、社媒和 UGC 视频。单个数据商只覆盖部分场景，且多以月费售卖；Treg 聚合多家 vendor，再按任务、质量和价格选 endpoint。团队把自己比作 Costco：价值并非声称拥有唯一最强供应商，而是持续选出更合适、更具性价比的组合。

【00:23:39】Treg 的潜在飞轮来自 Agent 用户的反馈。Agent 调用 API 后，可评价结果是否有用、哪些字段起作用；平台据此形成不同 endpoint 在准确度、覆盖面和性价比上的评分，再帮助后续 Agent 路由。应用公司不训练自己的基座模型，也可以让真实使用数据反哺产品。

## 三、Claude Code / Codex 周围正在长出新生态

【00:25:38】团队复盘最大的教训是：过去总想把 Harness、推理、沙盒、Memory 都自己做，但每一层都有专门公司快速迭代。现在选择只把一部分做深，再嵌入 Claude Code 和 Codex。

节目提到几类机会：Ego 提高 Agent 操作浏览器的效率；ChatCut 给视频剪辑保留可编辑中间状态，使 Agent 可以修改时间轴而非每次整片重生成；Apify、DataForSEO、Exa、Composio、Firecrawl 等数据与工具公司，因 Agent 会直接调用 API，用户从开发者扩展到大量终端知识工作者；Vibe Island 用灵动岛提示多个 Session 的状态；Orca 作为 Agent IDE，管理 Claude Code、Codex 等多种工具和任务迁移。

共同点是：基座与 Harness 越强，这些产品可服务的用户越多。创业公司还可以借用模型厂商补贴后的 Coding Plan。嘉宾举例称，用户支付约 200 美元套餐，可能获得按 API 计价约 6000–7000 美元的 Token 使用价值；这个口径是节目中的估算，并非审计后的公开价格结论。

## 四、人开始成为多 Agent 系统的瓶颈

【00:34:25】团队最有价值的实验，是两个月不开发新产品，只真实地让 Agent 运营公司。它帮助他们把“是 Skill/Prompt 没调好，还是方向本身不成立”区分开：零人公司短期不成立；Claude Code/Codex 生态值得押注。

【00:36:18】对 Loop Engineering，石天鑫的做法是“小而窄”：创新无法靠 Loop 自动完成，但运营可以。不要一开始搭一个包办公司的巨型循环，而是分别做监控数据库安全、发现攻击、整理代码、线上告警等短 Loop。每个 Loop 的任务小到不易出错，十几个 Loop 组合后才形成较健壮的系统。

【00:38:50】随着模型一次完成任务的质量上升，团队会同时跑 5–10 个 Session，人开始记不住哪个已结束、哪个等待 Review。解决思路从“人盯多个 Agent”转为“人只对一个主 Agent 或大副布置任务，再由它分发给其他 Agent”。石天鑫提到自己会用 Herdr 管理终端，让 Agent 互相沟通。

Jason 原来是 Claude Code 重度用户，Astra 发布后转向 Codex，原因是模型能力及视频复刻体验；石天鑫则长期同时使用两者，让多个模型并行完成同一任务再挑选结果。节目给出的原则是：持续使用当前最强模型，亲自感受差异，而不是长期锁死单一工具。

## 五、Fail Fast 与 AGI 之后的工具价值

【00:45:08】石天鑫认为，自己过去十年擅长的前端开发已经难以与 AI 正面竞争；除非做到全球最顶尖的一小群人，单项技能会快速贬值。他因此加入创业团队，希望把产品、工程和跨领域能力释放出来。

多次 Pivot 的痛苦在于，刚做出的产品可能一个月内就要判死刑。团队的判断标准是：还能否想到足以改变当前处境的新实验；若想不到，就应换方向。已知会失败的事情应尽快失败，把时间留给下一次尝试。

【00:49:22】即使相信 AGI 主要由模型进步带来，团队仍认为应用公司有空间：万能模型也需要工具和实时数据，也会在成本、速度和可靠性之间选择。节目举例说，如果模型自己解决任务要花 1000 美元 Token，而工具能把它降到 100 美元，工具仍有明确价值。创业者要做的是持续贴近前沿，判断未来 6–12 个月模型还不会经济地解决的部分，并把那一层做到更好。
