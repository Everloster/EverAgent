# AI 冲击下的公司：使用量、收入、利润与估值为什么会分开

一家公司被更多人使用，却可能更难卖出增值产品；另一家公司收入还在增长，市场却降低了对未来的预期。徐文浩和任鑫用这些看似矛盾的情况讨论 AI：技术创造价值，与某家公司取得收入、赚到利润，再到投资者愿意付什么价格，中间都有条件。[约 05:54—17:17、37:29—41:20](https://www.ximalaya.com/sound/1034331062)

这期采用刻意尖锐的闲聊方式，两位主持人也多次承认是个人观察、传闻或随口假设。“公司会死”在节目里混用了业务受损、产品转型、被收购和经营失败。**它适合产生待检验的商业假说，不能直接作为哪些公司已经破产、哪些股票会下跌的事实清单。**

本文读完主谈话，按价值链整理机制，并用 Linear、Lovable 的官方产品说明检验其中部分推断。企业裁员、并购金额、破产和估值变化没有逐项取得足够一手证据，未当作已核实事实转述。转写原件和修订稿保持私有。

## 渠道改变之后，使用和变现可能脱离

任鑫用 Chegg 说明一种渠道关系：原来搜索引擎把问题带到内容网站，AI 直接回答后，入口本身开始提供原来下游交付的结果。他用 Tailwind 说明另一种情况：开发者和 Agent 仍使用工具，却减少了工程师亲自浏览文档时顺便购买增值产品的机会。[约 05:54—12:01](https://www.ximalaya.com/sound/1034331062)

两个案例的口述经营数字本次未独立核实，但机制可以分开检验。前者需要看原渠道的外跳与访问变化；后者需要看使用是否继续增长，以及附加产品的发现、转化和购买渠道是否变化。不能用一个总访问量同时回答这两类问题。

按本文分析，一条原来的变现路径可能是：工具吸引开发者，开发者阅读文档，再看到付费模板或其他产品。Agent 接管文档检索后，第一步可以仍成立，后面的商业触点却可能减少。于是，用的人多不保证收入多；但销售渠道变化也不等于工具本身没有价值。

图片素材、外包和课程也被主持人归入受冲击范围。这里需要区分交付内容能否被生成，与客户是否仍需要许可、可靠结果、人工服务或系统化学习。节目对这些领域的方向判断较强，本次没有用个别案例推断整个行业必然消失。

## 财报增长和估值下降并不矛盾

SaaS 部分，两位主持人观察到一些公司经营数据并未同步恶化，市场却提前担心其收入模式。他们认为 AI 可能改变按席位、按人头或按工作时间收费的基础。[约 12:01—20:58](https://www.ximalaya.com/sound/1034331062)

这是一个可以理解的机制：当前收入反映已有客户与合同，估值还包含对未来增长、利润、竞争和风险的预期。但股票下跌的原因可以很多，不能只凭发生在 AI 发布之后，就证明由那次发布造成。

| 节目中经常混在一起的说法 | 它实际描述什么 | 核验需要什么 |
| --- | --- | --- |
| 股价或估值下跌 | 市场对权益的定价变化 | 起止日期、价格与比较口径 |
| 收入下降 | 一定期间的经营收入 | 同口径财务资料 |
| 裁员 | 员工或岗位调整 | 官方范围、时间与角色 |
| 被收购或转型 | 所有权或业务方向改变 | 交易结构及后续经营 |
| 破产、解散或停止服务 | 不同的法律或运营状态 | 正式公告、登记或程序记录 |
| 产品形态失效 | 用户解决任务的方式改变 | 使用数据、替代方案与实际任务 |

这是本文用于校准语言的表。收购人、产品资产或整家公司，不是同一事件；退出某个市场，也不等于全部业务停止。节目中有些状态混用，报告不沿用“已经死了”作统一标签。

## 成本下降三倍，生意一定缩成三分之一吗

任鑫的一个判断是：你用 AI 做了降本增效，竞争者几个月后也会做，所以不做不行，做了又未必多赚钱。他把某种情形概括为成本或人效改善三倍，生意规模变成原来的三分之一。[约 17:17—20:58](https://www.ximalaya.com/sound/1034331062)

其中最有用的部分，是提醒人关注成本优势能保留多久。结论却需要额外条件：客户愿意支付的价格是否同步下降、销量是否变化、固定成本如何调整、竞争是否足够强。不能从单项成本变化直接推出市场规模。

下面是本文自拟、已复算的例子，单位均为任意货币单位，不含固定费用：

| 情形 | 单价 | 数量 | 单次可变成本 | 收入 | 可变成本后余量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原方式 | 10 | 100 | 6 | 1,000 | 400 |
| 成本降为三分之一，价格不变 | 10 | 100 | 2 | 1,000 | 800 |
| 成本下降，但竞争使价格减半 | 5 | 100 | 2 | 500 | 300 |
| 降价后销量翻倍 | 5 | 200 | 2 | 1,000 | 600 |

同样从 6 降到 2，可以出现不同收入和余量。表内余量不是净利润，还要扣除研发、销售、维护和其他成本。若原计费依赖人员工时，而用户购买的是相同结果，自动化确实可能压缩可计费工作；若节省的时间扩大需求，也可能走另一条路径。

对 AI 产品，这意味着报价与收益分析要绑定结果。单纯卖 token、卖席位，与承担完整交付，拥有不同的定价空间；但按结果收费还需要清楚定义完成与失败，不能只换一个收费词就得到更高毛利。

## 项目管理会变，什么任务仍需要被管理

徐文浩描述自己所见的高效团队：快速响应反馈，短时间完成过去更长周期的工作，原来的拆票、看板、排 sprint 等方式价值下降。主持人进一步设想，协作可能变成共享 Agent 会话与交付上下文。[约 20:58—27:01](https://www.ximalaya.com/sound/1034331062)

这支持“某些团队的协作方式发生变化”，还不能证明项目管理这个问题消失。更快生产仍需要确定目标、分配资源、处理依赖、确认权限和验收结果；共享会话也需要说明谁接手、什么已完成、哪些结论仍待验证。

本次读取的 [Linear 官方 Agent 平台文档](https://linear.app/docs/agents-in-linear)描述了在 issue 上委派 Agent、用评论触发工作、按团队授予访问，以及查看 Agent 活动。这个产品事实说明，issue 与 Agent 可以组合成为新的协作方式；它不能证明 Linear 一定商业成功，也不证明原有周期管理会原样保留。

**本文判断：** 要检验产品形态的替代，需要先识别用户正在完成的任务。某种人手更新看板的流程被替代，保留共同目标和交付责任的需求可能仍在。新产品可以更少要求人填写状态，但状态和责任并不会因界面隐藏而自动不存在。

## Coding 工具的差异，不只在生成代码

节目比较多家 coding 产品的不同选择：面向个人开发者、企业数字员工、快速造应用和平台集成。具体收购与收入说法未在本次逐项核实，较值得保留的是主持人对产品价值的区分。[约 41:20—51:26](https://www.ximalaya.com/sound/1034331062)

代码生成变强之后，用户仍可能需要数据库、登录、部署、支付和团队协作。徐文浩用 Lovable 说明集成这些环节的价值。当前 [Lovable 官方内置后端说明](https://docs.lovable.dev/features/cloud)列出数据库、认证、存储、函数和托管，并说明后端权限与资源使用。这支持“产品承担的不只是生成前端代码”，不代表本报告实测了它能可靠交付任意应用。

模型原生提供某个功能，会减少一部分外围工具的差异化；但用户任务、服务整合和结果责任也会形成新的工作。不能仅根据模型能写出相似代码，就把集成系统的全部价值视为零。

主持人用“浮冰”形容暂时领先的能力：要意识到差异可能融化。这是对创业风险的比喻，不是用来计算每个产品寿命的模型。本次也没有证据决定某家公司应该坚持、转型还是出售。

## 买 token 再转卖，真正增加的价值是什么

两位主持人担心，应用公司按较高成本购买模型调用，再与提供补贴订阅的模型厂商竞争。徐文浩将其类比为早期网络卖车平台按零售价购车，再卖给用户的经历。[约 51:26—64:52](https://www.ximalaya.com/sound/1034331062)

类比的重点是上游价格与下游收费之间的空间。它没有证明所有应用都只是转售：一个 Agent 可能还提供工具、状态、行业知识、交付与支持，也可能通过缩短轨迹减少消耗。判断应看新增价值及完整成本。

API 单价和面向用户的订阅价格也不能直接换算。订阅可能有使用限额、不同优先级与补贴；应用成本还包括失败重试、外部工具、服务设施和人工支持。节目未提供同任务、同质量的完整账单，所以“二手贵 token”保留为竞争压力的概括。

这与[蒋冠军谈稳定性和成本](./2026-11-23_ai-lianjinshu_jiang-guanjun-personal-agent.md)能互相补充。提高工具成功率、减少重复推理，可能改善交付成本；但用户究竟为计算、结果还是省心付费，仍要通过产品使用检验。

## Neo Cloud 的风险，怎样从类比变成可检查条件

徐文浩把 GPU 云建设与互联网时代铺光纤类比：看好需求、扩大建设、增加杠杆，在同质竞争与高周转预期下可能过度扩张。任鑫进一步讨论，代理人的短期激励与出资人的长期风险可能不同。[约 31:19—41:20](https://www.ximalaya.com/sound/1034331062)

这个框架指向真实需要调查的关系：服务有多少收入承诺，客户什么时候付款，设备与供电何时可用，闲置或价格下降后如何承担负债。它不能由历史类比单独证明某一家公司会倒闭，也不能决定发生时间。

按本文分析，收入取决于可售容量、有效利用率和实际价格；支出涉及设备折旧、资金成本、电力、维护与服务。不同硬件、网络拓扑、可靠性和支持能力会影响客户总成本，因此“所有客户只看租卡单价”也过于简化。

节目还混用了图形斜率与增长率描述泡沫。预测增长稍高，确实可能在复利下积累偏差，但“十五度改二十度”等几何说法不能直接算出泡沫为 5%。自拟数学例子：同一起点，年增长 20% 与 15% 持续五年，终值比为 \((1.20/1.15)^5\)，约 1.237，即相差约 23.7%。这只验证复利算术，不说明真实需求增长率或企业估值。

节目谈到做空和尾部期权时，也明确承认举例数字是随口编的、现有证据不足以支持投资判断。本文不把那些收益数字保留成历史投资业绩，不据此形成交易方案。

## 通用 Agent 会吃掉垂直产品吗：节目里的两种回答

任鑫较担心上下文集中：用户把邮箱、支付与长期信息交给一个通用助理，便不愿向另一款垂直产品重填信息。若综合产品能覆盖多数场景，垂直入口可能被压缩。

徐文浩没有完全同意。他认为公司有资源与组织边界，拥有大用户网络不意味着能做好全部产品；用户任务和内容形态也可能分化。讨论中，双方没有给出最终答案。[约 01:21:04—01:28:38](https://www.ximalaya.com/sound/1034331062)

这场分歧值得保留。数据聚合是优势，但垂直任务可能需要特别供给、可信结果、额外权限或专业服务。最后可能形成独立入口，也可能成为通用 Agent 可调用的一项服务，不能把两种形态都理解成公司不存在了。

旅行部分也有类似区别：一些用户想快速完成预订，另一些喜欢浏览和比较。主持人转述的 Airbnb 用户数据没有取得原始材料，不作为统计事实。实际可检验的问题是：Agent 如何减少用户不想做的工作，同时保留用户愿意进行的选择。[约 64:52—70:18](https://www.ximalaya.com/sound/1034331062)

平台通过默认勾选或难理解收费获利的空间可能受挑战，这是主持人的使用观察。本文不把个别投诉当作整个平台涉嫌某项违法行为的证据；讨论的经济机制是，当助手帮助看清总价与条款，信息不对称可能减少。

## 新生态仍有机会，但功能更快被复制

沙盒、数据库和 Agent 工作管理工具被主持人视为新需求：更多 Agent 需要运行环境、状态和入口。但更强 coding 能力也降低了进入门槛，可能让相似功能更快出现。[约 70:18—75:12](https://www.ximalaya.com/sound/1034331062)

这能解释为什么需求增长与竞争加剧同时发生。复刻一个界面或 API，不等于复刻稳定服务、用户信任、分发和运营；但这些优势也不能默认永久保留。节目里“99% 都会黄”没有样本和统计依据，本文只保留其竞争激烈的判断。

功能品牌部分，两位主持人讲了相反的购物变化：一人发现更便宜的替代，一人因具体需求找到更贵的细分产品。它们说明 AI 匹配可能改变选择，不证明所有消费都将降价或涨价。护肤例子仅作为个人购买故事，不转成医疗或产品推荐；采购调查比例被主持人明确说是凭印象，未写入本报告的事实数字。[约 75:12—81:04](https://www.ximalaya.com/sound/1034331062)

## 公司留什么，人学习什么

节目最后回顾 Trilogy：部分互联网业务失败，原来的企业软件现金流仍支持公司生存，人才和经验也进入后来的项目。徐文浩把它用于说明，公司某个业务的结果和员工长期积累可以分开。[约 94:32—01:40:16](https://www.ximalaya.com/sound/1034331062)

这段是他的亲历与回忆，后续人物和并购履历没有在本次逐项传记核验。不能从少数成功经历推断，加入泡沫公司必然能创业成功。相对可取的学习是：理解用户任务、收入关系和真实交付，比仅熟悉某个短暂热门界面更可迁移。

任鑫提出保留现金和跑道，属于经验建议；“留一半钱”不是依据财务约束计算出的统一比例。对具体公司，还需要预算、债务、合同、融资和风险承受能力，不能照搬。

对学习工作台，这期最直接的要求是检查我们新增了什么价值。把源链接放入清单，只完成发现；转写解决可访问性；来源核对和机制解释帮助理解；报告、索引与提交读回形成可持续交付。若只是增加文章数量，却没有改善可靠性和阅读，不能仅凭产量宣称学习效果提高。
