# GPT-6 之后，机器人公司该自研什么？

机器人抓偏了，模型看一眼新画面，能指出哪里不对，再调整下一步。这种表现让本期嘉宾兴奋：过去专门训练的策略容易卡在错误轨迹里，通用模型却可能借助语义理解和交互记录继续尝试。但水杯已经倾斜时，等模型想清楚再补救，水可能早就洒了。

这两个场景串起了整期讨论。**通用模型扩大了机器人可以借用的能力，创业公司的工作因此重新分配：理解任务可以更多借助基础模型，及时、准确、可重复的物理执行仍要靠系统工程。** 三位嘉宾大体认同这个方向，对数据价值、模型架构和团队优势的判断则各有侧重。本文根据全文转写整理节目，并用官方 API 文档、原论文和厂商技术说明校准其中的技术推断。

## 先听清楚他们各自关心什么

[节目简介](https://www.xiaoyuzhoufm.com/episode/6ace096ee742e36efcc25e5a)介绍，王建明是英诺基金执行董事、石麻笔记主理人；韩磊是诺亦腾机器人联合创始人兼首席科学家；胡钰承是潜界科技 CEO。靖宇与李源参与主持、提问。

王建明从投资和行业观察出发，关心公司是否找到了值得长期做的问题。他将资本热度下降与技术进步分开，建议国内团队重视硬件、控制及执行系统。韩磊围绕数据获取和机器人系统，强调多模态数据怎样对齐、上下层怎样配合，以及桌面操作之外的全身控制。胡钰承从模型研究出发，看好语言模型的推理和纠错能力，同时认为具身团队仍需把动作模型做强。

## “模型会控制机器人”，到底是谁在执行

开头约 06:05—15:30，嘉宾最在意的并非模型输出了一条漂亮轨迹，而是它能观察动作造成的变化，再尝试纠正。胡钰承提到团队此前用另一模型做过仿真实验，完成任务的推理可能花上几十分钟。他以此说明能力已经出现、效率仍有距离。这是节目中的团队经验，本文没有取得原始运行记录；转写里该模型名称也不稳定，因此不补猜型号。

要理解“直接控制”，可以沿着实际接口看。OpenAI 的 [GPT-6 Astra 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)列明文本、图像输入与文本输出，并支持 function calling；[函数调用指南](https://developers.openai.com/api/docs/guides/function-calling)明确，Astra 的工具调用需要 Responses API。模型提出函数调用后，是应用代码执行动作，再把结果交回模型。文档没有承诺机器人控制频率、硬实时延迟或物理安全。

与节目讨论相关的 [RoboDojo 研究 v1](https://arxiv.org/html/2609.24170v1)给了一个具体实现：冻结权重的模型接收相机画面和机器人状态，输出末端执行器目标；非学习模块再做几何转换、逆运动学和路径处理。控制链中没有预训练的运动策略，但仍有大量机器人软件。

```text
相机画面、当前状态、历史动作结果
                  ↓
模型决定：末端下一步移到哪里，或放弃
                  ↓
应用处理目标 → 逆运动学与路径处理 → 控制器执行
                  ↓
新的观测进入下一轮
```

因此，“没有专门训练一个抓取策略”与“没有控制系统”差别很大。论文的轨迹按 **25 Hz** 重采样执行，不能写成模型 API 每秒完成 25 次看图、推理、决策。它证明的是一种可行的连接方式及其局部能力。

另一个需要留意的词是“学习”。模型根据本轮结果换一种动作，可以是上下文内调整；真正改变权重，需要另一个训练过程。论文的控制实验冻结权重，也不能据此断言其预训练从未包含机器人相关材料。节目中对训练数据的猜测，目前没有官方资料可以确认。

## 实验成绩离“桌面任务已经解决”还有多远

节目谈到不同团队的演示、模型组合和约六成成绩。这些讨论没有统一实验协议；本文不把口述数字合成一张排行榜，也不把它们与纯 Astra 控制实验直接比较。

能固定版本核对的是上述 [RoboDojo 论文](https://arxiv.org/html/2609.24170v1)，其主实验覆盖 42 个仿真任务，Astra 每任务运行 50 次。论文给出的 **Average Score 为 28.97，Average SR 为 22.48%**。Score 是过程奖励乘以 100，完成了一部分步骤也能得分；SR 才是完整成功率。榜单 Average 按五个能力轴取平均，不能随意换成全部轨迹混合平均。

这些数字支持“通用模型已经有值得研究的操作能力”，不足以支持“可靠执行已解决”。比较中的 40 个公开策略来自排行榜快照，也没有获得与语言模型相同的额外任务说明，不能把名次当作完全同条件重跑。

更直接的限制来自实机：论文第 5 节披露，模型多次发出不合理或不安全动作，部分试验造成设备损坏，研究者停止了测试；没有人员受伤。留下的 33 次试验是有选择的诊断材料，官方实机协议没有完成。

“看过示范就能更好完成”同样需要单独验证。在论文的 340 次匹配试验中，零样本成功数是 78，加入一种图像与末端位姿示范后为 61，加入文字示范后为 44。这只说明该示范格式和设置没有带来整体改善，不能推广成所有上下文学习都无效。它也提醒我们：**会在执行中纠错、会利用示范、会跨任务迁移，是三种需要分别测量的能力。**

节目约 60:00 起把桌面任务称为相对“静态”，主要是在和移动、全身操作比较。即使底座固定，接触、滑落和碰撞也会随时间发展。将此处整理成“固定桌面的部分任务可以开始收敛和工程化”较为准确；“静态任务已普遍解决”超出了现有证据。

## 快慢系统的分工，还要解决信息怎样及时到达

约 15:30—24:36，韩磊把长程理解和推理交给较慢的上层，把快速感知、运动和控制留在执行侧。节目使用的 System 2、System 1、System 0 是讨论分工的简称，不是所有厂商统一采用的接口标准。VLA 则指视觉、语言、动作模型；模型名称里有 Language，也不代表它对复杂临时指令的遵循已经足够好。

这个划分背后的实际问题，是观察什么时候失效。用一个**自拟算例**说明：目标以 0.4 米/秒移动，上层决策耗时 2 秒，那么仅在等待期间它就会移动 0.8 米。数值只是算例，但关系很明确：提高规划能力，不能直接消除旧观测造成的误差。

约 28:00—35:00，嘉宾进一步讨论为什么“GPT + VLA”不一定更强。韩磊推测，底层策略不适应测试分布时，可能给上层带来错误动作；胡钰承质疑先生成轨迹、再让大模型修正的组合，认为它未充分发挥底层实时执行的优势。这些是对实验现象的解释与设计建议，节目没有提供可以隔离原因的消融结果。

值得保留的工程问题是：上层发出的究竟是完整轨迹、短期目标，还是持续更新的条件？底层做到哪一步时接受新信息？旧计划失效后由谁停止动作？只画一个“大脑接小脑”的框图，还回答不了这些问题。

这里有一处必须纠正的来源差异。韩磊以 GEN-0 的 Harmonic Reasoning 为例，描述了上层推理过程中持续向下层注入信息的设想。但 [Generalist 官方介绍](https://generalistai.com/blog/gen-0)说的是异步、连续时间的感知与动作 token 流，并明确表示其设计不依赖 System 1 / System 2 架构或推理时引导。官方材料支持“思考与行动可以交错进行”，不支持把 GEN-0 直接还原成节目所描述的两层实现。后者应作为嘉宾的理解与启发保留。

## 仿真和数据的价值，会随着缺口移动

约 22:00—29:00，胡钰承提醒，基础模型的作用还包括生成仿真资产、搭环境和调整参数。这会降低实验准备成本。韩磊接着区分视觉差异与动力学差异：图像更像真实世界，不代表接触、摩擦等行为也准确。两位都没有说仿真已经不需要真实数据。

可以用一个**自拟例子**理解：生成杯子的三维形状，有助于搭建抓取场景；要知道它装水后怎样晃动、夹紧到什么程度会滑落，还需要质量分布、接触参数和现实校验。编程 Agent 帮忙生成场景，省下的是一部分建模工作；仿真参数是否适合目标任务，仍需验证。

到约 49:03—65:47，讨论从模型架构转向数据配方。三位都反对仅凭 VLA、世界模型等名称判断价值，强调应该先问数据帮助哪个训练阶段、解决哪种错误。世界模型与 VLA 也不天然互斥：一个系统可以预测未来状态，同时产生动作。

他们对 **ego 数据，即第一人称视角数据** 的判断，尤其需要保留条件。胡钰承认为，如果通用模型已能理解大量动作趋势，单纯第一人称视频的增量价值可能降低；韩磊强调，应把视频与手部位姿、运动、力或触觉等执行信息结合。这里不是在否定所有第一人称数据，更不是对其市场价格的实测预测。

胡钰承对“单靠视频或世界模型就涌现通用智能”持保留态度，偏好借助语言模型的推理能力。那是他的研究判断；不能扩写成学界已证明智能只存在于语言，或所有生成式模型都必须采用同一种架构。

从本期讨论可推导一个更有操作性的选数方法：先看失败缺少哪种信息，再决定采集什么。抓错目标可能需要更清晰的语义与场景；夹住后滑落可能需要接触、力和抓取过程信息；移动中失败则还涉及身体状态、地形与时序。不同错误对应的采集成本、标注方式和验证方法都不同，单报“多少小时”很难说明训练价值。

## 把执行数据收回来，还不等于自动学会

约 43:00—49:00，韩磊提出较现实的数据回流路径：先有能持续工作的策略，必要时人工介入，把执行记录收回，再评估并训练下一版。胡钰承则提出，强模型可以辅助判断任务进度、提供纠错意见，或承担类似 DAgger 中专家的部分工作。两者都是潜在用途，节目没有给出实际降本幅度。

这里至少有三件不同的事：

| 做法 | 产生什么 | 后面还缺哪一步 |
|---|---|---|
| 模型判断完成程度 | 奖励或进度标签 | 校准标签、选择训练方法，再验证策略是否改善 |
| 模型建议正确动作 | 面向当前状态的动作标签 | 确认建议可执行，累积训练数据并更新策略 |
| 模型当场重试 | 当前任务的新动作 | 若要长期保留经验，还需明确记录、训练或记忆机制 |

[DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)中的数据聚合，是让学习策略访问状态，由专家为这些状态提供动作标签，再合并数据、训练策略。它属于模仿学习方法；不能把“给一个奖励分数”“在线纠错”和“已经实现 DAgger”写成同一件事。把专家替换成大模型之后，专家标签是否可信又成为新的测量问题。

同样，offline 与 off-policy 也不等义：前者强调从固定离线数据学习，后者指学习时可使用不同于当前目标策略产生的数据。节目在谈真机成本时把这些概念放在一起，整理后应保留其核心意思——减少昂贵或危险的在线试错——而不固化概念混用。

如果要实际检验这一设想，可以先在仿真里固定一组失败状态，比较人工判断与模型的进度标签、动作建议，再检查训练后策略在留出任务上是否改善。只看模型评价自己的成功率，容易把误判也带进训练。本次未运行这项机器人实验。

## 创业建议应怎样落实到一家公司

约 39:08 起，王建明建议国内创业者重视硬件、控制和执行层，并认为资本降温可能使团队回到具体问题。约 49:03 起，他对中美公司的“概念与数据”“对标与差异化”作了比较。这是他的访问与投资观察，不能当作覆盖两国行业的统计结论。

这期没有讨论订单、毛利或回本期，因而不足以支持某类机器人公司的投资结论。它更适合帮助团队重新分配研发：如果上层理解能调用现成模型，有限人力是否更应投入动作精度、传感器对齐、故障恢复，以及客户场景里的持续运行？这些具体能力也更容易通过同场景对比验收。

三位最后的分歧比“大家都看好具身公司”更有价值。王建明和韩磊更强调具身原生团队对硬件、控制和系统的经验；胡钰承认为无论创始人来自哪一侧，团队都应同时具备模型 scaling 和机器人系统能力，至少还要把动作能力做大、做强。共同借用基础模型，不意味着各家公司只剩硬件装配。

节目结尾对未来 6—12 个月的期待，包括融资放缓但技术继续迭代、移动操作改善，以及更多落地尝试。这些是 **2026 年 10 月节目中的预测**，没有在本报告里转写成已发生的结果。

对一个准备落地的团队，本文建议把争论转为同任务下的比较：纯模型决策、专门动作策略、两者组合，分别记录完整成功率、执行耗时、人工介入与失败后果。保持任务分布、可用信息和预算可比；组合方式若多获得了任务说明或更多试错次数，单独记录。这样才能知道强模型究竟替代了哪段工作、增加了什么成本。

可靠性也要按使用长度理解。一个**自拟、独立同概率假设下的算例**：每次操作成功率 99%，连续 100 次全部成功的概率约为 36.6%；每次达到 99.9%，该概率约为 90.5%。现实错误会相关，且有恢复机制，这个乘法不能用作产品预测。它只是解释了为什么演示成功与长期服务之间，还有大量执行与运维工作。
