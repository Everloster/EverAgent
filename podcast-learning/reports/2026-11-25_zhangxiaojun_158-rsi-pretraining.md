# 沈驿康谈 RSI 与持续学习：研究闭环、训练误差和个人 Agent 的不同问题

AI 能帮研究者改代码、分析数据和运行实验，是否意味着它已经能自己训练下一代模型？模型用得越久越了解用户，是否又等于同一个研究闭环？这期访谈将 RSI、持续学习与 Personal Agent 放在一起讨论，最需要厘清的是它们分别改变什么，以及哪一种改进有实际证据。

沈驿康曾参与 IBM 和 xAI 的预训练工作，正在创办 Learning Machine。访谈约 3 小时 23 分钟，先谈市场与组织，再谈模型进展、RSI 和持续学习，后半段深入数据、架构、数值稳定与规模外推。本文以完整转写为基础，另读官方研究加速报告、持续学习综述的定义部分和 verl 的 rollout correction 文档。嘉宾对内部组织、行业排名和市场前景的判断保留个人经验的性质。[节目与章节说明](https://www.xiaoyuzhoufm.com/episode/6b05746801b0ab432eddab62)

## 人才与算力为什么仍要连接到研究方向

约 20:00—50:00，嘉宾用 xAI 的经历说明，工程速度和人才密度不能替代持续的方向选择。他认为公司需要把用户反馈转换成产品、数据和训练决策，才能在某个场景长期积累。

这条反馈链比“用户多，模型立刻更聪明”长得多。用户先提出问题，团队判断它是产品入口、速度还是能力不足；随后选择新的数据与任务、调整预训练或后训练，直到下一代模型交付后才能重新观察效果。某些界面修复很快，涉及预训练的改动则要等待更长周期。

用户反馈因此可以帮助确定“下一项值得研究什么”，但不是直接把所有聊天记录喂回训练。数据的代表性、质量、使用权限与能否区分用户真正要的结果都需要判断。领先公司的用户多，可能获得更好的问题线索；后来者仍可能通过专业领域或不同技术路线形成自己的反馈来源。

访谈关于团队人数、各实验室战略、人员调整的描述没有在本次取得独立完整的组织资料。不能从一个前员工的解释直接推出落后的唯一原因，也不能把“主战场清晰”当作保证胜出的充分条件。它提供的是一个值得检查的组织机制。

## 能力进步、演示效果与技术路线是不同证据

约 50:00—01:22:00，沈驿康谈到编码、长程 Agent、多模态理解、数学和机器人。主线是模型能力增长可能让以前需要专门系统的任务被通用模型处理。

他对编码进步的体验很具体：此前需要反复进入代码调整，后来更多只给意图、检查结果。但个人应用经验不能证明所有软件工程都已可靠自动化。架构选择、性能、权限和验收仍可能成为不同的限制，不能将主持人“Coding 已经 AGI 了”的问句当成正式能力证明。

在机器人部分，他区分反射或底层控制、熟练快速执行和需要较长推理的动作，使用 System 0/1/2 类比。这个类比帮助解释响应速度和通用规划怎样分工，却不是统一的机器人控制分类，更不等于某个模型真实采用了对应的大脑模块。

语言推理与多模态理解能够协作：文字提供问题和已有知识，图像、声音及动作观察提供语言没有描述充分的状态。模型对场景理解更好，可以改善后续决策；执行还要满足实时性、动作接口和环境约束。

嘉宾对 Astra 机器人能力“意外泛化”的解释和对世界模型竞争的判断，没有配套训练数据、消融与完整测试。写代码搭建仿真也可能有实现和物理模型误差，不能因规则由代码实现就断言场景绝不出错。本文保留这些作为技术路线讨论，未验证相应演示或接受“所有路线最终必然统一”的预测。

## RSI 的定义为什么会影响“实现了多少”

约 01:22:03 开始，沈驿康先把 RSI 定义成用这一代模型建立研究 Agent，参与下一代模型的数据、算法、kernel 和训练改进，理想情况下不需要人介入。他再提出更高要求：模型能够发现原先没有的问题或能力，并形成新的解决方法。

这是两个层次。一层是在已定目标上改进，例如让已有任务更准、训练更快；另一层改变研究问题本身，例如发现一种新的学习方法。一个系统在第一层很有效，不表示已经达到第二层。

OpenAI 的官方研究加速报告采用较宽的定义，把 AI 加速未来 AI 系统开发的过程纳入 RSI 指标，并明确指出，报告这些指标不应被理解为要追求完全 RSI。它测量的研究活动包括人和 Agent 协作，因此不能与“整条研发链无人介入”的窄定义直接混用。[官方定义与范围](https://openai.com/index/research-acceleration-jagged-frontier)

| 看到的行为 | 可以支持什么判断 | 尚不能单独证明什么 |
| --- | --- | --- |
| Agent 修好一个训练 kernel | 这个任务上的研发工作被加速 | 整体训练更好或研发已自动化 |
| Agent 提出数据改动，受控实验有效 | 此改动有可重复的局部收益 | 能跨任务、模型和规模持续自我改进 |
| 改进后的模型再帮助形成下一次改进 | 存在递归使用的候选闭环 | 闭环无限加速、无人监督或没有能力上限 |
| 提出原先没有的方法并独立验证 | 在具体问题上有新的研究贡献 | 普遍的自主研究能力 |

因此访谈中的“实现了 50%”，来自嘉宾将线性改进与新问题／新方法分成两部分后的主观估计。两部分未被证明工作量相等，也没有统一测试集和分母，它不能作为 RSI 工程进度条。

## 一个研究闭环要保留哪些依据

有效闭环需要一个可检查的问题、冻结的基线、候选改动、可比实验和决定是否保留的依据。Agent 可以反复提出修改，但评测必须能识别它究竟改变了什么。

```text
研究问题与基线 → 候选改动 → 可比实验 → 核对正确性与代价
      ↑                                      ↓
      └──────────── 保留或撤回改动，进入下一轮 ─┘
```

例如 kernel 快了 10%，先检查数值是否符合要求，再看完整训练是否更快到达同一质量。若 Agent 只是减少测量工作、改了输入形状或放松精度要求，得到的是新条件下的结果。它也许仍有价值，但不能当作原目标无代价的提升。

研究代码、时间和实验数量更多，同样不保证能力提升。OpenAI 的报告特别区分这些活动指标与能力结果，并发现研究任务的完成水平不均衡。其对关键研究想法的访谈中，多项想法被归因于人，模型更多帮助实施，部分预训练思路则在与 Codex 交互中完善。资料支持研究协作正在变化，尚不能支持研究者已经完全退出。[官方研究过程与结果](https://openai.com/index/research-acceleration-jagged-frontier)

本轮对 Agent 评测的学习也提供了一个直接反例：输出比值正确，却没有完成拟合。研究 Agent 如果能修改题目、评分器或测试范围，很容易优化出不再回答原问题的分数。保存版本、核查失败与替代解释，比只数“成功实验”更能说明闭环质量。[本轮评测报告](../../ai-learning/reports/knowledge_reports/Agent评测_任务评分器与运行记录的校准_深度解析_20261125.md)

## Infra、预训练与后训练，困难分别在哪里

沈驿康认为 infra 的目标相对明确：在精度等条件满足时提高吞吐、减少延迟。预训练可以先用小模型快速试验，积累对大模型的预测。后训练则有多个任务、评价集和副作用，更难用一项指标驱动。

这是任务设计上的差别，而不是某个领域天然已经解决。infra 的局部速度可能被其他瓶颈吃掉；小模型收益可能无法外推；后训练的一项分数改善可能损害其他能力。评估时要把改动作用于哪一环写清。

他提到使用现成 Claude 构建研究 Agent 的创业公司，并追问“优秀的是模型还是 harness”。两者都可能贡献收益。一个有意义的对照可以固定任务和预算，更换模型或 harness，检查哪项改变造成了差异。依赖强外部模型也不自动否定自身技术价值，但需要说明改进是否能保留、迁移，以及依赖变化后闭环还能否运行。

小公司率先形成这种闭环就会永久垄断的预测，依赖很多条件：能力能持续提升、研究时间能继续缩短、硬件和数据没有成为新瓶颈，对手也没有复制或提出另一条路线。嘉宾自己在访谈中逐项指出这些假设，本文保留它们，没有把未来优势写成必然结局。

## 持续学习改变的是部署后的经验积累

约 01:45:00 以后，沈驿康将持续学习解释为模型部署后仍能从任务经验增长知识和能力，使同领域后续任务更容易完成。它讨论的是学习怎样随使用继续发生；RSI 讨论的是 AI 怎样帮助开发更好的 AI。持续学习可以帮助研究 Agent，研究 Agent 也可能探索持续学习方法，两者关联，却不互相包含全部含义。

持续学习研究通常关注顺序学习新任务或领域时，能否保留旧能力。综述区分持续预训练、领域适应和持续微调，并强调遗忘与知识迁移的评测。[综述定义与分类](https://arxiv.org/html/2404.16789v2)

在产品里，还要区分几种改变：给当前上下文追加信息；保存可检索的记忆或规则；更新 adapter 或其他模型参数；以及几种方式组合。前两种可以让后续行为更符合用户需求，后者可以改变模型本身的学习结果。是否出现可迁移的能力改善，应由新任务和保留旧能力的测试来判断，不能只看记忆文件变长。

嘉宾没有公开自己方案的学习算法，因此本次不能断言其更新一定发生在模型权重，也不能补写成已证明解决遗忘的方法。

一个更有区分力的验证顺序，是先测新用户或新领域基线，再让系统依次接触带反馈的任务；随后测试同领域未见过的问题、旧任务，以及移除某项记忆后的表现。这样才能检查它究竟记住答案、检索到更多资料，还是学会了能迁移的方法。学习还需要处理错误反馈、删除请求和环境变化，长期改善不是自动成立的。

## Personal Agent 为什么又引出部署与商业模式

沈驿康设想，一个面向人的 Agent 整理长期信息、理解习惯，必要时请求专业服务；专业 Agent 则负责特定领域的任务。他希望个人模型与数据由用户掌握，和多种服务协作。

其中“个人”不等于必须放在手机。访谈明确允许在个人设备、私有服务器或专属云环境运行，因为电池、算力和是否持续开机会限制设备选择。用户控制、数据隔离、执行位置与个性化程度是几个独立条件。

“一百万用户，一百万模型”也不必然是复制一百万份完整权重。共享基座可以配独立 adapter、记忆和状态，完整参数副本是另一种选择。应比较效果、状态隔离、更新和迁移成本，而不是仅按模型数量判断实现。

嘉宾认为长期积累会提高切换成本：新助理即使读过文件，还需要理解用户的隐含习惯。这能解释用户粘性，也引出反向问题——如果用户无法导出、校验或删除积累的知识，粘性可能来自迁移困难。替换模型时如何保留来源和用户认可的偏好，是这条路线需要解决的产品问题。

在主动提醒上，他批评用面向所有人的平均策略与 DAU 目标不断打扰用户。这里的可用标准应是用户在这个场景是否希望被打扰，以及提醒是否真的帮助当前目标。个性化系统也可能学错，仍需要用户纠正和清晰的控制。

## 本地计算怎样改变成本，哪些费用还在

嘉宾希望小型、可适应用户的模型减少对超大云模型的依赖，让设备承担高频任务，专业服务处理必要的复杂问题。他将本地推理描述为云端 token 成本接近零。

从供应商账单看，离开云 API 的调用确实可能不再按 token 收费。但设备、能耗、存储、更新、学习计算与维护仍有成本，复杂任务也可能回云端。个人模型不必涵盖所有知识，可以减少某些负担；它是否仍能满足实际需求、需要多少学习样本和更新计算，必须测量。

中心化与分布式也没有由能力进步自动决定。云端可以做用户隔离与个性化，本地系统也可能依赖远程服务。访谈的大型机／个人电脑、门户／网站类比说明一种可能的演化路径，不能单独预测最终商业模式或售价必然降到零。

## 数据质量为什么不是一个固定标签

约 02:21:53 开始，预训练讨论给出很具体的提醒：人眼觉得整洁、高质量的数据，可能没有覆盖模型需要的真实知识。只按百科式文本选数据，某些标准测试可能不错，日常问题却出现知识空缺。

因此质量至少涉及内容准确性、重复、污染、覆盖与训练用途。同一份数据对知识获取、推理或对话风格的作用可能不同。数据配比还需要检查某类能力何时饱和、是否损害其他领域。访谈中的“某类 5% 就够”是经验例子，不是适用于任意语料的比例规则。

合成数据同样需要校验。更多推理文本不保证过程有效，也不能用模型自己说“高质量”替代任务检验。来源、样本构造、去重、错误分析和保留集共同决定这些数据能支持什么结论。

嘉宾将预训练、推理、后训练与 infra 的合作比作整体系统：预训练提出候选设计，推理考虑用户侧效率，后训练考虑 RL 与能力需求，infra 保证执行。所谓效果是各部分质量的“乘积”主要表达相互依赖，访谈未给出可直接代入的数学乘法模型。

## Rollout 与训练不一致为什么会干扰 RL

训练 Agent 时，rollout 引擎根据策略生成动作或 token，得到奖励，训练端再算概率与梯度。如果两个引擎使用不同精度、backend 或 kernel，即使权重和输入一致，计算出的概率也可能不同。模型更新之外的差异会进入优化。

verl 的文档明确区分三种策略：实际采样的 `π_rollout`、用于限制更新幅度的旧策略 `π_old`、正在训练的 `π_θ`。在其 decoupled PPO 表述中，采样纠正与更新比率分别是：

```text
ρ_t = π_old(a_t | s_t) / π_rollout(a_t | s_t)
r_t = π_θ(a_t | s_t)   / π_old(a_t | s_t)
```

`s_t` 是当前状态或已生成前缀，`a_t` 是该步动作或 token。`ρ_t` 处理实际采样与旧训练策略的差异，`r_t` 反映新旧训练策略之间的更新。若实际采样概率不同，直接假定 `π_rollout = π_old`，就会漏掉第一种差异。[verl 的三策略说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr_math.html)

来源还讨论旧 checkpoint、异步 worker 和历史回放带来的差异，以及重要性权重和拒绝采样的处理。本文核对的是机制和符号，没有复验这些方法在任意模型上都能消除崩溃。

下面的自拟代码演示浮点次序和概率比的两个基本问题，不运行神经网络。

```python
from math import exp

a, b, c = 1e16, -1e16, 1.0
print((a + b) + c, a + (b + c))  # 1.0 0.0

logp_rollout, logp_old = -2.0, -1.98
print(round(exp(logp_old - logp_rollout), 4))  # 1.0202
```

如果相同权重下出现这个自拟的对数概率差，采样纠正比就偏离 1。它不等于模型在学习后合法发生的策略改变。误差是否系统性、会怎样影响长期训练，仍要在真实运行中测量。

## 重复数据和 loss spike 不能只用一个原因解释

嘉宾区分跨样本重复与单条长序列中的重复 pattern。前者可能让模型更多记忆，后者可能使某些位置的梯度相关、加重稳定性问题。但不是任何重复数据都会引发 loss spike，也不是所有梯度都必然同向。

访谈用百万位置的梯度相加解释巨大更新，需要补上损失归一化条件：N 个同为 1 的梯度，求和为 N，求平均仍为 1。真实训练中的 loss reduction、mask、attention 交互、梯度裁剪和优化器共同影响更新，不能仅凭序列有一百万 token 就宣称梯度一定放大一百万倍。

Attention、MoE router、低精度计算和异常数据都可能影响稳定性。看到 attention 附近有异常，是定位线索，未自动证明根因就在 attention kernel。新架构的小型测试通过以后，仍需检查不同序列长度、batch 和训练阶段。

嘉宾还从优化器对更新几何的处理解释为什么可以改善稳定性。它可能帮助缓解某些不均衡，却不保证所有知识领域被自动均衡学习；要归因，需要对应的数据与优化器对照实验。

## 小模型外推、白盒化与蒸馏，各自留下什么问题

Scaling 团队要用许多小实验判断大训练的超参数、性能和风险。外推有效性依赖模型、数据分布、重复次数、训练计算和软件实现与目标相容。小实验使用新数据、大训练反复重复数据时，预测条件已经改变。

“小规模得到收益”因此只是进入下一轮验证的依据，不能直接保证千倍规模仍然有效。嘉宾提到未来可能出现 S 型放缓，是对外推上限的猜测，不是本次已经验证的大模型增长曲线。

他所谓“白盒化”主要指更理解训练内部的数值动态，而不是已经知道每个神经元表示什么。这一区分有助于避免将训练可控性误读为全部机制已解释。能预测某些失稳条件，也不意味着能解释所有能力怎样产生。

蒸馏则可能用较强模型的输出提升较小模型，减少短期成本。嘉宾担心团队因而减少对数据、RL 与训练栈的投入，长期依赖外部教师。这是资源分配的一种风险路径，不能推出蒸馏与原创研究无法并行。需要检查团队实际投入，以及教师改变或不可用时还能否继续改进。

结尾谈创业组织和专业模型生态，他设想少数人配 Agent 承担更完整的工作，公司仍有人制定目标并对结果负责。专业领域的知识、数据、执行与客户关系可以成为差异，通用模型能力强也不自动消除这些关系。这些是未来组织与市场的主张，本次没有把个人体感汇总成就业或行业份额统计。

## 对学习工作台最直接的启发

报告里，追加用户偏好、存档原始片段、检索旧知识和改写正文，分别改变当前上下文、长期可查记录与当前产物。它们可以让任务更好完成，但还没有证明模型自己完成持续学习或研发闭环。

更有用的改进是保留错误发生在哪一步、来源怎样支持修订，以及同类下一项任务是否减少了同一种错误。借助 Agent 提速后，仍要检查完整交付是否变好：来源可回查、计算可复算、状态与文件对应，读者才能从真实结果继续。
