# 硅谷101 E256：GPT-6 Astra 如何同时改写 Agent、机器人与 AI 制药

## ⚡ 速览

- Astra 把模型能力进一步推向真实任务，三个行业却卡在不同环节。
- Agent 卡在身份、权限与成本；机器人卡在物理闭环与泛化。
- AI 制药卡在湿实验、数据和时间，人类转向定义问题与验收。

本期录制于 2026 年 9 月 29 日。嘉宾分别来自个人 Agent、机器人和计算生物学一线：Pokee.ai 创始人朱哲清、破壳机器人创始人许华哲、华盛顿大学助理教授王晟。节目没有试图评出“哪个行业最先被改写”，而是在三个行业中反复追问同一件事：**模型能力越过旧 benchmark 后，距离稳定创造现实价值还隔着什么？**

## 核心分析

### 1. 共同变化：模型开始进入行动层，行业仍按自己的验证时钟运行

三位嘉宾对 Astra 的体感并不一致。朱哲清认为它在长程任务、上下文稳定性和审美上持续改进，但单看 coding，还没有重现上一代模型带来的范式跳变。王晟的团队则已把部分生物医学长任务切换到 Astra，尤其看中 Computer Use 和持续 8–24 小时执行 pipeline 的能力。许华哲看到的变化最激进：模型能在机器人任务中根据碰撞、尺寸和失败结果修正动作，还能把少量真实图片快速转换成仿真环境。

节目用两条 9 月事件说明 AI for Science 的关注点正在从“回答科学知识”转向“产生可验证发现”：主播转述 Claude 用约 21 小时提出 ART 新酶系统，科学界仍在等待实验确认；Biohub 则宣布把虚拟细胞计划扩大到 18 亿美元，试图汇集模型、数据和实验资源。两条都属于节目新闻回顾，金额与科学结论没有在本报告中独立核验。

这组分歧揭示了评价模型升级时容易忽略的变量：**同一项底层能力，在不同工作流中的边际价值不同。** coding 已有成熟工具链和很强基线，增量会显得较小；生物医学遗留软件长期缺 API，Computer Use 直接跨过了接口改造成本；机器人原本缺少能把语言推理、视觉理解和动作反馈连成闭环的通用上层，因此一次能力迁移就可能击穿旧 benchmark。

节目结尾把这个差异概括得很准确：AI 圈看到的是能力曲线，行业从业者看到的是落地周期。机器人要在物理世界反复试错，药物要等待细胞、动物乃至人体反馈，个人 Agent 还要通过商家的权限与经济性检验。**能力发布日可以相同，价值兑现日不会相同。**

这与此前的 [GPT-6 Astra 指令架构研究](../../ai-learning/reports/knowledge_reports/GPT6_Astra指令架构_从Prompt堆叠到按需控制_深度解析_20261015.md) 互补：技术博客解释了模型和 harness 如何按需加载控制；本期节目展示了 harness 之外仍需补齐的现实控制面。

### 2. Agent：真正稀缺的不是点击能力，而是合法代表用户的身份

节目先用生物医学“古董软件”说明 Computer Use 的直接价值。很多领域工具年代久、界面差、术语多，又没有现代 API；模型能像人一样看屏幕、移动鼠标和输入文字，就能复用现有软件资产。它还让使用者反过来观察模型如何操作软件，降低跨学科工具的学习成本。

但消费 Agent 一旦进入购物、旅行和客服，问题就从“会不会点”转为“商家是否允许它点”。朱哲清回顾 Manus 一类云端浏览器 Agent 的路径：网站会识别并屏蔽数据中心 IP，Amazon 等平台也不愿让无限量机器人比较价格、占用资源。对商家而言，一个用户带来一个代理仍可能等价于原有需求；一个用户同时放出二十个代理，却不会产生二十倍购买力，只会制造更多查询和流量成本。

因此，他把 **identity** 视为消费 Agent 的关键变量：如果 Agent 运行在用户自己的手机、PC 或可验证硬件上，商家更容易相信它代表真实用户，而不是批量爬取或套利程序。这个判断把“软硬件结合”从产品包装提升为权限协议：硬件承担身份与本地执行，软件编排任务，模型提供理解和决策。

第二个约束是成本。浏览器任务需要强模型、多轮视觉输入、云端虚拟机和大量 CPU；节目以 Meta Muse、Instinct 等产品为例讨论免费 token、虚拟机和模型 routing 的高成本。朱哲清提出的出路不是所有请求都调用最强模型，而是让端侧或私有算力承担多数普通步骤，只把少数难题路由给 frontier model。

[推测] 本报告把节目材料归纳成一个比“更聪明的 Agent”更完整的商业化条件：

```text
可执行能力 × 可验证身份 × 商家许可 × 单任务经济性
```

任一项接近零，演示再惊艳也难形成稳定产品。这个判断也能解释为何企业内 Agent 更容易先落地：企业可以统一身份、权限、软件环境与成本预算，开放互联网则需要逐个平台重新谈判。

节目也提醒，企业采用不是同步发生的。Grok Bot 在前沿用户中更多是尝鲜；法律、医疗等传统企业甚至仍在解决怎样离开 Microsoft Copilot、能否获准使用 Codex 或 Claude Code。模型发布速度与组织权限、采购和合规节奏之间存在明显鸿沟。

王晟进一步批评了现有生物医学 benchmark：许多题被定义成明确数据集上的 Kaggle 式预测，提升主要来自 coding 和长程执行，并不代表模型更理解生物医学；安全拒答还可能让实际体验变差，团队会改用 Kimi K3 等模型，或通过“这是 benchmark”之类提示绕开拒答。这个案例说明“小模型追上 benchmark”既可能是能力收敛，也可能是 benchmark 已偏离真实任务。

### 3. 机器人：Astra 提升了“脑”的上层，物理世界仍要求快慢双系统

许华哲给出的插花案例很有代表性：花茎分叉后，模型能判断需要先捏窄再插入花瓶。这类能力不是简单识别物体，而是把三维尺寸、失败原因与动作调整连起来。另一个方向是 real-to-sim：少量图片即可生成办公室或实验室仿真，减少过去大量拍摄、标定和人工修模工作。

筷子夹小球的对照暴露了代价。破壳自研模型会快速连续尝试，Astra 每一步都分析发生了什么、为什么失败，再调整动作，更接近可解释的人类思考；但它速度更慢，错误分析还可能把后续动作带入僵局。旋转物体、对孔插入等灵巧任务仍需反复尝试。

这会冲击传统机器人 benchmark，因为模型即使没有专门围绕某一榜单训练，也可能借助通用视觉、推理和工具能力取得高分。但节目没有把榜单胜利等同于部署完成。许华哲明确指出，物理任务仍需要低延迟决策、稳定控制和安全冗余；Astra 式慢推理适合规划、复盘和困难节点，快速反应仍需要轻量模型或专门控制器。Jev 这类只输出动作概率的“系统一”模型，可能成为快路径的一部分。

real-to-sim 同样有边界。许华哲认为 Astra 主要提高了三维外观重建，并没有让物理引擎自动变得更准确；把它描述成“仿真路线复活”带有 hype。仿真更易生成，不等于用仿真训练出的策略已经跨过 sim-to-real 差距。

另一方面，Astra 的跨本体泛化会直接利好硬件质量较高的机器人。节目提到斯坦福团队在两周左右把它接入机器人完成家庭任务，虽然仍是 demo，却说明“强模型 + 好本体”可以迅速形成新组合。做机器人大脑的公司也可能分化：一部分继续训练更快、更小的具身模型，学习 Astra 的推理和数据标注范式；另一部分转向部署，把自己的能力包装成 Astra 可调用的工具。

另一个核心变化是 TAMP 到 Agentic 的回归。TAMP 把任务规划与运动控制连起来，过去依赖显式前置条件逐步执行，显得古板；通用模型出现后，研究者可以把感知、规划、工具和控制能力组合为 Agentic harness，使传统规划重新获得价值。这里的变化不是规划被模型取代，而是模型让更多能力可以进入规划回路。

数据要求也随之改变。传统示范数据告诉机器人“做了什么”，复杂任务还要标注因果、失败原因和直觉物理：为什么杯子会滑、为什么动作要先后排序、哪些接触意味着风险。[推测] 模型可以帮助生成标签，但模型自标数据可能形成共同偏差，因此仍需要人类抽检和真实执行反馈。

节目还给出两项具体短板：双臂叠衣服这类难用语言描述的任务几乎做不了；第一次任务耗时一小时、第二次缩到约 45 分钟后，后续仍停留在 45 分钟，缺少人类或专用模型通过反复练习继续提速的能力。榜单飞跃因此没有消除机器人原生模型的训练价值。

Jev 的实测进一步限制了“快系统”叙事。它只输出状态上的动作概率，不能直接输入图像，需要先由视觉模型转换状态；破壳用它叠方块时，经常摞不起来或失去平衡。Astra 虽慢，却能观察第一个方块是否倾斜并修正下一个动作。许华哲因此认可机器人需要快系统，却不认为当前 Jev 已经能承担该角色；节目提到 OpenAI 可能推出带图像输入的快系统，属于传闻口径。

许华哲把机器人长期目标定义为零样本快速部署：现场不再需要五个博士驻厂三个月，而由普通人员用语言完成部署。其“2028 年初通用机器人开始实用、家庭覆盖 90% 任务”的时间判断属于个人预测，证据不足以当作行业共识。更稳妥的结论是：Astra 缩短了高层规划和任务适配路径，却没有消除硬件可靠性、动作速度、现场安全与物理反馈成本。

这一点与 [[2026-09-20_xiaoyuzhou-crossing_xumengdi]] 的“机器人仍处 GPT-1 阶段”形成张力：底层模型能力突然跃迁，但真实成功率仍要经过本体、数据和控制系统共同验证。

### 4. AI 制药：干实验趋向自动化，湿实验成为新的系统瓶颈

王晟把 Astra 的价值分成两层。第一层是软件操作：模型能使用 MultiQC 等专业工具，处理过去只能由熟练研究者完成的流程。第二层是长程研究任务：让模型连续运行、组合工具、分析数据并设计后续步骤。

主播转述，消费 Agent 的普通任务未必是前沿实验室最大的 token 消耗，AI for Science 中的数学与科学难题才需要大规模 agent 协作；Navier–Stokes 案例的消息数、token 和零售成本在节目转述中存在口径冲突，本报告只保留“科学任务可能消耗巨大推理预算”这一方向，不采用具体数值下结论。

节目认为，当前 AI 可以完成的实验设计约占完整科学过程的 30%；剩余部分包括合成与保存分子、培养细胞、确定给药周期、开展动物实验和根据失败重做。设计分子可以很快，真实验证可能需要数月乃至多年。这个时间差解释了为什么“AI 设计候选物”频繁出现，而真正由新一代模型端到端发现并通过验证的药物尚未成熟。

数据也不是抽象的“越多越好”。节目强调，制药公司在长期实验中积累的参数、材料、条件和真实验证结果不会因为 AlphaFold 等模型开源就自动公开；基础模型可以学习公开知识，却仍拿不到决定复现率和筛选效率的内部数据。因而垂直公司的护城河可能从模型权重转向实验数据与反馈速度。

节目提出一个值得关注的基础设施方向：湿实验公司把实验能力封装成 MCP/API，让模型能够提交设计、获得真实结果并继续迭代。前沿实验室也开始配置或合作湿实验能力。这里的关键并非让模型直接控制每台仪器，而是形成可审计的闭环：

```text
提出假设 → 分配真实预算与设备 → 执行实验 → 返回结果 → 更新下一轮设计
```

反馈周期越短，进展越快。蛋白质和酶设计较容易形成快速实验循环；衰老、罕见病和人体药物验证周期更长，推进会更慢。王晟因此主张设计“没有上限”的 benchmark，例如不断提高杀伤率、稳定性或疗效，而不是容易刷满的静态分类题。

ART 案例在这里承担的不是“AI 已完成科学发现”的证明，而是反馈周期假说的例子：酶和蛋白质实验相对较快，模型提出候选后可以更快得到湿实验信号；长周期疾病则很难形成同样密度的数据飞轮。节目明确保留了 ART 尚待验证的边界。

在人机分工上，他给出的答案也更具体：当问题、输入和测试集已经定义清楚，AI 可能比单个科学家更强；人类科学家继续负责定义值得解决的问题、设计评价方式、判断资源投入价值，并在医疗与重大科学决策中承担背书和责任。

### 5. 三个行业最终汇合：下一代 harness 要调度真实世界

本期最有增量的观点出现在最后。当前 Agent 研究大多讨论模型如何调用软件工具；三位嘉宾把问题继续向外推了一层：未来模型需要根据预算、时间、权限和现实资源，生成可执行指令，让人、机器人、实验室和企业系统协同完成任务。

关于“普通人是否还值得被蒸馏”，三位嘉宾给出了不同答案。许华哲认为机器人仍需要普通人的生活技能，每个人都是做饭、整理和行动方式的专家；王晟强调人也在反向蒸馏 AI，同时不断提出新的疾病、目标和个体问题；朱哲清则把重点放在学习能力——未来要蒸馏的也许不是某项固定技能，而是人怎样从零开始学习、纠错和迁移。三种回答共同反对把当前 benchmark 能力直接等同于一般学习能力。

三个行业的“最后一公里”其实是三种现实约束：

| 行业 | 模型之外的控制面 | 失败表现 |
|---|---|---|
| 个人 Agent | 身份、授权、网站规则、token 与机器成本 | 会操作但被封、成本高于任务价值 |
| 机器人 | 本体、传感器、延迟、安全、物理反馈 | benchmark 高分但现场不稳定 |
| AI 制药 | 实验设备、样本、预算、周期、合规与责任 | 候选生成快，验证与转化慢 |

[推测] 这对 EverAgent 双仓也有直接启发：任务路由不能只根据“哪个模型更强”，还应显式记录设备能力、外部权限、成本、证据回收和失败恢复。模型选择只是 harness 的一个变量；能否完成并验证真实任务，取决于完整控制回路。

## 关键数字与证据边界

| 数字 | 节目中的含义 | 证据等级 |
|---|---|---|
| 8–24 小时 | 王晟团队常见的生物医学长程任务 | 嘉宾一线经验 |
| 1 亿 token | Meta Muse 给用户的免费额度 | 嘉宾/主播口播，未独立核验 |
| 10 / 50 美元 | Astra 每百万输入/输出 token 价格 | 嘉宾口播，需回官方价格页核验 |
| 60%–70% | 朱哲清设想未来可在本地或私有算力完成的 token 比例 | 个人预测 |
| 30% | 王晟估计当前模型可覆盖的实验设计完成度 | 个人经验判断 |
| 2 TB | 王晟举例的单个生物医学对象数据规模 | 口播概数 |

## 增量观点

1. **“能力是否 SOTA”正在让位于“反馈闭环有多短”。** Agent 的反馈可以分钟级完成，机器人需要真实动作，制药可能需要月或年。闭环时长会决定模型能力兑现速度。
2. **身份是消费 Agent 的基础设施。** 浏览器操作只是动作层；没有用户代表权，平台会把 Agent 当成爬虫或套利者。
3. **机器人与科学实验都需要模型学会预算。** 最优答案并非无限推理，而是在时间、金钱、设备和风险约束下选择下一步。
4. **开放式 benchmark 更接近真实价值。** 静态题库容易被训练和优化，持续提高现实目标且由实验验收的任务更难刷榜，也更能产生新数据。
5. **人类价值从执行迁移到问题定义、评价与责任。** 这不是抽象的人文安慰，而是由现实系统中尚未被形式化的目标、约束和责任链决定的。

## 思考与追问

1. **我真正理解了什么？** 模型能力并不会直接变成行业价值，中间必须经过身份与权限、真实执行、验证反馈和责任归属。三个行业看似差异极大，其实都在补同一种“现实世界 harness”。
2. **我还没搞懂什么？** ①怎样为现实任务定义统一的“反馈周期 × 单次验证成本 × 失败风险”指标，从而比较 Agent、机器人和科学任务的自动化潜力？②个人设备怎样向商家证明 Agent 代表用户，同时避免暴露过多身份和行为数据？③湿实验 MCP 的结果如何保证可复现、可审计，并阻止模型在高成本实验中反复探索低价值路径？
3. **下一步听什么 / 查什么？** 跟踪 Astra 机器人评测的真实任务与成功率；研究 Agent 身份授权协议；选择蛋白质或酶设计案例，拆解一次“模型设计—湿实验—反馈迭代”的真实成本和周期。
