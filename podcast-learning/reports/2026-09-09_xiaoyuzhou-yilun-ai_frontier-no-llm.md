# 易论AI Vol.1：AI最前沿的人已经不聊大模型了

> **为什么值得读**：李继刚自 2026-07《明镜与点点》后第二次进本项目——这次不是读书方法论，而是他当下的主业判断（Agent+X 入口之争、个人上下文管理）；橘子（Cola）和歸藏补上了「做 agent 产品的人」和「靠 skill 变现的人」两视角。四个创业者围桌互怼，密度极高：几乎每个论断都带一线实操细节（盖章 84 张、缓存率 96%、抢外卖券、127.0.0.1）。**这是「FDE/Agent 落地」议题在 podcast-learning 的第三次出现**（Jove→曾鸣→本期），且李继刚的「上下文=要维护的车」直接接他自己的 F×X/取景框线。

---

## 一、概览（先看这5条）

1. **服务裹着能力**（李继刚的核心新论断）：模型能力与企业业务之间有一个 gap，填补它的是 FDE——「不是能力裹着服务，而是服务裹着能力」；产品交付≠结果交付，AI 应用的本质是服务不是软件（「SaaS 本身并不是一个软件，SaaS 是一个服务；AI 就是你用 token 提供的服务——软件已经死了」）。
2. **齿轮速度差**：技术两三个月一变、组织慢得多、制度（利益分配/商业结构）更慢——层层齿轮转速不匹配，**服务就是在填平这个速度差**。AI 在 coding 快，恰恰因为 coding 不经过支付/渠道/盖章这些慢齿轮（歸藏：签 8 份合同盖章 84 张没一次是对的）。
3. **Agent+X vs X+Agent 两条路**：以 agent 为入口把 X（IM/文档/PPT）化整为零装进来（飞书路线），还是在旧 X 里嵌一个对话框（微信小微路线）——李继刚押前者「后劲更足」，但橘子泼冷水：人的记忆力撑不起纯对话（订了票要看到界面才想起），**人类永远需要目录/dashboard 这个动态 UI**。
4. **上下文是一辆要维护的车，不是一个真实的房子**（李继刚）：上下文堆太多后，「即使明确在 prompt 里告诉他怎么做，他还是把我拉到以前的平均值」——信息茧房不只发生在推荐算法，也发生在自己的 AI 记忆里。解法：进入时清洗+边界约束+项目隔离+「不止 AI 要紧，你也得紧」。
5. **被漏看的另一半世界**：AI 圈都在卷提效，但 AI 内容消费（短剧渗透超 8 亿、Steam AI 游戏激增）的渗透率远超 agent——「我们这拨人默认另一个世界的人不存在」。三轴框架（原子世界×比特世界×token 世界）用来安放这个割裂。

## 四、主要话题（归并）

### A. FDE 与「服务」的再定义（接 Jove 期）
- FDE 判据（李继刚）：不是「带团队来开发完就走」（那是外包，落差还在），而是**落差填平**——组织在使用 agent 产品时对自己的业务有了更深理解。
- 三条填平路径：①5% 用得最好的人自跑出最佳实践，其他人用结果；②培训（有总比没有好）；③FDE 带着服务进场摸爬滚打。
- 零一万物样本（对标 Palantir）：先培训（带着产品用，转化率 75%）→ 再入驻 FDE（多有股权）；**FDE 不背销售指标，唯一成功指标是「把自己抽离掉」——客户带着你的脑子运转**；毛利高、复购多。
- 2C 同样有 gap：agent 给普通用户「除了豆包都不会用」；skill 是接住 gap 的东西但也有学习门槛——**「一个 skill 本身就是一套软件，它没有界面」**。

### B. 齿轮速度差：AI 改不了的慢变量
- 歸藏的清单：渠道、支付、财务、法务盖章、资质——「跟现实的吻合非常深，没法提效」。打款两个月、签 8 份合同盖 84 张章没一次对、大厂采购 ListenHub 入库两年后项目已死、换主体全部重来。
- 推论：**AI 为什么在 coding 快**——强化学习[?]+coding 不经过分发/付费/政府关系这些慢齿轮。「所以你越觉得 Stripe 牛逼——支付就是 Stripe，银行就是 Airwallex」（后链路自动化的标杆）。
- 咨询公司的选址逻辑：零一万物/Palantir 全挑传统行业（养鸡）——「越传统越容易出效果，越容易让甲方为价值付费」；内容行业反而卷不过（人家用得比你好）。
- 橘子的对冲：也许会出现「专治 OPC[?]（跑腿盖章）」的服务公司——人处理后台，agent 对外沟通（飞书 client/企微 client 已出现）；企业 SOP/入库流程是否也能出标准 client 给 agent 协作。

### C. Agent+X vs X+Agent：入口之争
- 定义（李继刚）：Agent+X=以 agent 为对话主场，X（发消息/生成 word/做 PPT）化整为零住进来；X+Agent=旧软件里嵌对话框（微信小微、Office 右侧栏）。
- 判断：有基本盘的公司一定选 X+Agent（不可能放弃立身之本）；但 X+Agent 「一定别扭」——旧组织做不好 agent、免费时代的成本结构撑不住（「以前服务器成本多低，现在每个 token 都是成本」）、旧基建有问题。
- 橘子的反例（重要）：纯对话撑不住人的记忆——「我订了票明天忘了，我需要看到那个界面才能想起来；Obsidian 上千笔记，我要看到那个东西才能想起来」→ **人类永远需要目录/界面，dashboard（动态 UI）是每个软件接下来必做的**。
- 手机思想实验（李继刚×橘子去年）：三年五年后手机就是一块屏，不解锁活已干完——「非常丝滑」，但手机不是用来干活的。
- **GitHub 是 agent 协作的天然纽带**：issue/PR 协议完善、不需要上下文、所有 AI 都懂；Cola 用户反馈→自动建 issue→Slack 派 agent 监控修复→release——agent 和人、agent 和 agent 默认在这里汇合。AI 提交三五十个文件、人审不过来→基于 AI 提交的新托管范式（Cursor Oranger[?]是雏形）；GitHub 免费是 vibe coding 繁荣的集市基础。
- 分发困境：vibe coding 的人做出来的东西**没有地方发**——互联网 2.0 基建高度封闭（抖音限流产品内容、小红书 redskill[?]是封闭内的渠道妥协）；「AI 给了他一个网页，他把 127.0.0.1 发给了别人」。

### D. 被漏看的 C 端与内容消费
- 割裂现场：「我们这拨人关注 agent 的效率生产；非常多 C 端用户不需要工作、不用 AI 工作，他们不讨论 agent 也不讨论 coding——你只能看见你能看见的。」
- 短剧数据：AI 短剧渗透**超 8 亿**；以前不看短剧（觉得降智）的内容人群开始看——李继刚的自我实验：明知剧情无脑仍被钩子一级级勾着走，「一个人的我在观察我」。短剧正在**网文化**（日更+长篇剧情+复杂世界观，世界观还是人来架构）。
- 蒋正克[?]论：两小时电影的好故事和两分钟短剧的好故事都是好故事，与时长/创作质量无关。
- 三轴框架（李继刚，顺着歸藏的思路）：原子世界×比特世界×token 世界三轴叠加——token×比特=生短剧写小说（效率）；token×原子=大疆飞救生衣、灾区投送、AI for science。
- AI for science 剪刀差：药物研发巨快×临床实验巨慢→未来三五年疾病治愈的集中爆发期；旁证：**实验猴涨价、不够用**。

### E. 上下文的潜力与边界（本场最硬的干货）
- 潜力侧（医疗案例三连）：①十年慢性病、10 个医生没人听完→Cola 听完推理出病因、医生确认、痊愈（甚至体重恢复）；②易亚婷甲减/缺铁性贫血自诊（AI 结合日常上下文建议查铁蛋白，临界值确诊）；③橘子女朋友胰岛素抵抗（空腹血糖正常掩盖、胰岛素释放实验爆表）。提炼：**大窗口上下文阅读×专业推理**=新能力组合；「医生不可能看完你所有的上下文，AI 可以」。
- 但**上下文获取是最核心也最薄弱的**：国内数据不开放；讽刺的是 Gemini 读自家 Google 服务还不如第三方（自家 MCP 在别人家反而做得好）。
- 边界侧（管理心法）：
  - 问题：「过去拥有我的上下文太多后，即使明确在 prompt 里告诉他怎么做，他还是把我拉到以前的平均值」——信息茧房的 AI 版。
  - 李继刚的比喻：**上下文是一辆要维护的车，不是一个真实的房子**；「你在往前走，以前做过的东西是你的过去；上下文永远要跟着你往前走」。
  - 管理四原则：不该读的不读（不要上来读所有）/做好索引/顶层设计进入时机（需要时才读）/进入时清洗+边界约束（每次先声明「这次基于什么背景、讨论什么话题」）。
  - 项目隔离：项目信息（客观）与认知迭代（主观）分层，做完就出[?]；「人也是这样的——记下结论就往前走」。
  - **六经注我**：agent 太多上下文不够用→坚持迭代自己的 agent，「这次觉得这个 agent 好就把它加进我的 agent」。
  - 取景框校准（易亚婷的用法）：明确「我想变成什么样的人」→ ljg-read 提炼 role model（如迪士尼老板）方法论→每天让 AI 对照「我跟他差在哪」→明确指标（共情感不够等）。「一旦你有一个方向，模型能管你很多；没有方向，它帮不上忙」。
  - 两层觉察（李继刚）：①形成自己的闭环（不要抄别人的）；②**意识到自己在一个环中，别被困住**——警示案例：某人的 agent「开发出解决幻觉问题的新框架」（这结论本身就是大幻觉），人和 agent 互相夸，闭环到上头[?]，被戳破时很痛苦。
  - 反茧房两法（歸藏）：发暴论看被杠多少；读长内容、找 AI 之外的信息源——「千万不要尽信[?] AI」。
- 生态注脚：海外用户天然「线上化」（Gmail/Notion/GitHub/Twitter 全有 MCP）；Grok Bot 的激进答案——只有聊天界面+云端虚拟机+按需一键授权，「任务需要时才弹出连接按钮」；π 和 DeepSeek Harness 的自迭代（忒修斯之船）方向牛逼但太远期。

### F. 模型价格与缓存经济学
- 双线价格律（歸藏观察+众人确认）：SOTA 模型价格持平或微涨；主流模型指数下降（LUNA[?] 满足 90% 需求、部分场景已免费；中转站已无利润空间）。
- 值不值：「为基准测试 5-10 分的差距付 50-100 倍的价格差，只看基准觉得不值，用起来发现非常值」（Opus 4.6 重写 DVC[?] 的稿子，prompt 没改，质量一键提升）。
- 缓存经济学（橘子，产品方视角）：DeepSeek 缓存黑科技——Cola 里 96%、harness 里经常 100%；**缓存 90%→95% 成本差两倍**（未缓存价格是缓存的 10-100 倍）；Claude Code 现在拉胯的归因：为降成本把模型和缓存压得过于极端。
- Harness×模型结耦的红皇后效应：若 harness 可任意切模型，用户切换零成本（昨天 3000 万用户今天归零）→ 模型厂的理性对策=联合训练拴住用户；但实际体感「切换基本无痛感」，现在拴用户靠的是 agent（生态）与缓存降价。DVC 在 Claude Code 外工具调用[?]差→后训练后（Flash 0731 起）各 agent 都跑得好——「数据一定会回流」。
- Harness 的终极形态（收束）：模型只是工具，「你得有 FDE；**产品就是自带一套 FDE**」——harness 要像多邻国：给用户目标、路径，打卡就走起来；每个 agent OS 的分化来自创造者自己的审美（他觉得用户该往哪走）；「证明了这个实践很好，告诉 100 个人能听的 10 个——P 人 J 人，人是很多样的」。

## 七、关键观点（原话引用）

> **李继刚·论 FDE**：「模型能力和你的业务中间有一个 gap，那个 gap 的填充是现在所说的 FDE。这句话再提炼一下的话，我认为是服务裹着能力，而不是能力裹着服务。」

> **李继刚·论 SaaS**：「SaaS 本身并不是一个软件，SaaS 是一个服务。SaaS 核心其实就是 SaaS 本身就是对软件的一个革命——软件不再重要了，卖的是服务。AI 也一样，AI 就是你用 token 提供的也是服务。软件已经死了。」

> **零一万物样本（易亚婷转述）**：「FDE 最终的指标，他不背销售指标——唯一的指标就是把自己给抽离掉。不是陪伴用户越久越好，而是你栽了之后抽离掉，客户还是能带着你的脑子去运转。」

> **李继刚·论速度差**：「技术的发展特别快，组织的变化速度没有这么快，组织中的制度、利益分配、商业结构更慢——层层像齿轮一样小齿轮大齿轮，速度不匹配，服务就在填平这个速度差。」

> **橘子·论界面**：「人的记忆力不足以支撑纯对话——我订了票明天忘了，我需要看到那个界面才能想起来。人类永远需要那个目录界面，但它会变成一个动态的 dashboard。」

> **李继刚·论上下文**：「我现在越来越感觉上下文是一辆要维护的车，不是一个真实的房子。你在往前走，以前做过的东西是你的过去——上下文永远要跟着你往前走。」

> **李继刚·论茧房**：「过去拥有我的上下文太多之后，我有新的思考，即使明确在 prompt 里告诉他怎么做，他还是把我拉到以前的平均值。」

> **李继刚·论觉察**：「两层觉察：第一层，我们应该形成自己的闭环，不该去抄别人的；第二层，我们要意识到自己在一个环中，别被困住了。」

> **歸藏·论反茧房**：「把暴论发到网上看被杠得多，可能就是一个茧房；另外就是去读长内容、找 AI 之外的信息源——千万不要尽信[?] AI。」

> **李继刚·论 harness**：「只给用户模型没有用，就是工具，你得有 FDE。产品就是自己带一套 FDE。harness 要像多邻国：给用户一个目标、一个路径，打卡就走起来。」

> **橘子·论割裂**：「我们这拨人关注 agent 的效率生产；非常多 C 端用户不需要工作，他们不讨论 agent 也不讨论 coding——你只能看见你能看见的。」

## 十、思考与追问

1. **我真正理解了什么？**
   这期四人谈拼出了「Agent 落地」的完整分层：**模型（能力）→harness（产品=FDE 内置）→服务（填平 gap）→制度（最慢的齿轮）**。李继刚的两句话构成闭环——对企业，「服务裹着能力」；对个人，「上下文是一辆车」：都是把 AI 的能力包进一个持续维护的载体里。而橘子的反例（人类永远需要 dashboard）提醒：入口之争的终局可能不是「纯对话」，而是「对话+动态目录」。与 Jove 期（FDE 岗位）、曾鸣期（组织=任务流+神经网络）对照：三方从岗位、组织、产品三个侧面讲同一件事——AI 的单位经济里，「人肉填充层」仍是最大变量。

2. **我还没搞懂什么？**（汇入 open-questions）
   - **「拉回以前的平均值」的机制**：李继刚观察到的上下文惯性是注意力分配问题、还是 RAG 检索偏向旧记忆的问题？如果是后者，「进入时清洗+边界约束」就是对的；如果是前者，可能需要遗忘权重机制——这直接关系个人 agent 记忆系统的设计（与 funes 记忆层、Agent Harness 学习计划阶段 6 联动）。
   - **缓存经济学的可持续性**：DeepSeek 96%/100% 缓存命中是「黑科技」还是特定对话模式的产物？90→95 差两倍的账对自建 agent 的模型选择意味着什么（与模型 plan 家底的选型直接相关）？
   - **Agent+X 的 dashboard 融合形态**：橘子说「chat 解决一切但要看着仓库才能想起」——动态 UI 会长什么样？是 Notion 式面板、还是对话流的自动摘要视图？有没有已发布的原型（Grok Bot 的界面算不算）？
   - 「腾讯系 agent 产品」（抢外卖券教育用户）到底是哪个产品——待下次遇到补充。
