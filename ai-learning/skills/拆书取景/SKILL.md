# 技能：拆书取景（x → f → f(x)）

> 通用研究方法论与证据规范见根 [METHODOLOGY.md](../../../METHODOLOGY.md)（强制），本文件只写拆书场景的特化部分。
> 思想来源：李继刚 [ljg-book](https://github.com/lijigang/ljg-skills)（播客 2026-07-09 李继刚期）。已按本项目纪律改造：
> **用他的取景框抽结构，用我们的证据规范验证结构**——ljg 系技能是抽取式的，材料薄时 AI 会靠书评/记忆"啪啪给结构"，本项目禁止这一点。

---

## 1. 触发场景

- "拆一下这本书" / "这本书在讲什么" / 给书名、PDF、样章、旧笔记
- 目标：读完既知道「这本书在讲什么」，也知道「它改变了我怎样回应这个问题」

**不适用**：论文精读（走 paper_analysis）、概念解析（走 concept_deep_dive / 科普讲解）、章节摘要。

---

## 2. 材料等级（先定级，再动手 —— 本项目证据纪律，ljg 原版只有简单提示）

| 等级 | 材料 | 报告标注 |
|------|------|---------|
| **完整拆书** | 有全文或足够书内材料 | 正常产出 |
| **初拆** | 只有目录、导言、样章、作者访谈 | 报告标题与正文注明「初拆」 |
| **假设版** | 资料很薄（仅书评/二手转述） | 注明「假设版」，x/f 全部标 **[待验证]** |

- 只给书名时：先拿足以支撑逻辑链的材料（目录/导言/样章/可核实书内片段）。**绝不允许凭模型记忆拆书**——模型训练语料里有大量书评，抽出的结构看似流畅实则无锚（METHODOLOGY §一）。
- 作者背景、思想源流、外部争论留在后台，只用于避免误读；正文只保留理解 x/f/f(x) 需要的部分。

---

## 3. 核心流程

### ① 定义 x：作者在处理什么问题

x 必须是可回答的问题，不是话题名。依次问：

- 哪个困境让作者非写这本书不可？
- 旧理解在哪里失灵？全书反复返回哪个疑问？
- 换一本同类书，这句话还成立吗？若成立，继续收窄。

多问题时选最能组织全书的主 x，副问题只在帮助主线时进入正文。

### ② 提炼 f：作者怎样回答

f 是作者对 x 的核心处理方式：一个概念/重新命名、一个关键区分、一个框架、一套方法、一条因果机制，或（文学作品）一个意象/人物关系/叙事运动。

- 不报术语，把 f 写成一句能运转的话：「面对 x，不应继续用 A 理解，而应通过 B 看见 C」。
- f 可有 2–4 个必要部件，但必须说明部件如何**共同**回答 x；无法删减的清单 ≠ 框架。
- **每个部件至少 1 个书内锚点**（场景/实验/人物片段/案例/比喻），锚点从不同位置共同指向同一个 f。

### ③ 计算 f(x)：回答之后怎么办

把 f 放回 x，观察它改变什么：看见（以前忽略什么信号）、判断（改用什么标准）、提问（先问什么）、行动（调整哪个动作）、克制（先停在哪里）。

- f(x) 必须从 f 推出：删掉 f 后 f(x) 若仍像一句普遍正确的话，说明写得太泛。
- **标注验证状态**（本项目加装）：f 的结论是已被实验/现实验证、仅作者论证、还是 **[推测]**，按 METHODOLOGY §二 分级。
- 文学作品不硬造步骤；f(x) 可以是一种新的容纳与注意。

### ④ 理解阻力扫描（选择性）

完成 f 后问：哪个机制最难仅靠文字成形，但一旦看懂其余概念自动归位？为它选成本最低的表征：

| 思想形状 | 优先表征 |
|---|---|
| 凸凹、分布、空间关系 | ASCII 曲线/形状图 |
| 步骤、因果传导 | 流程图/时间轴 |
| 循环、反馈 | 回路图 |
| 层级、部分与整体 | 结构图 |
| 两种机制对照 | 小表格 |
| 一两句话已足够 | 纯文字，不画 |

图不是标配；最多一张；只看图应能复述作者改变了哪个判断，否则删除。

## 4. 输出格式

保存到 `reports/knowledge_reports/拆书_{书名}_{YYYYMMDD}.md`，frontmatter 按领域规范（`report_type: knowledge_report`）。

```markdown
# 拆书：《{书名}》

> **x**：{作者在讨论什么问题}
> **f**：{作者用什么核心回答处理 x}
> **f(x)**：{接受 f 后应如何回应；验证状态}

## x：作者在讨论什么问题
（问题为何真实、旧反应为何不够；一个书内锚点落地，不写宽泛领域史）

## f：作者怎样回答
（正文重心：必要部件 + 部件关系 + 锚点怎样让它成立；图/表放机制首次解释之后）

## f(x)：怎样回应这个世界
（理解/判断/行动的具体改变 + 验证状态分级标注）

## 资料校准
（2–5 条真正支撑主线的材料，每条写「来源 + 支持什么」；材料等级：完整拆书/初拆/假设版）

## 💭 思考与追问（三问，METHODOLOGY §四 强制）
```

开头三行必须能连读：因为存在 x，作者提出 f；把 f 用在 x 上，得到 f(x)。正文通常 900–1600 汉字，短书更短，复杂书只在逻辑需要时更长。

## 5. 交稿前检查

- [ ] 遮住正文填三句：「这本书追问 ___」「它的回答是 ___」「因而下次面对这个问题我会 ___」——第二句拿掉后第三句仍成立 → f(x) 太泛；第一句换本书也成立 → x 太宽；第二句只剩术语 → f 没展开
- [ ] 材料等级已标注；凭记忆/书评抽的结构已标 **[待验证]** 或降级为「假设版」
- [ ] 每个 f 部件有书内锚点；没有顺着目录做章节摘要
- [ ] f(x) 的验证状态已按 §二 分级
- [ ] 更新 wiki 相关概念/实体页，未解问题汇入 `wiki/open-questions.md`
