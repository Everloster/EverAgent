# 技能：科普讲解（易懂优先 · 学习者反馈驱动）

> 通用研究方法论与证据规范见根 [METHODOLOGY.md](../../../METHODOLOGY.md)（强制）。
> 本技能是 A 类 ai-learning 的**体裁之一**（建直觉/入门/想通某原理时用），不是唯一体裁。
> 姊妹体裁：想要精确公式、消融数字、工程参数、落地细节时，走"深度专业"体裁（见 §0 场景表 + concept_deep_dive / paper_analysis）。
> 来源：2026-07-17 用户当面反馈——库里同主题两版报告（《Agent 请求全链路·科普讲解》vs《…深度解析》），
> 用户明确说科普版"最好、高质量、易懂"，深度版"看不懂、没怎么看"；同日用户补充"**有些场景喜欢科普，有些场景喜欢深度专业**"——故本技能按场景启用，不做全局默认。

---

## 0. 什么时候用科普体、什么时候用深度专业体（先判场景）

EverAgent 的本质是**"我读的东西"**：一篇报告只要用户读不下去 / 读不懂，对学习的贡献 = 0。
但"读得懂"不等于"永远用科普"——**同一个人，不同场景要的深度不同**。先判场景，再选体裁：

| 场景信号 | 选哪种体裁 | 理由 |
|---------|-----------|------|
| "帮我搞懂 X 是怎么回事""这个凭什么成立""快速建个直觉" | **科普讲解（本技能）** | 要的是想通、能复述，不要被术语劝退 |
| 第一次接触某领域 / 想通了机制层面就够 | **科普讲解** | 认知路径优先 |
| "要公式推导""消融数字""工程参数""怎么落地实现""对比各方案细节" | **深度专业**（concept_deep_dive / paper_analysis） | 要的是精确、可查、可动手，容忍高密度 |
| 逐篇论文精读 / 要 Table/Fig 级证据 | **深度专业**（paper_analysis） | 完整性优先 |
| 用户明确说"要专业/深入/别科普了" | **深度专业** | 尊重当次显式指令 |
| 不确定 | **先问一句**："这个你要**科普版**（快速建直觉）还是**深度专业版**（公式/参数/落地细节）？" | 别替用户猜 |

> ⚠️ 科普体 vs 深度专业体，是**两种平等的方法论，不是质量高低**：
> - 科普体：以**读者认知路径**为第一设计目标（钩子标题·贯穿类比·渐进式暴露）。
> - 深度专业体：以**知识完整性/精确性**为第一设计目标（公式逐符号·消融数字·工程参数）。
> 两者共享同一套一手证据规范（METHODOLOGY）。选错的代价是"读不下去"或"不够用"，所以**判场景比套模板更重要**。

## 1. 触发场景

- "帮我学 X" / "深入 Y" / "讲讲 Z 是怎么回事"——**且场景偏"建直觉/想通原理"**（见 §0 场景表）
- 用户对某个原理"想一次性想透"、第一次接触某领域
- 把一篇看不懂的旧报告"重写成易懂版"

反过来，用户要公式推导 / 消融数字 / 工程参数 / 落地实现 / 逐篇论文精读时，**不要硬套科普**——
走深度专业体（[concept_deep_dive](../concept_deep_dive/SKILL.md) / [paper_analysis](../paper_analysis/SKILL.md)）。场景不明就先问一句（§0 末行）。

## 2. 七味配方（从成功样本拆解，逐条可检查）

> 这七条是《Agent 请求全链路·科普讲解》之所以"赢"的可复现动作。写完后用 §4 自检表逐条打勾。

### ① 标题是钩子，不是目录
- ✅「无状态的鹦鹉，怎么学会了连续对话和自己用工具？」——一个读者**想知道答案的问题/悖论**
- ❌「客户端→网关→Harness→LLM→工具 请求全链路深度解析」——一串**名词罗列**
- 做法：标题里放一个**张力**（悖论 / 反直觉 / "凭什么"），让读者产生"我倒要看看"的痒感。

### ② 先给贴身类比，再引术语
- 把抽象概念挂在一个**能在脑子里看见的画面**上，且**全篇复用同一套角色**。
- 成功样本：🦜 鹦鹉（无状态 LLM）+ 🎩 管家（Harness），焊死在开头，贯穿到结尾的"一页纸"。
- 铁律：**类比先行，术语后到。** 读者先有直觉锚点，再接受学名，不会被生词劝退。

### ③ 一个例子贯穿全程，绝不中途换例
- 成功样本：全篇只用"查 2026 年 6 月杭州空调销量"这**一个**例子，从提问跟到出答案。
- 换例子 = 让读者重新建立上下文 = 认知成本翻倍。**一个例子走到底。**

### ④ 每节开头一行 `✦ 一句话`
- 让赶时间的读者只读这行就抓住本节主旨；愿意深读的再往下。
- 这是"分层阅读"的最小实现——同一篇报告服务两种读者（速览者 / 深究者）。

### ⑤ 渐进式暴露：主线是人话，硬证据折叠
- **主线正文**：人人能读的故事 + 类比 + 结论。
- **报文 / 伪代码 / 字段级证据**：塞进 `<details><summary>证据：…</summary>` 折叠块，想深究再点开。
- 这是"**既科普又不失严谨**"的核心机关——不牺牲一手证据，但不让证据挡在阅读主路上。
- 证据块里仍遵守 METHODOLOGY：带官方文档链接 / arXiv / 精确数值，标 `[推测]`。

### ⑥ 收尾装脑子：一页纸 + 总纲 + 纠错表
- **一页纸心智模型**：一张 ASCII 图，读者能在脑内重放整个机制。
- **N 句话总纲**：把全篇压成 3–5 条能背下来的话。
- **直觉陷阱表**：`| 你可能的误解 | 真相 |` ——主动校正读者最可能走偏的想当然。

### ⑦ 用真实数字落地抽象
- 抽象结论必须有一个**摸得到的实数**兜底。
- 成功样本：「你好」两个字 = 实测 39,671 token —— 把抽象的"上下文膨胀"变成能感知的震撼。
- 数字来源：优先 B 类 `ai-practice` 跑出来的真实测量，或官方文档明确数值；不编。

## 3. 输出骨架（按此结构写）

保存到 `reports/knowledge_reports/{主题}_科普讲解_{YYYYMMDD}.md`，frontmatter 同领域规范。

```
# {钩子式标题：一个悖论/问题}

> **这篇是什么**：一句话说清面向谁、读完能回答哪几个问题。
> **怎么读**：顺读最佳 / 赶时间看每节 ✦ 一句话 + 一页纸 / 深究点开「证据」折叠块。
> **证据约定**：带 报文/字段/数值 的结论来自官方文档（文末链接），标 [推测] 的是推断。

## 第一部分 · 先建立直觉
  - 抛悖论（①标题的展开）
  - 立类比角色（②），焊死画面

## 第二部分 · 跟着一个例子走一遍（③ 一个例子到底）
  - 主线：人话讲流程
  - <details>证据：真实报文/伪代码</details>（⑤）

## 第三部分 · 几个想不通的地方
  - 每节 ✦ 一句话（④）开头
  - 把"最容易卡住的点"逐个拆（它们通常是同一事实的不同侧面）

## 第四部分 · （工程/应用/前沿，视主题）

## 第五部分 · 装进脑子
  - 一页纸心智模型（ASCII 图）
  - N 句话总纲
  - 直觉陷阱表（⑥）

## 附 · 一个真实数字的实测拆解（⑦，如有）

## 🔗 延伸阅读（本库相关报告/wiki）

## 💭 思考与追问（三问，A 类强制）
  1. 我真正理解了什么？  2. 我还没搞懂什么？（汇入 open-questions）  3. 下一步做什么？

## 📚 参考来源（官方文档 / arXiv / DOI 全列，可复核）
```

## 5. ⭐ 学习反馈闭环（本技能的灵魂，别跳过）

> 用户原话：**"只是跑代码脚本的检查是自嗨，应该关注我的学习情况的反馈。"**
> 脚本查的是"报告像不像深度分析"；真正要迭代的是"用户读没读懂"。反馈是本技能唯一的迭代燃料。

### 5.1 每出一篇报告后，主动收一次反馈
交付报告时，附一句轻量征询（不强迫，用户可跳过）：
> "读完（或扫完）方便给个反馈吗？三档就行：**懂了 / 卡在某处 / 没读下去**。卡在哪、哪段啰嗦、哪段跳太快，随口说，我记进反馈日志、用来迭代模板。"

### 5.2 把反馈落进 FEEDBACK_LOG.md
拿到任何反馈（哪怕一句"这篇不错"/"太长了"），追加一行到本技能目录的
[FEEDBACK_LOG.md](./FEEDBACK_LOG.md)。这是**播种数据**，不是形式主义。

### 5.3 反馈 → 配方迭代（闭环收口）
积累反馈后，定期问一句"配方要不要改"：
- 某条正反馈反复出现 → 把那条做法**升格为配方硬规则**。
- 某类卡点反复出现（如"类比之后还是没懂""折叠块懒得点"）→ **改配方 §2 或骨架 §3**，并在 FEEDBACK_LOG 记一条"因 X 反馈，模板改了 Y"。
- 每次实质改动配方，同步更新本文件顶部来源说明 + §2 对应条目。

> **判断标准**：一次模板迭代是否有效，看的是"下一篇用户反馈有没有变好"，不是"lint 有没有过"。
> 这条闭环让技能**越用越懂这个具体的人**，而不是停在通用模板。
