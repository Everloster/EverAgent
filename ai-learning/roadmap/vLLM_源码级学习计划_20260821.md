## 实验载体：OpenMAIC（2026-09-02 增补）

- **由来**：用户反馈《V1 架构总览》直接读吃力 → 节奏调整为「应用驱动」：先在真实应用里建体感，有动机再回头挖源码。源码主线不变。
- **载体**：`../OpenMAIC`（清华开源多智能体互动课堂，Next.js + LangGraph）。AI 生成互动课等应用天然是 vLLM 的真实推理负载。
- **已跑通**：GLM Coding Plan 首发（coding 专用端点 `api/coding/paas/v4` OpenAI 兼容；glm-5.3 主力 + glm-5.3-flash 分流轻活，flash 视觉经 curl 实测可用）；本地 dev server 端到端生成验证通过（首课即 vLLM 入门迷你课）。配置在 `../OpenMAIC/.env.local`。
- **挂接实验**：阶段 2 prefix caching——OpenMAIC 每场景复用同一 ~30KB system prompt 串行调用，是现成的缓存命中率实验负载；届时 vLLM serve 后用 `OLLAMA_BASE_URL` 指向即可接入（OpenMAIC 该槽位免 key、专为本地后端设计）。
- **边界**：OpenMAIC 是应用层，不含 vLLM 代码，替代不了源码阅读主线；完整课堂生成需强模型（要吐严格合法大 JSON），本地 vLLM 小模型初期只撑大纲/讨论类轻场景。
- **断点（2026-09-02，用户飞行离线）**：首投因交互场景（一次吐完整 HTML+JS）+ thinking 常开撞 Node 5min Headers Timeout，6 次重试全挂 → 已改路由「交互场景→glm-5.3-flash + 关 thinking」并重启服务。重投任务 jobId `9JAUPt3CwV`（vLLM 入门迷你课 8 场景，http://localhost:3000 ）。回来续：若服务已死 `cd ../OpenMAIC && pnpm dev`；查任务 `GET /api/generate-classroom/9JAUPt3CwV`；终态 succeeded 取 `result.classroomId` → 直链 `/classroom/<id>`；failed 则砍交互场景重投。
- **结果（2026-09-02 晚）**：三投两败一成。①首投挂交互场景（5min Headers Timeout，6 重试全灭）；②二投 flash 路由**未生效**——OpenMAIC 的 `scene-content:<type>` 只认 slide/quiz/interactive/pbl 四种可路由类型，模拟器场景的 outline 类型（simulation/visualization3d 类）不在其中，回退基础键落默认 glm-5.3（教训：复合路由键的覆盖面要先读 `model-routes.ts` 的 LLM_STAGES 再写配置）；报错还从 Headers Timeout 升级到对端断开/TLS 断连，疑似 Clash Verge TUN 掐 ~5min 长连接（系统代理显示关闭，待 F 类翻配置坐实）；③三投在 requirement 里直接禁掉重型场景（只留 slide+quiz）→ **成功**。成品：《vLLM 入门：PagedAttention/Paging/Prefix Caching》8 场景，全程 glm-5.3。**排障过程本身即 vLLM 阶段 1/3 素材**：长输出生成、TTFT、超时与重试、中间盒杀长连接。
- **反馈（2026-09-09）**：用户**学完完整配音版并反馈「效果不错」**——应用驱动路径首次闭环成功。最终形态：本地 VoxCPM2 TTS（M5 Max MPS，自研 FastAPI server，48kHz）+ glm-5.3 文本，全程 34 段语音、~90 万 token（含全部失败重试与三节课）。时间账：文本 8min + 本地 TTS 25min（TTS 是新瓶颈，提速方向=拆分粒度/GPU 上 vLLM-Omni 后端，后者又是一举两得的 vLLM 实验）。PagedAttention 体感已建立 → 下次读《V1 架构总览》或开阶段 2 时可对照本课记忆。
- **模式制度化 + 第二节（2026-09-09 晚）**：第二节《调度器：continuous batching 的真身》交付（quhgC1KncC，6 场景 29 段配音，重投一次——长内容 slide 也会撞超时，「每页≤5 条要点」配方入档）。用户学完并完成测验。**「一阶段一循环」制度化**（用户拍板）：每阶段 = ①概念课开路（OpenMAIC，配方：slide+quiz only + 每页≤5 要点 + 本地 VoxCPM 配音）→ ②源码精读（对照课论断找代码证据标行号）→ ③阶段报告入 reports/。概念课储备：**阶段 1（调度）与阶段 2（内存）已覆盖**。课的边界明确：概念+类比层，到不了源码级——课是地图，码是地形。GPU 实测为独立支线（infra 开机随时插入）。
- **转向：课驱动主线（2026-09-10 用户拍板）**：用户对两节课反馈持续正面，明确「后面 vLLM 学习项目和计划都围绕 OpenMAIC 来」。课程序列九节排定（两节已学）：③《一个请求的一生》（阶段 0 重讲，治总览吃力）→ ④内存深潜（block pool/哈希复用/offload）→ ⑤Model Runner 一次 forward → ⑥采样与输出链 → ⑦投机解码（结清 EAGLE open-question）→ ⑧分布式 TP/PP/DP/EP → ⑨封顶完整版。源码报告降为按需深化（阶段 1 报告已存在作对照），每节课后收反馈再排下一节。

## 阶段 0 · 总览与跑通（约 1 次会话）

- **目标**：V1 架构地图 + GPU 机器上跑起来，建立"代码目录 ↔ 架构组件"的映射。
- **读**：官方设计文档（docs.vllm.ai）；`entrypoints/openai/`（API server）；`v1/engine/async_llm.py`、`llm_engine.py`（两个入口壳）。
- **动手**：GPU 机器部署（机器细节走 F 类私有仓 infra 档案）；pip 安装，跑一个小模型（如 Qwen3-0.6B），`curl` 发请求，看 `/metrics`。
- **产出**：《vLLM V1 架构总览：一个请求的一生（骨架篇）》

## 阶段 1 · 调度核心（约 2-3 次）

- **目标**：continuous batching 的工程真身；EngineCore 每个 step 里调度器的完整决策链（谁进、谁出、谁被抢占）。
- **读**：`v1/engine/core.py`（EngineCore 主循环）、`coordinator.py`；`v1/core/sched/scheduler.py`、`async_scheduler.py`、`request_queue.py`、`output.py`；chunked prefill、抢占/重调度逻辑。
- **动手**：压并发观察调度行为；改 `max_num_seqs` / `max_num_batched_tokens` 对比吞吐与 TTFT。
- **产出**：《vLLM 调度器：continuous batching 的真身》

## 阶段 2 · 内存管理（约 2-3 次）

- **目标**：PagedAttention 从论文概念到 block pool 数据结构；prefix caching 的哈希复用；KV offload 到 CPU/盘。
- **读**：`v1/core/block_pool.py`、`kv_cache_manager.py`、`kv_cache_coordinator.py`、`single_type_kv_cache_manager.py`、`kv_cache_utils.py`；`kv_cache_interface.py`；`v1/kv_offload/` 与 `simple_kv_offload/`；`v1/worker/block_table.py`。
- **动手**：prefix caching 开/关对比 TTFT 与缓存命中率（负载生成器可用 OpenMAIC 课堂生成，天然复用 ~30KB system prompt，见「实验载体」节）；一次 offload 实验。
- **产出**：《PagedAttention 工程实现与 KV 缓存体系》

## 阶段 3 · 执行层（约 2-3 次）

- **目标**：GPU 上一次 forward step 的全貌；attention backend 选择机制；CUDA graph / piecewise cudagraph 与 torch.compile 集成。
- **读**：`v1/worker/gpu_model_runner.py`（全仓最核心大文件）、`gpu_worker.py`、`gpu_input_batch.py`、`ubatching.py`；`v1/attention/`；`compilation/`；`cudagraph_dispatcher.py`。
- **动手**：torch profiler / nsys 抓一次 decode step 的 trace，拿着 trace 回源码找对应 kernel。
- **产出**：《GPU Model Runner 一次 step 的全貌》

## 阶段 4 · 采样与输出（约 1 次）

- **目标**：从 logits 到流式 token 的最后一公里。
- **读**：`v1/sample/`；`v1/engine/detokenizer.py`、`output_processor.py`、`logprobs.py`、`parallel_sampling.py`；`v1/structured_output/`（xgrammar 等后端）。
- **动手**：streaming、logprobs、structured output 各跑一次。
- **产出**：《从 logits 到流式 token：采样与输出链》

## 阶段 5 · 投机解码工程实现（约 1-2 次）

- **目标**：EAGLE / Medusa / n-gram 在服务引擎里怎么落地；接受率怎么统计。**结清 open-questions「EAGLE 特征层原理」**。
- **读**：`v1/spec_decode/eagle.py`、`medusa.py`、`ngram_proposer.py`(+`_gpu`)、`draft_model.py`、`extract_hidden_states.py`、`metrics.py`。
- **动手**：挂 EAGLE head 跑对比，看接受率指标与 tokens/s 变化。
- **产出**：《vLLM 投机解码工程实现（EAGLE 原理结清篇）》

## 阶段 6 · 分布式推理（约 2 次）

- **目标**：TP / PP / DP / EP 四种并行的落地路径；executor 抽象；容错。
- **读**：`distributed/`；`v1/executor/`；`ray/`；`v1/fault_tolerance/`；`v1/worker/dp_utils.py`。
- **动手**：多卡 TP 跑模型（规模看机器家底）；对 MoE 模型观察 EP 的专家分布（衔接 MoE 路由积累）。
- **产出**：《vLLM 分布式推理：四种并行的落地》

## 阶段 7 · 服务化周边（约 1-2 次，按兴趣点菜）

- **读**：`lora/`（热加载）、`multimodal/`（输入管线）、`reasoning/` + `tool_parsers/`、`v1/metrics/` + `tracing/`。
