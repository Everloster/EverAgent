# AI演义·19｜CoT：先生成中间步骤，再回答问题

[返回总览第 19 节](../AI演义_笔记分析与项目整合报告.md#paper-cot) · [上一章：InstructGPT](AI演义_18_InstructGPT_模型怎样学会按要求回答_科普讲解_20261105.md)

食堂原有23个苹果，午饭用了20个，又买来6个，现在有几个？先算剩下3个，再加6个，答案是9。2022年的CoT论文研究，语言模型先生成这样的步骤，是否比直接给答案更可靠。

Jason Wei、Xuezhi Wang等Google Research作者在提示中加入带过程的示例，让已有模型解新题时也写出步骤。在一些多步任务上，准确率显著提高，这组提示实验没有重新训练模型。[^paper] CoT全称Chain-of-Thought Prompting，通常译为思维链提示。

<a id="problem-and-history"></a>

## 1. 改变示例的写法

[GPT-3](AI演义_09_GPT2与GPT3_任务怎样进入上下文_科普讲解_20261105.md)已经展示few-shot prompting：在当前输入放几个示例，让模型按格式完成新任务。但规模增长没有让所有任务同样改善，多步应用题仍较困难。苹果题需要理解数量的增减，并保留第一次计算的结果。

此前已有用解释或中间步骤辅助训练的研究。CoT的具体问题是，能否只在当前提示中提供带过程的示例，改善已有模型的表现。[^history] 与InstructGPT的参数更新相比，它调整本次调用的上下文；两者可以组合，但这项实验本身不做微调，也不说明被测模型此前从未接受后训练。

<a id="few-shot-demonstration"></a>

论文Figure 1先给一道网球示范题：Roger原有5个球，买2罐、每罐3个，现在有多少？普通提示只写答案11，CoT示范则写出“新买2×3＝6个，再加原有5个，得到11”。随后两种提示都接上苹果题。[^example]

展示中，普通提示输出27；CoT先算23−20＝3，再算3＋6＝9。网球步骤由人提供，苹果步骤由模型生成，苹果答案未提前放入提示，整个调用也不进行梯度更新。这一例解释输入如何变化，成组评测才能说明改善幅度。

原始方法主要使用带步骤的few-shot示例。“只加一句逐步思考、不给示例”是后来Zero-shot CoT研究的设置。[^zero-shot]

<a id="intermediate-context"></a>

## 2. 写出的结果会成为后续上下文

自回归模型逐token生成，刚写出的文字也参与下一步预测。直接回答时，答案紧接题目；CoT先生成“午饭后剩3个苹果”，后续上下文就多了一个可用的中间状态：

> 数量与变化 → 午饭后剩3个 → 补货后有9个 → 最终答案。

这把多步问题展开成较小的生成步骤，也让模型在答案前使用更多计算。[^mechanism] 但可见文字只是一部分计算痕迹，不能据此断定每句话都忠实解释了内部运算。中间结果正确时可以帮助作答，错误时也会被后续继续使用。

<a id="main-experiments"></a>

## 3. GSM8K上的提升

GSM8K评估集有1,319道多步数学应用题。以下使用 **PaLM 540B（5,400亿参数）**；前两行均给8个示例，采用每步选择最高概率token的贪心解码，没有多次采样投票。[^results]

| 设置 | 最终答案准确率 |
|---|---:|
| 普通问答示例 | 17.9% |
| CoT示例 | 56.9% |
| CoT加事后外部计算器 | 58.6% |

前两行增加39.0个百分点，同一模型仅改变示例形式就有明显差异，仍有许多题未答对。

计算器一行需要单独解释：程序对已生成的算式进行事后计算，再尝试将修正结果传给后续算式。这能修部分算术错误，却不能保证列式符合题意，也不是模型逐步自主选择工具、观察返回值再规划。[^calculator]

作者博客的“约58%”包含计算器，“约74%”来自后续自洽投票工作。[^blog] 本章主要比较v6的17.9%与56.9%。论文2022年1月首发，后来增补PaLM、OpenAI模型和任务，所用v6为2023年1月修订版，不能把其中全部结果都归到首版。[^version]

<a id="ablation"></a>

## 4. 有用的是步骤，还是额外输出长度

作者更换中间输出，检查CoT收益来自哪里。下表为 **LaMDA 137B（1,370亿参数）**在GSM8K上、5种示例排列顺序的平均准确率，±表示顺序间标准差。[^ablation]

| 提示方式 | 准确率 |
|---|---:|
| 普通问答 | 6.5%±0.4 |
| 只写算式，再给答案 | 5.4%±0.2 |
| 先输出无信息点号 | 6.4%±0.3 |
| 先给答案，再解释 | 6.1%±0.4 |
| 先展开步骤，再给答案 | 14.3%±0.4 |

在这组设置中，额外输出点号没有相同收益，步骤的内容与位置都有作用。点号长度参照解题算式字符数，并未严格配平token和实际计算开销，所以这还不是所有等算力方案的比较。

单次自回归生成中，答案后面的解释无法回到过去影响已写出的答案。先写步骤，答案才可利用它；若允许修改或重新作答，就改变了流程。

只列算式也可能跳过了需要完成的语义拆分。例如必须先理解“用了”是减少，才能决定减法。更复杂的题目一次转成完整算式容易出错，自然语言步骤可以分段处理数量关系。不过论文在另一些简单题集上观察到算式提示也有改善，其作用随任务变化。

<a id="where-it-helps"></a>

## 5. 多步任务、规模与长度

PaLM 540B在单步与多步题上的差异很大：[^task-boundary]

| 题集 | 评估题数 | 普通提示 | CoT |
|---|---:|---:|---:|
| SingleOp，单步运算 | 562 | 94.1% | 94.1% |
| MultiArith，多步运算 | 600 | 42.2% | 94.7% |

简单题原本已经很少错，多步题则需要保留状态、组合关系，更可能从分解中获益。作者据此将任务难度、多步需求和模型能力作为尝试条件。

当时一些小模型会生成流畅但不合逻辑的步骤，准确率反而下降。“约100B才显现”也不是硬阈值：v6的PaLM 62B在GSM8K已由9.6%升至29.9%。[^scale] 参数规模、训练计算、数据与模型差异纠缠，不能单独确定普适分界。

论文还测常识问答、日期、体育判断，以及尾字母拼接和硬币状态追踪。[^other-tasks] 例如Lady Gaga有两个词，尾字母y、a拼成ya。示范使用2词名字，测试扩到3词、4词；PaLM 540B的CoT准确率依次为99.4%、94.8%、63.0%。它展示了有限的长度迁移，同时说明更长输入仍会使表现下降。

并非所有任务改善。v6标为GPT-3 175B、实际调用text-davinci-002的模型，在CommonsenseQA由79.5%降至73.5%。SayCan实验评估离散动作计划，不能将其分数写成机器人真实执行成功率。

<a id="errors-and-faithfulness"></a>

## 6. 答案正确，步骤仍可能错

Table 9有另一道苹果题：5个苹果派，每个切8块，剩14块，问吃掉多少。模型把“剩14块”读成“吃掉14块”，再说“剩26块”，最终却报出正确数字26。[^error-cases] 数值碰巧对了，“吃掉”与“剩下”的关系已经颠倒。

错误因此需要按位置检查。读错关系时，算术正确也无法补救；漏掉补货一步时，只得到3；列式正确也可能算错。第一种来自论文输出，后两种是围绕开篇苹果题构造的例子。

附录分类了50个LaMDA 137B错误回答，有些能小改修复，有些需大幅重写。[^error-analysis] 这些从答错集合抽取，不代表所有回答的错误率。原论文不同位置的部分汇总计数也有出入，本章采用可核对的具体案例，不推算总体比例。

检查时既核最终答案，也核题意、逻辑与算术。计算器主要解决算术，事实需要来源，约束需要对回题目。即使整份解答成立，也未证明它忠实呈现模型内部得出答案的原因，再让模型复述理由并非独立验证。

换示范作者、内容或顺序后，许多任务仍受益，幅度却会变化，硬币任务尤其敏感。[^robustness] CoT不是只有某一组措辞有效，也没有消除提示评估的必要。

<a id="related-methods"></a>

## 7. 几种相邻方法改变不同环节

| 方法 | 改变什么 |
|---|---|
| Few-shot CoT | 在当前提示中提供带步骤示例 |
| Zero-shot CoT | 不给示例，用提示引出步骤 |
| Self-consistency | 多次采样路径，汇总最终答案 |
| 用推导数据做SFT等训练 | 更新参数，改变生成倾向 |

Kojima等的Zero-shot CoT研究用“Let's think step by step”引出步骤，无需手工few-shot示例。[^zero-shot] Wang等的Self-consistency则用多路径采样和答案汇总替换贪心解码，增加了生成次数，也改变了选择方式。[^self-consistency]

多次得到9是一致性信号，但多个路径若共同误读条件，也会一致答错。投票不能替代外部真值。后训练则通过数据和优化更新参数，与本篇提示实验不同；本篇也未进行强化学习或围棋树搜索。仅凭生成步骤，无法还原后续产品的完整训练方法和内部过程。

<a id="practical-evaluation"></a>

## 8. 用对照判断是否适合自己的任务

[实践建议，未执行] 选择能核对答案的实际任务，分开示范题与评估题；比较普通问答示例和同题带步骤示例。若研究无示例提示或多次投票，另设条件，分别记录成本。

固定模型版本、题目、其他上下文和解码设置，给足输出空间，并记录实际token与耗时。关心成本收益时再做总预算相当的比较，分清额外调用与示例形式各自的收益。除最终正确率，还记录读错条件、漏步、算术错误和不可核验解释。

简单且已稳定答对的任务可能无需长过程；事实不足时补证据，精确运算用可靠工具。评价依据是具体错误减少多少、成本增加多少。[推测] Personal Context可为反复遇到的困难任务保留少量已核对示范、必要事实和验收标准，但本篇只支持示例形式会影响表现，没有验证完整的Context架构或“例子越多越好”。
