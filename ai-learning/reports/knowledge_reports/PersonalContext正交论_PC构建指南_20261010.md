# Personal Context 正交论：哪些积累值得保留，怎样持续维护

模型升级很快，积累的资料和经验还能用多久？个人上下文（Personal Context，下文简称 PC）提供了一种思路：把偏好、任务背景、研究结论和做事经验保存下来，让下一次使用 AI 时少解释一些、少犯一些已经犯过的错误。

但“保存了很多”不等于“下次能做好”。事实可能过时，经验可能适得其反，记忆可能在无关场景被调用。本文把“正交论”作为一项**条件性互补假说**：如果资料准确、与任务有关、取用得到授权，且维护和检索成本可接受，模型进步可能提高这些积累的用途。这里的“正交”只是一个比喻：资料可以与模型分开保存，能否继续发挥作用还要看使用结果。[推测]

本文先解释哪些积累值得保留，再讨论记忆如何用错、怎样维护，以及如何判断它有没有帮上忙。材料来自乱翻书的一期个人助手讨论、三篇厂商技术文章和本仓公开实践。访谈提供问题与案例，厂商文章提供工程经验和受限实验；目前还没有本仓长期使用收益的对照数据。

## 1. “正交”是一个提问方式

### 1.1 与模型分开保存，不等于价值与模型无关

个人偏好、研究证据和决策记录，可以保存在某款模型之外。换模型时，它们不会因为权重替换而物理消失。但能不能继续使用，仍取决于格式、检索、权限、语义和任务。

例如，一份“某项服务上个月已经迁移”的记录，即使迁移到更强模型，也可能因没有记录后续回滚而误导排错。相反，一套明确记录版本范围和失败条件的排错步骤，可能连续几代模型都用得上。前者是事实，后者是程序；类别本身不能决定耐久性。

“模型更强，同一份 Context 更有用”有两个可能机制 [推测]：模型能从原有资料中完成更复杂的工作；调用成本降低后，原本不值得自动化的任务开始值得做。但增加调用次数不保证增加有效产出，更不保证收益抵消维护成本。Jevons 式需求扩张在这里只是类比，没有本仓长期数据支持。

### 1.2 事实与经验，都有时效和适用范围

**事实与决策记录，要分清“当时”和“现在”。** 保存原始依据能避免重复调查，但当前状态改变后，旧结论不能继续充当现状。记录发生时间，并为后续更正留下入口。

**偏好与约束，要允许更正。** 用户明确表达的要求可以减少反复解释；一次临时要求却未必适合长期保存。旧偏好不应盖过当前指令。

**程序与经验，要写清适用条件。** 领域方法、工具约定、失败诊断可以复用；针对某代模型弱点的补丁则可能过时。用版本范围和真实失败判断去留。

**推断与画像，要保留不确定性。** 猜测可以作为待验证线索，但反复摘要不能让它变成事实。它应与用户明确表达的信息分开保存。

这里需要区分**历史真实性**与**当前适用性**。“上月曾采用某方案”可以一直是有效历史；“现在应采用该方案”却可能已失效。保留历史记录，不代表让模型在每次任务中都读取它。

### 1.3 两篇厂商原文为什么看起来方向相反

OpenAI 观察到，针对旧模型累积的详细步骤、过宽 Skill 描述、每次强制通读文档等，可能限制 GPT-6 Astra 的判断或造成额外工作。因此需要重新检查指令。[^s3]

IBM 的 ALTK-Evolve 则从训练任务的执行轨迹里提炼操作规则，加入系统提示，模型权重不变。在客服任务基准 τ²-bench 的留出集上，作者报告了以下结果：[^s4]

| 设置 | 规则条件 | Pass⁴ 变化 |
| --- | --- | --- |
| GPT-4.1，零售 40 题 | 全部 292 条保留规则 | 57.5% → 67.5% |
| GPT-4.1，航空 20 题 | 14 条高支持规则 | 35.0% → 45.0% |
| GPT-5.5，航空 20 题 | 从自身轨迹重新提炼规则 | 55.0% → 70.0% |

Pass⁴ 指一个任务在四次尝试中都成功的任务比例，不是“至少成功一次”。GPT-5.5 的实验重新提炼了规则，**不是把 GPT-4.1 的同一套规则直接迁移过去**。不同领域的最佳规则数量也不同；“支持次数”统计规则来自多少个训练任务，不是规则正确的概率。

收益还带来输入成本：原文在完整基础任务集（含训练与测试任务）上统计了 agent 加用户模拟器的每对话成本，不能把它与留出集成绩当作同一统计样本，也不能把对话轮数略减直接写成实测延迟降低。[^s4]

两篇材料共同支持的是一项更具体的原则：**按信息在当前任务中的作用决定去留。** 明确工具合同和有证据的领域方法可能继续有效；为某代模型弱点添加的补丁则需要重验。不能只凭“它是经验”就删除，也不能只凭“以前有效”就永久保留。

## 2. 从个人助手的讨论里，能学到什么

### 2.1 四种产品路线是观察视角，不是价值证明

乱翻书 275 在约 30:14–34:31 讨论了四条路线，以下按节目描述概括，不作当前产品功能承诺：[^s1]

- **Town 从邮箱等高频场景开始。** 连续的任务背景有助于观察用户怎样修改结果；能否促成持续使用，以及用户愿意授权哪些动作，仍要看实际交付。
- **Instinct 降低从消息发起任务的成本。** 自然交互可以减轻输入负担，但入口方便不代表执行可靠或数据容易导出。
- **Grok Bot 让多个 Bot 分工。** 资料和任务可以按职责组织；节目也质疑额外协作是否值得增加的耗时和 token。
- **Muse 用免费与分发推动采用。** 低门槛可能带来更多真实任务，但留存、成本和商业模式仍有待验证。

这些路线提示了不同的积累入口。产品投入和融资反映商业预期，尚不能说明 PC 已产生可持续收益：抢占入口、补贴和市场情绪，也可能解释同样的投入。

### 2.2 记住一件事，和恰当地使用它，是两种能力

节目约 **57:41–58:46** 举了一个历史案例：用户曾提到正在申请签证，新对话问起无关话题，助手却把答复强行绕回签证。嘉宾同时说明这是此前经历，当时的产品可能已经有所改善。[^s1]

这个案例支持“记忆调用可能不合时宜”，不能用于估计当前豆包错误率，也不能据此断言其内部采用哪种 Memory 架构。问题不只是记没记住，而是系统是否判断了这条记忆与当前任务有关。

节目约 **02:03:10–02:04:48** 进一步讨论：获取 Context 之后，还要处理、关联和判断时效；上一周成立的事情，这一周可能已经失效。[^s1] 因此，即使一条记忆当初完全正确，今天也未必适用。

也不必把所有资料都先“炼成完整画像”。一个清楚的当前约束，例如“本次只比较开源方案”，可能比复杂的长期画像更有用 [推测]。有些任务甚至不需要个人信息；无关时不调用记忆，同样是有效行为。

### 2.3 信任、习惯与授权不能混成一层

节目末尾谈到信任和习惯，也有嘉宾强调中间的 Context 处理机制；这是一组产品判断，不是所有嘉宾一致验证出的市场定律。[^s1]

信任是用户对系统的判断，习惯是使用行为，授权则回答“允许谁在什么范围内做什么”。良好交付可能促成用户扩大授权，也可能只是使用户更愿意继续审阅草稿。系统不能替用户完成这个授权决定。

同样，能导出对话不代表能带走原产品的权限。更换产品、工作单位或执行主体时，原来的访问权、数据使用许可和操作授权都需要重新核对。授权可以缩小、到期或撤回。

## 3. 五个维度，帮助分类而非排序

整理 PC 时，可以从以下五个维度看已有材料。它们帮助发现遗漏，不代表价值高低，也不要求各建一个文件。同一份记录可能涉及多个维度。[推测]

- **身份与偏好：** 哪些是用户明确表达、现在仍有效的要求？可以记录表达习惯，不要从一次任务推断人格。
- **事实与知识：** 依据是什么，何时成立，后来有无更正？研究报告、实验结果、决策记录都可归入这里，但要保留事实与推断的区别。
- **关系与协作：** 谁负责什么，哪些约定能在当前用途下共享？协作职责有助于完成任务，公开人物资料却不能充当私人关系网。
- **程序与经验：** 在什么条件下应怎样做，何时停止沿用？排错方法、工具约定和 Skill 都需要适用范围与反例。
- **委托与授权：** 哪些行动已获允许，范围与撤回条件是什么？以当前任务和项目协议为准，信任记录本身不能授予权限。

工作上下文（Work Context）与 PC 有交集，不能仅归为“事实与知识”和“程序与经验”的组合。工作中也有身份、关系和授权，个人任务也有程序知识。公司材料或他人资料是否能保存和迁移，受所属组织及使用目的约束，不因记录在个人目录里就成为个人可带走的资产。

### 行动门控为什么不等于授权

Laya 的既有研究讨论过：什么时候直接行动，什么时候转交更高层处理（act/escalate）。这是一个考虑出错成本的决策问题。[^s7] 把这个思想抽成一个**示意计算**：假设正确行动收益为 +1、错误为 −3、转交处理为 −0.5，且 `p` 是校准后的正确概率，则：

```text
行动收益 = p × 1 + (1 − p) × (−3)
         = 4p − 3
转交收益 = −0.5
行动更划算：4p − 3 > −0.5
即 p > 0.625
```

62.5% 只属于这组人为给定的收益假设。改动损失、概率校准或转交处理的效果，阈值就会变化；不能据此说模型实际已经学会这个阈值。更不能把“预计做对的概率高”当成“已获授权”：未授权的动作，即使预测正确率很高，也不应执行。

## 4. 怎样构建，而不让维护变成负担

### 4.1 分清保存的资料和这次模型读到的内容

Anthropic 将 Context Engineering 描述为持续选择进入模型上下文的信息，强调取用高信号内容、合适的提示抽象层次，以及按需检索。[^s2] 在 Personal Context 中，可以据此区分几种职责 [推测]：

**原始材料负责保留依据。** 原文、决策记录、实验输出供回查和重新解释，不必在每次任务中全部读入。

**长期记忆（Memory）保存以后仍有用的信息。** 事实、偏好和经验可以从历史记录中提炼，但保存过的内容不应自动全部变成长期记忆。

**索引负责找资料。** 路径、摘要、时间和状态帮助定位，事实仍以负责维护的来源为准。

**当前上下文服务这一步任务。** 放入本次需要的指令、证据和工具结果；窗口够大，也不意味着全部资料都有用。

**执行状态说明工作做到了哪里。** 已完成步骤、真实产物和未决操作需要留下记录。一段画像或聊天摘要不足以证明事情已经做成。

按需检索也有代价：Anthropic 明确指出，运行时探索可能比预先检索慢，工具和导航不清楚还会造成无效探索。适合的组合通常要同时考虑资料变化速度和任务需要，不能把“尽量少读”机械变成目标。[^s2]

### 4.2 四条维护原则

1. **可控制、可导出。** 需要长期复用的记录，尽量使用可检查的格式并保留恢复路径。自持不等于绝对安全；本地或私有仓也需要权限、备份和删除能力 [推测]。
2. **找到负责维护的来源。** 一条当前事实应能回到负责更新它的文件；摘要或检索结果发生冲突时，核对来源与时间。路径和 SHA-256 能说明内容出处或是否变化，不能证明内容本身真实。[^s5]
3. **更新比堆积重要。** 旧研究可以保留历史并加更正入口；临时偏好要避免变成长久约束。删除个人信息时还要处理派生 Memory、索引、缓存与副本，仅从当前输入裁掉不算完成删除 [推测]。
4. **按用途取最小必要部分。** 公开仓保留公开知识和脱敏方法；私人事实不进入公开产物。获得授权的私有资料，可以在合适的受控环境用于任务。“不能公开”与“永远不能进入任何模型输入”是两种不同边界。[^s5][^s6]

### 4.3 选 Memory 方案时，先查这些问题

选型时，先用具体问题检查候选系统。[推测]

- **记错了，能否查回原始依据？** 看系统怎样提取、更新和删除记忆，冲突时覆盖什么，误记与误删能否恢复。
- **能否分清过去和现在？** 带时间的事实或关系，应能按有效时间查询。
- **换产品后，导出的资料还能用吗？** 不只看文件是否完整，还要看接收方能否理解语义，以及权限是否被错误地一并迁移。
- **压缩后，关键约束还在吗？** 检查摘要有没有丢掉反例、未完成事项和用户要求，并保留返回原始记录的路径。
- **多个 Agent 共用时，会不会相互覆盖？** 查看读写权限、冲突处理与任务状态，并观察共享是否减少了重复工作。

向量库、知识图谱和 Markdown 是实现选择，不能代替这些问题的答案。本文没有完成全面产品调查；现有证据也不足以确认存在可跨产品通用的授权方案。

### 4.4 本仓已经有什么，仍缺少什么证据

本仓公开部分已经体现了一些分工：[^s5][^s6]

- **偏好与执行规则分开。** `PROFILE.md` 类文件记录明确偏好；根协议主要负责执行约束和任务路由。
- **报告保留分析，知识页提炼当前理解。** 两者都要保留来源与更正，区分事实、解释和推断。
- **公开实体页介绍人物、机构或产品。** 它们没有表示私人关系和协作历史。
- **协议、Skill 与工具约定保存部分做事经验。** 修改频率本身不能说明经验贬值多快，效果仍要用任务结果检验。
- **授权已写入根协议和共享执行协议。** 使用现有规则即可，重点是当前执行者能否读到并遵守，无须再为分类单建一份委托文件。

本仓可以展示组织方法、来源和修订记录，尚不足以证明长期使用收益、跨产品授权迁移或跨设备接班效果。检索能命中一页、报告通过复核和任务实际做好，需要分别验证。

### 4.5 从一个会反复发生的任务开始

[推测] 不必先建齐五类目录。先选择一项会重复发生的工作，例如每周读技术文章并回答一个研究问题：

1. 保存原文链接和必要证据，写清当时的结论及未解决问题。
2. 下次遇到相同问题，先定位已有记录，再补变化；避免为同一事实维护多份互相矛盾的摘要。
3. 只有某项偏好或方法在后续任务中确实有用，才把它提炼为长期记录。
4. 信息变更、任务失败或维护负担升高时，回查旧记录；不强制每日记录、每周审阅、每月重构。

这样积累的是有实际用途的资料。文件数量、字数和调用次数，都不能代替使用结果。

## 5. 怎么知道这套积累有没有帮助

以下是可用于真实任务的评估设计，**本报告没有运行这些对照，也不报告虚构收益** [推测]。

**重复解释有没有变少？** 记录需要补充背景的次数，以及首次得到可用结果的耗时。同时看错误假设：少问问题也可能只是擅自猜测。

**旧知识有没有用对？** 检查相关证据是否被找到、过时信息是否被识别，并核对最终答复。检索命中一页，不等于正确使用了它。

**经验有没有减少失败？** 在模型、任务与工具尽量一致时，比较带与不带该经验的结果；再用未参与调规则的任务复查。

**新要求能否覆盖旧记忆？** 测试临时要求、偏好更正与撤回，不能只挑顺从旧偏好的例子。

**总投入有没有下降？** 把整理、检索、运行、返工与验收一起计算。若维护没有带来收益，就缩小积累范围。

不需要每次都开展完整 A/B 实验。日常任务出现具体失败时，先检验相关记录；当要把某条规则推广到多种模型或大规模流程时，再增加相应对照。评估范围应与要作出的决定相匹配。

## 6. 风险与失效条件

- **资料过时或被污染。** 有来源的记录也可能判断错误；关键事实需要核对，派生摘要应随更正更新。
- **画像固化。** 过去偏好覆盖当前要求，或无关记忆反复进入回答。应允许用户明确改写、撤回，检查与当前任务的相关性。
- **迁移名存实亡。** 文件导出成功，但语义、附件、权限或引用关系丢失；不能因此宣称 Context 已可跨产品复用。
- **隐私集中。** 集中资料方便检索，也集中泄露风险。公开/私有分工、按用途共享与删除能力都需要落实；本地推理本身不等于没有泄露风险。
- **收益不足。** 若即时收集少量背景已足够，或维护持续超过节省的工作量，应该缩小积累范围，而非加更多流程证明体系有价值。

这些风险共同限定了“互补假说”：模型能力提升只是其中一个变量，资料质量、任务相关性、权限与成本同样会改变结果。

## 思考与追问

1. **可以保留的认识是什么？** 与具体模型分开保存、有来源且能更新的资料，有机会减少重复工作。事实与经验都值得按使用效果维护，不能按类别预判谁永久有价值。
2. **仍缺少什么证据？** 哪些积累在后续真实任务中持续有用；跨模型换用后收益是否保持；更正、撤回与遗忘能否贯穿原始记录及派生内容。产品投资和厂商经验不能替代这些验证。
3. **下一步最值得观察什么？** 在后续真实研究任务中，看已有材料是否被正确复用、旧结论是否被及时纠正，以及维护是否减少总工作量。先解决可观察的问题，再决定是否需要新的组件。
