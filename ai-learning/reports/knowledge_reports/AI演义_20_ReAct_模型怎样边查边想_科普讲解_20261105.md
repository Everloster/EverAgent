# AI演义·20｜ReAct：让下一步行动用上外部反馈

[返回总览第 20 节](../AI演义_笔记分析与项目整合报告.md#paper-react) · [上一章：CoT](AI演义_19_CoT_中间步骤怎样帮助模型作答_科普讲解_20261105.md)

Apple Remote最初为控制哪个程序设计？除了遥控器，还有什么设备能控制它？这道题先要确定程序，再找另一种控制方式；缺少事实时，延长推导也可能只是继续猜。

2022年，姚顺雨、Jeffrey Zhao、Karthik Narasimhan、Yuan Cao等来自Princeton与Google Research的作者提出ReAct，将Reasoning与Acting组织在一起：模型决定下一步动作，工具执行并返回观察，模型再据此继续。[^paper]

<a id="why-interaction"></a>

## 1. 缺事实与丢失任务目标

Figure 1中，CoT模型误把Apple Remote最初控制的程序认成Apple TV，再推到iPhone、iPad和iPod Touch。推导连贯，起点却错了。仅行动的Act-only对照做了相关查询，最终提交`Finish[yes]`，没有回答用户要找的设备。[^example]

前者缺少可靠事实，后者拿到信息却未能将它接回任务。ReAct尝试用推理组织查询，再用实际返回修正推理。单个展示例说明研究问题，效果仍需看后面的成组实验。

<a id="apple-remote-walkthrough"></a>

## 2. 查找失败怎样改变查询

论文使用简化Wikipedia接口。模型先确定要查Apple Remote最初控制的程序，发出`Search[Apple Remote]`，返回提到 **Front Row媒体中心**。这使下一步目标变为寻找Front Row的其他控制方式。

`Search[Front Row]`没有找到对应词条，返回相近名称，包括Front Row Seat to Earth、Front Row Motorsports和Front Row (software)。模型据此改查`Search[Front Row (software)]`。工具的失败信息在这里帮助它消除了名称歧义。

新查询返回软件介绍。原图省略了部分观察，随后显示模型得出可用Apple Remote或键盘功能键控制的判断，最终提交`Finish[keyboard function keys]`。本章保留原图的省略，不补造完整返回；复述的也是历史问答实验，不是核验当前Apple产品说明。

这条过程的作用在于：外部返回实际进入了下一次判断。若模型只自行写“我查到了相近结果”，没有工具执行，就未取得新证据。Finish只表示提交和停止，是否答对还需对照问题与来源。

<a id="model-tool-observation"></a>

## 3. 推理、请求和返回各来自哪里

| 记录 | 来源与作用 |
|---|---|
| Thought | 模型生成，用于拆解问题、整理进度和选择下一步 |
| Action | 模型提出操作请求，外部程序执行 |
| Observation | 工具或环境返回操作结果 |

“需要查Front Row”只改变上下文，搜索请求执行后才取得网页信息。后续上下文包含原问题、已有推理、动作与观察，为当前任务保存工作记录；它没有自动写入参数，也不保证新会话能继续。[^mechanism]

主要实验给冻结模型少量示范轨迹，再让它对新任务生成推理和动作，不在交互时更新参数。查询获取信息，游戏中的拿取则改变环境状态，具体动作由接口决定。返回也可能不完整、不相关或出错，需要继续判断。

<a id="action-space-and-rhythm"></a>

知识问答接口只提供三种动作：[^api]

- `search[entity]`：命中词条时给开头5句，否则返回最多5个相近词条。
- `lookup[string]`：在当前词条逐次找含指定字符串的句子。
- `finish[answer]`：提交答案并停止。

这不是完整互联网浏览能力。词条名和截取范围都会影响结果。家务与购物环境另有移动、打开、拿取、搜索商品和选择规格等动作。

推理频率也可变化。问答中较密集地交替，长决策任务则在相关位置才写，例如决定去哪找物品、找到后切换子目标。[^sparse] 不必每次操作都附长篇推理，重点是进度与新返回能影响后续行动。

<a id="knowledge-results"></a>

## 4. 查询并未在所有问答中占优

Table 1使用 **PaLM 540B（5,400亿参数）**：[^qa-results]

| 方法 | HotpotQA答案精确匹配率 | FEVER判断准确率 |
|---|---:|---:|
| 普通提示 | 28.7% | 57.1% |
| CoT | 29.4% | 56.3% |
| Act-only | 25.7% | 58.9% |
| ReAct | 27.4% | 60.9% |

HotpotQA需要结合多个Wikipedia段落，FEVER判断资料支持、反驳某陈述，还是信息不足。两者都只给问题或陈述，不预先提供支持段落，示范数分别为6与3。

ReAct都超过Act-only；相对CoT，FEVER高4.6个百分点，HotpotQA却低2.0个百分点。查询增加证据，也增加检索、筛选和组织的负担。

作者还与CoT-SC自洽投票组合。单独CoT-SC为33.4%／60.4%；ReAct在限定步数内无法回答后转CoT-SC，HotpotQA达到35.1%；先CoT-SC、一致性不足再用ReAct，FEVER达到64.6%。组合增加了采样或查询，不能当作一次普通ReAct调用的成绩。

具体设置为21条CoT采样轨迹、温度0.7；ReAct转出的步数上限是HotpotQA 7步、FEVER 5步。反向切换在多数答案出现次数不足n/2时触发，n为样本数。同表监督系统为67.5%／89.5%，使用专门训练条件，并非等预算比较。

Table 1与相邻方法段未明确列实际评估题数。附录A.1的500道HotpotQA、官方README的500道随机验证题属于另外的比较，不能拼入本表。[^version] 本章采用2023年3月v3，首版日期为2022-10-06。

<a id="failures"></a>

## 5. 查到了，也可能认错对象

作者抽查200条HotpotQA轨迹：ReAct与CoT各50条正确、50条错误。这是按成败分层选出的样本，不是线上随机故障统计。[^error-analysis]

ReAct错答组中，论文将47%归为推理错误、23%归为搜索结果问题，前者也包括反复思考与重复操作。接口返回失败不保证模型会像Front Row案例那样调整计划。

附录还有一个最终匹配却过程错误的例子：题目比较San Marco与About Time两款桌游的发布时间，ReAct查成威尼斯地区与电影，最终仍报出San Marco。查询确实发生了，实体和证据却不对应题目。

错答分类表未给ReAct标出幻觉，但正确样本中仍有6%被归为事实或推理有问题，不能据前者宣称幻觉消失。作者也发现部分参考答案过时，因此匹配分数、证据质量和现实正确性要分别检查。

<a id="decision-making"></a>

## 6. 在环境里完成连续动作

ALFWorld是文字家务环境，要求寻找、移动、清洗、冷却等，模型接收描述并输出文字动作，没有真实机器人。推理在这里负责检查状态和切换子目标。[^decision-results]

Figure 1的胡椒瓶任务中，Act-only反复对空水槽“拿取”，返回始终是什么也没发生；ReAct根据可能位置继续找，找到后转向放置，打开抽屉完成任务。这只是一次展示，但说明完成状态为何影响行动。

作者在134个未见测试游戏上评估，每类给2条示范、比较6组提示：

| 设置 | 总体成功率 |
|---|---:|
| ReAct，6组平均 | 57% |
| ReAct，6组最佳 | 71% |
| Act-only，6组最佳 | 45% |
| BUTLER，原基线8次试验最佳 | 37% |

摘要中的34个百分点来自71%−37%，是最佳结果差。BUTLER经过模仿学习，训练与搜索条件也不同。Act-only按正文从同批轨迹删除推理，更直接检验推理作用；但附录一份标为无推理的提示仍含一行`think`，与实际输入的关系尚未查明。[^prompt-caveat]

受限且密集的状态反馈格式ReAct-IM，最佳成功率为53%，低于ReAct的71%。[^im-ablation] 这支持常识判断、进度检查和子目标切换在所测任务中的作用，不能当作对另一完整机器人系统的复现。其失败例要求放好清洗过的刀，模型找到后直接放置，漏洗且反复放置。作者认为“找一把干净的刀”可能让模型误把目标当成已达到状态，这仍是原因解释。

WebShop使用真实商品资料模拟购物，在500条测试指令上统计是否满足全部要求：ReAct **40.0%**，Act-only 30.1%，模仿学习29.1%，加入强化学习的基线28.7%，人类专家59.6%。该指标与平均满足多少属性的分数不同，也不产生真实订单。

Table 10要求特定口味、16包、低于50美元。Act-only选了另一口味的100包、85美元商品；ReAct检查选项并选相应口味和16包。页面相关并不足够，还要逐项对上用户约束。

<a id="training-and-human-correction"></a>

## 7. 从轨迹学习与直接修正上下文

少量示范同时要求模型组织推理和操作，对能力有要求。Figure 3中，PaLM 8B、62B仅靠提示时，ReAct在所比四种格式中最差；使用3,000条最终答案正确的生成轨迹微调后，ReAct成为图中最好的训练格式。[^finetuning]

训练步数不同，属于初步实验，不是严格等计算比较。它说明交互记录可以成为训练数据，但一次查询与接收返回本身并非强化学习更新。[推测] 只按最终答案筛轨迹，仍可能留下桌游案例那样的过程错误，可靠示范需要额外核查。

另一个ALFWorld案例中，模型误以为第二把钥匙链也在刚才的抽屉。人删除错误推理，补充寻找其他位置的提示，后续行动改变并完成任务。[^human-edit] 这修改的是接下来读到的上下文，未更新权重。可见轨迹提供了干预入口，但单例不保证总能修复，也未证明文字揭示了全部内部计算。

<a id="history-and-reading"></a>

## 8. 研究与工程的连接

ReAct承接WebGPT、SayCan、Inner Monologue等前驱，Agent和语言模型工具交互都早于它。[^history] 其贡献在于用更灵活的语言推理组织行动，并系统比较效果。论文注明姚顺雨在Google实习时完成这项工作，作者来自Princeton与Google Research，问题横跨推理与环境交互。

讲义与播客还讨论了选题和动手实践。嘉宾将CoT、ReAct放在ChatGPT热潮之前，强调发现尚未被广泛关注的缺口；这属于研究经验，不能据此预测引用量或否定公式更复杂的工作。[^lecture]

谈到年龄与持续学习时，嘉宾同时提到年轻研究者较少历史包袱、资深研究者也能不断学习，没有给统一年龄规律。亲手写代码与管理流程、人员、指标也是不同参与方式，口述观察不代表地区工程文化统计。

他以自己写前端为例：构想可直接转成实现，交给别人则要先经PRD、原型和沟通，传递中可能损失信息。他用“压缩—解压”描述这种过程，解释为何重视更宽的能力跨度和读论文。这一经验不要求所有团队取消文档或分工。

本系列中，InstructGPT训练回答行为，CoT组织中间步骤，ReAct将动作与环境反馈接入过程，下一章Tülu 3进一步公开后训练数据、方法与评价。它们可以配合，但并非后一篇直接接着前一篇权重训练的谱系。

<a id="practical-implications"></a>

## 9. 检查任务是否推进

[实践建议，未执行] 可以固定一组任务与工具，对照Act-only和ReAct，记录成功率、查询次数、重复动作与失败恢复。读轨迹时，查看查询是否对应未解决的问题、新返回是否改变计划，以及提交答案或操作结束时是否有相应证据。失败还需区分规划、工具结果和过时评价标准。

这些检查不能由记录中出现“Thought”代替。权限、持久记忆和跨设备会话也不是本篇提供的完整系统；状态保存与停止条件仍需实现。论文自己的环境限制包括不能修改Wikipedia、WebShop不能真下单，开放网页和物理环境的隐私与动作风险仍需另行处理。[^ethics]
