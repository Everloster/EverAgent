# 《AI演义》30｜Stable Diffusion v1.4：一句提示词，怎样穿过整套文生图系统？

[返回原报告第 30 节](../AI演义_笔记分析与项目整合报告.md#paper-sd14) · [上一节：LDM](AI演义_29_LDM_潜空间怎样降低图像生成成本_科普讲解_20261106.md) · [下一节：DiT](../AI演义_笔记分析与项目整合报告.md#paper-dit)

你输入一句话：**“窗边花瓶里的一朵红花。”**

过了一会儿，屏幕上出现一幅花照。这个过程看起来像“AI 理解文字，然后画图”，但这句话省略了最值得弄明白的部分：谁理解文字？谁决定构图？谁把中间结果变成像素？为什么换一个随机种子，花瓶就挪了位置？

前一章的 LDM 给出了方法：在较小的潜空间里逐步生成。本章选定 **Stable Diffusion v1.4** 这个具体模型，沿着同一句提示词走一遍，看看方法、数据、权重和采样程序怎样组合起来。

这里的中文提示词只是贯穿讲解的例子，不是本轮生成测试。v1.4 主要使用英文图文训练；把例子写成 *a red flower in a vase by a window*，更符合它的训练语言。本文不展示未经运行的“实测效果”。[^card]

<a id="method-model-program"></a>

## 1. 先分清三件事：方法、模型和程序

如果问“Stable Diffusion 的论文是哪篇”，通常会指向 LDM 论文。但读完论文，还不能自动知道 v1.4 用了哪个文本编码器、经历了哪些训练，也不能知道某个软件默认采样多少步。

这三个层次分别回答不同的问题：

| 层次 | 本章对应什么 | 它决定什么 |
|---|---|---|
| 方法 | Latent Diffusion Models | 先压缩图像，在潜空间里学习和运行扩散 |
| 具体模型 | Stable Diffusion v1.4 checkpoint | 选用哪些组件，以及训练后实际得到的参数 |
| 推理程序 | 官方采样脚本或 Diffusers pipeline | 怎样读取提示词、调用采样器、解码并处理输出 |

**Checkpoint 可以理解为训练到某个阶段保存下来的模型参数。** 它不是一份提示词，也不是一个聊天界面。推理程序加载这些参数，才把已经学到的能力用于新输入。

原 LDM v2 的文本实验使用 BERT tokenizer 与联合训练的 Transformer 条件编码器；v1.4 则使用**固定的预训练 CLIP 文本编码器**。因此，“论文提出潜空间扩散”与“v1.4 具体用冻结 CLIP”需要分别查论文和模型卡，不能互相代替。[^ldm] [^card]

<a id="text-encoder"></a>

## 2. 文字先变成一串表示，不是直接变成图片

提示词进入系统后的第一站，是文本编码器。

程序先把句子切成 token，再交给 CLIP 的文本 Transformer。Token 是分词器使用的符号单位，不必等于一个完整单词，更不必等于一个汉字。编码器输出一串数值表示，作为后面生成时的条件。[^encoder]

这里很容易与第 25 节的 CLIP 混淆：

- CLIP 的图文对比学习，把图片与文字映射到可比较的表示空间。
- **v1.4 生成时取的是文本编码器未汇聚成单一向量的序列输出**，让去噪网络可以读取不同 token 的表示。

因此，不能把过程理解成“先算一句话与一张图的总相似度，再照着分数画”。纯文本生成开始时，甚至还没有一张完成的图片可以这样比较。官方代码中的 `FrozenCLIPEmbedder` 返回 `last_hidden_state`；其行为与另一个返回整体文本表示的类不能混为一谈。

“CLIP ViT-L/14 文本编码器”这个称呼也值得拆开：ViT-L/14 标识所选 CLIP 模型的配对版本，本章实际使用其中的**文本 Transformer**，不是把文字当成图片切成 14×14 的图块。

### 冻结，不等于它不再工作

“固定”或“冻结”是说训练这个扩散模型时，不更新这部分参数。提示词仍然需要经过文本编码器，才能得到条件表示。官方配置写明 `cond_stage_trainable: false`，编码器代码也关闭了参数梯度。[^config]

这有点像使用一套已经学好的词语表达系统，再让画图网络学会怎样依据这些表示行动。它省去了在这一训练阶段重新学习整套语言表示，但不能保证文字关系都会被正确画出来。

原参考实现的 tokenizer 设置了 **77 个 token 的最大长度**，会做截断与填充。这不是“77 个词”，也不是现代所有文生图应用统一遵守的输入上限；加入特殊 token 后，能够承载的正文空间还要相应考虑。这里描述的是已读取的 v1 参考代码，不把后来软件的长提示词扩展倒填进去。[^encoder]

<a id="latent-and-unet"></a>

## 3. 真正反复修改的，不是屏幕上那张大图

v1.4 的自编码器让图像的高、宽各缩小 **8 倍**。以一张 **512×512×3** 的彩色图片为例，对应潜表示的形状是 **64×64×4**。[^card]

这里的 4 个通道不是红、绿、蓝再加透明度。它们是模型学到的表示，需要配套解码器才能变回可观看的图片。

生成新花照时，系统可以直接创建一份这个形状的随机噪声，不需要先藏好一张花照再把它弄模糊。网络的训练确实看过真实图像，但新一轮纯文本采样的起点是新噪声。

接下来，U-Net 反复收到三类信息：

1. **当前的潜空间状态**：这幅图现在生成到什么程度。
2. **当前时间步**：它处在怎样的噪声级别。
3. **文本条件表示**：这次希望生成什么。

它预测当前状态中的噪声，采样器据此计算下一状态。U-Net 是本例去噪网络的骨架；扩散是组织训练和生成的方式，二者不是同义词。

怎样把“红花”“花瓶”“窗边”与图像特征联系起来？网络在部分层里使用**交叉注意力**：图像特征提供查询，文本表示提供键和值。可以把它理解成，生成过程中的图像位置按需要读取提示词信息；但这只是帮助理解信息流，不等于每个词都被严格分配到唯一位置，也不保证空间关系必然正确。[^ldm] [^config]

高、宽各缩小 8 倍，空间位置数是原来的 **1/64**。不过潜通道数、网络宽度、文本处理和解码仍然要计算，不能说“整个程序因此快了 64 倍”。

<a id="training"></a>

## 4. 训练时有答案，生成时没有那张原图

假设训练资料里有一张窗边花照，以及与它配对的文字描述。训练过程可以这样看：

```text
真实花照 → 编码器 → 干净的潜表示
                          ↓ 加入程序已知的噪声
                   带噪潜表示 + 时间步
                          ↓
文字描述 → 文本编码器 → U-Net 预测噪声
                          ↓
                与实际加入的噪声比较
```

答案来自程序自己加入的噪声，不需要人工为每一张图写一份“怎样去噪”的教程。U-Net 看见的是带噪状态、时间步和条件表示，而不是被当成答案直接喂进去的干净原图。[^card]

训练反复进行后，网络学到不同噪声级别下，哪些变化更符合图像分布及文字条件。生成时没有训练例子的干净潜表示；系统从新的噪声出发，依靠已学参数一步步得到新潜表示，再解码为图片。

这也解释了两个常见误会：

- **不是每次用户输入一句话，系统就重新训练一个模型。** 普通采样使用的是已有参数。
- **不是生成时在线检索一张训练图作为标准答案。** 但“不按这种方式检索”，并不等于模型绝无记忆训练样本的风险；模型卡明确报告了重复训练图像的记忆现象。

<a id="cfg"></a>

## 5. CFG：为什么要让同一个模型“有提示”和“没提示”各想一次？

即使去噪网络能够接收文字，普通条件预测也未必足够贴合提示词。一个重要办法是 **Classifier-Free Guidance，通常简称 CFG，无分类器引导**。[^cfg]

先看训练中的小变化：v1.4 在后续训练中有 **10% 的文本条件被丢弃**，让同一套网络也练习不依赖具体文字的预测。丢掉的是条件，不是把 10% 的图片删除，更不是让 10% 的图片停止参与训练。[^card]

于是，采样时可以让同一网络回答两个问题：

- **无条件预测**：不指定这句话，当前状态通常应该怎样变化？
- **有条件预测**：如果目标是窗边花瓶里的一朵红花，预测会怎样不同？

参考实现把两种噪声预测按下面的方式组合：

> 引导后的预测 ＝ 无条件预测 ＋ 引导强度 ×（有条件预测 − 无条件预测）

直观上，它突出“因为这句话而发生的变化”。这里没有再训练一个独立的图像分类器来打分，所以叫“无分类器”。也不是养了两套互不相关的模型：两种预测共用参数；代码可以把两组输入拼成一个加倍的 batch，再调用同一个网络。[^plms]

### 引导强度不是质量旋钮

按这份代码的约定，引导强度 **1** 会回到普通有条件预测，不是无条件生成；大于 1 才是在这个基础上强化条件方向。原 CFG 论文采用另一套权重记法，不能把论文中的数字直接当作软件界面里的同名值。[^cfg]

增加强度是在改变采样偏好，而不是让模型多学了知识。CFG 原论文展示的是**样本质量与多样性之间的取舍**，不是“越大越好”的定律。

回到花照：提示的影响可以更突出，但模型仍可能画不好花瓶与窗户的关系，也可能更集中地生成某类样式。引导无法凭空补上模型没有学好的表示能力。

<a id="sampling"></a>

## 6. 从随机起点走到图片：采样器负责怎样走

将前面的部件连起来，一次纯文本生成的主线是：

```text
提示词 → 固定的 CLIP 文本编码器 ─────────────┐
                                            ↓
新潜空间噪声 → U-Net 预测 → CFG 组合 → 采样器更新
                    ↑                      │
                    └──── 下一状态继续 ────┘
                                  ↓ 最后
                              图像解码器
                                  ↓
                              像素图片
```

U-Net 提供预测，采样器决定如何利用这些预测、怎样选择时间步以及更新状态。**同一套模型参数，可以配不同的采样程序。**

官方 README 的参考命令使用 **PLMS、50 步、引导强度 7.5、512×512 分辨率**；固定版本模型卡的 Diffusers 示例则使用默认 PNDM 调度器。两者都是来源里真实出现的用法，不应写成“Stable Diffusion 天生只有一个默认采样器”。[^readme]

这里还需要分开三个数字：

| 数字 | 实际指什么 | 不代表什么 |
|---|---|---|
| v1 参考配置中的 1000 个扩散时间步 | 加噪与去噪建模所用的时间范围 | 用户必须运行 1000 次采样迭代 |
| 参考命令的 50 个采样步 | PLMS 选定的采样迭代数 | 模型恰好只做 50 次前向计算 |
| 最后的 1 次解码 | 将生成完成的潜表示变回图片 | 整个生成过程是一步完成 |

为什么 50 步不严格等于 50 次网络前向？官方 PLMS 首步会额外估计一次下一状态的模型输出；CFG 还让每次模型调用处理有条件与无条件两组输入。比较速度时，步数只是部分信息。[^config] [^plms]

PLMS 的这份实现要求 `eta=0`。不能机械地照搬基本 DDPM 的描述，说它每一步都重新加入一份随机噪声。起始随机性仍然存在，但具体采样算法怎样处理后续状态，要看对应实现。

### 随机种子为什么重要？

同一句话并没有规定花瓶的所有形状、光照和细节。随机起点让系统可以从不同位置开始生成，这就是改变 seed 可能得到不同图像的原因。

固定 seed 有助于比较同一套设置下的变化；但若同时改了采样器、数值精度、软件版本或设备，不能只凭 seed 相同，就保证逐像素输出相同。

<a id="data-and-checkpoints"></a>

## 7. 模型不是“在 LAION 上训练过”这么简单

一句“使用 LAION 数据”会掩盖两类重要选择：**用哪些图文，以及从哪个 checkpoint 接着训练。**

v1.4 模型卡给出了下面的训练沿革。表中的“步”是训练更新次数，不是图片数量：[^card-training]

| 保存的版本 | 从哪里开始 | 模型卡记录的训练阶段 |
|---|---|---|
| v1.1 | 前期训练 | LAION-2B-en 上 237,000 步、256×256；随后在高分辨率子集上 194,000 步、512×512 |
| v1.2 | v1.1 | 美学筛选子集上 515,000 步、512×512 |
| v1.3 | v1.2 | 美学筛选子集上 195,000 步、512×512，并以 10% 概率丢弃文本条件 |
| v1.4 | **v1.2** | `laion-aesthetics v2 5+` 上 225,000 步、512×512，并以 10% 概率丢弃文本条件 |

v1.3 和 v1.4 都从 v1.2 继续，**不是 v1.1 → v1.2 → v1.3 → v1.4 的单一路径**。

模型卡记载，v1.1 使用的高分辨率子集包含约 **1.7 亿**个原始分辨率至少 1024×1024 的例子；训练输入会按相应阶段处理到表中的分辨率。v1.2 的美学子集则要求原图至少 512×512、预测美学分数大于 5、预测水印概率小于 0.5。

这些是自动筛选条件，不是逐张人工授权、事实正确或画面绝无水印的保证。模型卡与仓库 README 对 v1.2 子集的名称也略有差异，因此这里保留“美学筛选子集”，不强行把所有名称说成完全一致。

### CLIP 在这里出现了两次，但做的不是同一件事

LAION-5B 的数据构建论文使用图像与文字编码之间的相似度，筛掉大量关联较弱的图文对。英语筛选使用 CLIP ViT-B/32；这与 v1.4 生成时所用的 CLIP ViT-L/14 文本编码器不是同一项调用。[^laion]

| 出现的位置 | CLIP 帮忙做什么 |
|---|---|
| 数据构建 | 判断图片与配文是否足够相关，辅助筛选训练材料 |
| v1.4 生成 | 把用户提示词编码成条件序列，供去噪网络读取 |

前者影响模型有机会学到什么，后者影响用户怎样表达生成要求。把二者连起来看，才会发现一个表示学习成果怎样同时进入数据与模型两端。

但相似度筛选也会继承模型自己的偏好与盲区。LAION 论文明确说明自动过滤并不完美；v1 模型卡也没有把训练材料描述成全部安全、去重或人工核验的数据。

<a id="evaluation-and-cost"></a>

## 8. 怎样判断它变好了？先把比较条件说完整

模型卡不是只摆几张漂亮图片。它记录了针对不同 checkpoint 和引导强度的比较：**从 COCO2017 验证集随机取 10,000 条提示词，生成 512×512 图像，使用 50 步 PLMS，并比较 1.5–8.0 范围内若干 CFG 强度。** 作者还注明，没有专门针对 FID 分数优化。[^card-eval]

这个设计说明：比较不能只写“v1.4 比 v1.2 好”，还应问——在哪个引导强度、用什么指标、采用什么采样程序？用户眼中的好看、文字符合程度和结果多样性，也不是一个指标能够全部回答的。

本文核对了评价设置，没有从未逐点核验的曲线里抄取精确分数，也不据此宣称某个 checkpoint 在所有强度下都占优。

### 训练成本与运行门槛，是两回事

模型卡记录的训练配置为 **32×8 张 A100**，使用梯度累积，整体 batch 为 **2048**。这是模型训练设置，不是“个人生成一张花照也需要这么多卡”。[^card-training]

官方 README 列出约 **8.6 亿参数的 U-Net** 和 **1.23 亿参数的文本编码器**，并写出参考实现至少 10GB 显存的运行条件。模型卡同时给出半精度和 attention slicing 等低显存建议。

这两份说明属于不同实现与设置，不能将一个数字当作今天所有设备、所有分辨率、所有优化方案的通用最低门槛。本章没有进行本机部署或速度测试，也不以“潜空间很小”直接推断任意设备都能实时生成。

<a id="editing-and-controls"></a>

## 9. 已有一张花照时，为什么还可以用它改图？

纯文生图从新噪声开始。图生图则可以先把已有图片编码进潜空间，再加一定程度的噪声，依据新提示词生成。

例如，你已有一张窗边花照，希望把红花改成另一种风格。起点不必完全丢掉原来的构图；可以保留部分信息，同时给模型重新生成的空间。

官方 README 将这种图像修改机制联系到 SDEdit，并提供 `strength` 参数：值越接近 1，加入的扰动越多，允许的变化越大，也越可能失去输入图原来的语义。[^img2img]

不要把它与 CFG 强度混成同一个旋钮：

- **图生图 strength** 调整从原图保留多少、扰动多少。
- **CFG scale** 调整采样时有条件与无条件预测如何组合。
- **采样步数** 调整生成过程怎样离散地走完。
- **随机种子** 控制随机选择的起点等因素。

它们共同影响结果，但作用位置不同。把所有不满意都归因于“提示词不够长”，往往找错了问题所在。

<a id="limits-and-history"></a>

## 10. 能画出花，不代表已经理解了所有关系

v1.4 模型卡对局限写得很直接：文字渲染不好，复杂组合关系容易出错，人脸与人体可能生成不当；英文之外的语言效果较弱，自编码过程也有信息损失。[^card-limits]

所以，“红色方块在蓝色球体上方”这样的指令，可能比“漂亮花照”更能暴露问题。前者要求属性与空间关系正确绑定；后者只要符合一类常见图像分布，就容易给人很强的视觉印象。

模型卡还承认没有采取额外的数据去重措施，并观察到重复训练图像的记忆。因此，不能因为生成从噪声开始，就断言它绝不可能重现训练材料。

安全检查和水印则属于另一层。官方参考程序包含生成后的安全检查，以及帮助识别机器生成内容的不可见水印；它们是附加防护，**不是“网络本身保证安全”，也不证明水印不可移除**。[^readme]

官方权重采用带用途限制的 CreativeML OpenRAIL-M 许可。README 说明可以在条款下商用，同时明确不建议在缺少额外安全措施时直接将权重投入服务或产品。这里依据模型卡与 README 说明边界，不替代许可证全文或具体法律判断。

<a id="three-questions"></a>

## 11. 思考与追问：三个问题，把整套系统串起来

**为什么 CLIP 能参与画图，却不等于 CLIP 自己会画图？**  
在 v1.4 里，它负责把文字变成可读取的条件；噪声预测、采样更新和图像解码由其他部件完成。

**为什么“50 步生成”和“最后只解码一次”不矛盾？**  
前面多步发生在潜空间里，结束后才把潜表示解码为像素图片；多步生成并没有变成一步。

**为什么提高 CFG 不能保证所有提示词都画对？**  
它调整已有有条件预测与无条件预测的组合，不会在推理时补做训练，也不能消除组合关系、数据偏差和有损表示等限制。
