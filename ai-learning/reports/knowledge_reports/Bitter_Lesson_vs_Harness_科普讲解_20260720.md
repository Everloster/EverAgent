# AI 越来越强，我们给它搭的「脚手架」会被自己淘汰吗？

> **这篇是什么**：用大白话讲清一个正在真实发生的争论——当大模型一年比一年强，我们辛辛苦苦在它外面搭的那套「手脚 + 流程 + 说明书」（学名 **Agent Harness / 智能体脚手架**），会不会像当年的手工棋谱一样，被 AI 自己变强给淘汰掉？背后那条 AI 70 年的铁律叫 **Bitter Lesson（苦涩的教训）**。读完你能回答：哪些脚手架会死、哪些反而活得最久、哪些不死反强，以及**怎么一眼判断**。
>
> **怎么读**：顺读最佳（15 分钟）｜ 赶时间只看每节开头的 `✦ 一句话` + 第五部分「一页纸」｜ 想看真实工业证据和原始引句，点开 `证据` 折叠块。
>
> **这是啥体裁**：科普版（建直觉、想通道理）。库里另有一篇同主题的**深度专业版**《Bitter_Lesson_vs_Agent_Harness_推演与网上观点审阅_20260707》，带完整生死表、五份网络观点逐条交叉审阅、可证伪信号——想要精确论证去读那篇，这篇负责帮你"想通"。

## 第一部分 · 先建立直觉：师傅、徒弟，和两个必须先懂的词

我们先立一套画面，全篇都用它，不换。

> 🧑‍🏫 **师傅 = 你（写 AI 系统的工程师）**
> 🧑‍🎓 **徒弟 = 大模型（Claude / GPT 这类"大脑"）**
>
> 徒弟天赋极高，但有个特点：**他一年比一年强，而且强得没有上限。** 今年还需要你手把手带，明年可能就自己会了，后年可能反过来嫌你教的招式绑手绑脚。

### 地基词①：Bitter Lesson（苦涩的教训）—— 徒弟终会超过师傅的经验

`✦ 一句话：AI 70 年的历史反复证明——"人把经验一条条教给机器"短期有用，但长期一定输给"给机器足够算力、让它自己学"。`

拿教下棋打比方，教电脑下棋历来有两条路：

- **A 路（灌经验）**：请象棋大师把毕生心得——"当头炮怎么应""这种局面该跳马"——一条条写成规则塞进去。
- **B 路（给算力）**：只告诉电脑规则，然后给它海量算力，让它自己狂算几亿盘、自己悟出门道。

历史一次次上演同一幕：**A 路开局领先，B 路后来居上，最终把 A 路碾死。** 因为人的经验有限、会过时、还带偏见；而算力年年翻倍、机器自己学出来的东西**没有天花板**。图像识别当年靠工程师手工设计特征（叫 SIFT），风光一时，后来被"让神经网络自己学特征"彻底取代——同一个剧本。

这教训之所以"**苦涩**"，是因为 AI 研究者总不甘心，总忍不住把自己的聪明才智塞进系统，然后一次次被"通用方法 + 傻堆算力"打脸。提出者 Richard Sutton 的原话是——

<details>
<summary>证据：Sutton《The Bitter Lesson》原句（2019，逐字核对）</summary>

- 核心命题：*"The biggest lesson that can be read from 70 years of AI research is that **general methods that leverage computation are the most effective, and by a large margin**."*
- 哪两种方法能一直随算力放大？*"The two methods that seem to scale arbitrarily in this way are **search and learning**."*（**搜索** 和 **学习**——记住这两个词，后面判"谁不死"全靠它）
- 引句经 WebSearch 多来源交叉核对（sungeuns.github.io、stampy.ai、komazawa PDF 转载一致），核实日期 2026-07-20，消除原深度报告中的 `[转引]` 标注。原文站点 incompleteideas.net 为纯 HTTP，本地 WebFetch 因强制 HTTPS 升级抓取失败，故走 WebSearch 兜底。
</details>

### 地基词②：Agent Harness（智能体脚手架）—— 师傅给徒弟立的规矩和流程

`✦ 一句话：光有个大模型只是"会聊天的大脑"；要让它真干活，得在外面套一层"手脚 + 流程 + 说明书 + 护栏"，这层就叫 harness。`

一个裸的大模型，其实只会一件事：**你问一句，它答一句。** 它没有手、没有脚、记不住昨天、也不会自己去查文件。

你想让徒弟真正"上工"——自动改代码、上网查资料、操作文件、连续干好几步——就得给他配一整套东西：

- 一份**操作手册**："接到任务先读相关文件，再动手改，改完先跑测试，最后才提交"；
- 一堆**工具**：能读文件的手、能跑命令的脚、能上网的眼睛；
- 一条条**护栏**："绝对不许直接推送到主分支""删文件前必须先确认"；
- 一个**记事本**：把干过的事记下来，免得转头就忘。

这套外挂装备就是 harness（原意是套在马身上、让马能拉车干活的**挽具**）。

> 💡 **你现在用的这个 TRAE CLI，本身就是一套 harness。** 它就是那套让"会聊天的大脑"变成"能改你代码的助理"的手脚和规矩。

## 第二部分 · 跟着一个任务走一遍

`✦ 一句话：用"AI 助理帮你修一个 bug 并提交"这一个任务，看清 harness 里到底装了哪些零件——这些零件后面会一个个上"生死台"。`

假设你雇了这位徒弟当 **AI 编码助理**，丢给他一个任务：**"帮我修复登录页的这个 bug，然后提交。"**

在 harness 的操持下，他是这么干的：

```
① 操作手册说："先读代码" → 他去读了登录相关的几个文件
② 操作手册说："再动手改"   → 他改了那段有问题的逻辑
③ 操作手册说："改完先测"   → 他跑了测试，绿了
④ 护栏拦了一道："可以 commit，但绝不许 push 到主分支" → 他只本地提交，停手等你
⑤ 记事本记下："这次修 bug，测试一次过" → 供下次参考、也供系统复盘
```

这五步里，藏着 harness 的**四类不同零件**：

| 零件 | 在上面第几步 | 它的本质 |
|------|------------|---------|
| **写死的操作手册**（先读→再改→再测→再交） | ①②③ | 人替徒弟规定"该怎么做题" |
| **写死的护栏**（绝不许 push 主分支） | ④ | 一条不容商量的安全红线 |
| **工具**（读文件、跑测试的手脚） | 贯穿全程 | 徒弟够不到的外部接口 |
| **复盘/记事本**（记录 + 供系统自我改进） | ⑤ | 让这套流程自己越变越好的机制 |

**关键问题来了**：当徒弟明年强到"不用你教就知道该先读后改、测试哪里跑"，上面这四类零件——**哪些会变成累赘被扔掉，哪些反而更重要？**

## 第三部分 · 上生死台：哪些会死，哪些能活（核心）

`✦ 一句话：结论不是"harness 整个会死"或"整个会活"，而是它内部被重新分了一次生死——按一条极简的判据。`

先把那条判据亮出来，它是整篇的钥匙：

> 🔑 **判据**：这个零件是在编码"**人觉得该怎么做题**"，还是在提供"**徒弟再聪明也绕不开的接口 / 保证**"？
> —— 前者会被淘汰，后者淘汰不掉。

拿它去量第二部分那四类零件：

### ☠️ 会死：写死的操作手册、固定流程、固定分工

`✦ 一句话：你替徒弟想好的"标准做题步骤"，正是他变强后第一个想扔的东西。`

"先读→再改→再测"这种写死的剧本，本质是**你在替徒弟规划思路**。徒弟弱的时候这是救命的拐杖；徒弟强了，这就是绑手绑脚——他可能有更聪明的顺序，却被你的剧本锁死。

这不是空想，是工业界已经踩出来的坑：

<details>
<summary>证据：三个真实的"淘汰现场"（工程复盘 [网络观点]）</summary>

- **PostHog**（一年做生产 agent 的复盘）：GPT-4o 时代"必须"加的流程编排图，如今用**单个模型循环反而更可靠**——原话 *"agents beat workflows"*，"本来为了提高可靠性而加的架构，实际上降低了可靠性"。
- **Tavily**：七个月后**整个推翻**第一版精心设计的研究架构——"当时觉得又精巧又聪明，还以为这是好事，结果下一代模型一来，这些假设全成了瓶颈"。改用极简做法后 token 砍掉 **66%** 还刷到 SOTA。
- **为老模型写的容错代码**（比如给格式不稳的旧模型套的重试 / 兜底解析器）：新模型一来直接成 *"dead weight"*（死重量）——教科书级的 Bitter Lesson。
- 来源：DevDash Labs《Context Engineering and the Bitter Lesson》转述 PostHog / Tavily 复盘，2026-02。标 [网络观点]，是他人主张非定论；三家结论互相独立印证。
</details>

同理，"把任务写死拆成三步""安排几个固定分工的子助理各管一摊"——都是**进口了人类组织的局限**，都在这一类，都会慢慢死。

### 🛡️ 活最久：安全红线、确定性护栏

`✦ 一句话：护栏活下来，不是因为徒弟学不会，而是因为"绝对不出错"本身就是需求——而聪明只能给你"几乎不出错"。`

"绝不许 push 到主分支""这笔转账必须双人复核才放行"——这类护栏为什么淘汰不掉？

这里有个特别反直觉、但特别关键的点：

> **聪明的徒弟给你的是"概率"（99.9% 不会闯祸）；护栏给你的是"保证"（结构上就闯不了祸，0%）。**
> 在高风险场景——法律、金融、删库、转账——你要的不是"几乎不出错的天才"，而是"**不可能出错的闸门**"。这两者永远不能互相替代。

所以护栏躲过镰刀，**不是靠"能力缺口"（模型学不会），而是靠"需求类型"（确定性本身就是产品要的东西）**。镰刀只砍"填补能力缺口的东西"，砍不到"保证型需求"。

有个绝妙的活体标本：有位工程师写文章说"提示词工程已死"，把给 AI 的说明书从几百行砍到**只剩三行**——可他砍不掉的其中一行，正是 `never git push`（绝不许推送）这条硬护栏。他一边宣告"教怎么做题的都没用了"，一边亲手留下了那条安全红线。

<details>
<summary>证据：CLAUDE.md 砍到三行的活标本 [网络观点]</summary>

- blog.exe.dev / ClawdBytes《Prompt Engineering Is Dead》（2026-05-23）：作者的 CLAUDE.md 只剩三行——一条硬规则 `never git push`、一条操作偏好、一条元指令，其余全靠信任模型。金句 *"Goals are durable, orders are brittle."*（目标耐久，命令易碎。）
- 它同时印证了两件事：①"教怎么做题"的长篇提示词确实在死；② 但那条 `never git push` 硬护栏砍不掉——正是"确定性护栏活最久"的活标本。
</details>

> ⚠️ 有个细节别记错：**不是所有"写死的代码"都活。** 只有"安全红线 / 极简自强化"这种活；那种"专门补模型某个短板"的代码（比如给旧模型擦屁股的重试逻辑），照死不误——因为它填的正是"会被 scaling 填平的能力缺口"。判据永远是那句钥匙，不是"代码 vs 提示词"。

### ✅ 不死反强：让 harness 自己进化的那套循环

`✦ 一句话：让系统自己复盘、自己搜索更优配置的那套机制，不但不死，还越用越猛——因为它就是 Bitter Lesson 亲自盖章的"搜索"。`

回到第二部分第 ⑤ 步那个"记事本 + 复盘"。如果你把它升级成一套**自动循环**：让系统自己试不同的流程配置、自己打分、自己留下好的淘汰差的——

这东西为什么不死反强？因为还记得地基词①里 Sutton 钦点的两大永动方法吗——**搜索（search）和学习（learning）**。"让 harness 自己进化"这个动作，**本身就是搜索**。它不是 Bitter Lesson 的反例，它是 Bitter Lesson 在 2026 年新长出来的一只手。

而且有硬数字：有个实验**完全不动模型**（徒弟冻结不变），只让外层 harness 自己进化，就把一个法律基准从 **63.4% 干到 80.1%**——证明"进化这个过程"本身是巨大的、独立于模型变强的杠杆。

<details>
<summary>证据：冻结模型、只进化 harness 的一手数字</summary>

- 来源：本库报告 46《不要训模型，进化 Harness》（Niklaus 2026 一手实测，已核验）。冻结模型、仅进化外层 harness，法律基准 63.4% → 80.1%。
- 有意思的微观信号：同一个实验内部，**提示词部分（教怎么做题）换个模型家族就失效**，而**代码部分（护栏/接口）能跨家族迁移**——"会死的知识层"和"能活的底座层"，在一篇实验里就当场裂开了。
</details>

## 第四部分 · 其实有"两把镰刀"，不是一把

`✦ 一句话：淘汰 harness 的力量有两股——一股是"模型自己变强"，另一股常被忽略："整个世界正在改造成模型好用的样子"。`

大多数人以为，削 harness 的只有"模型变强"这一把镰刀。其实有两把在同时砍：

- **镰刀一 · 模型变强**（经典 Bitter Lesson）：徒弟自己把当年的短板补上了，你替他填坑的东西自然作废。
- **镰刀二 · 世界改造**（生态迁移）：越来越多的工具、网站、接口主动改成"AI 友好"的样子（比如 MCP 这类给模型量身定做的协议）。**不是徒弟变聪明了，而是外部世界主动改成了他顺手的形状**——于是那些"胶水层""适配层"harness 从另一头被溶掉。

两把镰刀都躲得过的，只剩前面说的两样：**进化循环**（搜索，Sutton 祝福）和**安全护栏**（确定性是刚需）。

> 把"两把镰刀"单独拎出来，是原深度报告相对原创的一个拆分——网上多数讨论只盯着镰刀一。

## 第五部分 · 装进脑子

### 🗺️ 一页纸心智模型

```
        Bitter Lesson（算力+通用方法长期必胜）
                     │  决定「天花板有多高」
                     ▼
   ┌──────────  Agent Harness（脚手架）──────────┐
   │  决定「你离天花板有多近」                      │
   │                                              │
   │   ☠️ 知识层：写死的操作手册 / 固定流程 / 固定分工   │ ← 被镰刀吃掉，随模型变强而变薄
   │      "人替徒弟想好该怎么做题"                    │
   │                                              │
   │   🛡️ 底座层：安全护栏 / 工具接口 / 极简自强化工具   │ ← 薄薄一层，砍不到底
   │      "徒弟再聪明也绕不开的保证/接口"              │
   └──────────────────────────────────────────────┘
                     │
                     ▼
        ✅ 进化循环（搜索本身）——"够到天花板"这个动作
           不死反强；人退到"设计怎么复盘、怎么打分"

     两把镰刀：① 模型变强   ② 世界改成 AI 友好（生态）
     一把祝福：进化循环（= Sutton 钦点的 search）
```

### 📌 五句话总纲（能背下来就够）

1. **Bitter Lesson**：教机器"人的经验"短期赢、长期一定输给"给算力让它自己学"。
2. **Harness**：给"只会聊天的大脑"套上手脚+流程+护栏，它才能真干活（TRAE CLI 就是）。
3. **冲突**：harness 里"教怎么做题"的部分，正是 Bitter Lesson 判死刑的那种东西。
4. **生死判据一句话**：编码"人觉得该怎么做题"的 → 死；提供"再聪明也绕不开的接口/保证"的 → 活。
5. **结局不是归零，是换性质**：工程量从"写死规则"搬到了"设计进化循环 + 守住安全护栏"。

### 🚧 直觉陷阱表

| 你可能的想当然 | 真相 |
|--------------|------|
| "Bitter Lesson 说人工没用，那 harness 整个会死" | 不。是 harness **内部**分生死：知识层死、底座层活、进化循环不死反强 |
| "提示词工程已死 = 脚手架工程已死" | 标题党滑坡。死的是"教怎么做题"的 how 层；"要什么"的 what 层和护栏在活 |
| "只要代码写死的就耐久" | 错。补模型短板的写死代码照死；只有安全护栏 / 极简自强化的写死代码才活 |
| "进化 harness 是 Bitter Lesson 的反例" | 反了。它**就是** Sutton 钦点的"搜索"，是 Bitter Lesson 的亲儿子 |
| "淘汰 harness 只靠模型变强" | 还有第二把镰刀：世界主动改成 AI 友好（生态迁移）从另一头溶掉胶水层 |

## 💭 思考与追问

1. **我真正理解了什么？**
   Bitter Lesson 和"搭 harness"不是矛盾，而是**嵌套**：算力定天花板、harness 定你离天花板多近、进化循环是"够上去"这个动作本身。一条钥匙判生死——"在编码'人觉得该怎么做题'（死），还是在提供'再聪明也绕不开的接口/保证'（活）"。所以工程师的活不会消失，只是从"写死规则"换成了"设计进化循环 + 守住安全护栏"。

2. **我还没搞懂什么？**（已在深度版汇入 open-questions，此处不重复登记）
   - "能力缺口填补物 vs 保证型需求"能不能**事前**判定？——同样是写死的代码，`todo_write`（活）和 JSON 重试（死）事后好解释，但有没有事前判据预测哪段会老化成累赘？
   - 两把镰刀谁更快？模型变强 vs 生态标准化，谁先削平 harness，决定了 harness 是"被吸收"还是"被标准化"消失。

3. **下一步做什么？**
   - 收一次这篇的**学习反馈**（见文末），决定"科普版重写库存深度稿"这条路要不要继续走。
   - 若想动手：在 `ai-practice/` 做个跨代模型对照小实验——同一套 harness 在弱/强模型上各跑一遍，量"harness 增量随模型变强而缩小"这条可证伪信号，把推演变实测。
