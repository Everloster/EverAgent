# 《Agent 演义》10｜T3：项目、worktree 与项目动作

## 概述

T3 的 Project 指向环境中的代码目录，thread 可以在原 checkout 或独立 worktree 中工作。项目动作把测试、开发服务和准备步骤放到可重复使用的入口；`t3.json` 则让这些约定随仓库一起保存。[^projects][^actions]

专业用户应先决定哪些任务共享现场、哪些需要独立分支，再把准备和验证命令整理成项目动作。多仓项目还要明确各仓的关系与实际修改位置。

**提炼句：** 项目配置的价值，是让下一次开工仍然落在正确的现场与命令上。

## 取景框 f(x)

**x｜问题：** 怎样让不同 thread 和 Agent 打开同一个项目时，得到可工作的现场？

**f｜取景框：** 把代码位置、工作区隔离和重复动作一起设计。

**f(x)｜判断变化：** 不只保存一段任务提示，还保存准备、测试和预览的具体入口，并核对覆盖设置。

## 什么时候新建 worktree

短任务或只读调查可以使用当前 checkout。需要独立改动、不同实现路线或并行服务时，选择 New worktree。共享 checkout 的 thread 共享分支；T3 会协调分支切换与运行状态，不能把两个 thread 名称当成两份独立代码。[^threads]

Card Gallery 的 API 和界面可以分工，但最终集成应有一个明确版本。各 worker 测试通过后，把改动整合到目标现场，再运行联合验收。

## 把常用命令放进项目动作

下面是针对自拟项目的 `t3.json` 示例，语法依据用户指南：

```json
{
  "$schema": "https://t3.codes/schema/t3.json",
  "defaultThreadEnvMode": "worktree",
  "scripts": [
    {"name": "Test", "command": "python3 -m unittest discover -s tests -v", "icon": "test"},
    {"name": "Dev", "command": "python3 api/server.py --port 4188", "icon": "play", "previewUrl": "http://localhost:4188", "autoOpenPreview": true, "stopOnSettle": true}
  ]
}
```

在 Settings → Projects → Actions 中导入或配置动作，再从项目／线程入口执行。Dev 的自动预览有桌面平台条件；测试命令仍要确认实际 cwd。多个现场同时运行时，给服务不同端口，不要让所有 Dev 动作争用 4188。[^actions]

## 准备动作应等待什么

需要安装依赖的项目可以配置 worktree 创建时的动作。`runOnWorktreeCreate` 与 `async` 决定是否启动准备，以及 Agent 是否等待准备结束。

需要依赖才能运行测试时，等待准备完成更清楚；能独立推进的调查可以与准备并行。权限较低的 Agent 创建工作区时，某些自动脚本会被跳过，不能把脚本存在当成已经执行。

本卷示例没有第三方依赖，所以先用 Test 和 Dev 两个动作即可。加入动作后检查终端输出、服务端口与完成状态，而不是只看按钮点过。

## 为什么项目设置改了却不生效

T3 的部分设置按照 Project override → Environment setting → `t3.json` → Built-in default 取值。仓库配置不是最高优先级。[^projects]

在 Settings 顶部确认正在编辑哪个 environment、哪个 project；使用继承链入口查看覆盖。设备偏好、服务器设置和项目覆盖又各有范围。修改浏览器 A 的偏好，不会自然变成所有设备的统一默认。

| 想保存的约定 | 放在哪里更合适 | 核对什么 |
|---|---|---|
| 仓库通用测试与开发命令 | `t3.json` | 路径、依赖、平台条件 |
| 某个项目的执行习惯 | Project override | 是否覆盖仓库默认 |
| 这台主机的路径与环境 | Environment settings | 代码与工具属于哪台机器 |
| 个人界面与快捷键 | Device preferences | 换设备后是否另需设置 |

## 多仓与清理怎么安排

多仓项目适合前后端分仓、共享父目录或含外部依赖的工作。先确认项目根目录和实际仓列表，查看 diff 时选择正确 repository。项目父目录的 `t3.json` 与嵌套仓配置有不同读取范围，不能假定所有子仓配置都自动生效。[^multi]

worktree cleanup 与 thread Settle／Archive 不同。配置清理前检查对活跃 session、共享目录、未提交与 ignored 文件的保护条件。重要的本地准备材料也要纳入自己的现场管理方式，不能只因“已提交代码”就认为目录可随时删除。

这章的验收是你下一次开 thread 时，能找到正确仓、运行正确命令、打开正确服务；产品动作减少重复设置，不替代实际结果检查。
