# AI演义·06 seq2seq 与 Attention：模型怎样翻译一句话？

> 本篇展开[《AI演义》主报告的第 6 节](../AI演义_笔记分析与项目整合报告.md#paper-seq2seq)，可以单独阅读。主要对照讲义第 12 页、播客约 33:50–46:30 的讲述，以及 Sutskever 等人的 seq2seq 论文和 Bahdanau 等人的 Attention 论文。[^podcast]

把 **The black cat is sleeping.** 翻成法语，可以写成 **Le chat noir dort.**，意思是“黑猫正在睡觉”。

我们看得懂这两句话，并不意味着翻译只是查词典：英文里 black 在 cat 前面，法文里 noir 在 chat 后面；英文的 is sleeping，在这里由一个法文动词 dort 表达。程序既要保留“谁在做什么”，又要按另一种语言的顺序，把长短不同的句子写出来。

这一节围绕这句自拟例子，讲清两项改变：**seq2seq 用一个网络读入原句，再用另一个网络逐词生成译文；Attention 让生成过程能够反复读取原句各处的信息。** 前者把变长输入与输出连接起来，后者改变了信息怎样交到生成器手里。

两篇论文的贡献可以按这个顺序理解，发表时间却不是这个顺序。它们是 2014 年同一研究环境中的不同探索，后文会把实际时间和实验结果分开核对。

<a id="translation-problem"></a>

## 1. 翻译里，藏着不止一个预测问题

先想想上一节的 Word2Vec。它能把词变成可学习的数值表示，让不同词的用法变得可以比较。但即使已经知道 black、cat、sleeping 各自对应什么词，模型仍然没有完成翻译。

它还要处理三件事。

**输入和输出可以长短不同。** 读了几个英文词，不规定必须写出同样数量的法文词。生成过程需要自己决定何时结束。

**对应关系不一定从左到右。** 在这个例子里，模型写完 chat 后才写 noir，相当于先处理“猫”，再回到前面的“黑”。遇到更复杂的句子，还会出现更远的重排。

**一个词的译法依赖周围。** is sleeping 在此表达一个整体；单独逐词替换，很难得到合适的法语句子。前面的信息必须影响后面的选择。

当时常见的**统计机器翻译，SMT**，会把短语翻译、目标语言是否通顺、词序调整等因素组合起来，再搜索较好的译文。它并不是“没有学习、全靠人写规则”，其中也有从语料估计的模型；复杂之处在于许多部件与特征需要分别设计、训练和配合。两篇论文提出的方向，是让一个整体可训练的神经系统，直接从源句生成译文。[^background]

这里也要纠正口播中的一个简化：传统固定尺寸网络的问题，不是“五个词进去，就必须五个词出来”。**固定维度描述的是计算接口或表示的大小，并不等于输入与输出的词数必须相等。** 真正要处理的是：怎样用共享的计算过程，接收未知长度的输入，并生成另一个未知长度的序列？

<a id="encoder-decoder"></a>

## 2. seq2seq：先把原句读进去，再把译文写出来

Sutskever、Vinyals 与 Le 的方案，使用两套 **LSTM，长短期记忆网络**：一套负责读原句，叫**编码器**；另一套负责写译文，叫**解码器**。两者共同训练，但不是同一套参数。[^seq2seq-model]

### 编码器读的，不是一本事先写好的词义词典

每个输入词先变成一组数值，即词的嵌入表示。循环网络读取当前词时，还会接收上一步传来的**隐状态**，据此算出新状态。这里的隐状态，可以先理解为“到目前为止，网络形成的内部表示”。

读到 The，有一个状态；再读 black，这个状态发生变化；读到 cat 时，新的状态已经受到前面词语的影响。**同一套网络参数，在不同位置反复使用。** 句子变长，主要是多执行几步，而不是临时给每个词造一套全新的模型。

普通循环网络沿很多步传递信息时，训练可能很困难。LSTM 在内部增加了记忆与可学习的控制，让信息有机会较久地保留，也能在需要时更新。可以把它想成会不断修订的工作笔记；不过这份“笔记”是一组数值，不是网络藏起来写好的一段中文摘要。

读完原句后，编码器把最终的内部表示交给解码器。它的大小由模型结构决定，不随着当前句子长度不断加宽。原论文实际采用四层 LSTM，并用 8,000 个实数表示一句话；这说的是内部状态规模，不是“可以记住 8,000 个单词”。[^seq2seq-model]

### 解码器每次只接着写一步

假设这个自拟例子的模型已经学会正确翻译。解码器拿到原句的表示，先给法文词表里的候选词计算概率。选出 Le 后，把它作为已经写出的前文，再预测下一个词，继续得到 chat、noir、dort，最后输出结束标记 **EOS**。

EOS 不是句号的同义词，而是告诉生成过程“这个序列结束了”的特殊符号。模型因此能够生成长短不同的译文，不需要提前知道答案有几个词。

这一过程叫**自回归生成**：前面已经生成的内容，参与后面的预测。整个句子的概率由这些逐步的条件概率共同决定；不是模型先在内部拿到完整法文答案，再把它一个词一个词显示出来。[^seq2seq-model]

这个最初方案中，解码器拿到的是一次性交接的整句表示。它的内部状态之后会继续变化，但没有一条额外的通道，让它在每一步重新读取源句各位置的编码结果。这正是后面 Attention 要改变的地方。

<a id="training-and-search"></a>

## 3. 训练时有正确前文，使用时怎么办

网络不是只看英文，便自动知道对应法文。两篇论文使用的是**平行语料**：大量相互对应的源句与译句。它们通过提高正确译文的条件概率，联合调整编码器、解码器和词表示等参数。[^training]

仍用黑猫这个例子。训练到预测 noir 的一步时，模型可以看到正确前文 Le chat，然后检查自己给 noir 多大的概率。预测反馈沿着计算过程传回去，让那些有助于翻译的参数得到调整。训练并不需要人给每个隐状态标注“这里必须记住黑色”，也不需要把中间表示写成人类语言。

这种训练方式通常称为 **teacher forcing，使用正确前文训练**。到了实际翻译时，正确译文还不存在，模型只能接着自己已经生成的词往下写。因此，训练中看到好前文，并不保证使用时永远不会走错。一次选择可能改变后面整条生成路径。

作者使用 **beam search，束搜索**，减少只走一条路的风险。可以把它理解为：每一步暂时保留少量较好的译文前缀，让它们各自继续生长，再留下累计得分较好的候选。

例如，一个候选已经写成 Le chat，另一个写成 Le petit。搜索会让它们分别尝试后续词，而不是把不同候选的前文混到同一句里。每条候选还要保留自己的解码状态。碰到 EOS，才把该候选收为完整译文。例子只说明搜索方式，并非论文的实际输出。[^search]

束搜索是近似搜索。它不能保证找出所有可能译文中得分最高的一句，更不能保证模型认为高概率的译文一定符合原意。**模型学到了什么，与搜索怎样使用模型，是两个有关但不同的问题。**

这也解释了为什么“端到端”不等于没有工程选择。人仍要准备平行语料、确定词表与网络、选择训练和搜索方法；变化在于许多中间部件可以受同一个翻译目标共同训练。

## 4. 为什么把英文倒着读，反而更好

Sutskever 等人采用了一个初看奇怪的办法：**把源句的词序倒过来，目标句仍按正常顺序生成。** 实际模型的编码顺序因此与前面为方便理解而使用的正常阅读顺序不同。[^reverse]

忽略标点，示意就是：

- 原来的输入：The → black → cat → is → sleeping
- 倒序后的输入：sleeping → is → cat → black → The
- 输出仍然是：Le → chat → noir → dort

为什么这有帮助？编码和解码接在一条时间链上时，如果按正常顺序读入，最早的英文词必须经过后面许多输入步骤，才等到最早的法文词开始生成。倒序后，The 靠近输入结束的位置，也就更接近最先要生成的 Le。

作者认为，这会制造更多较短的依赖，让训练更容易在部分源词与目标词之间建立联系。**它并没有缩短所有对应关系的距离；论文明确说，对应词之间的平均距离没有因此改变，也没有给出这一现象的完整解释。**[^reverse]

在表 1 的单模型对照中，正常源词序的 LSTM 得到 **26.17 BLEU**，源句倒序的模型得到 **30.59 BLEU**，两者都使用宽度为 12 的束搜索。倒序是这项工作的实际贡献之一，不能把成绩只归于“换成了 LSTM”。

它还有一个值得保留的反例意义：**固定规模的整句表示，并不意味着句子一长就必然失败。** 这篇论文的倒序模型在长句上表现良好；图 3 的图注称，少于 35 词的句子没有出现性能退化，最长句只有较小退化。这是该模型与测试集的结果，不是任意长文本都能被无损保存的保证。[^seq2seq-long]

所以，把 Attention 的动机讲成“所有固定向量模型遇到长句都不能用”，反而会遮掉同期研究的重要证据。

<a id="attention-step"></a>

## 5. Attention：译到这里，该回看原句哪里

即便一个整句表示能够工作，研究者仍然可以问：生成 Le、chat、noir、dort 时，要用的信息不同，为什么只能在开头交接一次？

Bahdanau、Cho 与 Bengio 的方案，保留源句每个位置的表示，让解码器在生成过程中重新读取它们。论文把模型称为 **RNNsearch**。这里的 search 指在已经编码的源句中计算软对齐，不是搜索互联网，也不是另建一个文档检索系统。[^attention-model]

### 先给每个位置留下带上下文的表示

编码器采用**双向循环网络**：一条从左往右读，另一条从右往左读。再把同一个位置的两份状态拼接起来，得到论文所说的 **annotation，源位置表示**。

例如 black 的 annotation，既受到 The 的影响，也受到后面 cat、is sleeping 的影响。它不是孤立单词 black 的那一行词向量；它是网络读过这句话之后，为这个位置计算出的表示。

这样，源句有多少个位置，就可以留下多少份表示。每份表示的维度仍然固定，但保存的份数随输入长度变化。**取消的是“整句话只能挤进一次交接”的约束，不是从此不再使用固定维度向量。**[^attention-model]

双向读取也意味着：这套论文模型先取得完整源句，再进行这样的编码和翻译。不能因为有 Attention，就把它描述成无需后文的实时同声传译系统。

### 到每一个目标步，重新决定怎样汇总

现在假设模型已经生成 Le chat，准备接着写。以下是用于理解机制的理想化过程，并非真实模型对这句话的测量结果。

1. **带着当前进度去打分。** 模型用上一步的解码状态，分别与源句各位置的 annotation 计算匹配分数。
2. **把分数变成一组权重。** softmax 把这些分数归一化，让各位置权重非负、合计为 1。
3. **按权重汇总源信息。** 把每份 annotation 乘上对应权重，再相加，得到这一步的 **context vector，上下文向量**。
4. **继续生成并更新状态。** 当前上下文向量与已经生成的前文一起，参与下一个词的预测和解码状态更新。下一步又重新计算权重。[^attention-model]

“加权相加”可以用一个小算例看清。暂时只考虑两个源位置，假设它们的表示是 `[1, 0]` 与 `[0, 2]`，这一步的权重为 0.75 和 0.25，那么上下文向量就是：

```text
0.75 × [1, 0] + 0.25 × [0, 2] = [0.75, 0.5]
```

它不是把两个位置选一个留下，而是按当前比例混合信息。下一步权重变化，混合结果也可以变化。这是**自拟的两位置算术演示**，不是黑猫例子的真实模型输出；向量的两个分量也不代表人为指定的两个词义。[^attention-model]

回到黑猫的翻译例子，如果训练使模型学会了合适的读取方式，准备生成 noir 时，就可能更多使用 black 附近的信息；之后生成 dort 时，又可以转向 is sleeping 附近。

这里有一个关键先后关系：**打分时，模型还不知道下一个词一定是 noir。** 它依据已经存在的解码状态与源句表示，决定怎样读取，再据此预测词。不能解释成先把正确目标词拿出来，与原句逐词比较，这会把尚未产生的答案偷偷放进算法。

权重也不要求只选中一个词。它可以同时照顾几个位置；目标语言的一词对应源语言的多词，或者词序发生变化，都可以通过不同的软权重表达。论文因此称它为 **soft alignment，软对齐**。

### 三个容易混在一起的东西

| 名称 | 在这套模型里是什么 | 作用 |
|---|---|---|
| 源位置表示 annotation | 为源句某个位置算出的一组数，已经包含上下文信息 | 提供可读取的源信息 |
| 注意力权重 | 当前目标步分配给各源位置的比例 | 决定这次怎样汇总 |
| 上下文向量 context vector | 按这组比例加权相加后得到的一组数 | 把这次汇总的源信息送给解码器 |

解码器自己的隐状态则记录生成过程中的内部状态。它与表中的三个对象相互作用，也不能简单叫作同一个“注意力”。

还有一个实现细节值得分清：Sutskever 那篇使用 LSTM；Bahdanau 这篇实验使用 Cho 等人提出的门控循环单元，即通常归入 **GRU** 的结构。两者都属于带记忆控制的循环网络，但不能把这里的模型统称为“加了 Attention 的 LSTM”。[^attention-implementation]

<a id="learn-alignment"></a>

## 6. 没有人标出“黑对应 noir”，它怎样学会对齐

如果必须先请人给所有句子逐词连线，才能使用 Attention，工作量会很大。Bahdanau 的方案不要求这种人工逐词对齐标签。

它仍然依靠源句与正确译句组成的训练数据。假如训练到应该输出 noir 的一步，当前读取方式却使这个词的预测很差，翻译损失就会把反馈传回生成部分，也传回权重计算和编码部分。随着许多句子反复训练，**能帮助正确翻译的读取方式，有机会被共同学出来。**[^alignment-training]

这里之所以使用柔和的权重与加权和，一个重要原因是这些计算可以传递梯度。若直接做不可微的“只挑某一个位置”，训练方式就要另外处理。原论文把对齐模型设计成一个小型前馈网络，用上一步解码状态和源位置表示计算分数；它的参数也随整个系统一起更新。

但这个过程不保证每一行权重都对应人类心中的标准词语连线。训练目标首先是提高正确译文的概率，annotation 本身又包含周围词的信息，所以某个位置权重较高，并不能证明最终词义只来自那个孤立单词。

论文的图 3 把权重画成灰度矩阵：横轴是英文源词，纵轴是生成的法文词，越亮代表权重越大。图中既有沿对角线的对应，也有形容词、名词的顺序交换，以及多个源位置共同参与的情形。作者还说明，四幅图里后三幅从无未知词、长度在 10–20 词之间的测试句中抽取。[^alignment-figure]

这些图让“译到哪里，主要读取哪里”变得可以观察。它们提供的是模型行为的定性线索，不是对全部测试集的对齐准确率评测，也不是完整的因果解释。

注意，**Attention 的读取与束搜索不是同一个搜索**。前者在一条候选译文内部，决定怎样汇总源句信息；后者在多条候选译文之间，决定保留哪些生成路径。Bahdanau 模型也会用束搜索生成译文，两者可以一起工作。

<a id="experiments"></a>

## 7. 两篇论文，究竟取得了什么成绩

两篇都用英法翻译检验方法，但不能把摘要里的好消息合成“两篇都全面击败当时所有翻译系统”。模型数量、词表、训练时长与评分范围，都影响结果。

**BLEU** 是把机器译文与参考译文比较得到的自动评价分数。它检查单词及连续词片段有多少能匹配参考，对重复匹配设上限，再对过短的译文施加惩罚；否则，反复输出一个常见词，或者只译出很短的一截，都可能钻评价的空子。它主要用于整批译文的比较，不是逐句判断对错，所以 **34.81 BLEU 不表示“34.81% 的句子翻译正确”**。[^bleu]

这里通常是分数越高越好，但分词、大小写与评分脚本也会影响结果，跨论文比较必须保留口径。[^seq2seq-results]

### seq2seq：最好结果来自五个模型一起判断

Sutskever 等人使用 WMT’14 英法数据中的约 **1,200 万句对**，包含约 3.04 亿英文词与 3.48 亿法文词。源语言词表为 16 万，目标语言词表为 8 万；不在词表中的词统一映射为 UNK，即未知词标记。下表采用论文表 1，以及表 2 对最佳 WMT 系统按同一脚本重算的口径。[^seq2seq-results]

| 直接生成译文的方法 | 比较条件 | 测试 BLEU |
|---|---|---:|
| 单个 LSTM，正常源词序 | 束宽 12 | 26.17 |
| 单个 LSTM，倒序源句 | 束宽 12 | 30.59 |
| 五个倒序 LSTM 集成 | 束宽 2 | 34.50 |
| 五个倒序 LSTM 集成 | 束宽 12 | 34.81 |
| 论文的短语统计翻译基线 | 同一测试与评分口径 | 33.30 |
| 该论文按同脚本重算的最佳 WMT’14 系统 | 供当时水平参照 | 37.0 |

因此，**超过 33.30 基线的是五模型集成，单个倒序模型的 30.59 还没有超过它**；34.81 也没有超过表中的 37.0。多模型集成让若干独立训练的模型共同参与预测，不能写成某一个 LSTM 的单独成绩。

论文还报告 **36.5 BLEU**，但那是另一项实验：先由统计翻译基线给出 1,000 个候选，神经模型再参与重排。它仍然依赖统计系统产生候选，不能与纯神经直接生成的 34.81 混成同一结果。[^seq2seq-results]

这些成绩也不是只靠一句漂亮的网络描述。单个模型约有 **3.84 亿参数**；作者把四层 LSTM 分到四张 GPU，另四张负责大词表输出计算。该实现训练约需十天。模型能力、词表成本、搜索与并行工程，共同决定了当时能做多大的实验。[^seq2seq-engineering]

### Attention：长句更稳，不等于完整测试集已经最好

Bahdanau 等人同样使用 WMT’14 英法平行语料，筛选后约 3.48 亿词，没有另用单语料。每种语言的词表只有 **3 万词**；测试集为 **3,003 个句子**。他们比较基本编码器—解码器 RNNencdec 与带 Attention 的 RNNsearch，并分别用长度不超过 30 或 50 词的训练句子训练模型。[^attention-results]

下面摘出表 1 中“训练长度上限为 50”的结果。名称中的 50 是训练数据的长度上限，不能理解成模型在测试时只能接收 50 个词。

| 模型 | 全部测试句 BLEU | 无未知词子集 BLEU |
|---|---:|---:|
| 基本编码器—解码器 RNNencdec-50 | 17.82 | 26.71 |
| Attention 模型 RNNsearch-50 | 26.75 | 34.16 |
| 训练更久的 RNNsearch-50 | 28.45 | 36.15 |
| Moses 统计翻译系统 | 33.30 | 35.63 |

Attention 模型明显优于作者比较的基本编码器—解码器，但最好模型在**完整测试集上仍低于 Moses**。只在源句和参考译文均无未知词的子集上，训练更久的版本才达到 36.15，高于 Moses 的 35.63；这一子集评测还禁止模型生成 UNK。不能省掉这些筛选条件，只留下“超过统计翻译”。[^attention-results]

Moses 还使用了神经模型没有使用的额外单语料。两个神经架构虽使用相同数据与训练程序，编码器结构也不同：RNNsearch 多了一条反向循环网络。因此，这组结果支持整个方案的效果，不能当成严格等参数、只改一个 Attention 开关的消融实验。

训练预算同样影响比较。附录表 2 中，RNNsearch-50 训练约 **111 小时**，继续训练的版本约 **252 小时**，使用 Quadro K-6000。后一个数字解释了论文星号版本“训练更久”的实际含义；不能把它藏进一句“训练约五天”里。[^attention-training]

<a id="long-sentence-case"></a>

## 8. 一个长句错误，怎样显出问题所在

分数之外，Bahdanau 论文给了一个很具体的例子：一句较长的英文，说明医生基于自己在医院的医护人员身份，拥有让病人入院接受诊断或治疗的权利。

基本编码器—解码器在前半句尚能维持意思，到了后面，却把“基于他作为医护人员的身份”，译成了“根据他的健康状况”。译文仍像一句话，关键关系却变了。Attention 模型在这个案例里保留了原句所说的职业身份。[^long-examples]

另一个例子谈 Disney 怎样通过数字平台延长节目寿命、建立观众关系。基本模型在较后的位置偏离原意，连引号也没有正常收束；Attention 模型在作者展示的版本中保留了这些内容。

这两个例子让瓶颈变得具体：**流畅地接着写，并不等于仍然忠实于源句。** 持续读取源信息，可以帮助生成过程保留后面的关系与细节。

论文的长度分组实验也支持这种改善，但要区分版本：图中最稳定的是 RNNsearch-50；RNNsearch-30 在超出训练句长后仍明显下降。Attention 没有自动抹去训练分布的边界。前面那篇倒序 LSTM 又提醒我们，这不是所有固定状态模型必败的证明。两篇选择了不同架构、词表与训练条件，结果应该并列理解，不能把一篇的较弱基线，当成另一篇已经做出的最强模型。[^seq2seq-long][^long-examples]

Attention 仍留下几项实际限制。

**词表外的名字仍可能变成 UNK。** 一个词没有可用的独立词条，读取原句的位置并不会自动修复输出词表。两篇都把未知词作为实际问题；这也是 Bahdanau 模型在无未知词子集上表现更好的背景之一。

**读取不是免费的。** 每生成一个目标词，都要给源句各位置计算权重。只看这部分计算次数，源句长度乘以译句长度决定了需要多少次配对打分；它不是整套模型的完整复杂度表达式。论文认为这对普通句长尚可接受，但可能限制它在其他任务中的使用。[^attention-cost]

**循环计算仍然存在。** 双向编码器仍沿两个方向逐步传递状态，解码器也仍依赖前一步。Attention 改变了怎样取得源信息，并没有把整套系统变成无循环的网络。

**记忆容量没有变成无限。** 每份 annotation 与当前上下文向量仍是有限维表示，读取可能选错，生成也可能出错。论文检验的是句子翻译，并没有证明这套结构能可靠处理整本书，或者给出无限长度的上下文窗口。

<a id="people-and-history"></a>

## 9. 放回人物与历史，两条探索怎样连起来

Sutskever 那篇的三位作者是 **Ilya Sutskever、Oriol Vinyals、Quoc V. Le**，论文首页均署名 Google。Ilya 也是前面 AlexNet 论文的作者之一；这让我们看到，同一位研究者如何参与视觉与序列学习两种问题，而不必把他后来的所有经历都塞进这一节。[^history]

Attention 论文的三位作者是 **Dzmitry Bahdanau、Kyunghyun Cho、Yoshua Bengio**。首页分别列出 Bahdanau 所在的 Jacobs University Bremen，以及 Cho、Bengio 所在的 Université de Montréal。这条研究路线围绕神经机器翻译、编码器—解码器与长期依赖问题发展。

官方 arXiv 历史显示，Bahdanau 论文首次提交于 **2014 年 9 月 1 日**，Sutskever 论文首次提交于 **9 月 10 日**。本文读取的则分别是 Bahdanau 的 v7 和 Sutskever 的 v3，它们包含后来的修订。**首发时间、当前版本、教学上的讲解顺序，需要分开。**[^history]

两篇当前版本会讨论、引用对方的工作，也都提到更早的编码器—解码器研究。Bahdanau 还专门讨论了 Graves 在手写生成中使用的注意力方式及其单向移动限制。因此，更合适的历史定位是：**它把可学习的软对齐有力地引入神经机器翻译，而不是凭空发明了人类此前从未有过的全部注意力思想。**[^attention-cost]

现在可以接回《AI演义》的主线了。Word2Vec 把一些语言规律放进可复用的词表示；本节让整个系统学习怎样把一句话变成另一句话，并进一步开放了生成过程读取源信息的方式。这是理解问题的连接，不意味着这两篇模型直接拿来前一篇 Word2Vec 的权重。

原论文还观察到，seq2seq 学出的句子表示对词序变化敏感，对某些主动、被动语态改写则较为稳定。它展示了一小组句子的二维投影，说明翻译训练有机会形成有意义的整句表示；这仍是定性例子，不是所有同义句都能被正确识别的证明。[^seq2seq-representation]

接下来就轮到另一个问题：既然可以在生成时灵活读取信息，**表示本身是否还必须沿循环状态链一步一步计算？** [继续第 7 篇：GNMT 与 Transformer](./AI演义_07_GNMT与Transformer_从翻译系统到并行架构_科普讲解_20261105.md)，再看系统规模与网络结构怎样继续变化。

<a id="questions"></a>

## 10. 思考与追问

**如果把 Attention 的所有权重强行设成相等，会发生什么？** 每一步会得到相同的源表示平均值，失去随生成进度改变读取重点的能力；但解码器本身还在循环运行，所以这并不让整个模型停止工作。究竟下降多少，需要在同一训练与评测条件下实验，本文没有做这个消融。

**把隐状态加宽，与允许每一步重新读取，解决的是同一件事吗？** 前者增加表示容量，后者改变信息的访问方式。二者都可能帮助翻译，却不能仅凭一个长句案例就决定哪条路线总是更好。

**模型译文很通顺时，还应该检查什么？** 可以从上面的医生案例入手，看主体、身份、否定、时间和因果关系是否仍与源句相符。单个漂亮译例、平均 BLEU 或一张对齐热图，都不足以替代这些具体检查。
