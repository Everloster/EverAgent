# 《Agent 演义》15｜T3：多环境、远程与移动工作

## 概述

T3 把执行放在 host environment，让桌面、网页和手机作为 client 连接。远程工作需要处理主机在线、连接路线、代码位置、Agent 登录和客户端权限。[^remote]

专业用户可以从其他设备继续同一条工作主线，但不能把“网页还能打开”当成“Agent 仍在执行”。多环境与 linked environments 又服务于不同层面的协作。

**提炼句：** 能从多处进入任务，前提是知道它由哪台主机承担。

## 取景框 f(x)

**x｜问题：** 怎样在多设备、多主机的 T3 工作中保持可靠的执行与接管？

**f｜取景框：** 按执行主机、连接路线和访问范围安排工作。

**f(x)｜判断变化：** 先确认 host 与任务现场，再看 client；连接恢复后检查真实运行状态与未完成工作。

## 先把执行放在合适的主机

本机适合交互密集和本地工具；工作站或服务器适合持续任务与资源需求。主机必须有代码、provider CLI 和相应登录。另一台设备的登录或文件不会自动成为这个 environment 的资源。

T3 Connect、LAN／私有网络和 desktop-managed SSH 是不同连接方式。选择依据已有基础设施和需要访问的设备；无需同时配置所有路线。[^remote]

## 桌面关闭与服务器在线分开判断

文档说明，关闭桌面应用最后一个窗口会停止它的本地服务器；无人值守场景应检查 background service。手机和 hosted web 是远程控制入口，执行主机休眠或关机时工作无法持续推进。[^background]

在 Card Gallery 中，先在目标主机跑短测试并启动服务，确认客户端看到同一工作区和端口，再开始长任务。先验证最小路径，比一开始配置大规模跨机分工更容易排查。

## 连接成功后还要检查范围

确认 environment 名称、project、branch／worktree 和当前 thread。多个主机都有同名仓时，不能只按项目标题判断实际位置。

不同 client 的显示、快捷键与本地偏好可能不同；服务器设置和项目覆盖属于执行环境。选择 All environments 也只是对当前连接环境的批量操作，不是永久统一所有未来设备。

## 手机适合怎样接管

查看状态、回答一个明确问题、检查少量相关信息、把复杂审查留待桌面，是常见的移动工作方式。审批或修改前先确认问题涉及的任务与权限。

离线阅读、排队消息与实际执行是不同能力。恢复连接后，检查同步状态和远端变化，不因本地草稿还在就推断服务器已经收到。

## 远程浏览器的 localhost

T3 预览有本地加载、host streaming 和 preview tunnel 等路径。打开服务器上的开发服务时，localhost 的含义应跟着实际 host 与路由理解；手机自己的 localhost 不是那台服务器。[^remote]

需要手动操作 Agent 的预览页时，使用 Take control，再在结束后释放，避免双方同时改变页面。浏览器 profile、流式体验和桌面预览也可能有不同条件。

## Linked environments 与 guest links

Linked environments 面向 Agent 跨主机启动、消息和委派，是有权限范围与版本条件的 beta 功能；不是普通 client 配对的另一种名字。权限和能修改的 thread 要按实际访问边界确认。

Guest link 面向分享一条任务的观察或协作入口，使用前检查分享范围和访问规则。让别人看到任务、让另一个主机执行任务、让自己的手机接管，是三种不同选择。[^guest]
