# 同一个 GPT-5.5 考出四个分数——Agent 的智能，几分靠模型、几分靠 Harness？

> **这篇是什么**：接着上一篇《Agent LLM 评分体系科普》里最扎眼的现象——同一个模型、同一个 benchmark，分数从 24.9 到 58.6——往深里挖一层：**Agent 的智能里，LLM 占多少、Harness 占多少？** 读完你能回答三件事：① 为什么不能给出一个固定百分比；② 控制变量后，模型、Harness、思考档位各自值多少分；③ 工程上应该先修哪边。
> **怎么读**：顺读最佳（约 15 分钟）；赶时间只看每节 `✦ 一句话` + 第五部分一页纸；所有数字的出处点开「证据」折叠块。
> **证据约定**：控制变量数据来自第三方评测 Artificial Analysis（经 [models.dev](https://models.dev) 收录，2026-07-20 拉取）；Harness 对换实验来自本库已核实的论文精读（报告 46，Niklaus 等人的 Meta-Harness 实验）。`[推测]` 为我的推断。

## 第一部分 · 先建立直觉：大脑没变，变的是"考试条件"

✦ **一句话：LLM 是棋手的大脑，Harness 是他的棋盘、纸笔、时钟和助手——同一个棋手，考试条件一换，名次能差出二十倍。**

想象一位围棋高手去参加比赛。他的**大脑**（= LLM）没变，但组织者给的**考试条件**（= Harness）每次不同：

- A 场：**盲棋 + 10 秒快棋**——不许看棋盘，纯靠脑子记，每手 10 秒。
- B 场：**正常对弈 + 纸笔记录**——标准条件。
- C 场：**配一个摆棋助手 + 不限时**——可以试摆变化、慢慢想。
- D 场：棋桌是坏的，**棋子放上去会滑到隔壁格子**——再强的大脑也赢不了。

同一个棋手，在四场比赛里的"胜率"会差多少？差几倍毫不奇怪。这时候问"他的棋力是多少分"，**不给考试条件就是一句空话**。

Agent 的成绩单就是这回事。把这个类比焊死：

```
Agent 考分 = f( 大脑 LLM , 考试条件 Harness , 思考时间 , 考场版本 )
                ↑                ↑
           模型本身          提示词/工具接口/重试/记忆/
                          上下文管理/校验兜底代码/权限
```

而且先记住一个反直觉的伏笔：**"考试条件"之间的差异，有时候比"棋手之间"的差异还大。**

## 第二部分 · 跟着 GPT-5.5 的四个分数走一遍：把变量一个个拆开

✦ **一句话：用第三方统一协议下的控制变量数据，可以分别称出"换模型""换思考档""换 Harness"各自值多少分——结论是：三者是同一量级。**

上一篇留下的悬案：GPT-5.5 在 SWE-bench Pro 上有 24.9 / 26.2 / 30.9 / 58.6 四个分数。现在做严格一点的解剖——第三方评测机构 Artificial Analysis（下文简称 AA）用**同一套评测协议**（pass@1、公开 harness、标注思考档位）跑了很多"同一模型 × 不同 harness/档位"的组合，这就给了我们梦寐以求的**控制变量实验**。

### 拆变量①：只换模型（harness、档位不动）

Terminal-Bench v2.1（AA 协议，pass@1）：

| 对比 | 分数变化 | 含义 |
|---|---|---|
| GPT-5.4 → GPT-5.5（都用 Codex harness + medium 档） | 69.8 → 75.8（**+6.0**） | 一次**模型代际升级** ≈ 6 分 |
| Claude Opus 4.6 → 4.7（都用 Claude Code + medium 档） | 70.2 → 71.4（**+1.2**） | 另一次代际升级 ≈ 1 分 |

### 拆变量②：只换思考档位（模型、harness 不动）

| 对比 | 分数变化 | 含义 |
|---|---|---|
| GPT-5.5：medium → xhigh 档（都用 Codex） | 75.8 → 84.1（**+8.3**） | 一次**思考档位提升** ≈ 8 分 |
| Opus 4.7：medium → max 档（都用 Claude Code） | 71.4 → 73.8（**+2.4**） | ≈ 2 分 |

### 拆变量③：只换 Harness（模型、档位不动）

| 对比 | 分数变化 | 含义 |
|---|---|---|
| GPT-5.5（medium 档）：Codex → Cursor CLI | 75.8 → 73.4（**−2.4**） | **顶级 harness 之间** ≈ 2 分 |
| Opus 4.7（medium 档）：Claude Code → Cursor CLI | 71.4 → 70.6（**−0.8**） | ≈ 1 分 |

<details><summary>证据：控制变量数据的完整出处</summary>

全部来自 `https://models.dev/models.json` 收录的 AA 记录（source = artificialanalysis.ai/agents/coding-agents，2026-07-20 拉取）。三组变量在三个 benchmark 上方向一致：

- **模型代际**（Codex+medium）：GPT-5.4→5.5，Terminal-Bench +6.0、SWE-Bench Pro +7.8、Coding Agent Index +6.8
- **思考档位**（GPT-5.5+Codex）：medium→xhigh，TB +8.3、SWE-Pro +4.7、Index +4.9
- **Harness**（GPT-5.5+medium）：Codex→Cursor CLI，TB −2.4、SWE-Pro −1.3、Index −2.6
- 注意 SWE-Bench Pro 上 Opus 4.6→4.7 是 11.8→36.4（+24.6）——模型代际差异在不同考试上大小悬殊，说明"换模型值多少分"本身也随任务而变。

</details>

把这组数字放一起看，就是本文的第一个核心结论：

> **在"都是顶级 harness"的前提下：换一次 harness ≈ 1–3 分，换一次思考档 ≈ 2–8 分，换一次模型代际 ≈ 1–8 分。三者是同一量级——谁都压不过谁。**

GPT-5.5 想从 73.4 提到 84.1（+10.7 分），可以走三条路：换个更好的 harness（+2.4）、拉高档位（+8.3）、或者等下一代模型（~+6）。**没有哪条路是"唯一正解"，这就是"各占多少"没有固定答案的第一层原因。**

### 但故事还有另一半：当 harness 不在顶级区间时

上面是"顶级考场之间"的比较。如果把视野放到**整个 harness 空间**——包括没调好的、不配套的——差异会爆炸。本库报告 46 核实过的一手实验（Niklaus 等，Harvey 法律 Agent 基准，1251 个任务）：**同一个 DeepSeek 模型、同一个评判标准**，只换外面的 harness：

| Harness | 通过率 |
|---|---|
| mini-swe-agent | **3.5%** |
| Goose | 23.2% |
| Pi | 45.4% |
| 原版 LAB（官方自带） | 63.4% |
| 针对该模型进化优化后 | **80.1%** |

**同一个模型，3.5% 到 80.1%，差 23 倍——全部来自外面的脚手架。** 这正好补上类比的 D 场：棋桌是坏的（harness 与模型不匹配，比如输出格式对不上、文件落不了地），天才大脑也交不出卷子。

于是第二个核心结论：

> **Harness 占多少，取决于你站在 harness 空间的哪个位置：从"坏 harness"到"好 harness"是 20 倍的鸿沟；从"好"到"更好"只剩个位数分。Harness 的价值遵循陡峭的边际递减。**

<details><summary>证据：五 harness 实验的出处与两个关键细节</summary>

来源：本库《46_evolve_the_harness_2026.md》精读（已核实一手数据），原实验为 Harvey LAB 基准，24 dev + 100 held-out test。

两个值得记住的细节：

1. **Pi harness（45.4%）比官方原版（63.4%）还低 18 分**——名气大的通用框架，不配着模型调反而帮倒忙。"好框架 ≠ 对你模型的框架"。
2. 进化优化中贡献最大的单点改动是一段**确定性代码** `deliverable_landing_gate`：模型总把答案文件写错目录/文件名，评判读不到而丢分；加一段"交卷后自动把文件挪到正确位置"的死代码（零额外 token），dev 通过率 72.8%→79.2%。**模型不是不会做，是交卷姿势错了。**

</details>

## 第三部分 · 几个想不通的地方

### 3.1 所以到底各占多少？给一个诚实的三层答案

✦ **一句话：模型定上限，Harness 定兑现率，协议定读数——三者是乘法关系，不是加法，所以不存在"七三开"这种答案。**

问"LLM 占百分之几、harness 占百分之几"，预设了智能是可以按成分切分的加法模型。但数据支持的是**乘法模型**：

```
Agent 表现 = 模型能力上限 × Harness 兑现率(0~1) + 评测协议噪声
```

- **模型定上限**：推理、知识、代码能力的物理天花板在权重里。harness 再好，也榨不出模型没有的棋力（兑现率永远 ≤ 1）。
- **Harness 定兑现率**：同一个大脑，兑现率可以从 0.04（3.5% 那档）到接近 1。坏 harness 是"乘以 0"，顶级 harness 之间是"0.9 和 0.95 的差别"。
- **协议定读数**：榜单版本、pass@1 还是 resolve rate、时间预算——不改变智能本身，但改变你看到的数。

乘法关系意味着**任何一个因子崩了，总分就崩**，没法用"模型占 70%"来理解 mini-swe-agent 的 3.5%——那不是模型变弱了，是兑现率掉到了 4%。

### 3.2 为什么没有一个 harness 能"通吃所有模型"？

✦ **一句话：因为模型和 harness 不是独立变量，它们之间有"交互项"——同一个 harness，对这个模型加分，对那个模型减分。**

如果 harness 是中性的"通用装备"，那顶级 harness 就该对所有模型都加分。实测不是：

- **Cursor CLI 对 GPT-5.5 减 2.4 分，对 Opus 4.7 的 Coding Agent Index 反而加 1.3 分**（59.9→61.2）——同一 harness，符号相反。
- 报告 46 的跨模型迁移实验：为 DeepSeek V4 Pro 进化出的 harness，给**同家族**的 V4 Flash 用还有 +14.4 分收益，给**不同家族**的 Nemotron-3 Ultra 用只剩 **+0.4 分**，约等于零。
- 原论文的解释很干净：**确定性代码类改动（校验器、格式兜底）能跨模型迁移；提示词类的"打法手册"是模型专属的**，换模型要重调，甚至倒扣分。

用棋手类比说：每个棋手有自己的**习惯和暗号**——给 A 棋手配的记谱法和摆棋助手，直接搬给 B 棋手可能越帮越忙。所以更准确的函数要带上交互项：

```
Agent 表现 = f(模型, harness) + 交互项(模型 × harness) + 协议噪声
```

这也解释了为什么"榜单上某 harness 跑出的模型排名"不能直接搬到你自己的 harness 上——**排名是带着婚配关系的**。

### 3.3 思考档位算模型还是算 Harness？

✦ **一句话：它是"harness 正在被模型吃进肚子里"的活证据——这条边界本身在移动。**

思考档位（medium/xhigh/max）很有意思：旋钮由模型厂商提供，但**拧旋钮的是 harness**。它同时属于两边。这指向一个更大的趋势——

回看历史：2024 年的 harness 要教模型"先规划再动手""失败后重试""把长任务拆步"；2025–2026 年，这些被厂商用 agentic RL **直接训进了模型**，harness 里相应的提示词 playbook 就成了赘肉。这正是本库《Bitter Lesson × Harness》说的"镰刀一：模型变强，把填补能力缺口的 harness 吃掉"。**test-time compute（思考档位）就是内化的最新一层**——以前要靠 harness 组织多轮采样/反思才能买到的分，现在一个参数就给了。

所以"各占多少"是一个**随时间移动的答案**：harness 负责的地盘在被模型逐年蚕食。但有两样东西模型永远吃不进去——**环境权限和校验兜底**：文件落在哪个目录、数据库有没有写权限、交卷前跑不跑测试，这些在模型身体外面，属于"保证型需求"而非"能力缺口"。镰刀砍不到它们，`deliverable_landing_gate` 那段死代码就是证明。

### 3.4 工程上先修哪边？

✦ **一句话：先修兑现率，再换引擎——把现有模型的 harness 调到位，几乎永远是投入产出比最高的一步。**

把前面所有数字换算成工程决策：

1. **先修 harness**：一段零 token 的兜底代码就能 +6.4 分（`deliverable_landing_gate`），这是全市场最便宜的能力提升。你的 Agent 表现不好时，第一嫌疑不是模型笨，是**它在某个环节"交卷姿势错了"**——查轨迹，找那个"乘以 0"的环节。
2. **再拧档位**：medium→xhigh 白捡 2–8 分，代价是 token 成本和延迟——按任务的错误代价决定拧多高。
3. **最后才换模型**：代际升级 ≈ 1–8 分，而且要重调提示词 playbook（交互项警告）。换模型不重测 harness，等于给新车加旧油。
4. **读榜/选型时**：任何不带 harness、档位、时间预算、榜单版本四要素的"第一名"，都当作不可审计处理。

## 第四部分 · 装进脑子

### 一页纸心智模型

```
        Agent 的智能，一笔乘法账
                             
   模型上限 ──────────────┐
   （权重里的棋力，          │   ×   Harness 兑现率
    harness 榨不出             │      （0.04 ~ 1.0）
    没有的能耐）               │      坏 harness = 乘以 0
                              │      顶级 harness 之间 = 0.9 vs 0.95
        └──── 乘法式，不是加法 ────┘
                     │
        + 交互项（模型×harness 有婚配：
          Cursor 帮 Claude、坑 GPT；
          提示词 playbook 换家族即失效）
                     │
        + 协议噪声（版本/指标/预算）
                     │
   时间维度：模型每年吃掉一层 harness（镰刀）
        但环境权限 & 校验兜底永远在体外
```

### 五句话总纲

1. **"各占多少"没有固定百分比**——因为是乘法不是加法：模型定上限，harness 定兑现率，协议定读数。
2. **顶级区间内，三者同量级**：换 harness ≈ 1–3 分，思考档 ≈ 2–8 分，模型代际 ≈ 1–8 分（AA 控制变量实测）。
3. **顶级区间外，harness 是 20 倍变量**：同一模型跨 harness 从 3.5% 到 80.1%，坏 harness 是把总分乘以零。
4. **模型 × harness 存在交互项**：没有通吃的 harness；确定性代码是通用资产，提示词 playbook 是模型专属。
5. **趋势是模型持续内化 harness**（思考档就是最新被吃掉的一层），但权限与校验永远留在体外——那是 harness 的最后领地。

### 直觉陷阱表

| 你可能的误解 | 真相 |
|---|---|
| "模型决定 70%，harness 决定 30%" | 乘法关系下谈占比没意义：坏 harness 是把总分 ×0，不是 −30% |
| "换个顶级框架就能提升" | Pi 比官方原版低 18 分——不配套的好框架是负资产 |
| "分数低就是模型不行" | 首查兑现率：文件落盘、格式、权限，可能一段死代码就 +6 分 |
| "调 prompt 是 harness 工程的全部" | 实测贡献最大的改动 6 个里 5 个是确定性代码，不是提示词 |
| "harness 调好就一劳永逸" | 换模型要重调（交互项）；且模型升级会内化掉一部分（镰刀） |
| "思考档拉满总是最优" | +2~8 分对应 token 成本和延迟上涨，按任务错误代价拧档位 |

## 附 · 一个真实数字的实测拆解

本篇的"乘法账"全部可复核：

- **同一模型 23 倍方差**：Harvey LAB 上同一 DeepSeek 模型，五套 harness 通过率 3.5% / 23.2% / 45.4% / 63.4% / 80.1%（本库报告 46 核实的一手数据）。
- **控制变量三组对比**（AA，Terminal-Bench v2.1，pass@1）：模型代际 +6.0（GPT-5.4→5.5）；思考档 +8.3（medium→xhigh）；harness −2.4（Codex→Cursor CLI）。三条路通向同一个 +10 分。
- **交互项**：同一 Cursor CLI，对 GPT-5.5 是 −2.4，对 Opus 4.7 的 Index 是 +1.3；DeepSeek 定制 harness 跨家族迁移收益 +0.4 ≈ 0。

## 💭 思考与追问

1. **我真正理解了什么？** "LLM vs harness 各占多少"是个错误提问方式——它们是乘法因子加交互项；控制变量数据显示顶级区间内换 harness/换档位/换模型是同量级的三条路，区间外 harness 是 20 倍变量；确定性代码是可迁移资产，提示词 playbook 不是。
2. **我还没搞懂什么？** ① 兑现率能否被**事前**预测——不看轨迹，能否从模型+harness 的接口特征预判哪里会"乘以 0"？② AA 数据里 Opus 4.6→4.7 在 SWE-Bench Pro 上 +24.6 分、TB 上只 +1.2 分，"模型代际值多少分"随任务剧烈波动，背后是能力维度差异还是考试饱和？③ 思考档位的分是"买到了真能力"还是"买到了更贵的采样"——同样 84 分，xhigh 烧的 token 是 medium 的几倍？
3. **下一步做什么？** 把"查兑现率"变成一个可执行动作：写一个检查清单/小工具，对着自己 Agent 的失败轨迹逐项排查"交卷姿势"类错误（落盘、格式、权限、超时），先于考虑换模型。
