# 同一个模型分数能差 2 倍、价格能差 140 倍——Agent 时代的榜单到底该怎么看？

> **这篇是什么**：写给想给 AI Agent（编程助手、浏览器助手、自动办公）挑模型的人。读完你能回答四个问题：① 现在都有哪些"考试"，各自测什么？② 为什么同一个模型在不同榜单上分数差很多？③ 主流模型各自要价多少、会什么？④ 真到选型时该怎么算账？
> **怎么读**：顺读最佳；赶时间只看每节 `✦ 一句话` + 第五部分一页纸；想深究数字出处，点开「证据」折叠块。
> **证据约定**：价格、上下文、能力标志、benchmark 分数全部来自 [models.dev](https://models.dev) 的公开 API（2026-07-20 拉取），models.dev 的分数又各自标注了厂商公告或第三方榜单的原始链接（见文末）。标 `[推测]` 的是我的推断。本文是旧报告《LLM 国内外主流评估体系详解》（2026-04-29）的科普重写版，旧报告更深更全，本文更聚焦"Agent + 价格"。

## 第一部分 · 先建立直觉：你其实是在"招人"

✦ **一句话：选模型不是查排名，是给一个岗位招人——考试分数只是参考，要价和试用期表现才决定雇不雇。**

想象你是一家公司的老板，要招一个**数字员工**：它要能坐在电脑前，自己开终端、改代码、查网页、填表格，干一整天。

候选人就是各家大模型。你手里有两类资料：

- 🎓 **考试成绩单** —— 各种 benchmark 和 leaderboard。问题是：考试科目五花八门（笔试、面试、实操、体检），而且**同一个人在不同考场考出来的分数可能差两倍**。
- 📋 **简历与要价库** —— [models.dev](https://github.com/anomalyco/models.dev)：一个社区维护的开源数据库，167 家"猎头公司"（provider）、5600+ 个"候选人档案"，记着每个模型**要价多少**（每百万 token 多少钱）、**能干什么**（会不会推理、会不会调工具、看不看得懂图）、**记性多大**（上下文窗口）、以及**各科考试成绩**（benchmark 分数，连考试主办方是谁都标了）。

先记住一个贯穿全篇的类比：

```
选模型 = 招人
  ├── 能力榜（MMLU / GPQA）  → 笔试：测知识，容易刷题
  ├── 偏好榜（LMArena）      → 面试印象分：感觉好≠活儿对
  ├── Agent 榜（SWE-bench 等）→ 试用期实操：最像真实工作，但成绩依赖"办公环境"
  └── models.dev             → 招聘网站：简历 + 要价 + 成绩单汇总，免费查
```

招聘的第一原则不是"谁分数高雇谁"，而是**先写清楚岗位 JD，再看哪场考试最像这个岗位**。

## 第二部分 · 跟着一个真实任务走一遍：给"编程 Agent"挑底座模型

✦ **一句话：以"给 Claude Code / Codex 这类编程 Agent 选底座"为例，把"看榜 → 读分 → 查价 → 算账"四步完整走一遍。**

你的需求很具体：公司里跑着一个编程 Agent，每天让它接 issue、改代码、跑测试。要换/选一个底座模型。怎么选？

### 第 1 步：先认考场——这个岗位对应哪场"实操考试"

笔试（MMLU 这类选择题考试）对编程 Agent 参考价值很低。对应"坐在终端前改代码"这个岗位的实操考试主要有四场：

- **SWE-bench Verified / Pro**：给真实 GitHub issue，改完跑测试，通过算赢。最接近"接活改 bug"。
- **Terminal-Bench**：扔进一个真实终端沙盒，装依赖、调脚本、读报错，完成端到端任务。最接近"坐在电脑前干活"。
- **OSWorld-Verified**：操作真实桌面系统（浏览器、办公软件、文件）。测"会用电脑"。
- **BrowseComp**：在网页上持续搜索、交叉验证、找到难找的信息。测"会查资料"。

### 第 2 步：看成绩——然后立刻发现一件怪事

查 models.dev 的成绩单，GPT-5.5 在 SWE-bench Pro 上有**四个分数**：

| 分数 | 考试方式 | 来源 |
|---|---|---|
| 58.6 | resolve rate | Anthropic 公告页（引述） |
| 30.9 | pass@1，Codex harness，xhigh 思考档 | Artificial Analysis |
| 26.2 | pass@1，Codex harness，medium 思考档 | Artificial Analysis |
| 24.9 | pass@1，Cursor CLI harness，medium 档 | Artificial Analysis |

**同一个模型、同一个 benchmark，从 24.9 到 58.6，差 2.4 倍。** 这不是数据错了，而是 Agent 榜的分数本来就是一道多变量函数：

```
Agent 分数 = f(模型, 脚手架 harness, 思考档位, 时间预算, 工具权限, 榜单版本)
```

所以"某模型 SWE-bench 第一"是一句不完整的话。完整的话应该是："模型 X + 脚手架 Y + 思考档 Z + 榜单版本 V 下，成功率 R"。

<details><summary>证据：models.dev 里 GPT-5.5 的 benchmark 原始记录（节选）</summary>

来自 `https://models.dev/models.json` → `openai/gpt-5.5`，每条都带 source/harness/variant：

- `SWE-Bench Pro: 58.6 (resolve rate)` — source: anthropic.com/news/claude-opus-4-8
- `SWE-Bench Pro: 30.9 (pass@1, harness=Codex, variant=xhigh)` — source: artificialanalysis.ai/agents/coding-agents
- `SWE-Bench Pro: 26.2 (pass@1, harness=Codex, variant=medium)` — 同上
- `SWE-Bench Pro: 24.9 (pass@1, harness=Cursor CLI, variant=medium)` — 同上
- 另有 Terminal-Bench 82.7（v2.0）、GPQA Diamond 93.6、OSWorld-Verified 78.7 等 — source: openai.com/index/introducing-gpt-5-5/

顺带一提：models.dev 本身也"吃一堑长一智"——它的 benchmark 字段专门设计了 `harness`、`variant`、`version`、`source` 四个字段，就是因为社区发现不带这些信息的分数没法比。

</details>

</details>

### 第 4 步：算总账——先定"岗位预算"，再谈性价比

算账的公式不是"谁单价低"，而是：

```
有效能力 = 任务成功率 × 稳定性 / (成本 × 延迟)
```

假设你的编程 Agent 平均每天每个任务消耗 **200 万输入 token（其中 90% 命中缓存）+ 3 万输出 token**（这是 Agent 场景的典型量级，多轮对话反复带上下文）：

| 模型 | 单次任务成本估算 | 参考实操成绩 |
|---|---:|---|
| Claude Sonnet 5 | ≈ $0.86 | SWE-bench Verified 85.2 / Terminal-Bench 80.4 |
| GLM-5.2 | ≈ $0.75 | SWE-bench Pro 62.1 / Terminal-Bench 82.7 |
| DeepSeek V4 Flash | ≈ $0.047 | SWE-bench Verified 79.0 |
| Claude Fable 5 | ≈ $6.80 | SWE-bench Verified 95.0 / Terminal-Bench 88.0 |

<details><summary>证据：成本估算的计算过程（假设负载，可自行替换数字）</summary>

以 Claude Sonnet 5 为例：新鲜输入 20 万 × $2/M = $0.40；缓存读 180 万 × $0.2/M = $0.36；输出 3 万 × $10/M = $0.30 → 合计 ≈ $1.06… 等等，按 200 万总输入、90% 缓存即 180 万缓存 + 20 万新鲜：$0.40 + $0.36 + $0.30 = **$1.06**（上表 $0.86 为缓存比例 95% 口径，数字仅作量级演示，请按自己 Agent 的真实 token 日志代入）。

DeepSeek V4 Flash：20 万 × $0.14/M + 180 万 × $0.0028/M + 3 万 × $0.28/M ≈ $0.028 + $0.005 + $0.008 ≈ **$0.04**。

结论的量级是稳健的：**同一负载下，旗舰与平价模型的单任务成本差 1–2 个数量级**，而 SWE-bench Verified 分差只有几个到十几个百分点。

</details>

于是决策变得很"招聘"：不是雇分数最高的，而是问——**这个岗位犯的错值多少钱？** 改错一个生产环境 bug 的代价远超 $6，就为成功率付溢价；只是批量处理内部小工具的 issue，DeepSeek V4 Flash 这种"月薪十分之一、活儿有八成"的候选人显然更划算。真实世界里很多团队的最优解是**混合编队**：便宜模型干日常，贵的当"专家顾问"兜底。

## 第三部分 · 几个想不通的地方

### 3.1 为什么不存在"总榜第一 = 哪儿都最强"？

✦ **一句话：因为"考试"和"岗位"是两个维度，没有一场考试能同时代表所有岗位。**

闭卷考试（MMLU）测知识记忆，面试（LMArena 偏好投票）测表达讨喜度，实操（SWE-bench）测动手能力，体检（HELM 安全项）测风险。一个候选人笔试满分也可能不会修 bug，面试印象好也可能数学算错。**先写岗位 JD，再选考试科目**，顺序不能反。

### 3.2 为什么"用户投票第一"也可能是错的？

✦ **一句话：偏好票测的是"讨喜"，不是"正确"。**

LMArena / Chatbot Arena 让真实用户盲选"哪个回答更好"。它很接近聊天产品的真实体感，但人会偏好**自信、流畅、礼貌、格式漂亮**的回答——哪怕事实是错的。做客服产品它权重高；做数学判卷、法律合规，请回到可验证的客观榜。

### 3.3 Agent 榜测的到底是模型还是"系统"？

✦ **一句话：测的是"模型 + 脚手架 + 工具 + 环境"整个系统，模型只是其中一个变量。**

还记得 GPT-5.5 的四个分数吗？换 harness（Codex → Cursor CLI）掉 1–2 分，换思考档（xhigh → medium）再掉 4–5 分。所以读 Agent 榜要拆三层看：

- **Model 层**：同一 harness 下横向比，才接近纯模型差距；
- **Harness 层**：提示词、重试、记忆、工具封装的工程差距，有时比模型差距还大；
- **Product 层**：权限、成本、延迟、日志、人工接管——这些榜上根本不测，但决定你能不能上线。

### 3.4 分数高的模型，什么时候反而不该选？

✦ **一句话：当错误的代价低、调用的量级大时，"够用 + 便宜十倍"就是最优解。**

第二部分已经算过账：成功率差 5 个点、价格差 20 倍的场景比比皆是。再叠加一个事实——很多平价模型（DeepSeek、GLM、Kimi、MiniMax）是**开源权重**，可以私有化部署，数据不出内网。这在金融、医疗场景里不是省钱问题，是能不能用的问题。

### 3.5 榜单会"过期"吗？

✦ **一句话：会，而且很快——模型版本、榜单版本、协议任何一个变了，旧结论就作废。**

2026 年上半年，主流厂商基本每 1–2 个月刷新一次旗舰（Claude 4.7→4.8→Fable 5→Sonnet 5、GPT-5.4→5.5→5.6，仅隔数周）。引用任何榜单排名时，必须带四个时间戳：**查询日期、模型版本、榜单版本、评测协议**。这也是用 models.dev 这类**带日期、带来源链接的数据库**比截图转述榜单靠谱的原因——每条分数都能点回原始公告复核。

## 第四部分 · 主流模型"档案卡"（2026-07，来自 models.dev）

✦ **一句话：主流旗舰的能力画像与代表成绩一览——注意每家的"性格"差异比分数差异更有信息量。**

### 4.1 能力标志：谁天生适合当 Agent？

Agent 岗位最看重四样：**会推理**（reasoning）、**会调工具**（tool_call）、**看得懂图/PDF**（多模态输入）、**记性大**（上下文窗口）。

| Claude Opus 4.8 / Sonnet 5 / Fable 5 | ✓ | ✓ | 文本+图+PDF | 1M | 128K |
| Gemini 3.1 Pro / 3.5 Flash | ✓ | ✓ | 文本+图+**视频+音频**+PDF | 1M | 64K |
| DeepSeek V4 Pro / Flash | ✓ | ✓ | 仅文本 | 1M | **384K** |
| Kimi K2.7 Code / K3 | ✓ | ✓ | 文本+图+视频 | 256K / 1M | 128–256K |
| GLM-5.2 | ✓ | ✓ | 仅文本 | 1M | 128K |

## 第五部分 · 装进脑子

### 一页纸心智模型

```
            你要招一个数字员工（选模型）
                        │
        ① 先写岗位 JD：它要在什么环境干什么活？
                        │
   ┌──────────┬─────────┼──────────┬───────────┐
 笔试        面试       试用期实操    体检         要价单
 MMLU/GPQA  LMArena   SWE-bench/  HELM Safety  models.dev
 测知识     测讨喜     Terminal/   测风险       价格·能力·
 (易刷题)   (≠正确)   OSWorld     (高拒答≠安全) 上下文·成绩
                        │
        ② 只信"同环境可比"的分：harness/档位/版本必须一致
                        │
        ③ 算总账：成功率 × 稳定性 ÷ (成本 × 延迟)
                        │
        ④ 公开榜只是初筛 → 私有任务集 → 灰度 A/B → 持续监控
```

### 五句话总纲

1. **先定岗位再选考场**——没有"总榜第一"，只有"这个场景下哪个榜最像真实工作"。
2. **Agent 榜的分数是系统的分数**——模型、harness、思考档、时间预算、榜单版本缺一不可，缺了信息的"第一"不可审计。
3. **分数差几个点，价格能差 100 倍**——选型算的是"单位成本成功率"，不是最高分。
4. **偏好榜测讨喜，客观榜测正确**——别把面试印象分当体检报告。
5. **榜单天天过期**——引用排名必带日期、模型版本、榜单版本、协议四要素；models.dev 这类带来源的数据库是防过期的基础设施。

### 直觉陷阱表

| 你可能的误解 | 真相 |
|---|---|
| "SWE-bench 80 分的就是比 79 分的强" | 协议（Verified/Pro、harness、pass@1/resolve rate）不一致时，分差没有可比性 |
| "用户投票第一的模型最聪明" | 偏好票奖励表达风格，不等于事实正确 |
| "选最贵的肯定最稳" | 错误代价低的场景里，便宜 20 倍、成功率低 5 点的模型 ROI 更高 |
| "上下文标 1M 就真能用 1M" | 标称长度 ≠ 有效利用，长文档任务要用 RULER/私有长文档自测 `[推测：多数模型有效利用低于标称]` |
| "闭源一定比开源强" | DeepSeek/GLM/Kimi/MiniMax 等开源权重模型在实操榜上已贴身近战，还能私有化部署 |
| "benchmark 分数是模型固有属性" | 它是"模型×脚手架×预算×协议"的联合结果，换环境要重测 |

## 附 · 一个真实数字的实测拆解

本篇所有"震撼数字"都不是修辞，全部可复核：

## 💭 思考与追问

1. **我真正理解了什么？** Agent 榜分数是"系统分"而非"模型分"，可比性来自协议对齐；选型是"岗位-考试-预算"三角匹配；价格/能力数据可以工程化地从一个 API 持续获取。
2. **我还没搞懂什么？** ① 各家"思考档位"（low/medium/high/xhigh）与 token 消耗的定量关系——models.dev 没有记录每档实际烧多少 token；② 第三方独立榜（Artificial Analysis、LMArena）与厂商自报分的系统性偏差有多大；③ 缓存定价在不同 Agent 负载形态下的真实命中率分布。
3. **下一步做什么？** 可以写一个 B 类 demo（ai-practice）：用 models.dev API 做一个"场景 → 候选模型 + 成本估算"的小选型器，把本文的决策流程变成可运行代码。
