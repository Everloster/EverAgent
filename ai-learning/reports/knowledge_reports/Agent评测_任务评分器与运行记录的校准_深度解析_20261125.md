# Agent 评测怎样才可信：任务、评分器与运行记录要一起校准

一个 Agent 说“拟合完成”，评分器发现输出文件根本不存在。另一个 Agent 交出了正确的峰强度比，却没有完成任务要求的曲线拟合。这两种失败都发生在 Hugging Face 的示例研究中。它们提醒我们，评测分数既受模型能力影响，也受任务说明、工具、运行环境和评分器影响。

《How to build and maintain an agentic evaluation》以拉曼光谱分析为例，追踪一项任务怎样从能力主张变成分数，再讨论评测公开、修订、污染和饱和的问题。最有用的部分是它把“验证模型”前移了一步：先检查测量方法能否识别正确结果、空结果和钻空子的结果。[官方文章](https://huggingface.co/blog/agentic-evals)

## 分数究竟属于谁

问答评测主要检查答案。Agent 任务还包含它能使用的工具、执行步骤，以及环境被改变后的状态。例如处理一份光谱时，模型可能需要读文件、安装依赖、选择拟合窗口、运行程序并保存结果。任何一环的配置变化，都可能改变成功率。

因此，比较对象至少要写成“模型、provider、Agent harness、任务版本、环境、评分器和运行预算”的组合。Agent harness 负责让模型与工具反复交互；evaluation harness 负责安排多次运行、隔离任务、记录结果和汇总成绩。前者决定它怎样干活，后者决定这些尝试怎样被测量。把两者都叫“评测框架”容易漏掉可变条件。[评测组成说明](https://huggingface.co/blog/agentic-evals)

一次 rollout 指 Agent 从接到任务到停止的一次完整尝试。过程中可以执行很多命令；把一次命令失败算成一次 rollout，或者把重试中的最佳片段拼起来算成功，都会改变统计对象。trace 则保存消息、调用与观察，使读者可以检查“完成”发生在什么证据之后。

这里的一个反例很具体：Agent 在第一条回复里既提出命令，又调用 `mark_task_complete`。即使命令稍后真的执行，宣布完成时它还没有看到输出。模型的结束信号可以通知调度器停止，但任务是否达成仍要由保存结果和可信检查决定。

## 从“会分析光谱”缩到真正能测的能力

拉曼光谱的横轴表示散射光相对入射光的频移，常用单位为 cm⁻¹。石墨烯的峰形和峰强度提供材料信息。文章将问题缩为：拟合指定峰、按明确约定计算 D/G 强度比，并保存准确结果。它没有据此宣称 Agent 能独立审核完整实验报告。

作者先复用 Terminal-Bench 的 `raman-fitting` 任务，再改成 `raman-lab`：八份合成光谱、三个峰、不同噪声和缺陷程度。已知生成参数让参考答案可得，但这八份是开发集。真实仪器中的坏测量、荧光背景、不同激光条件或需要请求重测的情形，仍需另行覆盖。[原任务与改编方法](https://huggingface.co/blog/agentic-evals)

原任务的一个问题是，指令没有把横轴换算及参数约定讲充分，参考解却按特定单位和拟合范围评分。这会把猜中评分器约定混进能力测量。解决办法是先对齐指令与检查条件，再判断模型是否失败。

用一个自拟单峰例子说明这种约定的必要性。洛伦兹峰可以写为：

\[
y(x)=b+a\frac{\gamma^2}{(x-x_0)^2+\gamma^2}
\]

其中，\(x\) 是拉曼频移，\(x_0\) 是峰中心，\(b\) 是背景，\(a\) 是高于背景的峰高，\(\gamma\) 是半高半宽。峰的全宽为 \(2\gamma\)，扣除背景后，整个峰的积分面积为 \(\pi a\gamma\)。因此，“强度”若指峰高，D/G 比是 \(a_D/a_G\)；若指面积，则是 \(a_D\gamma_D/(a_G\gamma_G)\)。

设 D 峰高为 8、半宽为 20，G 峰高为 40、半宽为 10。峰高比是 0.2，面积比是 0.4。两份答案都能使用“强度比”这个名字，数值却不同。任务必须写清定义，而评分器也必须沿同一定义检查。这里的数值和公式示例用于教学，未冒充原研究的数据。

## 评分器也要接受反例

文章中的 shortcut 直接读取局部最高点，猜测峰宽，再计算 D/G 峰高比。它在八个任务上都给出了可接受的比值，却没有拟合光谱。只检查比值的评分器就会让它满分通过。作者随后加入拟合检查，才拒绝了这种捷径。[shortcut 检查](https://huggingface.co/blog/agentic-evals)

设计这种检查时，应分清任务真正要求的能力与不必要的实现限制。若目标只是得到准确参数，更快的合法求解方法应当通过。若目标要求解释峰形，仅用最高点就不够。评分器可以检查保存参数重建的曲线、残差、峰位置和宽度；不能只规定“必须调用某个 Python 库”，否则可能拒绝另一种正确拟合。

有效的验证至少包含参考解、什么也不做的 Agent、已知省略必需工作的捷径，以及合理的替代正确解。前两种检查能发现环境损坏和空结果误判，后两种检查能发现假通过与假失败。实际容差应由领域专家根据测量噪声、拟合窗口和用途确定。

下列自拟检查把“峰高比正确但宽度错误”展示出来，可以直接用 Python 运行。

```python
from math import isclose

reference = {"D": (8, 20), "G": (40, 10)}  # 峰高、半宽
shortcut = {"D": (8, 5), "G": (40, 5)}
def height_ratio(peaks):
    return peaks["D"][0] / peaks["G"][0]

ratio_pass = isclose(height_ratio(shortcut), height_ratio(reference))
fit_pass = all(
    isclose(shortcut[peak][i], reference[peak][i], rel_tol=0.01)
    for peak in reference for i in (0, 1)
)
print(ratio_pass, fit_pass)  # True False
```

这段代码只展示为什么单一比值检查不够，尚未完成一套光谱拟合评分器。真实数据还需要比较曲线和容差，避免把存在等价参数解的拟合一律拒绝。

## 三次机会和三次都可靠，服务的是不同决策

文章报告的早期 `gpt-oss-120b` 运行在八个改编任务上共尝试 24 次，成功 11 次。七个任务至少成功一次，仅一个任务三次都成功。因此这次运行的平均成功率为 11/24，即约 45.8%；实测 pass@3 为 7/8，即 87.5%；实测 pass^3 为 1/8，即 12.5%。

这里的 pass@3 直接按每个任务的三次实际运行统计，表示“允许三次尝试，是否出现成功”；pass^3 表示“三次是否全部成功”。不能把 87.5% 写成无人监督的一次成功率。也不能在未知独立性时，用平均成功率的三次方代替实际统计。[指标及早期结果](https://huggingface.co/blog/agentic-evals)

这一区别直接影响产品选择。有人检查结果并决定是否重试时，至少成功一次很有用。批处理会自动接收每次输出时，重复运行是否稳定、失败是否可检测更重要。重试还有时间、费用和人工审查成本，应与分数放在一起。

同一光谱的三次运行共享任务难度。文章因而按任务聚类计算标准误，而没有把 24 个结果当成完全独立的样本。八个开发任务仍很少，标准误也不覆盖任务选择偏差、评分器错误或真实数据分布变化。

## 公开怎样帮助评测继续有用

公开测试题便于审查，也可能进入训练材料。隐藏题目可以减少直接接触，却不会自动修好任务，也不会阻止模型最终掌握被测能力。污染指提前接触题目或答案，饱和指任务已不能有效区分被测系统；高分本身不能区分二者。

文章提出按部件公开：可以保护仍在使用的试题，同时开放环境定义、工具接口、评分方法、合成开发样例、修订记录和经审查的 traces。被保护的题目还需要受控的专家核验渠道，不能让“保密”替代验证。[公开策略](https://huggingface.co/blog/agentic-evals)

即使榜单饱和，任务仍能成为新 harness 的回归检查，环境和评分器也能用于建立更难的下一代任务。这个后续价值依赖保存版本和已知问题：修订了容差或依赖后，应说明旧分数是否仍可比较。

对 EverAgent 而言，最直接的用途是检查学习任务的交付语义。模型说报告完成时，实际文件、来源范围、计算输出及远端提交状态应各有可检查的依据。评测时可以用缺文件、错数字和引用不支持结论的样例挑战检查方法；仅检查 frontmatter 中是否出现 `completed` 测不到这些能力。这是本文的项目应用推导，未实施新的强制质量门。

本次完整阅读文章主文和操作附录，核对固定版本 README、逐次结果表及分析程序，并运行峰高比反例与结果复算。未重跑 Harbor、HF Sandbox 或六个模型；真实实验室覆盖、其他审计研究的统计数字和长期维护效果不属于本次复验范围。
