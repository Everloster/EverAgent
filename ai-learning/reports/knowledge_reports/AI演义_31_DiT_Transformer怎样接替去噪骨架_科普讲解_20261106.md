# AI演义·31｜DiT：去噪这份工作，Transformer 能接手吗？

[返回原报告第 31 节](../AI演义_笔记分析与项目整合报告.md#paper-dit) · [上一节：Stable Diffusion v1.4](AI演义_30_StableDiffusion_v14_文生图系统怎样协同工作_科普讲解_20261106.md) · [继续阅读：两种观察技术史的视角](../AI演义_笔记分析与项目整合报告.md#lenses)

画花这件事，我们已经拆成了几个部分：把图像放进较小的潜空间，逐步预测噪声，依据条件调整采样，最后解码成图片。

但为什么反复做噪声预测的，总是 U-Net？

前面的 ViT 已经证明，图像可以切成小块，交给 Transformer 处理。那么，**同样一份带噪的图像表示，能不能也交给 Transformer？如果给它更多计算，生成效果是否会持续改善？**

这就是 *Scalable Diffusion Models with Transformers* 要研究的问题。论文首版公开于 **2022 年 12 月 19 日**，本文采用 **2023 年 3 月 2 日的 v2**。作者把这类骨架称为 **Diffusion Transformer，简称 DiT**。[^paper]

先记住最重要的一句话：

> DiT 不是让 Transformer 打败扩散，而是让 Transformer 成为扩散模型里面负责去噪的网络。

本章继续用花照解释表示和计算，但原论文的主要实验是 **ImageNet 类别条件生成**，不是输入“窗边花瓶里的一朵红花”这类自由文字。不要将解释例子误认成论文已经完成的文生图实验。

<a id="backbone-not-framework"></a>

## 1. U-Net 是怎样成为默认选项的？又为什么可以换？

扩散模型需要一个网络，在不同噪声程度下预测怎样改变当前状态。这个任务没有规定，网络必须长成 U-Net 的样子。

不过，U-Net 有很合适的图像处理结构：一边逐渐缩小空间尺寸，提取较大范围的信息；另一边恢复空间尺寸，并借助跳跃连接利用前面的细节。DDPM 又继承了已有图像模型的许多组件，使它成为一条可靠的工作路线。

到 DiT 论文时，这种扩散 U-Net **已经包含空间自注意力层**，并不是只会看小邻域的纯卷积网络。因而，不能把这次变化简化成“旧模型没有全局交流，新模型第一次加了注意力”。[^background]

作者真正想做的是：把去噪骨架改成更接近标准 ViT 的结构，系统研究它的规模、输入 token 数和计算量怎样影响生成质量。

如果效果好，就有机会复用 Transformer 在其他领域积累的结构与训练经验。但这是需要实验支撑的研究方向，不是“名称里带 Transformer，就天然强于所有 CNN”的证明。

<a id="what-changes"></a>

## 2. 换掉中间这块，外面的生成方法还在

把前一章的主线缩成一行：

```text
潜空间噪声 → U-Net 反复预测 → 采样器更新 → 最终潜表示 → 图像解码器
```

DiT 的研究主线是：

```text
潜空间噪声 → Transformer 反复预测 → 采样器更新 → 最终潜表示 → 图像解码器
```

改变的是中间的去噪网络。前向加噪、已知噪声监督、逐步反向采样，以及图像压缩和解码，这些思想仍然保留。[^architecture]

论文采用现成的预训练图像自编码器，复用 Stable Diffusion 的 **8 倍下采样变分自编码器（VAE）**；然后在这个空间里训练新的类别条件 DiT。它不是把 v1.4 的 U-Net 权重换个文件名，就变成了已经训练好的 Transformer。

这套系统也不是“从输入到输出全都没有卷积”。**去噪骨架采用 Transformer，自编码器仍是卷积 VAE。** 部件之间可以混合，并不需要为了统一名称把所有东西推倒重来。

<a id="patches-and-tokens"></a>

## 3. 先把带噪潜网格切块，但不要把空间关系切没了

用一张 **256×256** 的花照说明尺寸。经过 8 倍下采样，潜表示是 **32×32×4**。训练时先给这个潜网格加噪，再把它送给 DiT。[^patchify]

如果每个小块覆盖潜空间的 **2×2 个位置**，32×32 的网格就被分成 **16×16＝256 个块**。每个块经过线性映射，变成一个 token；再加入位置表示，交给 Transformer。

这里有两个特别容易搞错的地方：

1. **2×2 指潜网格，不是原图只有 2×2 像素。** 编码器已经先做过一次空间压缩。
2. **图像 token 不是词，也不是模型新生成的一串文字。** 它只是供网络处理的向量序列。

位置表示让网络知道各个块原来在哪里。自注意力让这些块的表示相互读取信息；前馈层再进一步变换各个位置的特征。

继续用花照理解：某个块里的颜色，是否属于花瓣，要结合附近形状甚至整个画面。自注意力提供了跨位置的信息通道，但“可以相互读取”不等于模型已经正确理解了所有物体关系。

### 切得更细，计算就更多，但参数未必更多

同样是 32×32 潜网格：

| 潜空间块大小 p | 输入 token 数 |
|---|---:|
| 8×8 | 16 |
| 4×4 | 64 |
| 2×2 | 256 |

块边长减半，token 数增加 4 倍；注意力等计算随之增加。但同一套层仍可在不同位置复用参数，所以，**网络参数量近似不变，也可能做多得多的计算**。

这正是论文不满足于只比较“几亿参数”的原因。输入组织方式也在决定网络究竟做了多少工作。

<a id="conditional-blocks"></a>

## 4. 时间步和类别，怎样告诉 Transformer？

只给网络一堆带噪 token 还不够。它需要知道现在噪声多重，以及这次希望生成哪个类别。

论文比较了四种条件接入方式。它们不是四种完全不同的生成方法，而是 **Transformer 块怎样使用时间与类别信息**的不同设计。[^conditioning]

| 设计 | 直觉解释 |
|---|---|
| In-context conditioning | 把时间和类别也变成 token，接在图像序列后面，一起处理 |
| Cross-attention | 图像 token 保持一组，时间与类别另成一组，增加交叉注意力读取条件 |
| adaLN | 条件不一定要当 token；也可以调节各层归一化之后的缩放与平移 |
| adaLN-Zero | 在自适应归一化之外，进一步控制残差分支的输出，并用零初始化安排起步方式 |

这里的 in-context 不是“给模型几个问答例子让它学会新任务”。本论文只是用这个名称表示，把条件向量当作额外输入 token。

### adaLN：条件也可以成为网络里的调节器

假设当前噪声很重，需要判断整体结构；噪声较轻时，更需要修正细节。同一个特征通道，在这两种情况中的作用可能不同。

adaLN 根据时间步和类别的表示，产生一组缩放与平移参数，调节网络内部特征。可以把它理解成，条件不只是一份可供查询的资料，也可以直接影响各层怎样处理资料。

这种调节在同一层里对所有 token 使用同一套条件参数；它与让每个位置单独读取一段长文字的交叉注意力，具有不同的形式。原论文主要比较时间与类别条件，不能据此断言 adaLN 在所有文字条件任务上都一定更好。

### Zero：先让残差块接近“把输入传过去”

[本系列第 3 节 ResNet](AI演义_03_ResNet_深层网络如何训练_科普讲解_20261104.md) 里出现过一条思路：让网络学习对已有表示的修正，比要求每层完全重建表示更容易组织。

adaLN-Zero 给残差分支加上可调缩放，并让相关缩放从零开始。这样，**初始化时每个 DiT 残差块可以先表现为恒等映射**，再随着训练逐渐学会修正。[^conditioning]

这不是把整个网络的所有权重都设为零，也不是说最终的噪声预测永远等于输入。残差块、输出预测层和完整生成系统，是不同层次的对象。

看结果前，先解释两个后文常用的缩写：

- **FID** 比较生成图片与真实图片在特征空间中的分布差异，通常越低越好；它不是单张图片的“正确率”。
- **CFG（无分类器引导）** 在采样时组合有条件与无条件预测，调整条件对生成的影响，具体机制见[上一章](AI演义_30_StableDiffusion_v14_文生图系统怎样协同工作_科普讲解_20261106.md#cfg)。“无额外 CFG”仍然使用类别条件，只是不额外强化引导。

在 Table 4 的 XL/2 比较中，训练 **400,000 步**后的无额外 CFG 的 FID 分别为：in-context **35.24**、cross-attention **26.14**、adaLN **25.21**、adaLN-Zero **19.47**，越低越好。统一使用 50,000 个生成样本评价；这组表格采用 ft-MSE 图像解码器。[^block-results]

结果支持选择 adaLN-Zero 这套设计，但不能把差距全部归因于一个“零”字：它还增加了控制残差输出的参数。Table 4 中，adaLN 约有 **6 亿**参数，adaLN-Zero 约有 **6.75 亿**；条件子层与计算量也不完全相同。它们比较的是完整的条件接入配方，并非所有变量都固定后只改一个初始化数字。

<a id="output-and-training"></a>

## 5. Transformer 输出什么？不是一次交出最终图片

经过多层计算后，每个 token 被线性映射回一个小块，再按原位置拼成网格。

论文的输出有两部分：**噪声预测，以及反向采样所需的对角协方差参数**。它们都与输入潜网格的空间形状对应；不是预测一个囊括所有像素两两关系的巨大协方差矩阵。[^output]

还要把两种“还原”分开：

- 把 token 重新排成潜网格，是 DiT 每次前向中的输出整理。
- 把最后生成的潜表示变成像素图片，是最终图像解码器的工作。

网络给出预测后，采样器更新当前状态，然后下一步再次调用网络。因此，**Transformer 一次可以处理整组图像 token，并不意味着一次就完成整幅图的生成**。

它也不是像语言模型那样先生成第一个图像块，再按顺序生成第二个块。这里的 token 是一轮去噪计算的输入组织方式，生成主过程仍是扩散时间步上的迭代。

### 原来的噪声学习办法仍然有用

训练仍从真实图像的潜表示出发，加入已知噪声。噪声预测使用简化的平方误差目标；为学习反向协方差，论文还保留相应的变分目标。不能只因它也叫 DDPM，就把早期固定方差的具体配置原样搬过来。

作者沿用许多已有扩散训练设置：在 ImageNet 上做类别条件训练，batch 为 **256**，AdamW 学习率保持 **0.0001**，没有使用权重衰减和学习率 warmup，主要数据增强是水平翻转，评价使用 **EMA（指数滑动平均）参数**：把训练过程中多个时刻的参数做平滑平均，再用这份参数副本生成评价样本。这里说明的是这篇论文中稳定工作的配方，不是所有 Transformer 都不需要 warmup 的通用建议。[^setup]

<a id="scaling"></a>

## 6. “更能扩展”不是一句口号，要看怎样加计算

作者沿着两条轴扩展模型：

1. **把网络做大。** 增加层数、隐藏宽度等，得到 S、B、L、XL 四档。
2. **把输入切得更细。** 在同样潜表示上使用 p＝8、4、2，让网络处理更多 token。

组合起来是 **12 种模型**。论文先在相同的 400,000 个训练步上比较，再看训练过程中与总计算量之间的关系。[^scaling]

例如，在固定 XL 骨架、无额外 CFG 的 Table 4 中：

| 256×256 图像对应的模型 | 每次前向计算，GFLOPs | 参数量，约百万 | 400,000 步后的 FID |
|---|---:|---:|---:|
| DiT-XL/8 | 7.39 | 676 | 106.41 |
| DiT-XL/4 | 29.05 | 675 | 43.01 |
| DiT-XL/2 | 118.64 | 675 | 19.47 |

**参数几乎没变，计算和结果却变了很多。** 小块产生更多 token，给网络更多细粒度计算机会，同时带来更高成本。这里“/2”表示潜空间块边长 2，不是模型尺寸减半。

GFLOPs 在这里表示一次前向的浮点运算量，以十亿次为单位；不是硬件每秒性能，也不是生成一张完整图的总成本。表中还**不包含图像 VAE 的参数和计算**。

论文发现，在其测试范围内，更大模型、更细块通常对应更低 FID。Figure 9 做了比“同样训练步数”更进一步的比较：把横轴换成**估计的总训练运算量**。作者用“单次前向运算量 × batch × 训练步数 × 3”估算；最后的 3，是把前向加反向合计近似为三次前向，并非实测耗时。

在这种共同预算口径下，小模型即使多训练一些步，也会逐渐不如较大模型划算；固定 XL 骨架时，预算足够大后，XL/2 也超过了 XL/4。也就是说，结果不只是“花更多钱往往更好”，还说明**同样一笔较大的计算预算，怎样分配给模型大小、切块方式和训练长度，会影响效果**。[^scaling]

不过，相同训练步数不等于相同训练成本；较好的规模曲线也不是无限外推的定律。这项研究主要固定在 ImageNet 数据上，**没有同时证明任意扩充数据集、任意换任务都会得到相同收益**。

<a id="sampling-budget"></a>

## 7. 小模型多画几步，能不能追上大模型？

扩散有一个很诱人的选择：模型已经训练好了，还可以增加生成时的采样步数。于是自然会问，能不能用一个小模型多走几步，省下训练大模型的成本？

论文专门做了这项比较，而不是把“增加推理计算”与“增加模型计算”混在一起。作者对训练了 400,000 步的模型，比较 **16、32、64、128、256、1000** 个采样步。[^sampling-budget]

其中一个很说明问题的例子是：

| 模型与采样设置 | 每张图的估计采样计算 | FID-10K |
|---|---:|---:|
| DiT-L/2，1000 步 | 80.7 TFLOPs | 25.9 |
| DiT-XL/2，128 步 | 15.2 TFLOPs | 23.7 |

更大的 XL 模型只走 128 步，估计采样计算约为前者的五分之一，FID 仍然更低。

这个结果的启示很具体：**更频繁地询问一个能力有限的去噪器，不一定能替代一个预测更好的去噪器。** 在这些实验里，更多采样计算不能简单填平模型差距。

但也别把它扩大成“多步采样没用”。它说明的是这些模型、训练阶段和采样设置下的取舍；表中的 FID-10K 用 10,000 个生成样本，不能拿去与下一节 FID-50K 的数值直接拼接比较。这些 FLOPs 也不是实际墙钟耗时。

<a id="benchmark-results"></a>

## 8. 最终结果很强，但“第一”有清楚的范围

前面的 400,000 步主要用于研究设计和扩展规律。最终模型训练得更久：**256×256 的 DiT-XL/2 训练了 7,000,000 步，512×512 版本训练了 3,000,000 步**。不能把最终最好结果说成在前面短周期里就已经取得。[^results]

### 256×256：引导带来明显改善，也改变覆盖范围

Table 2 使用类别条件 ImageNet、50,000 个生成样本和 250 步 DDPM 采样，最终图像解码器采用 ft-EMA：

| DiT-XL/2 的采样设置 | FID，越低越好 | Recall，衡量分布覆盖的一面 |
|---|---:|---:|
| 无额外 CFG | 9.62 | 0.67 |
| CFG＝1.25 | 3.22 | 0.62 |
| CFG＝1.50 | 2.27 | 0.57 |

无额外 CFG **仍然是类别条件生成**，不能误写成无条件模型。随着引导加强，FID 变好，Recall 则下降，这延续了上一章讨论的质量与多样性取舍。

同表 LDM-4 在 CFG＝1.5 时的 FID 为 **3.60**、Recall 为 **0.48**；DiT 的这组结果更好。StyleGAN-XL 的 FID 是 **2.30**，DiT 的 **2.27** 是表中最低值，但很小的指标差距不等于每一张图、每一种评价都压倒性领先。

### 512×512：优于表中的扩散方法，不是优于全部方法

在 512×512 上，同样的 p＝2 会使 **64×64×4** 的潜网格产生 **1024 个 token**，每次前向增至 **524.6 GFLOPs**。Table 3 中，DiT-XL/2 在 CFG＝1.5 时的 FID 为 **3.04**，优于表中此前扩散组合的 **3.85**。[^results]

但表中 **StyleGAN-XL 为 2.41**，更低。因此，这里的准确说法是“超过该表此前的扩散结果”，不能写成“所有图像生成模型中全面最好”。

### 配套解码器也会影响分数

附录 D 使用同一个 256×256 DiT，替换三个预训练图像解码器。在 CFG＝1.5 下，FID 从原解码器的 **2.46**，变成 ft-MSE 的 **2.30**、ft-EMA 的 **2.27**。[^decoder]

为什么可以不重训 DiT 就换解码器？这三套自编码器的**编码器相同，只对解码器做了不同微调**，因此它们接收的是同一种潜表示。这个兼容条件很重要：实验没有证明，任意两个 VAE 的解码器都能随意互换。

因此，2.27 不是孤立地由 Transformer 这一个词产生的。训练阶段、引导、采样、图像解码器和评价协议，都参与了这个结果。这里的 ft-MSE、ft-EMA 是两套预训练图像解码器的版本名，不要与前面 DiT 自身训练时使用的 EMA 参数混成同一个选择。

附录还说明，论文的 CFG 实际施加在潜表示的前三个通道，而非全部四个。四通道引导可以通过不同强度得到相近或更好的数值；所以，只报一个 CFG 数字，仍可能遗漏实现口径。本章保留主表的 2.27，不把附录另一种配置的数字悄悄替换进去。

<a id="cost-and-limits"></a>

## 9. 它省了什么，又没有证明什么？

DiT 的结果说明，潜空间中的 Transformer 可以成为高质量、可扩展的去噪骨架。但需要区分两种比较：

- 与像素空间的巨大 U-Net 相比，潜空间模型的计算可以少很多，其中也包含**表示空间改变**带来的收益。
- 与潜空间 LDM-4 相比，256×256 的 DiT-XL/2 单次前向约 **118.6 GFLOPs**，LDM-4 约 **103.6 GFLOPs**；DiT 不是每次计算更少，而是在这一计算规模下取得了更好的样本指标。[^cost]

把二者混起来，就容易把所有收益都归给 Transformer，忘记潜空间压缩已经先做了一部分工作。

训练依然不是轻量任务。论文用 JAX 和 TPU-v3 pods，最重的 DiT-XL/2 在 **TPU v3-256、全局 batch 256** 上约 **5.7 次训练迭代/秒**。这个数字是训练吞吐，不是个人电脑生成图片的速度。

论文也没有取消以下限制：

1. **生成仍要多步调用网络。** 架构可扩展，不等于已经实时或一步生成。
2. **自编码器仍有信息损失。** 换去噪骨架没有自动变成无损恢复。
3. **更细 token 带来更高计算和存储负担。** 质量收益必须与预算一起看。
4. **ImageNet 类别条件结果不是开放文本或视频结果。** 本文结论不能直接替代那些任务的实验。
5. **评价范围有限。** FID、IS、Precision/Recall 各看不同侧面，不是事实正确、版权合规或内容安全的保证。

最后一点是使用生成模型时仍需单独检查的边界，不是声称这篇论文已经完成了全面安全审计。

<a id="history-and-synthesis"></a>

## 10. 走到第 31 节，前面的线索怎样汇合？

DiT 值得放在这一组章节的最后，并不是因为它终结了图像生成研究，而是因为前面的几种思想在这里发生了清楚的会合：

- **ViT** 提供把空间表示变成 token 序列的办法。
- **ResNet 的残差与初始化经验**进入 adaLN-Zero 的设计。
- **DDPM** 提供已知加噪、噪声预测和逐步生成的框架。
- **LDM** 提供较小、可解码的图像空间。
- **CFG** 提供采样时调整条件影响的办法。
- **规模研究**要求把参数、输入 token、训练计算和采样计算分别记清楚。

这些方法没有按照“新名字出现，旧名字消失”的顺序简单替代。它们在不同层次上组合，让后续研究能够重新选择部件。

### 但别把后来的故事倒灌成这篇论文的实验

讲义和口述说“替换 Stable Diffusion 里的 U-Net”，容易让人以为作者直接改好了原有的开放文生图系统。原论文的结论却明确把 **探索 DiT 在 Stable Diffusion、DALL·E 2 等文生图模型中充当替换骨架**列为后续方向。本文的实验贡献，是在潜空间类别条件生成上训练和比较 DiT。[^future]

“Transformer 统一不同领域”在这里首先是一项研究机会：相似的骨架可能共享软件、硬件和训练经验。这可以与主稿的 Hardware Lottery 视角联系起来理解，但不是论文测得的一项“生态收益率”，也不证明任意现成优化都能不加修改地迁移。

作者署名同样按原文处理：**William Peebles — UC Berkeley；Saining Xie（谢赛宁）— New York University**。首页脚注说明这项工作在 Meta AI 的 FAIR 实习期间开展，星号对应 Peebles。后续任职、Sora 团队沿革和具体视频模型架构，不由这张首页自动证明，也不作为本章已经核实的事实。[^people]

从 Brook 走到 DiT，可以形成一种读技术史的方法：**先问当时卡在哪里，再问换了哪个部件，最后看实验究竟支持多大的结论。** 这样再读一项新工作，就不必只盯着“是否 SOTA”，也不会因为熟悉几个术语就以为理解了整个系统。

<a id="three-questions"></a>

## 11. 思考与追问：用三个问题收尾

**DiT 出现后，扩散被淘汰了吗？**  
没有。Transformer 在这里承担扩散内部的去噪预测，训练与采样仍然属于扩散路线。

**为什么参数差不多的两个 DiT，效果和成本可以差很多？**  
因为潜网格切块方式改变了输入 token 数，同样的参数要处理更多位置，计算量随之变化。只比较参数量会漏掉这一维。

**为什么不能把 ImageNet 的 2.27 FID 当成“所有提示词都会画得很好”？**  
它来自特定类别条件基准、训练长度、引导、采样与解码器配置；并没有覆盖任意文字理解、复杂组合、视频或安全性。
