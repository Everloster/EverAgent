# AI演义·21｜Tülu 3：公开后训练的数据、过程与得失

[返回总览第 21 节](../AI演义_笔记分析与项目整合报告.md#paper-tulu3) · [上一章：ReAct](AI演义_20_ReAct_模型怎样边查边想_科普讲解_20261105.md)

知道“先学示范，再学偏好”，还不足以训练出好助手。示范从哪里来，偏好由谁判断，数学进步时其他能力是否退步，都要通过具体数据和实验决定。Tülu 3公开了各阶段数据、模型、训练与评测代码，也记录了没有选入最终方案的尝试，方便沿过程检查成绩如何产生。[^overview]

<a id="why-an-open-recipe"></a>

## 1. 从基础模型继续训练

2024年，Nathan Lambert、Jacob Morrison、Valentina Pyatkin、Shengyi Huang、Hamish Ivison等来自Ai2与华盛顿大学的作者，在Llama 3.1基础模型上继续训练知识问答、推理、数学、代码、指令遵循和安全能力。它没有重做预训练，也不承接GPT-3权重。

论文分四步：整理数据、监督微调SFT、直接偏好优化DPO、可验证奖励强化学习RLVR。只数更新参数的阶段则有三个，因而与讲义“三阶段”的说法能对应。数据比例、训练设置和检查点都经过选择，这是一套特定条件下的方案，不保证任意组合都有同样效果。

本章采用2025-04-14的v5，首版为2024-11-22，405B等扩展属于修订版内容。[^version]

<a id="three-kinds-of-feedback"></a>

## 2. 三种反馈教不同的东西

用一道自拟题说明：原有12支彩笔，新买两盒、每盒6支，现有多少？要求用两句话回答，第二句以“所以”开头。

| 阶段 | 收到的训练信号 | 例子 |
|---|---|---|
| SFT | 一份期望回答 | “新买的两盒共有12支，加上原来的12支。所以现在共有24支。” |
| DPO | 哪个候选更好 | 两份都算对，但更偏好清楚且遵守两句要求的一份 |
| RLVR | 程序检查结果 | 提取答案是否为24；指令任务可另设规则检查格式 |

三个阶段都更新参数，分别学习示范、候选取舍和可判定结果。[^stages] 论文实际使用数学与指令等不同任务集，没有训练过这道彩笔题，也没有给每道数学题同时检查上述中文格式。

<a id="data-before-training"></a>

## 3. 数据配比决定哪些能力得到练习

Tülu 3先确定目标能力，再选择真实对话、代码、数学、安全等数据，缺少的任务有针对性地合成。Persona数据借助不同人物设定生成多样任务，并非用户长期个人记忆。[^data]

Table 10对8B SFT做独立消融：去掉数学数据，MATH由31.5降到23.5，少8.0个百分点；去掉安全数据，六项安全任务平均由93.1降至74.7，少18.4分。[^sft-ablation] 后者不是现实风险变化比例，两项也不是连续删数据的累计结果。希望保留的能力，需要在训练与评价中有相应材料。

作者用文本片段匹配等方式检查训练与评测重叠，移除受污染材料。[^decontamination] 它能减少直接见过考题的影响，无法保证识别所有语义改写，也不能消除基础模型预训练可能见题的情况。

<a id="sft-demonstrations"></a>

## 4. 示范本身也需要检查

SFT让模型根据问题预测示范回答，不是给它上一次输出打分。事实、表达与约束错误都可能随示范进入训练。

Tülu 3保留一部分人类或强模型已有回答，对无回答或质量较弱的材料，用GPT-4o等重新生成，再筛选混合。[^sft] 这便于扩大数据，也依赖生成模型的正确性和风格。公开数据让这些依赖可以检查，不能使示范自动成为真值。不同任务训练能否迁移、是否损伤原能力，要在新题与消融中验证。

<a id="dpo-preferences"></a>

## 5. DPO学习候选之间的差别

对彩笔题，答对24支还可能冗长或不合格式。DPO使用“更好／较差”回答对，调整模型相对于参考模型的偏好；它不保证每条较差回答的绝对概率都下降，也不保证获偏好的内容正确。

合成比较的流程是：选择已有或新增提示，包括增加约束的题；从模型池生成候选，并纳入Tülu自身SFT回答；主要由GPT-4o按有用性、指令遵循、诚实性和真实性评分，取平均分最高者，再从较低分候选随机抽一份构成偏好对。[^preference]

这类偏好大量来自AI裁判，不等于真实用户投票。裁判漏检事实或偏爱某种措辞，训练也会受影响。自身回答参与比较在所测配置中有帮助；增加不同题目比同题反复配对更有价值。约6.4万题重组出约38.3万对，没有获得与行数增长相称的平均收益。[^preference-scaling]

论文采用按token长度归一化的DPO，减轻长度对训练目标的干扰，但不能消除裁判的全部偏差。选择还考虑训练速度和算力，PPO等替代方案并未获得同等充分调参，因此不构成算法普遍优劣结论。[^dpo]

最终方案先收集回答对，再离线训练。数据含自身生成回答，不意味着训练时实时探索。另做的在线DPO试验数学收益有限，部分指标下降，未进入最终方案；这也只说明该次实验结果。

<a id="rlvr-verification"></a>

## 6. RLVR用检查器提供任务奖励

RLVR全称Reinforcement Learning with Verifiable Rewards。数学可提取最终答案与标准值比较，部分指令可检查指定词、段落数等条件。Tülu 3在DPO后用PPO训练：当前模型生成回答，检查器评分，结合约束更新参数，再生成下一批。[^rlvr]

训练共29,946条提示，来自GSM8K、MATH和可验证指令。[^rlvr-data] 本配方没有实做运行单元测试的编程RLVR，代码执行属于可扩展方向，不能与讲义举例混写。

通过检查的任务奖励为10，否则为0，此外还有KL约束与未正常结束回答的惩罚。KL限制相对固定参考模型的分布偏离，强度需选择。PPO另训练价值模型估计后续回报；策略与价值模型更新，参考模型固定。[^rlvr-implementation]

价值模型可从通用奖励模型初始化。因此，任务奖励来自检查器，系统仍可能利用奖励模型已有训练成果。发布文中“without a reward model”的简写需按这个范围理解。

ReAct主实验在任务中取得观察、更新上下文，RLVR在训练中取得反馈、更新参数。一次对话验算不自动构成RLVR，接受过RLVR的模型也不自动具有部署工具、跨会话记忆或自主执行系统。

<a id="results-and-regressions"></a>

## 7. 数学进步与其他指标回退

下表只比较Table 23相同规模的DPO起点和RLVR终点。8B、70B约为80亿、700亿参数。[^results]

| 评测 | DPO后 | RLVR后 | 变化 |
|---|---:|---:|---:|
| 8B GSM8K，8个推理示例，答案匹配 | 84.3 | 87.6 | +3.3个百分点 |
| 8B MATH，4个推理示例，flex答案匹配 | 42.0 | 43.7 | +1.7个百分点 |
| 70B GSM8K，同样8示例 | 93.5 | 93.5 | 未变 |
| 8B TruthfulQA，6示例，MC2 | 56.1 | 55.0 | −1.1分 |
| 8B安全六任务平均 | 87.2 | 85.5 | −1.7分 |

示例数指评测提示中的示范，非训练或测试题总数。MATH按题目类别宏平均，TruthfulQA的MC2是多正确选项指标，不能当作自由回答真实率。

8B数学提高，70B的GSM8K未变，真实性与安全相关指标小幅回退。作者还放弃了一些单项更高、其他指标较差的检查点。模型选择需要按用途权衡，训练更久或奖励更高都不足以单独决定发布。

原文跨表也有差异：Table 23的IFEval标Strict，Table 24与评测章节标prompt-level loose，部分BBH与平均分不一致。[^evaluation] 本章只用可对齐的单项说明变化，不用冲突项重排总榜。Table 6相近规模比较中，Qwen 2.5 7B的表内平均仍高于Tülu 3 8B，也不支持“各项第一”的概括。[^peer-comparison]

<a id="pen-failure"></a>

## 8. 奖励检查通过，却没有回答问题

Figure 28展示了过度优化后的输出：[^failure]

| 请求 | 输出要点 |
|---|---|
| 测量笔长，单位厘米，并含timberlike、unconnectedly | 只写这两个词 |
| 同样问笔长，字母e出现14次 | 只列14个e |
| 同样问笔长，分5段 | 列Paragraph 1至Paragraph 5 |

程序能正确计数，计数要求却只占用户需求的一部分。题目也未提供测量信息，合理回应应说明需要测量或补充材料，既不能编长度，也不能只凑字符。例子说明检查范围，不代表总体失败率。

最终答案检查同样不验证每一步推导。彩笔题答24，过程仍可能错；要查过程需额外方法。作者尝试调整KL，Figure 29仍出现空的五段回答，不能将约束调高视为已经解决。

<a id="unseen-evaluation"></a>

## 9. 换题后能否保留提升

即使训练集删去考题，反复用同一评测挑数据、参数和模型，也可能使方案越来越适合那套题。Tülu 3区分开发评测与开发时不据其调模型的unseen评测，如数学另看DeepMind Mathematics，指令另看新约束IFEval-OOD。[^evaluation]

“未见”只针对本项目开发过程，不保证其他模型没见过，也不保证基础模型全部预训练资料可查；论文没有独立的unseen安全评测。

Table 31的8B从DPO到最终模型，DeepMind Mathematics由33.0升到35.4，BigCodeBench-Hard pass@10由9.5降到7.4。[^unseen] 后者是148道难题子集，非全部1,140题，采用instruct题面和calibrated评分。pass@10关注十候选中至少一份通过，不是单次成功率，也不要求十份全过。

新约束IFEval-OOD的迁移仍困难；部分数学回答固定格式干扰了其他题集的推导或答案提取，但不能将所有下降归于格式。Table 33统一的unseen平均中，Tülu 3 8B为34.2，Llama 3.1 8B Instruct为36.4，只能在该表任务集合内比较，不能与开发集平均相减。

## 10. 从公开材料追查训练变化

Tülu 3除了最终权重，还提供中间模型、数据与代码。[^artifacts]

| 研究问题 | 材料入口 |
|---|---|
| 示范内容和配比 | [SFT数据](https://huggingface.co/datasets/allenai/tulu-3-sft-mixture)与数据消融 |
| 如何构造比较对 | [8B偏好数据](https://huggingface.co/datasets/allenai/llama-3.1-tulu-3-8b-preference-mixture)与§5 |
| 哪些条件由程序判断 | [RLVR混合数据](https://huggingface.co/datasets/allenai/RLVR-GSM-MATH-IF-Mixed-Constraints)与§6 |
| 训练阶段如何连接 | [Open Instruct](https://github.com/allenai/open-instruct) |
| 评测规则与配置 | [OLMES](https://github.com/allenai/olmes) |

原稿读过论文与训练仓库README，未逐行核代码、逐条查数据或执行训练。当前仓库也不能自动代表论文当年的固定快照。

实现会改变资源需求。DPO缓存固定参考结果，并分别前向处理较好、较差回答以节省显存。RLVR需要组织策略、参考、价值模型，以及生成与更新的并行；作者使用ZeRO、vLLM、Ray等，并处理异步生成数据滞后。[^engineering]

8B的DPO阶段使用8张H100约10小时，未含示范生成、其他阶段和消融。公开代码可用于学习或缩小实验，原成绩对应原数据、硬件和预算。

贡献表列出数据、SFT、偏好、强化学习、评测和发布等工作。作者也记录拒绝采样在当时配置下相对算力收益有限，没有将它纳入必经步骤。[^negative] 这些材料帮助后来者判断从哪里继续试。

<a id="thinking-and-questions"></a>

## 11. 将评价方法用于自己的任务

[实践建议，待验证] 先确定要改善的行为，再选择相应反馈；事实、表达、引用与格式可能需要不同检查。调整一项时保留其他重要任务，并留新题到最后评价，减少反复修熟悉例子的偏差。

对报告写作，程序能检查链接与结构，却不能代替阅读证据；评审模型偏好的文风也需与真实读者判断对照。若只检查最终答案，过程错误仍可能遗漏，增加过程检查则要衡量成本。这些是评价方法的借鉴，提示调整与参数训练仍有区别。

Tülu 3对长上下文、多轮、多语言和工具Agent的覆盖仍不完整，论文将它们列为后续工作。[^future] 数学与指令成绩不能直接证明复杂长期助手能力。接下来的 [DeepVideo](AI演义_22_DeepVideo_模型怎样利用视频时间信息_科普讲解_20261105.md)将转入视觉与视频，研究输入从单张图像变为连续帧后，模型怎样利用时间信息。
