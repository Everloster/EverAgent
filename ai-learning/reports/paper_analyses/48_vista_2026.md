# VISTA：视觉原生 Harness 论文精读

> **一句话**：不训练任何模型，只改"模型获取、保存和使用视觉信息的方式"——把每帧原样存档（无损视觉记忆）、让模型带着问题按需回看（主动视觉检查）——Claude Opus 5.0 在 ARC-AGI-3 的相对人类动作效率（RHAE）从官方基线 40.68 升至 **100.00**（25 个公开游戏全通、动作数比首玩人类少 57.4%），GPT-5.6 Sol 达 99.00。**首个不用程序合成、纯视觉路线达到 ARC-AGI-3 满分或近满分的系统。**

---

## 0. 两段式研究说明

本报告是「源码（infra 仓 refer 手册）+ paper（本报告）」双段任务的公开侧产物。源码侧已核验：论文宣称的全部组件在 MIT 代码里真实落地（`play/inspect/read_pixels/history` 四工具、GUIDE/WORKING 双笔记、三重恢复分类学、Claude Code/Codex CLI 经 Docker+MCP 被雇佣为玩家主体）。**paper 与代码一致性：未发现冲突**——这在 agent 论文里本身是稀缺属性。

## 1. 问题设定：为什么"文字记忆的 harness"在视觉世界不够

ARC-AGI-3 不给规则：agent 必须观察-行动自己摸索。已有思路把画面转成数字文本网格再写程序模拟——但环境越复杂，外观/空间/动态越难完整文字化；且交互历史变长后早期画面被挤出上下文或被摘要替代。**核心洞察：模型第一次看一帧时，未必知道哪个细节后来会变得重要**——所以不能提前摘要，只能全存、按需取。

VISTA 的研究问题：*不额外训练模型，如何让 agent 在推理需要时重新检查过去看到的视觉信息？* 这与 Anthropic 去年 11 月的 harness 博文（任务清单+进度文件，纯文字状态跨上下文窗口）直接对话——VISTA 把同一哲学推广到视觉域。

## 2. 方法：三组件 + 双笔记（paper §3 与源码互证）

| 组件 | paper 表述 | 源码落地（见 refer 手册） |
|------|-----------|------------------------|
| **视觉观测** | 64×64 官方帧 8× 最近邻放大为 512×512 PNG，保留颜色/外观/空间关系 | `tools.py` 的 `DEFAULT_DISPLAY_SIZE=1024` 坐标系；inspect 的 region 裁剪**无平滑放大**（保像素证据） |
| **无损视觉记忆** | 每次动作后保存环境返回的**所有**画面（含动画中间帧），按回合号+帧号索引 | `session.py`/`artifacts.py` 归档管线；默认每次 play 只回末帧，中间帧全进档案（上下文不浪费） |
| **主动视觉检查** | inspect：选历史回合/裁剪区域/多帧对比 | schema 强制 `question` 必填（"State the visual question these views should answer"）≤16 views；`read_pixels` ≤64 views/≤4096 samples 读数值像素 |
| **双笔记** | GUIDE.md（跨关可复用规则）+ WORKING.md（当前关状态/计划） | `harness.py:64` GUIDE 初始为 `"No reliable model yet."`——显式认知空白，逼模型自己挣出世界模型；64KB/16KB 上限 |

**执行循环**（源码 `episode.py`，60 行）：观察→结合经验提出行动假设→（信息不足则 inspect/read_pixels 找证据）→**先预测动作效果**→执行→对比预期与实际→修正规则理解。预测-验证写进 7 行 system prompt："Before each action, state what you expect to see. Afterward, state all visible changes, expected or not."

## 3. 实验与消融（精确数字）

### 3.1 主结果（ARC-AGI-3 公开集 25 游戏）

| 系统 | 模型 | RHAE | 动作数 | 通关 |
|------|------|------|--------|------|
| 官方基线（无程序） | Opus 5.0 high | 40.68 | — | — |
| 官方基线（无程序） | GPT-5.6 Sol max | 13.33 | 10,619 | 4/25 |
| **VISTA** | **Opus 5.0 xhigh** | **100.00** | 比首玩人类**少 57.4%** | **25/25** |
| **VISTA** | **GPT-5.6 Sol max** | **99.00** | 9,126 | 25/25 |

### 3.2 逐组件消融（Figure 5，GPT-5.6 Sol，ARC-AGI-3）——本论文最硬的证据链

| 配置增量 | RHAE | 动作数 | 通关率 |
|----------|------|--------|--------|
| 官方 text grid 基线 | 13.33 | 10,619 | 16% |
| (i) + PNG 图像观测（换掉文本网格） | 47.32 | 16,343 | 36% |
| (ii) + 提高动作/时间上限 | 51.66 | 22,544 | 44% |
| (iii) + 连续对话 | 65.82 | 28,626 | 60% |
| (iv) + GUIDE.md/WORKING.md | 70.05 | 23,702 | 76% |
| (v) + 无损记忆与 inspect | 94.10 | 12,261 | 96% |
| (vi) + read_pixels（完整 VISTA） | **99.00** | **9,126** | **100%** |

**读法**：单纯把文本网格换成图像就 +34 分（47.32）——说明瓶颈首先在观测表征；但真正跳变来自 (v) 无损记忆+inspect（70→94，且动作数反降）——**"能回看"比"看得清"更值钱**；(vi) read_pixels 再 +5 且动作数降到 9,126——像素级证据让模型敢于少试错。注意 (iii) 连续对话的动作数峰值（28,626）：更多预算若无记忆支撑只带来更多瞎试。

### 3.3 开放权重模型（Figure 8，GLM-5.3 Flash 320B）

| 配置 | RHAE |
|------|------|
| 官方实现 | 1.89 |
| VISTA w/o visual harness（去 inspect/read_pixels） | 13.27 |
| **VISTA 完整** | **66.93** |

**35 倍提升且无需训练**——harness 红利对开放权重模型更大（基线越弱，脚手架越值钱）。对我们手上的 GLM 生态是直接可复现的实验位。

### 3.4 泛化（同 GPT-5.6 Sol，对比各官方基础框架）

- GameWorld（170 任务）：成功率 40.0% → **63.3%**
- AI GameStore（10 游戏，人类中位数=100）：47.3 → **140.3**（超人类中位）
- BabyVision（39 道迷宫/连线，纯静态图）：41.0% → **63.2%**——**没有交互也能获益**，证明放大/读像素本身就是视觉推理增益

### 3.5 其他消融

- 图像倍率（2×/4×/8×/16×）：token 消耗 39.8M/28.2M/30.7M/71.1M——8× 是甜点（512px）；16× 只贵不好。
- 上下文上限（触发压缩的位置）与压缩前后行为：源码侧的三重恢复分类学 + 压缩握手（先更新 WORKING.md 再 compact）是这里的工程对应物。

## 4. 源码宝石精选（详细版在 infra refer 手册）

1. **7 行 system prompt**：全部认知策略（可修正世界模型/预测-验证/双笔记）压进三句话——与工程 harness 的千行 prompt 形成光谱两端。
2. **harness 套 harness**：Claude Code/Codex CLI 被当作通用执行引擎经 Docker+MCP 雇佣——coding agent 的工具循环被当成任意长期任务的运行时（这本身是对"coding CLI 已成通用 agent 底座"的一次学术背书）。
3. **恢复即宪法**：`episode.py` 模块头一句 "never invent a continuation or recovery prompt"——所有恢复 prompt 预先声明，运行时不得即兴；三重恢复（Compact/Retry/Runtime）用标记文件状态机实现，终止原因全是机器可读枚举。
4. **凭据隔离**：`credential_free_environment()` + `replace_oauth_token()`——与 EverAgent Token Plan「凭据只在执行域解析」同构。

## 5. 与知识库的连接

- **Agent Harness 学习计划**（codex/dsh/pi）：VISTA 是第四样本——学术自觉形态。三仓是"harness 内部机制"，VISTA 是"harness 的认知理论"：GUIDE/WORKING 显式化了 dsh/codex 隐式做的上下文管理。编号 46 的《evolve the harness》精读 + 本篇 = harness 论文线的两块基石。
- **ARC-AGI-3 日报线**（2026-09-04 记"半年饱和、2 倍于 Chollet 预期"）：VISTA 正是饱和的主力工作之一——且论文显示饱和方式是"harness 增强"而非"模型增强"，这是对"ARC-AGI-3 测的是什么"的重要注脚。
- **李继刚「上下文是一辆车」/ Hindsight mental models**：GUIDE.md=沉淀结论（mental model 的手工最小版）、WORKING.md=工作记忆、无损视觉档案=未摘要的原始证据——同一个"分层整理 vs 堆上下文"设计空间的第三次独立发明。VISTA 的 (v) 消融（+24 分）给这个流派提供了最硬的量化证据。
- **GLM 生态**：Figure 8 的 GLM-5.3 Flash 320B 结果（1.89→66.93）是现成的复现实验位（模型 plan 家底直接可用）。

## 6. 批判性评估

1. **任务域窄**：交互式解谜/游戏的"视觉"与真实机器人视觉差距大（作者也承认，具身是 future work）；静态 BabyVision 的增益（63.2%）相对温和。
2. **成本未充分披露**：99 分的 token 消耗是多少？消融给了 per-game token（8× 约 30.7M 总量级），但完整 VISTA@Opus xhigh 的每游戏成本需要从 arcprize scorecard 反推——"满分"的美元价格是落地关键问题。
3. **RHAE 的口径**：动作效率以"首玩人类"为基线，二玩人类会更强；57.4% 少于首玩人类 ≠ 超越人类上限。
4. **无损档案的可扩展性**：25 个游戏×几百回合的帧量轻松；但千小时具身任务的档案检索（turn/frame 索引够不够）未讨论——Hindsight 式的检索层可能是下一步。
5. **单一团队自测**：基准分数有 arcprize 官方 scorecard 背书（可复现性强于一般论文），但跨团队复现还没出现。

## 🤔 思考与追问

1. **我真正理解了什么？**
   VISTA 用一个干净的六段消融证明了：在视觉 agent 里，**"记忆的组织方式"贡献了最大的单段跳变（+24 RHAE）**，超过观测表征升级（+34 中含基线切换）之后的任何单项。这与文本侧的结论（Anthropic harness 博文、李继刚的上下文管理、Hindsight 的分层记忆）在完全不同的模态里收敛到同一设计原则：**不要摘要，要可检索的原始证据 + 按需重组**。这是"harness 层创新 > 模型层微调"这一命题目前最硬的证据。

2. **我还没搞懂什么？**（汇入 open-questions）
   - 完整 VISTA@Opus xhigh 的每游戏 token/美元成本（从 scorecard 反推）；(v) 档段动作数反降（12,261<23,702）的机制——是"回看减少了试错"还是"inspect 调用挤掉了 play 调用"？
   - 视觉档案的检索接口（turn/frame 索引）在长程任务（千+回合）下是否需要语义检索层？VISTA 的显式注意力能否与 Hindsight 式 embedding 检索互补？
   - "先预测后验证"在 prompt 里只占一句，但它是否是不可移除组件？论文没有单独消融它（藏在 (iii) 连续对话里）。

3. **下一步做什么？**
   - **复现实验位（B 类候选）**：GLM-5.3 Flash 320B + VISTA 在 Razer Ubuntu 侧跑 ARC-AGI-3 公开子集（arcprize key 可申请），对照 Figure 8 的 66.93——检验 harness 红利在我们自己的模型栈上的成色。
   - 把「分层整理 vs 堆上下文」做成跨模态 synthesis：Anthropic 博文（文本）+ 李继刚（个人实践）+ Hindsight（产品）+ VISTA（视觉/学术）四源对照，产出 wiki/syntheses 页。
   - 深挖 refer 手册"未读区"（Budget 体系/quota.py/batch.py），补全源码侧。
