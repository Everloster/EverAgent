# 47. 字节级蒸馏突破 Token 天花板（Marathe & Pagnoni et al., 2026）

> 一句话：把蒸馏的学习单位从 token 换成字节——教师的 token 概率分布经**单次前向**转换到字节级（近似版 Marginalize-It / 精确版 End-Of-Token），~1.28B 学生在约万亿字节上过度训练，缩放律外推预测天花板 **52.4% vs Token 蒸馏的 48.4%（+4 个点）**，且只需 1/6 训练文本、1/5 logit 存储。**但所有"超越"都是外推：实测最大 checkpoint（44.6%）仍未超过 Llama-3.2-1B（45.9）与 Gemma-2B（50.3）；换验证集，追平点移动 27 倍。**

## 1. 历史叙事：字节 vs Token 之争为何此刻升温

Token 化（BPE 系）统治 LLM 十年，字节级建模从未退场但一直是"理想派"路线：**ByT5**（Xue et al. 2022，免分词但训练慢、推理贵）、**MegaByte**（Yu et al. 2023，patch 化实现亚二次注意力）、CANINE（2022，无词表编码器）、**BLT**（Pagnoni et al. 2025，local encoder/decoder + 熵驱动 patch——**本文共同一作 Pagnoni 正是 BLT 作者**）、H-Net（2026，动态分块）、EvaByte（2025）。

三股力量让争论在 2026 年重新升温（论文 §9 叙事 + 本报告梳理）：
1. **小模型服务成本**倒逼：端侧/边缘部署要 1B 级强模型，蒸馏+过度训练是标准配方（论文 p.1）；
2. **字节侧证据累积**：BLT 证明"patches scale better than tokens"，Lee et al. 2026 证明字节模型随算力逼近 BPE；
3. **蒸馏的暗伤被摆上桌面**：token 蒸馏要存教师全量 logit——2T tokens × 128,256 词表 = **1.026 EB**（float32，p.25），工业惯例只能存 top-k（本文取 k=600），**学生实际学的是被截断的教师分布**。字节词表仅 ≈260 维，全分布直接存，这一刀省掉截断损失 + 存储降 5 倍。

## 2. 方法：Token 分布 → Byte 分布的两种转换（§2，p.4-5；附录 F，p.46-49）

**问题形式化**：教师在位置 t 给出 128,256 维下一 token 分布；每个 BPE token 可解码为字节串。学生逐字节建模，需要沿真实字节路径的条件分布 P(b_k | b_<k, context)。前作（Hayase 2025；Phan 2024）能精确转换但**需对每个中间前缀各跑一次教师前向**，长序列上不可行（p.3）。

### 2.1 Marginalize-It（近似）

- 第 1 字节：全词表按首字节聚合（**精确**）；
- 第 k 字节（k≥2）：把候选集收缩为"前缀匹配真实字节且长度 > k"的 token 子集，聚合第 k 字节并**重新归一化**；
- **丢失**：在 k 步前已结束的 token 的概率质量被静默摊给幸存候选。例：P(isu)=0.5/(0.5+0.125)=0.8、P(isk)=0.125/0.625=0.2，而 P(is)=0.125 消失（p.4 的例子）；
- 伪代码（p.46）单趟可完全向量化：沿 gold 路径逐字节收缩 live 集合 + bincount 聚合 + 归一化。

### 2.2 End-Of-Token（精确）

两处改动：①字节分布扩 1 维存 **<eot>**（词表 257；学生完整词表 261，Table 1 p.6）；②训练数据里每个 BPE token 后插入 <eot>：[<bos>,<eot>,T,<eot>,i,r,a,m,<eot>,i,s,u,<eot>,<eos>,<eot>]。于是"已结束 token 的概率质量被 <eot> 吸收"——计算第三字节时 is（带 <eot>）仍在候选集内，教师分布**精确保留，且无需额外教师前向**（p.4）。四种边角情形分析（F.2，p.46-49）：Case I/II 两法都精确；Case III（备选路径更短）与 Case IV（更长）只有 EOT 精确。

**代价**：每 ≈4.5 字节多一个 <eot>（单位序列变长 4.5→5.5 units/token），**每单位数据训练算力 +30.94%**（Table 3 注，p.8）。注意口径：这是"每 BPE token 的训练 FLOPs"账（39.65→51.92 ×10⁹），**不是总算力账、更不是推理成本**。

### 2.3 与 top-k 截断的关系

等存储前提（§3.1 p.6）：Token 学生存 top-k 的 float32 值 + int32 索引 + int32 id；字节学生存 260 维全分布 + int16 id。解得 k≈**600**（p.26）——即论文里 Token 蒸馏学生学的就是 top-600 截断分布；字节方案绕开截断，这本身就是信息优势。

## 3. 实验设置（§3 p.6；附录 A p.24-26）

- **学生**：Llama-3 式 dense decoder-only，SwiGLU，d=2048，FFN 5632，25 层 16 头；三者**层参数严格相等 = 1,284,608,000**；差异仅在 embedding：Token-1B 总参 1.81B（词表 128,256）vs 字节系 ≈1.286B（Table 9，p.24）。
- **教师**：Llama 3-8B（验证集 BPB 0.85511）；离线 dump logit。
- **六组**：Token 监督 / Token 蒸馏(top-k) / Bytes 监督 / Marginalize-It 蒸馏 / Bytes+<eot> 监督 / End-Of-Token 蒸馏（Table 1，p.6）；L_KD = α·L_KL + (1−α)·L_CE，**α 取值论文未报告** [存疑]。
- **数据**：Llama-2 预训练混合语料；1 token ≈ 4.5 字节；刻度扫到 ≈1 万亿字节（Bytes 9 档至 968B、EOT 9 档至 1.2T units，Figure 3，p.7）；LR ∈ {1e-3, 4e-3, 8e-3}，每 run 64×H200；字节模型初期 loss spike，靠 qk-norm + 调序列长度稳定（p.25）。
- **评测**：8 个 benchmark——ARC-E/C、HellaSwag、PIQA（选择）+ MBPP、Natural Questions（生成）+ Flores En↔De（翻译，BLEU 单列）；**"平均 top-1"口径只用前 6 个**（§6.4，p.14）。

## 4. 缩放律拟合与外推结构（§4/§6；附录 D/E）

两阶段（沿用 Gadre et al. 2024 框架）：

- **阶段一 compute→验证 BPB**：幂律 y = b·x^a + c（式 1，p.7），含不可约项 c；R² ≥ 0.9974（Table 2/13）；
- **阶段二 BPB→下游平均 top-1 误差**：指数衰减 z(y) = ε − k·e^(−γy)（式 2，p.14），渐近精度 z⋆ 由阶段一的 c 约束。**下游拟合未报告 R²；全程无形式化置信区间** [存疑]。

实测到 ≈10²² FLOPs，渐近点外推到 10²³+（Figure 3 明确区分 Interpolation/Extrapolation 区）。关键数字全部出自 **LR=4e-3 + 验证集 1** 单一组合（Table 5，p.16）：

| 方案 | 渐近 BPB c | 渐近精度 a⋆（6 任务平均） |
|---|---|---|
| Token 蒸馏 | 0.9407 | **48.4%** |
| Marginalize-It 蒸馏 | 0.9016 | **50.5%** |
| End-Of-Token 蒸馏 | 0.8983 | **52.4%** |
| Bytes 监督 | 0.8967 | 51.2% |
| Bytes+<eot> 监督 | 0.8891 | 51.6% |
| Token 监督 | 0.9568 | 46.0% |

**追平点**（Table 6，p.18）：EOT 蒸馏达到 Token 蒸馏渐近精度需 BPB 0.9145 → 反解得 **6.33×10²² FLOPs**；MI 需 2.04×10²³（贵 3.2 倍）。**效率账**（Table 7）：该算力下 EOT 耗 5.48×10¹² 真实字节 vs Token 蒸馏 3.48×10¹³ → **数据省 6.35×（≈1/6）**；logit 存储 **省 5.19×（≈1/5）**。

## 5. 批判性分析

### 5.1 外推可信度：叙事很硬，支点很软

- **头部数字全系单一组合**：换 LR，1e-3 下天花板 46.6/49.0/49.7、8e-3 下 45.7/47.0/49.8（Table 15，p.36）——EOT 领先仍在，但 Token 蒸馏在 8e-3 时甚至输给 Token 监督（45.7 < 45.8），蒸馏本身的增益并不稳。
- **换验证集，追平点爆炸**：验证集 2 上 EOT 追平点 6.33×10²² → **1.69×10²³（+27 倍）**，MI 到 1.60×10²⁵，1e-3 下无法计算（Table 22，p.44）；EOT 领先幅度从 4.0 缩到 1.8 个点，且 MI 蒸馏（48.9）被 Bytes 监督（50.5）反超（Table 21，p.43）。论文自己承认："验证集选择会改变训练曲线的追平点，从而改变对'哪个模型更好'的感知"（§D.3，p.40）。
- **外推纯度**：作者自陈"some of our larger training runs epoch"（§10.1，p.21）——大尺度 run 存在多 epoch，严格说不是纯 scaling 数据。
- **"超越开源模型"全是预测**：渐近外推 52.4 vs Llama-3.2-1B 45.9（+6.5）、Gemma-3-1B-pt 44.3（+8.1）、Gemma-2B 50.3（+2.1）；但**实测最大 checkpoint 的 EOT 平均只有 44.6%**，尚不及 Llama-3.2-1B 与 Gemma-2B（Table 18，p.37）。量子位完全没提这层。

### 5.2 +4 个点的实际意义 vs 推理成本缺失

+4 个点是**渐近差**，且仅 6 任务平均、对验证集敏感（缩到 1.8）。更关键的是论文自承 **"End-Of-Token-1B models remain significantly expensive at inference time"**（§10，p.20-21）：逐字节解码让序列长 4.5-5.5 倍，自回归步数同倍增长；"与等推理成本的更大 Token 模型公平比较"超出本文范围。也就是说——**"天花板更高"是在训练算力轴上说的；在部署最关心的推理成本轴上，这场比赛还没开始**。ByT5 当年的死因（"训练慢、推理贵"）并未被本文解决，只是被缩放律绕开了。

### 5.3 +30.94% 开销被如何处理

量子位忠实保留了这一数字且语境正确（per unit of data）。但值得点破的是论文自己的叙事技巧："unintended but remarkable consequence: the ≈30.94% additional compute … turns out to further improve asymptotic performance"（p.4）——EOT 相对 MI 的优势里，有多少来自"精确保留分布"、多少来自"每 token 多算 31%"？论文没有拆这个因子（Table 3 注只说单位数据算力越高渐近 BPB 越低）。**EOT 可能部分是"花钱买性能"**——这对"精确转换"的方法论卖点是个需要在意的 confound。

### 5.4 中文/多语言与长上下文视角（本报告分析，非论文内容）

- **中文**：UTF-8 下一汉字 = 3 字节，而 Llama-3 tokenizer 对中文约 1 字/ token。字节模型在中文上序列膨胀 ≈3×，<eot> 密度变成每 ≈3 字节一个（开销比英文更高）；Llama-2 语料英文主导，论文唯一多语言评测是 Flores En↔De（拉丁字母），**中文场景无任何证据**——优势（无 OOV、对混合脚本健壮）与劣势（序列成本×3、<eot> 比例失调）都只能算假设。[分析]
- **长上下文**：字节模型的有效上下文按字节计，1M token 窗口 ≈ 4.5M 字节单元，注意力成本压力显著大于 token 模型；BLT/H-Net 的 patch 化正是为此存在，而本文学生是**纯平字节流 dense transformer**，长上下文不是其目标场景。[分析]

### 5.5 原文内部瑕疵（精读发现，引用时留意）

Table 2 与 Table 13 的 R² 两格打架（疑误抄列）；附录 G 例子 0.462 vs 0.463 前后不一；§6.1 obs 2 与同页 obs 1 及图注矛盾（疑笔误）；Table 18 的"880B"刻度与 Figure 3 最大刻度对不上、单位未注明；蒸馏 α 未报告；下游拟合无 R²。

## 6. 实用视角：个人/小团队何时选这条路

**值得考虑的场景**：①自建离线蒸馏管线、教师 logit 存储是瓶颈（字节方案 1/5 存储 + 免 top-k 截断的信息损失）；②训练语料贵/少（1/6 文本效率）；③输入含大量噪声文本、混合脚本、非自然语言符号（无 OOV 的天然健壮性）。
**不该选的场景**：①推理成本敏感（逐字节解码 4.5-5.5× 步数）；②快速出活（低算力区 Token 蒸馏全面占优，字节模型"起步慢"）；③中文为主（证据空白+序列膨胀）。
**与经典蒸馏法的取舍**：top-k LogDistill 是省存储的行业惯例（本文证明它等价于让学生学截断分布）；on-policy GKD 用学生分布采样缓解 train/inference mismatch，与本文正交——**字节转换可以叠加在 GKD 上**（教师分布转换与学生采样是两个维度）。对小团队的现实建议：先按本文伪代码（附录 F.1，p.46，几十行）实现 Marginalize-It 做 A/B——它是单次前向、无 +31% 开销的版本；确认字节路径在你的数据/任务上成立后再上 <eot>。

## 8. 量子位转述核对

**准确**：三种方案天花板（48.4/50.5/52.4，正确写成"个百分点"）、6.33×10²² 追平点、1/6 文本、1/5 存储（保留 k=600 前提）、+30.94%（语境正确）、"51.2 > 50.5 因近似丢概率"、"未做等推理成本比较"、层参数/教师/数据规模/评测构成、两方法机制描述。
**遗漏**：①**最大遗漏——"超越"全是外推**，未提实测 44.6% 仍落后 Llama-3.2-1B/Gemma-2B；②天花板口径是 6 个（非 8 个）benchmark 平均；③验证集敏感性（追平点 ×27）；④MI 追平点 2.04×10²³、EOT 监督 51.6%、大 run 多 epoch。总评：转述忠实度高、无实质夸大，但"天花板破了"的标题 + 遗漏外推属性，读者容易把预测当事实。

## 思考与追问

1. **验证集让追平点移动 27 倍，缩放律"天花板"叙事还剩多少决策价值？** 论文的稳健性证据是 Leave-One-Out 的 Δc 散布（字节系 0.0065-0.0181，远大于 Token 系）——字节模型本身就对拟合更敏感。对工程决策而言，是不是该把"渐近差"折现成"在 X×10²² FLOPs 处的预测差 + 实测中点验证"再行动？判别性实验该长什么样（在 3-6×10²² 处放一个实测点看是否落在预测带内）？
2. **<eot> 是"免费的边界监督"吗？** 它名义上为保留教师分布而生，实际上把 BPE 边界作为显式分割信号注入学生——这与 BLT 的熵驱动 patching、H-Net 的动态分块是否殊途同归？反向问：把 <eot> 加进 **token 模型**自身的预训练（显式教分割），能不能也白捡性能？这个 ablation 论文没做，是不是比"蒸馏"更便宜的验证入口？
3. **字节蒸馏 × on-policy 的组合点在哪？** 本文全是离线蒸馏（教师分布预先 dump）；GKD/on-policy 用学生采样纠正分布失配。字节空间词表小、全分布可得，是否使 on-policy 蒸馏的 KL 计算也变得更便宜（无 top-k 偏差）？小团队自建管线时，"字节转换 + on-policy"会不会是比"token top-k + 离线"更优的默认起点？
