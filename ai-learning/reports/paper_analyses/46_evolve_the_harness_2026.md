## 🎯 一句话总结

> 同一个**冻结不动**的模型，只靠一个自动循环去改它外面的"脚手架"（提示词 + 工具 + 校验代码），就能把一个法律 Agent 基准的通过率从 **63.4% 干到 80.1%**（一手实测，held-out 测试集）——而**贡献最大的那几处改动，不是改提示词，而是加了几行确定性的校验代码**。这戳中了当下最大的误区：一遇到 Agent 不行就想换更强的模型 / 微调，其实**模型周围的工程（harness）才是被严重低估的杠杆**。

## 🧭 追问深入：这次"进化"的到底是哪一层？

> 你读上一篇 J-space 时卡在"全局工作空间是权重还是 harness"。这篇正好是它的**镜像问题**：这里说的"进化 harness、不训模型"，进化的到底是什么？把一个 Agent 系统拆三层，一眼就清楚：

| 层 | 是什么 | 这篇里变不变 | 本文的做法 |
|----|--------|------------|-----------|
| **① 模型权重** | 训练学到的固定数值 | **完全冻结** | 一个字节都不动（DeepSeek-V4-Pro） |
| **② Harness / 脚手架** | 模型外面的：**系统提示词、工具定义、校验/后处理代码、编排逻辑** | **← 就是进化这里** | 自动循环反复重写它 |
| **③ 单次调用的激活** | 处理某个具体任务时的当下神经活动 | 随输入自然变化 | 不是本文对象 |

**所以"进化 Harness"= 只动第 ②层**。这和"微调 / 训练"（动第①层权重）是**两条完全不同的路**——这正是标题"Don't train the model"的字面意思。

**再往里拆一层，第②层内部还分两种东西，本文最重要的发现就藏在这**：

- **② a 提示词类**（prompt playbook）：系统提示、few-shot 例子、"你应该这样想"的指导语——**软的、靠模型理解**。
- **② b 确定性代码类**（deterministic code）：工具、校验器、后处理修复——**硬的、写死的 if-else，不依赖模型发挥**。

> 💡 **本文的杀伤性结论**：自动循环挑出的**最强 6 处改动里有 5 处是 ②b（确定性代码），不是 ②a（提示词）**。换句话说，大家以为"调 Agent = 写更好的 prompt"，但实测**最大的分数来自加几行'兜底代码'**。作者给它起名叫 **"被管理糟糕的天才假说"（mismanaged geniuses hypothesis）**：模型本身很聪明（天才），失分往往不是不会做，而是**输出格式/落地环节被搞砸了**，用死代码兜住就行。

**一个最典型的例子（贡献最大的单点改动）**：`deliverable_landing_gate`——模型把答案文件**写错了目录 / 起错了名**，导致评判根本读不到，白白丢分。修复方法**不是求模型别犯错**，而是加一段确定性后处理：solve 完把文件挪到对的位置。**零额外 token、纯代码**，dev 集 pooled 通过率 72.8%→79.2%。

## 🔬 Step 1｜一手实验到底做了什么（Niklaus 原文）

**目标**：给一个法律 AI Agent 提分，但**不许训模型**（模型太贵/太慢/闭源，改不动）。

**四个角色**（都是现成模型，全程不训练）：
- **执行者**：`DeepSeek-V4-Pro`，权重冻结——它是被优化的"手"。
- **提议者**：`Claude Opus 4.8`——读失败案例，提出"harness 该怎么改"。
- **评判者**：`claude-sonnet-4-6`——按 rubric 给每个任务打分。
- **框架**：**Meta-Harness loop**（arXiv 2603.28052）——把上面三个串成一个自动进化循环。

**循环怎么转**（how-it-works）：
```
现有 harness 跑 dev 任务 → 评判打分 → 挑失败案例
   → Opus 4.8 提议一处改动（改提示词 / 加工具 / 加校验代码）
   → 新旧 harness 各跑 3 遍取均值 → 比较
   → 新的比旧的高 ≥ 1 分才"晋级"（min_delta=1）→ 否则丢弃
   → 循环
```

**打分公式**（这是理解一切的关键，别被"通过率"单一数字骗了）：
```
score = pooled_criterion_rate           # 各条 rubric 标准的通过比例（主项）
      + 0.5 × all_pass_rate             # 一个任务所有标准全过的比例（加权 0.5）
      - 0.005 × tokens_per_million      # token 惩罚项：鼓励省钱
```
每个任务跑 3 trial，晋级门槛 min_delta = 1 分。**注意有 token 惩罚**——所以"零额外 token 的确定性代码"天然占优，这也解释了为什么胜出的多是 ②b 而非 ②a。

## 🔬 Step 2｜核心结果（一手实测数字）

**基准 = Harvey LAB**（Legal Agent Benchmark，1251 个公开任务），切成 **24 个 dev（调参用）+ 100 个 test（held-out，只测一次）**。

**主结果（held-out 测试集，最可信）**：

| 指标 | 进化前 | 进化后 | 变化 |
|------|--------|--------|------|
| pooled criterion（各标准通过率） | 63.4% | **80.1%** | +16.7 点 |
| all-pass（整题全对率） | 0% | **5.0%** | +5.0 点 |

**dev 集**：pooled 63.1%→83.3%（**+20.2 点**），all-pass 到 4.2%。（dev 比 test 高属正常——dev 是被反复优化过的，test 才是真本事。）

**"同一个模型，五个分数"（最颠覆的一张表）**——同一个 DeepSeek 模型、同一个评判，套不同的现成 harness：

| Harness | pooled 通过率 |
|---------|--------------|
| Pi | 45.4% |
| Goose | 23.2% |
| mini-swe-agent | 3.5% |
| **原版 LAB（vanilla）** | **63.4%** |
| **进化后** | **80.1%** |

> **同一个模型，从 3.5% 到 80.1%——差距 20 多倍，全来自外面的脚手架。** 这就是"性能与模型无关（被低估）"这句话唯一站得住的证据：**换 harness 的方差，压过了大家平时纠结的换模型。** 注意 Pi（45.4%）都比原版 LAB（63.4%）低 18 个点——**好框架未必通用，得配着模型调**。

## 🔬 Step 3｜跨模型能不能迁移（最实用的一节）

进化好的 harness，换个模型还灵吗？一手给了明确答案：

| 换成的模型 | 相对表现 | 说明 |
|-----------|---------|------|
| DeepSeek-V4-**Flash**（同家族小号） | **+14.4 点** | 迁移得很好 |
| Nemotron-3 Ultra（**不同家族**） | +0.4 点 | 几乎没用 |

**结论（原文原话大意）**：**代码类/健壮性类的改动（②b）能跨模型迁移；提示词类的"打法手册"（②a）是模型专属的，换模型甚至会倒扣分。**

> 这条极其实用：你辛苦调的 prompt playbook 是"给这个模型量身定做的战术"，换模型要重调；但你写的**校验器、格式兜底代码是通用资产**，一劳永逸。**又一次印证：确定性代码 > 提示词。**

## 🔬 Step 4｜Karpathy 那半个故事（二手文的另一半来源）

二手文把 Niklaus 的实验和 Karpathy 的另一件事缝在了一起。Karpathy 侧的真相：

- 在自己的 **nanochat**（一个从零训 GPT-2 级模型的极简仓库）上，跑了一个 autoresearch 循环，**~700 次实验、约 20 处被采纳的改进**，把"训到 GPT-2 水平"的时间从 **2.02 小时压到 1.80 小时（快 ~11%）**。
- 仓库 `karpathy/autoresearch` **90,122 stars**（实查）。
- **注意**：Karpathy 这个是**优化训练配方/超参**（偏训练侧的自动搜索），和 Niklaus"冻结模型只进化 harness"**不是一回事**——但两者都指向同一个精神：**把'调优'这件事本身自动化、循环化，人退到设计循环的位置**。

> 二手文的合理内核：这两件事共同说明"**自动化的迭代循环（loop）** 是比'一次性调一个大模型'更被低估的杠杆"。但把它们的数字混着说，就成了标题党。

## 🤔 Step 5｜个人理解

**读完最大的洞察**：这篇的价值**不在"76%"这个噱头，而在一个反直觉的工程事实**——当你的 Agent 表现不好，第一反应"换更强模型 / 微调"往往是**最贵且收益最不确定**的路；而**"给它加几行兜底校验代码"这种最不性感的操作，反而是投入产出比最高的**。`deliverable_landing_gate`（把写错地方的文件挪回去）就是活教材：模型不是不会做题，是**交卷姿势错了**，一段死代码就救回一大截分。

**第二个洞察：为什么是确定性代码赢？** 因为打分公式里有 **token 惩罚项**，而"聪明的提示词"往往要靠更长的思考/更多 token 换来，性价比被压低；确定性代码零 token 还稳定。**这提醒我：设计自动优化循环时，'奖励函数'里塞什么，直接决定它进化出什么形态。** 想要省钱的 harness，就在 reward 里罚 token——它真会照着长。

**类比**：模型是个**能力极强但马虎的天才实习生**。你有两条路让他产出更好：(A) 送他去再读个博士（微调模型，贵、慢）；(B) 给他一套**清单 + 自动检查工具**——"交之前核对文件名、放对文件夹、跑一遍格式校验"（进化 harness，便宜、可迁移）。这篇用数据证明：**大多数时候 (B) 的边际收益被严重低估了**。

**我最警惕的过度解读**：标题"**与模型无关**"是错的。一手数据明明白白——Pi 框架比原版低 18 点、prompt playbook 换家族模型就失效——**harness 和模型是强耦合的**。准确的说法是"**harness 的优化空间被低估了**"，而不是"模型不重要"。模型是天花板，harness 决定你离天花板多近。

## 💭 思考与追问

1. **我真正理解了什么？**
   我理解了"进化 harness、不训模型"进化的是**第②层脚手架**（提示词+工具+校验代码），且一手数据显示**最强改动集中在②b 确定性代码而非②a 提示词**（top 6 里 5 个是代码），根因是打分公式带 **token 惩罚**、且代码类改动**可跨模型迁移**而提示词不能。我也厘清了二手爆款文的"76%""1/7 成本""与模型无关"是**拼接/夸大**——一手诚实数字是 held-out **63.4%→80.1%（+16.7 点）**，且 harness 与模型强耦合（Pi 反而比原版低 18 点）。

2. **我还没搞懂什么？**（汇入 open-questions）
   - **Meta-Harness 的晋级判据会不会过拟合 dev？** min_delta=1、3 trial 取均值，dev +20.2 点但 test 只 +16.7——这 3.5 点差距是正常泛化损耗还是轻度过拟合？判定标准是什么？

   - **二手文的"1/7 成本"到底从哪来？** 一手只给了 token 单价（≈20 倍价差）和单次跑 $120–160，没有"1/7"。是某个特定对比口径，还是纯误传？
