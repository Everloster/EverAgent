# vLLM 课 6：vLLM 最后一公里：采样与输出

## 场景 1：最后一公里：从 logits 到你看到的文字

大家好，欢迎回来。今天我们开启新的一讲——『最后一公里：从 logits 到你看到的文字』。先抛一个问题：模型在 GPU 上算了半天，产出的 logits 其实只是词表上的一个概率分布，还不是文字。那这堆数字，是怎么一步步变成你屏幕上逐字蹦出来的回答的？这就是今天要拆的链路。  先看来路。前五讲我们解决的是『算得快』：调度、批量执行、KV cache 复用——这些功夫全发生在引擎的『后厨』里。但算得快只是半个故事，菜炒得再快，客人没见到、没吃上，也等于零。  所以本讲换到前台视角，解决两件事：『说得对』和『看得见』。对应到链路上——采样层决定『说什么』，输出层决定『何时被看见』。一个问题在厨房，两个问题在前厅。  完整链路四步走：起点是 logits，词表上每个 token 的概率分布，可以理解为模型的『原始意图』；接着 sampling 从这份分布里采样出 token，决定这一步说什么；然后 detokenize 把 token 增量解码成文字；最后 streaming 把文字流式推送到你的屏幕上。四步走完，回答才算真正到了你手上。  记不住顺序没关系，用餐厅的类比串一遍：后厨已经把菜炒好了——这是 logits；装盘，夹哪块、摆多少——这是 sampling；一路小跑端上桌——这是 streaming。注意，这三步各有各的讲究：装盘摆烂、上桌拖延，菜炒得再快，客人的体验照样崩。  本讲就围绕五个关键词展开：sampling、detokenize、streaming，还有 logprobs——也就是采样时保留下的对数概率——以及 structured output，让模型按 JSON 这类固定格式说话。接下来，我们从 sampling 开始，一步步走完这最后一公里。

## 场景 2：采样第一步：logits 变概率，temperature 调软硬

接下来进入采样环节的第一步。模型每一步会给词表里的每个 token 打一个 logits 分数，也就是未经归一化的原始打分；softmax 负责把这组分数变成一个加起来等于一的概率分布。在这一步里，唯一的调节旋钮就是 temperature。  看这个公式：分子对每个 token 的分数做指数放大，分母负责归一化。关键在指数上除的那个 T——它一变，整个分布的形状就跟着变，是尖还是平，全由它说了算。打个比方，temperature 就像调酒师手上的配方比例旋钮。  T 小的时候，分布更尖。就像一位严格的调酒师，只照经典配方走，永远只调最稳的那一杯——分数最高的 token 几乎拿走全部概率，其余基本没戏。输出稳定、可预期，但也偏保守。  反过来，T 大的时候分布摊平。调酒师开始自由发挥，稀有搭配也可能被端上来——低分 token 也分到可观的概率，输出更多样、更有惊喜，当然也更容易翻车。  最后记一个特例：temperature 等于 0，分布退化成单点尖峰，等价于 greedy decoding——每步只选分数最高的 token，零随机性。小结一下这一页：softmax 管打分变概率，temperature 管分布尖还是平。带着这个旋钮的概念，我们继续往下看采样怎么选 token。

## 场景 3：截断直觉：top_k 与 top_p 只留靠谱候选

接下来看采样环节里最实用的一个直觉——截断。top_k 和 top_p 这两个参数，本质上在做同一件事：把候选集砍到只剩靠谱的那几个 token。  为什么非截断不可？因为概率分布的长尾里全是低概率 token，按概率采样时它们偶尔也会中签——一旦抽中，输出就是一段莫名其妙的胡话。所以采样之前先截断候选集，是性价比最高的一道护栏。  先看 top_k，它是固定名额制：不管分布长什么样，只保留概率最高的 K 个 token。好比酒吧只备最受欢迎的几款基酒，冷门的干脆不进货。名额固定，不随分布松紧变化——分布很尖时可能名额浪费，分布很平时又可能不够用。  再看 top_p，也叫核采样，也就是 nucleus sampling：按概率从高到低累加，保留累计概率刚好达到 p 的最小集合。这是『看情况录取』——分布越尖入围越少，越平入围越多，录取线随分布松紧自动浮动，比 top_k 的死名额更自适应。  一句话记住区别：top_k 是固定名额，top_p 是看情况录取。中间这个 vs，就是两种截断哲学的分界线。  不管选哪种策略，截断之后的流程都一样，看这条三步流水线：先截断候选集，再对剩下的概率重新归一化，最后按概率采样。重新归一化这步千万别漏，否则剩余概率加起来不等于一，采样就失真了。  最后一点：top_k 和 top_p 不是二选一，可以叠加使用——常见做法是先 top_p 截掉长尾，再套一层 top_k 兜底设上限。工程上两个一起调，胡话率能压得很低。小结一下：截断是为了砍掉长尾胡话，top_k 名额固定、top_p 动态入围，截断后归一化再采样。

## 场景 4：增量 detokenize：像活字印刷一样只排新字

接下来我们看输出的最后一步：detokenize，也就是把模型吐出的 token ID 变回用户能读的文字。不管前面算得多快，这一步都是必经之路，所以它做慢了，整个输出就慢了。  先看一个反例。如果每来一个新 token，就把整段文本从头到尾重新解码一遍，单步成本就是 O(n)——回答越长，每生成一个字都更贵，输出到后面越来越慢，这是不可接受的。  vLLM 的做法是增量 detokenize：每一步只解码新到的那一个 token，之前的结果原样复用。单步成本降到 O(1)，不管输出已经多长，每一步都一样快。  这就像活字印刷：排版工人只把新取来的字模排上版，已经排好的版面绝对不碰。没有人会每加一个字，就把整版拆掉重排一遍——道理是相通的。  但这里有个容易踩的坑：一个新 token 可能只是某个汉字 UTF-8 字节的不完整片段。这时候不能急着输出半个乱码，要先缓存，等下一轮字节补齐了再一起交给用户。记住这三点——只解增量、复用旧结果、不完整字节先缓存——vLLM 的长输出就能一直保持稳定流畅。

## 场景 5：流式输出：按调度 interval 定期吐字

接下来我们看流式输出。核心就一句话：模型边生成边把文字返回，用户不必干等整段生成完毕，体验上文字是逐渐'长'出来的。  这里有个容易被误解的细节：vLLM 不是每生成一个 token 就立刻发一次——token，也就是模型输出的基本词元。吐字节奏真正跟的是调度 interval，也就是调度器的固定周期。所以文字是一阵一阵推送的，而不是一字一发。  具体机制看这张表。每到一次 interval，引擎会收集所有 running 请求在这一轮新增的 token，批量产出增量结果。注意过滤规则：本轮没有新产出的请求，不会出现在结果里；只有攒到了新字的请求，才会被筛出来推送给用户。  还是用铁路道岔来理解最直观：道口不是来一节车厢就放行一次，而是按班次放行——哪个班次到了、哪条线攒够了新车厢，就发哪条。流式吐字完全同理：攒够再发，不来一节放一节。  小结一下这页：流式输出按调度 interval 定期吐字，每轮批量收集增量，只推送有新产出的请求。记住'攒够再发'这四个字，这个机制就通了。

## 场景 6：logprobs：给每个 token 打上置信度

接下来我们看 logprobs——给每个 token 打上置信度。模型生成时其实像个调酒师：采样负责按配方比例倒出下一个原料，而 logprobs 则把配方上每种原料的精确比例都报给你听。  定义很简单：候选 token 在当前前缀下的对数概率，也就是概率取个 log。值域从负无穷到 0——越接近 0，模型对它越有把握；越往负无穷跑，说明越不确定。  写成公式就一行：token t 在给定前缀下的条件概率 P 取 log。为什么要多此一举取 log？因为概率连乘会数值下溢，log 之后乘法变加法，数字稳定又好算，这也是信息论里的惯用做法。  关键在这一条：logprobs 不是另起炉灶单独算的，它和采样共用同一个概率分布。看右边这条链——logits 行是整个词表的原始得分，softmax 把它变成分布、temperature 在这里生效，top_k 和 top_p 再做截断。采样从这里抽签，logprobs 就从这里取值，两者看到的是同一份账本。  它还可以按需返回概率最高的前 N 个候选，连同名次一起——默认榜单是 5 名。这就像看赛马赔率：不只告诉你哪匹马被看好，整个场子每匹马的赔率都摆在那里。  实践价值大多源于这一句：低 logprobs 往往意味着模型在犹豫。用它做置信度评估，再顺手把犹豫的低置信输出筛掉，就是质量过滤；它还能构造蒸馏数据的软标签——不只给学生一个标准答案，而是把每个候选的完整比例都给出去。  小结一下这页：logprobs 与采样同源同分布，是概率取 log 后的置信度标注，默认榜单长度 5，低分即犹豫。概念清楚了，下一页我们看请求参数里具体怎么开启它。

## 场景 7：Structured Output：铁路道岔保证输出合法

接下来我们看 structured output，也就是结构化输出。在 JSON 模式下，语法合法是硬约束——不是尽量合法，是必须合法。很多同学习惯在 prompt 里写「请务必输出合法的 JSON」，但这本质上只是恳求，模型只是大概率听话，总有小概率翻车。  真正可靠的做法，可以用铁路道岔来类比：道岔在列车到达之前就提前扳好，token 依次生成就像列车一节一节往前走，而岔路已经被封锁——列车想出轨都出不了，只能沿着合法轨道一路走到终点。  实现方式叫语法约束采样，分三步。第一步，把 JSON schema 编译成状态机。状态机就像一张地图，记录当前走到哪一步、下一步允许出现哪些字符。  第二步，状态机在每个状态给出当前的合法字符集；第三步，也是关键一步：每轮采样之前，把非法 token 的概率直接置零。注意顺序——约束发生在采样之前。这样一来，输出合法就从概率问题变成了确定问题，岔路是被物理封锁的。  最后强调一点：temperature 和 top_p 照常生效。约束只改变候选范围，不改变采样方式——好比在合法轨道上，列车想开多快依然是它自己的自由。这就是 structured output 能保证输出必然合法的原理。

## 场景 8：小测：最后一公里你通了吗

好，我们来到了这节课的最后一关——"最后一公里"小测。一共三道选择题，考的就是刚才我们一起走过的那段路。请独立完成，凭自己的直觉去判断，先不回头翻内容。  提交之后，我会陪你逐题复盘，把还没打通的地方一起理顺。放轻松，去试试吧。

**q1. 关于采样参数 temperature（温度，控制概率分布尖锐程度的缩放因子）、top_k 与 top_p（核采样，按累计概率动态截断），下列说法正确的有哪些？**

- A. temperature 越低，softmax 后的分布越尖锐，输出越保守确定；越高分布越平坦，输出越发散多样 ✅
- B. top_k 每步固定保留概率最高的 k 个 token，候选数量与分布形状无关 ✅
- C. top_p 按累计概率动态截断，分布尖锐时保留下来的候选可能很少 ✅
- D. temperature、top_k、top_p 都会改变 logits（模型输出的未归一化分数）的相对大小排序，因此都会改变 argmax 的结果

> 解析：A 正确：temperature 相当于调酒配方比例，低温把基酒比例放大（分布尖锐、口味确定），高温把各成分拉平（分布平坦、口味多变）。B 正确：top_k 是固定名额制，无论分布形状如何都恰好保留 k 个候选。C 正确：top_p 是动态累计制，分布越尖锐，达到累计概率 p 所需的候选越少。D 错误：temperature 只是等比缩放 logits，不改变排序；top_k 与 top_p 只做截断，概率最高的 token 始终被保留，因此 argmax 结果不受三者影响，它们改变的是采样空间而非最高分归属。

**q2. 在流式生成中，vLLM 的 detokenize（把 token id 还原为文本字符串的步骤）为什么采用增量式解码，即每步只为新增 token 做反查，并维护跨步的未完成字节缓冲？**

- A. 为了让每个 token 互相独立解码，避免 token 之间产生依赖
- B. 因为中文、emoji 等 UTF-8 多字节字符可能被拆进相邻的多个 token，必须与前序残留字节拼接才能正确解码；同时避免每步对全序列重复解码的开销 ✅
- C. 为了改变模型采样时的概率分布，使流式输出更流畅
- D. 因为 tokenizer 词表大小有限，一次性解码整段文本会超出词表容量

> 解析：B 正确：一个多字节字符可能被切到两个甚至多个 token 里，如果孤立解码单个 token，字节序列不完整就会输出乱码；增量解码把本次新增字节与上一步未完成的字节缓冲拼接，凑齐后再输出，同时每步只处理新增部分，复杂度从每步 O(n) 降为 O(1)。A 错误：恰恰相反，多字节字符要求跨 token 维护状态，并非彼此独立。C 错误：detokenize 发生在采样之后，不参与也不影响概率分布。D 错误：解码是按 token 逐个查表拼接字符串，与词表总大小无关。

**q3. 基于 grammar（如 GBNF、JSON Schema）的 structured output（结构化输出）约束，为什么能保证生成结果必然符合语法？**

- A. 模型生成结束后，用正则表达式校验并过滤掉不合法的输出
- B. 在 prompt 中加入输出格式示例，引导模型倾向于生成合法结构
- C. 每步解码前，把当前语法状态下不合法 token 的 logits（未归一化分数）置为负无穷，使其概率为零，采样只能发生在合法转移集合内 ✅
- D. 把 temperature 设为 0 走贪心解码，每步总能选出语法上最合适的 token

> 解析：C 正确：语法约束相当于铁路道岔——不是等列车开错了再拉回来，而是在每一步提前把非法岔路锁死。具体做法是在采样前将非法 token 的 logits 置为负无穷，softmax 后概率恰为零，无论 temperature、top_k、top_p 如何设置，采样都只能在合法集合内进行，因此任何一条完整路径都必然可被语法接受。A 错误：事后过滤不提供保证，失败时只能重试或丢弃。B 错误：prompt 引导只是提高倾向，没有必然性。D 错误：贪心选择只保证局部概率最高，与语法合法性无关；且 temperature 大于 0 时语法约束依然成立，靠的是 logits mask 而非降温。
