# vLLM 课 7：vLLM 投机解码：原理与三流派

## 场景 1：回顾与本讲目标

好，前面我们刚刚把 KV Cache 和采样这两块地基打牢了。这一讲，我们要站在它们之上，回答一个非常实际的问题：大模型推理的 decode 阶段，为什么慢得像挤牙膏？先花一分钟快速回顾，再看清今天的路线图。  第一个回顾点，KV Cache。它把历史 token 对应的 K 和 V 缓存下来，decode 每生成一个新 token，就不用把之前的内容重新跑一遍 forward，直接读缓存就行。一句话总结：算过的不重算，这是 decode 能一步步往前推进的前提。  第二个回顾点，采样，Sampling。每一步 forward 结束后，模型给出的其实是所有候选 token 的概率分布，采样决定的就是——这一步到底把哪个 token 挑出来输出。top-k、top-p、温度，调的都是这个挑选动作。  基础齐了，现在把今天的核心问题亮出来：decode 每一步只产出一个 token。打个比方，这就像一辆运力很强的大卡车，每次出车却只送一件货——慢的往往不是卡车本身，而是一趟一趟的往返。那这个瓶颈到底卡在哪？是算力不够，还是另有隐情？这就是我们今天要拆解的问题。  来看今天的学习路线，一共四站。第一站，定位真正的瓶颈，答案会有点反直觉——是带宽，不是算力；第二站，讲破解思路——起草-验证，让'实习生'批量写草稿，'老板'只负责签字校对，一次确认多个 token；第三站，横向对比三大流派：ngram、Medusa 和 EAGLE；最后一站，落到两个关键指标——接受率与回退，草稿写得再多，通不过校对也得回炉。路线清楚了，我们这就出发，先去把那个真正的瓶颈揪出来。

## 场景 2：Decode 为什么慢：带宽瓶颈

接下来我们进入一个很关键的问题：decode 阶段为什么慢？答案可能和直觉相反——卡住 GPU 的不是算力，而是内存带宽。  先看这个基础事实。decode 是逐个 token 生成的——每生成 1 个 token，模型就要完整地做一次 forward。  而每做一次 forward，就意味着整个模型的权重都要从显存里读一遍。注意，是每一个 token 都要读一遍全部权重——几十 GB 的参数，一次都不能省。  于是我们得到一个反直觉的结论：瓶颈在内存带宽，不在算力。GPU 大部分时间并不是在计算，而是在等数据从显存搬运过来——算力大量闲置，权重读取变成了每个 token 的固定成本。  我们可以用大卡车运货来建立直觉：一辆大卡车，每次只送一件货，马力再大也快不了，而且每一趟都必须跑完全程。对应过来，'一趟'就是把全部权重读一遍，'一件货'就是一个 token。记住这个画面——后面讲 continuous batching、量化这些优化手段时你会发现，它们本质上都是在让这辆卡车一趟多拉几件货，或者把货做得更轻。

## 场景 3：投机解码核心思路

好，接下来我们进入今天的重头戏——投机解码。它的核心思路一句话就能说清：让便宜的小模型打草稿，让大模型来验证，一次 forward，就能白赚好几步。为什么能'白赚'？我们一步步拆开看。  第一步，小模型起草。我们选一个便宜得多的小模型——比如参数量只有大模型几十分之一的——按普通的自回归方式，一口气草拟出 k 个 token。小模型跑 k 步的开销，可能都赶不上大模型做一次 forward，所以起草这一步成本几乎可以忽略。  第二步，大模型批量验证。把这 k 个草稿 token 拼成一整段，一次性喂给大模型，只做一次 forward。关键在于，这一次 forward 会同时算出每个位置上大模型自己想输出的下一个 token——相当于把 k 份草稿一口气全部校对完了。  第三步，通过即白赚。从前往后逐个比对：草稿和大模型的判断一致，这个 token 直接入账；一旦碰到不一致的，就在那个位置用大模型的结果替换，后面的草稿全部作废。所以只要草稿猜得准，一次 forward 就能一口气前进好几步，这就是提速的来源。  打个生活中的比方：实习生把一堆文件都写好，老板不需要一份一份地看，而是翻一遍、统一签个字——签一次字，批一堆活。实习生就是草稿模型，老板就是大模型，'签一次字'就是那一次验证用的 forward。  最后强调一个最关键的点：大模型验证时做的计算，和它正常解码时做的计算是一模一样的，输出分布完全不变。所以投机解码是严格无损的加速，这是它和量化、蒸馏这类'有损换速度'的方法本质上的区别。好，思路清楚了，那草稿模型到底怎么选、猜错了会不会反而亏？我们接着往下看。

## 场景 4：流派一：ngram 零成本草稿

接下来一个关键问题：草稿到底从哪来？我们看第一个流派——ngram 零成本草稿。它是所有草稿方案里最轻量的一档：不用训练小模型、不加任何参数，草稿纯靠查表查出来，可以说是白捡的加速。  先解释名词：ngram 就是连续 n 个 token 组成的片段，比如「import numpy」就算一个 2-gram。它背后的假设很朴素——语言里大量内容是重复的，历史里出现过的片段，后面跟的内容很可能还会再出现。所以草稿不需要模型来生成，直接从 prompt 和生成历史里查表复用。  具体分三步走。第一步，圈定匹配源：prompt 加上已经生成的历史，这些文本现成就有，一分钱不花；第二步，查表：拿当前位置最近 n 个 token 做后缀匹配，在历史里找一模一样的片段；第三步，命中之后，把那个片段后面的内容直接搬过来当草稿——相当于自己抄自己写过的话。  草稿出来之后，校对环节还是老规矩：这批草稿 token 交给大模型一次 forward 并行验证，猜中的直接采纳。所以就算查表查歪了，代价也很小——大不了这一轮不加速而已，不会出错。  那什么时候用它最划算？重复性强的内容：代码里的样板、固定模板、术语反复复读，这些场景历史里全是可复用的片段，命中率很高。但局限也很明显——全新内容基本猜不中，比如续写一段从没出现过的创意文案，查表十次九次落空。好在它零成本、无额外参数：有得赚就加速，没得赚也不亏，所以工程上经常把 ngram 默认打开，当成一份免费午餐。

## 场景 5：流派二：Medusa 多头同猜

看完了第一种靠小模型代笔的流派，我们再来看第二种思路——Medusa 多头同猜。Medusa 这个名字取自希腊神话里长着好多蛇头的怪物，起得很形象：一个身体，多个脑袋。它的想法是，不另请草稿模型，而是让主模型自己多长几个头出来，一起猜。  先看核心结构：主模型保持原样不动，在它顶层的隐藏状态上，额外接出若干个解码头。注意，这些解码头不是独立模型，就是几层很小的网络，训练起来也便宜。所以它和双模型方案最本质的区别在于：草稿能力是长在主模型自己身上的。  关键就在这一句：主模型共享 forward。一次前向计算跑完，主干正常输出一个 token，同时几个解码头从同一个隐藏状态里各自读出自己的猜测。换句话说，猜测几乎是搭顺风车完成的，不需要单独再跑一遍模型。  你看这三个解码头，面对同一个位置，一个交出候选 1，一个交出候选 2，一个交出候选 3——同一时刻，三条路一起摆上了桌。这就是『多头同猜』里『同』字的含义：猜的是同一个位置，只是各自下注。  那这么多候选怎么验证？这就要请出 tree attention 了。把所有候选 token 组织成一棵候选树，一次 forward 并行验证整棵树，命中的路径全部收下。运气好的时候，一轮就能接受好几个 token，而验证成本始终只有一次前向。  这个流派的优点也很清晰：草稿头和主模型共享 forward，额外开销只有那几个小头的计算量，相比养一个独立的草稿模型，几乎可以忽略不计。省了内存，也省了调度两个模型的麻烦。  还是打个比方：这就像一个人同时打几份草稿——不用雇实习生，自己顺手多写几份，然后老板把这几份草稿拿来一次性批完。好，Medusa 的思路我们总结成一句话：不动大模型本体，外挂几个头同时猜，再用 tree attention 一次验完。带着这个印象，我们接着往下看。

## 场景 6：流派三：EAGLE 特征层预测

好，接下来登场的是三大流派的最后一位选手，也是目前实战中接受率表现最好的一派——EAGLE，特征层预测。注意，它和前两派的做法有一个本质区别，我们马上展开。  先看它最核心的一句话：在特征层，也就是隐状态（hidden state）这一层去预测下一个 token，而不是只看 token 本身。回想一下，ngram 看的是已生成的 token 序列，Medusa 虽然加了神经网络头，但输入也是 token 的 embedding。而模型 forward 的时候，每个位置其实都会算出一个高维隐状态向量，那里的信息量比 token 大得多。EAGLE 就是直接把预测的起点搬到了隐状态上，信息更丰富，起点就高了一截。  它的核心直觉特别妙：模型的中间特征其实已经'知道'接下来要说什么了，只是还没走到输出那一层。打个比方，Medusa 像是听老板说了上半句去猜下半句，而 EAGLE 是直接读心——老板脑子里其实已经想好了整句话，草稿头要做的就是把这一层'心思'读出来，提前把稿子写好。  更划算的是，这个草稿头本身非常轻量，它和主模型共享底层表示，训练开销小。而且因为草稿是从信息更丰富的隐状态里读出来的，草稿质量天然更高，所以接受率通常比 Medusa 还要好——相当于这位实习生不但便宜，起草的稿子还更接近老板真正想说的话，返工率自然就低了。  最后我们用这张三大流派对比表，把今天这条线收拢一下。ngram 零额外训练成本，草稿全靠统计规律，接受率看运气；Medusa 需要训练额外的解码头，吃的是 token 层信息；EAGLE 从隐状态出发，草稿头轻量、与主模型共享表示，接受率通常最高。一句话总结这条主线：草稿的信息来源越接近模型真实的'想法'，接受率就越高。记住这个规律，后面讲工程实现和参数调优时，我们会反复用到它。

## 场景 7：接受率与回退

刚才我们把"草稿批量校对"的完整流程走了一遍，就像实习生写好一整段、老板一次性签字。这一页回答两个非常实际的问题：这份草稿到底能通过多少？没通过的部分又怎么处理？先看第一个关键词——接受率。  统计口径要抠清楚：分子是这一轮被大模型接受的草稿 token 数，分母是草稿 token 总数——两边都只数草稿，大模型自己补写的那个不算进来。举个例子：草稿模型一次写了 5 个 token，大模型点头通过了 3 个，那这一轮的接受率 α 就是 3 除以 5，等于 0.6。  为什么要盯住这个数？回想一下，普通的自回归解码就像大卡车每次只送一件货；而接受率足够高时，大模型一次 forward 就能直接产出 k+1 个 token，一趟把车装满。反过来，接受率一旦掉下来，很多轮只能白捡一两个 token，还要付回退的代价，加速比就明显缩水。所以接受率基本决定了这套机制能赚多少。  那被拒绝了呢？看这一排草稿：t1、t2、t3 都顺利签字，到 t4 大模型摇头了——分布对不上。这里的规则很关键：回退不是整轮作废回到开头，而是只回到第一个出错的位置，前面已经通过的三个 token 全部保留。具体动作是：把 t4 和它后面的 t5 整体丢弃，后面的草稿猜得再准也不作数；然后由大模型在这个出错位置亲自重新采样 1 个 token，把坑填上。  正因为出错的地方永远由大模型亲手补写，我们才敢打包票：最终输出和纯大模型逐步解码的结果逐 token 完全一致——这就是无损保证，加速是白捡的，质量一点不打折。这一页记住三句话：接受率决定加速上限；拒绝后从第一个出错位置回退、丢弃其后全部草稿；重新采样兜底，输出永远无损。带着这三条，下一页我们看实际的加速比到底能到多少。

**q1. 大模型推理的 decode 阶段（逐个生成 token）为什么说瓶颈主要来自访存带宽而不是算力？**

- A. 每生成一个 token 都要把全部模型权重从显存搬进计算核心一次，而单步计算量很小，GPU 大部分时间在等数据搬运，好比大卡车每次只送一件货 ✅
- B. decode 阶段每次的矩阵乘法规模巨大，GPU 算力被跑满，因此瓶颈在计算而非访存
- C. KV Cache（缓存历史注意力的键值）容量不足，导致必须反复重算前面所有 token 的表示
- D. 采样算法（如 top-p 采样）本身的计算开销远超模型一次 forward 的开销，成为主要瓶颈

> 解析：decode 阶段是典型的访存受限（memory-bound）：每个 step 只处理一个 token，却需要读一遍全部权重，算力利用率极低，带宽才是瓶颈——这正是投机解码能提速的前提（批量验证把多次访存合并成一次）。B 说反了，逐 token 解码时算力远未跑满，compute-bound 的是 prefill 阶段；C 错在 KV Cache 的作用恰恰是避免重算历史 token；D 错在采样开销相对模型 forward 可以忽略。

**q2. 关于投机解码（speculative decoding）“起草—验证”的流程与无损性，下列说法正确的是？**

- A. 起草方先快速产出若干草稿 token，目标大模型一次 forward 并行校对整批草稿（好比草稿批量校对），通过拒绝采样保证输出分布与单独用大模型解码完全一致，即严格无损 ✅
- B. 验证环节由小模型对草稿 token 打分，被拒绝的 token 直接丢弃且不做任何补充采样，因此输出质量可能下降
- C. 大模型需要对每个草稿 token 分别单独跑一次 forward 逐个验证，所以总耗时与普通解码相同
- D. 为了换取吞吐提升，投机解码允许牺牲一定精度，把接受阈值调低来多接受一些低概率草稿 token

> 解析：正确流程是：起草方（实习生）快速写草稿，大模型（老板）一次 forward 批量验证多个位置，验证通过即可一步确认多个 token，把多次串行访存合并为一次，这是加速的来源；拒绝采样保证与大模型单独解码同分布，因此严格无损。B 错在验证者应是目标大模型，且拒绝后必须按修正分布补采样一个 token，不会丢内容；C 错在批量并行验证正是提速关键，逐个验证就没有收益；D 错在标准投机解码是无损的，不存在调阈值牺牲精度的说法。

**q3. Medusa、EAGLE、ngram 三个起草流派的草稿来源各不相同，且验证被拒时有统一的回退规则。下列描述正确的是？**

- A. Medusa 靠接在主干上的多个额外解码头并行猜多个位置的 token，EAGLE 在特征层自回归地预测下一个特征再解码，ngram 从 prompt 或已生成序列中查表复制片段；某个 token 被拒后，回退到该位置按修正后的残余分布重新采样一个 token，其后所有草稿全部作废 ✅
- B. 三个流派都用同一个独立小模型（draft model）来起草；某个 token 被拒后，为保留草稿劳动成果，其后的草稿 token 继续有效
- C. Medusa 通过查 ngram 表起草，EAGLE 使用独立小模型起草，ngram 流派使用多头并行起草；token 被拒后直接原样接受该草稿 token
- D. 三个流派草稿来源完全相同，区别只在大模型验证的频率高低；token 被拒后需要从头重新生成全部草稿再整体验证一遍

> 解析：三流派草稿来源：Medusa 是在主干模型上加多个解码头并行预测若干后续位置（自起草）；EAGLE 在特征（隐层表示）层面自回归地预测下一特征再映射回 token（自起草，效果通常更好）；ngram 是检索式，直接从 prompt 或已生成文本里按 n 元匹配复制片段。它们与“独立小模型起草”这一经典流派并列。回退规则：在第一个被拒位置，按 max(0, 目标分布 − 草稿分布) 归一化后的残余分布重新采样一个 token，同时丢弃其后全部草稿——因为草稿是串行依赖的，前一个错了后面不可信。B 错在三个流派来源不同且被拒后草稿必须作废；C 把三者的来源张冠李戴，且被拒 token 不能原样接受；D 错在来源并不相同，回退也只是局部重采样而非推倒重来。
