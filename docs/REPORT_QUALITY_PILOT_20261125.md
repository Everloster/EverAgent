## 四篇代表稿：两种视角分别看什么

上一轮的 f 偏向执行方法；这轮先总结材料，再提取观察框架。下面使用真实稿件片段对照，阅读效果仍待用户评价。

### Agent 评测

[打开新稿](../ai-learning/reports/knowledge_reports/Agent评测_任务评分器与运行记录的校准_深度解析_20261125.md)

上一轮的 f：

> 把任务要求落实为可检查的交付，再用参考解、空结果、错误捷径和合法替代解检验评分器；按任务保留每次运行，分别统计一次成功与重试表现。

现在的概述：

> Hugging Face 用拉曼光谱展示两种评测失灵：Agent 宣布完成，却没有保存结果；交出了正确的峰强度比，却没有做要求的拟合。文章从反例出发，讨论任务定义、评分器、运行记录和重试指标怎样决定分数的含义。

> 应先确认检查方法能区分正确解、空结果和错误捷径，再解释模型成绩。保存版本、公开可审查部件和区分污染与饱和，让评测能够继续被修订。 [原文](https://huggingface.co/blog/agentic-evals)

> **提炼句：** 可信的分数，首先需要可信的测量方法。

现在的取景框：

> **f：** 把 Agent 评测看成一套测量系统：任务说明定义要测什么，环境决定能做什么，评分器决定什么算完成，运行记录说明结果怎样产生。模型只是其中一个变量。

> **f(x)：** 同一个高分，可能来自真实完成能力，也可能来自评分漏洞；同一模型的分数变化，也可能来自环境或判定条件。选模型前先审查测量对象，使用 pass@3 时还要知道怎样从多次尝试中识别正确解。

### NVMe KV 缓存

[打开新稿](../ai-learning/reports/knowledge_reports/NVMe_KV缓存_命中保留时间与写入寿命_深度解析_20261125.md)

上一轮的 f：

> 先用同容量实验分清读取成本，再看 GPU 与外部池各承担多少命中、加载能否藏进排队时间；最后把会话恢复间隔、容量和持续写入联系起来。

现在的概述：

> AMD 与 Embedded LLM 使用 MoRI UMBP，在 16 张 MI355X 上比较同为 1.8 TB 的 DRAM 与 NVMe 缓存池。繁忙 Agent 负载的吞吐接近，与命中率、GPU 已保留的状态以及读盘能否和排队重叠有关。

> 扩容收益主要来自前缀留得更久，长期运行还要计算持续写入与 SSD 寿命。介质延迟、保留容量和耐久预算应分开衡量，再放回请求时间线。 [原文](https://vllm.ai/blog/2026-11-23-skip-the-dram-tier)

> **提炼句：** 缓存的价值既在取得快，也在下一轮来时它还在。

现在的取景框：

> **f：** 把缓存看成随时间运转的保留系统：会话间隔决定要留多久，写入与淘汰决定能留多少，调度决定加载增加多少等待。介质速度只是其中一个变量。

> **f(x)：** 同容量比较回答读取代价，扩容比较回答保留收益，DWPD 回答长期写入负担。只有对应自己的命中分布和负载，才能判断吞吐结果是否可迁移。

### 沈驿康：RSI 与预训练

[打开新稿](../podcast-learning/reports/2026-11-25_zhangxiaojun_158-rsi-pretraining.md)

上一轮的 f：

> 按改变的对象拆开研发闭环、部署后的学习与个人状态，再检查基线、反馈和验证过程；预训练部分则回到数据、数值误差和规模外推的具体条件。

现在的概述：

> 沈驿康区分 AI 参与模型研发、部署后积累能力、个人 Agent 理解用户，并讨论预训练的数据配比、数值稳定、rollout 与训练差异和规模外推。

> 应先确定改进对象，再选择验证：研发闭环比较冻结基线，持续学习看新任务迁移与旧能力保留，个性化分清上下文、记忆和参数更新。RSI“50%”是嘉宾的主观分法。 [节目](https://www.xiaoyuzhoufm.com/episode/6b05746801b0ab432eddab62)

> **提炼句：** 先问哪里发生了改变，再问凭什么说它更好。

现在的取景框：

> **f：** 从改进对象和反馈闭环看进步。研发方法、参数、外部记忆和运行输入各有作用，实验、用户反馈与长期使用又有不同验证时钟。

> **f(x)：** 更懂用户不必然更新了权重，改好 kernel 不必然自动化整条研发链。局部收益要回到原目标检验，数据、精度和规模变了，外推依据也可能失效。

### 蒋冠军：Personal Agent

[打开新稿](../podcast-learning/reports/2026-11-23_ai-lianjinshu_jiang-guanjun-personal-agent.md)

上一轮的 f：

> 把一次代办拆成理解目标、取得相关记忆、调用可用服务、满足授权和确认结果，再检查哪些失败能通过任务、工具与训练环境的对齐减少。

现在的概述：

> 蒋冠军以航班延误赔偿测试展示组合能力：用户只接受现金，航空公司先给代金券，Agent 继续沟通并拿回七十元。随后讨论记忆、授权、工具路径、后训练和完整任务成本。

> 一次成功展示能力上限，日常使用依赖可靠下限。长期目标比单次代办更难；升级模型可能撤掉临时补丁，但用户需求、服务与评测仍可积累。 [节目](https://www.ximalaya.com/sound/1034046447)

> **提炼句：** 一次办成让人愿意试，反复办成才让人敢托付。

现在的取景框：

> **f：** 从能力上限与服务下限看助理。探索新产品关心有没有办法，日常服务关心同类任务能否反复达标，以及失败时怎样发现和处理。

> **f(x)：** 模型、记忆与工具要放进同一代办链检查。确认是执行条件，相关性与失效是记忆条件；一次成功或上下文减少不能直接换算成总体成功率和费用收益。
